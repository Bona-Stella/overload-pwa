## 3. 확정된 제품 정책

### 3.1 가입·인증·계정

- 신규 사용자 회원가입 필수. Google SSO / 이메일 6자리 일회용 인증코드 지원. 이메일 비밀번호 / Apple 로그인 / 게스트 제외.
- 회원가입과 로그인은 통합 진입 후 신규/기존 흐름을 구분한다. 닉네임은 선택이며 키·몸무게·성별은 가입 때 수집하지 않는다.
- 기존 계정 재인증 후 새 로그인 수단을 연결하고 새 수단 소유를 확인한다. 동일 이메일만으로 자동 연결·통합하지 않는다. Google은 제공자의 고유 계정 식별자를 기준으로 구분한다.
- 마지막 로그인 수단의 무조건 해제를 제한한다. 계정 복구는 연결된 인증 수단을 사용한다. 독립된 두 계정의 운동 데이터 병합은 후속 과제다.
- 계정 탈퇴와 계정 유지형 운동 데이터 전체 초기화를 구분한다.

### 3.2 세션·로그아웃

- 정상적인 앱 재실행은 자동 로그인 유지. 종료·화면 잠금만으로 로그아웃하지 않는다. 명시적 로그아웃·탈퇴와 필요한 재인증은 별도로 처리한다.
- 운동 중 인증이 만료돼도 기존 운동을 지속한다. 완료 후 필요한 재인증을 수행하고 **동일 계정**의 미동기화 기록만 전송한다.
- 미동기화 로그아웃은 ‘동기화 후 로그아웃’과 ‘로컬 기록 유지 후 로그아웃’, 취소를 제공한다. 전자는 서버 저장 확인 후에만 완료하며 실패 시 원본/로그인을 유지한다. 후자는 이전 계정 전용 기록으로 보존하고 다른 계정의 조회·접근·전송을 막는다.
- 서버 저장 확인 전 미동기화 기록을 보호한다. 로컬 저장소의 유실 가능성과 운동 완료/로컬 저장/서버 저장을 구별한다.

### 3.3 로컬 우선·다중 기기·충돌

- Task 001–005 로컬 저장·복원 동작을 보호한다. 중요한 변경은 로컬 저장 후 동기화한다. 세트 완료·중량 승인/이벤트·유산소 상태 전환을 동기화 대상으로 검토하며 **타이머를 매초 서버에 보내지 않는다.**
- 같은 기록의 재시도/응답 유실이 중복 저장을 만들면 안 된다. 소유권·제어권·변경 버전·삭제/초기화 경계를 검증한 충돌 없는 변경은 자동 동기화한다.
- 진행 중 운동 세션 하나는 한 기기에서만 수정하고 다른 기기는 같은 계정의 해당 세션을 조회할 수 있다. 제어권 이전은 명시적 사용자 요청으로만 수행한다.
- 정상 이전은 기존 기기의 최신 기록 동기화 후 진행한다. 기기 사용 불가 시 서버 마지막 저장 상태와 누락 가능성을 안내하고 강제 이전할 수 있다. 이전 기기의 미동기화 기록은 최신 기록을 덮어쓰지 못한다.
- 서로 다르게 수정한 같은 데이터는 자동 덮어쓰지 않는다. 서버/로컬의 **차이점만 표시**, 누락·변경 수행 정보를 선택적으로 복구하고 **하나의 유효한 운동 세션**으로 통합한다. 원본은 복구 검증에 필요한 범위에서 보존하고 복구 확인 전 정상 동기화 완료로 표시하지 않는다.
- 같은 계정의 세션 충돌 복구는 독립 계정 간 데이터 병합과 다르다. 충돌 원본은 추가 운동 실적으로 중복 집계하지 않는다.

### 3.4 완료 기록 수정·삭제와 평가

- 과거 완료 운동 기록의 명시적 수정·삭제를 허용한다. 수정 전 정보·변경 사실과 삭제 사실을 추적할 수 있도록 설계한다.
- 현재 유효한 기록으로 기준 기록과 현재 점진적 과부하 평가를 재계산한다. 삭제된 기록/무효인 이전 버전은 현재 평가 근거에서 제외한다.
- 승인된 진행 중량은 자동 변경하지 않는다. 과거 승인 이벤트를 임의로 삭제·수정하거나 현재 재평가 결과로 대체하지 않는다.
- 당시 정보/판단과 수정 후 현재 판단을 구별한다. 원래 수행·판단의 보존/표현과 재평가의 관계를 설계한다.
- 단일 실제 세션 비교, 루틴/배치/구성/승인 중량별 기준, 부분·임시·혼합 기록 제외, 웨이트/유산소 구별 등 기존 정책을 유지한다. 비교 알고리즘을 이번에 교체하지 않는다.
- 삭제된 기록은 오래된 기기의 재동기화로 되살아나면 안 된다.

### 3.5 전체 초기화·탈퇴·개발 데이터

- 새 루틴 생성은 이력/기존 루틴별 진행을 유지한다. 전체 초기화는 계정/수단을 유지하고 루틴·웨이트/유산소 이력·진행 중 운동·승인 이벤트·관련 운동 기준을 삭제 대상으로 한다.
- 전체 초기화는 내보내기 안내, 본인 재인증, 최종 확인 필요. 과거 기기의 미동기화 기록이 초기화 이후 재생성되지 않도록 한다.
- 일반 기록 수정/삭제에서 승인 사건을 보존하는 원칙과, 명시적인 전체 초기화의 승인 이벤트 삭제는 적용 범위가 다르다. 탈퇴는 계정/수단까지 포함하는 별도 흐름이다.
- 기존 데이터는 **배포 전 개발용 테스트 데이터로 계정 이전 불필요**. 이번 문서 작업에서는 삭제하지 않는다. 실제 폐기 및 실사용 전환은 별도 기준/실행 절차를 설계한다. 실사용 데이터는 유실·중복·계정 간 노출을 막는다.

## 5. Task 006 기술 설계 대상 12개

아래는 **필요한 설계 결과와 검증 조건**이다. 구체적인 테이블/컬럼, 트랜잭션·락·버전 방식, 엔드포인트/HTTP 상태/DTO는 아직 확정하지 않았다.

| 번호 | 설계 대상 | 결정해야 할 내용과 충족 조건 |
