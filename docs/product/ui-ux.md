# Overload — 초기 UI/UX 명세 v1.0

- 작성일: 2026-10-26
- 디자인 결정: **다크 모드**, 모바일 퍼스트, 운동 중 **한 번에 한 종목 집중(A안)**
- 상태: **Task 002용 기능 와이어프레임 / 색상·크기 토큰은 초기 제안으로 실화면 검토 시 조정 가능**
- 기능 정의 기준: [`requirements.md`](./requirements.md)

## 1. UX 우선순위

1. 세트를 마친 직후 사용자가 할 일은 가능한 한 **`세트 완료` 한 번**이어야 한다.
2. 현재 운동 중량·기준 반복 횟수·이번 실제 입력·완료 여부를 혼동하지 않는다.
3. 운동 시간은 언제나 보이고, 오른쪽 타이머와 하단 버튼은 현재 상태에 맞춰 전환한다.
4. 기록 화면에서 다른 종목이나 루틴의 상세 설정으로 이동할 필요가 없도록 필요한 조작을 제공한다.
5. 예기치 않은 앱 전환/화면 새로고침 후에도 원래 진행 중이던 단계로 돌아온다.
6. 권고(증량/감량/디로딩)와 상태(완료/미완료)는 색상뿐 아니라 **텍스트**로도 전달한다.

## 2. 정보 구조와 이동

```text
[앱 실행]
 ├─ 진행 중인 세션 있음 → [홈의 '운동 이어하기'] → 저장된 운동 단계 복원
 └─ 진행 세션 없음 → [홈: 오늘의 루틴 자동 선택]
       ├─ [루틴 탭] → 루틴 목록 → 루틴 생성/편집 → 운동 종목 검색/추가
       ├─ [기록 탭] → 운동 이력 → 운동 세션 상세
       └─ [운동 시작] → [워밍업/스트레칭]
                            └─ [준비운동 완료] → [운동 진행: 현재 한 종목]
                                   ├─ 세트 완료 → [세트 사이 휴식]
                                   │                ├─ 휴식 종료
                                   │                └─ +30초
                                   ├─ 마지막 남은 세트 완료 → [현재 종목 완료 기록 + 경과시간]
                                   │                        ├─ 다음 종목으로 → [다음 미완료 종목 / 경과시간 유지]
                                   │                        └─ 남은 종목 없음 → [모든 종목 완료 / 운동 종료 및 요약]
                                   ├─ 종목 목록 → 현재 세션 내 다른 종목 선택/순서 변경
                                   ├─ 중량 변경 → 오늘만 / 진행 중량 변경
                                   ├─ 스크롤 하단 → 기구 세팅 메모
                                   └─ 운동 종료 → 미완료 세트 확인 → [운동 요약]
```

기본 탭바는 **홈 / 루틴 / 기록** 세 항목이다. 설정은 홈 헤더에서 접근한다. 운동이 시작되면 탭바를 숨기고 한 종목 집중 화면을 쓴다. 사용자가 의도적으로 종목을 고르는 메뉴는 제공하되 전체 종목을 한 스크롤 화면에 계속 나열하지 않는다.

## 3. 화면별 명세

### 3.1 홈 — `Home`

**목표:** 앱을 열면 별도 설정 없이 오늘의 운동을 시작할 수 있다.

```text
┌──────────────────────────────────────┐
│ OVERLOAD                       [설정] │
│ 월요일 · 오늘의 운동                  │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ PUSH DAY                         │ │
│ │ 벤치프레스 · 인클라인 · ...        │ │
│ │ [       운동 시작       ]        │ │
│ │ [  오늘만 다른 루틴 선택  ]       │ │
│ └──────────────────────────────────┘ │
│ 이번 주 일정  월 화 수 목 금 토 일    │
│ 최근 운동 (선택 표시)                │
│ ──────────────────────────────────── │
│       홈        루틴       기록      │
└──────────────────────────────────────┘
```

- 요일이 변경되면 해당 요일의 기본 루틴이 나타난다. **자동 시작은 하지 않는다.**
- 예정 휴식일에는 휴식일로 표시하되 수동 시작 진입을 허용한다.
- 이미 진행 중인 세션이 있으면 인사 문구보다 앞에 `운동 이어하기` 카드를 배치하고 인사 영역을 줄인다. 같은 세션이 새로 생성되는 것을 막는다.
- 오늘만 다른 루틴을 선택해도 주간 일정의 원본 매핑은 바꾸지 않는다.

### 3.2 루틴 목록 — `RoutineList`

- `새 루틴` CTA, 각 루틴의 이름/요일/종목 수/총 작업 세트 수, 편집·삭제 액션.
- 편집 저장 전에 중복 요일 지정이나 기존 루틴 덮어쓰기를 알린다.
- 삭제는 확인을 받는다. 과거 완료 운동 이력은 삭제하지 않는다.

### 3.3 루틴 생성·편집 — `RoutineEditor`

- **하나의 세로 스크롤 화면**에서 다음을 설정한다.
  1. 루틴 이름 (텍스트)
  2. 월→일 순서의 요일 버튼 7개 (복수 선택, 요일 미지정 허용; 내부 일요일 ID 0 유지)
  3. 운동 종목 카드들의 목록과 순서 변경 조작
  4. 카드별 본세트 수, 목표 최소 반복 횟수, 목표 최대 반복 횟수, 신규 종목의 최초 중량 kg / 기존 승인 중량 읽기 전용 표시
  5. 종목 추가/제거, 저장/취소
- 입력 검증: 이름 필수, 운동 1개 이상, 본세트 수는 양의 정수, `최소>0`, `최대>=최소`, 중량은 0 이상 유한한 숫자. 소수 중량 허용.
- 중량 단위는 첫 MVP에서 kg를 표시한다. 소수점 입력과 숫자 키패드를 제공한다.
- 최초 중량은 해당 진행 상태의 시작값이다. 승인 진행 중량이 있는 종목 편집 시에는 최초 중량 입력을 숨기고 **현재 진행 중량: NN kg**를 읽기 전용으로 보여준다. 운동 화면의 `중량 변경 → 오늘만 변경 / 진행 중량 변경 확인`으로 안내하며 기존 최초 중량을 덮어쓰지 않는다.
- 입력마다 즉시 원본 루틴을 바꾸지 않고 `저장` 시 갱신한다. 취소 시 편집 초안을 버린다.
- 키보드가 열렸을 때 `저장`이 가려지지 않게 스크롤/하단 영역을 처리한다.
- 세트 수, 반복 범위가 변경되면 기존 기준 기록과 비교하지 않는 **새 비교 구성**이 될 수 있음을 표시한다.
- 루틴 내 동일 종목 여러 배치 등 특수한 경우에도 각 배치의 진행 상태가 섞이지 않게 **안정적 식별자**를 유지한다.

### 3.4 운동 종목 선택 — `ExercisePicker`

- 종목 이름 검색, 선택 결과 목록, `사용자 종목 추가`.
- 종목을 선택하면 편집 화면의 기본값(예: 3세트, 6~10회, 최초 중량 미설정)을 가진 카드로 추가한다. 기본값은 시연용이며 사용자가 수정한다.
- 향후 부위별 통계를 위한 확장 가능성만 남긴다. Task 002에서 세밀한 근육 매핑을 강제하지 않는다.

### 3.5 스트레칭/워밍업 — `WarmupScreen`

```text
┌──────────────────────────────────────┐
│ 전체 운동 시간          00:07:35     │
│                                      │
│        스트레칭 & 워밍업              │
│        자유롭게 준비하세요            │
│        세트 기록 없음                │
│                                      │
│ 다음 운동: 벤치프레스                │
│                                      │
│       [  준비운동 완료  ]            │
└──────────────────────────────────────┘
```

- 운동 타이머는 **홈의 운동 시작 클릭 시점**부터 측정한다.
- 워밍업 세트, 휴식 카운트, 몸풀기 중량을 입력·저장하지 않는다.
- 새로고침/앱 전환 후에도 준비운동 단계로 복귀한다.

### 3.6 운동 진행 — `WorkoutExerciseScreen`

```text
┌──────────────────────────────────────┐
│ [전체 운동 00:42:18] [휴식 02:15]   │  ← 상단 고정
├──────────────────────────────────────┤
│ PUSH DAY                   [종료 ⋯]  │
│ [◀] 벤치프레스    1 / 5 종목    [▶] │
│ 목표: 6~10회 × 3본세트              │
│ 진행 중량: 60 kg 🔒  [중량 변경]     │
│                                      │
│  세트      기준        이번    완료  │
│   1         10          10      ✓    │
│   2          9           9      ○    │
│   3          7           7      ○    │
│                                      │
│ [현재 세션에서 세트/종목 변경]       │
│                                      │
│ 기구 세팅 메모 (아래로 스크롤)       │
│ ┌─────────────────────────────────┐  │
│ │ 높이 3 · 그립 눈금 2 ...          │  │
│ └─────────────────────────────────┘  │
├──────────────────────────────────────┤
│ [      현재 세트 완료        ]       │  ← 하단 고정
└──────────────────────────────────────┘
```

- **한 번에 한 종목만** 메인으로 보여준다. 현재 종목명/순서, 본세트/반복 목표, 승인 진행 중량을 분명히 한다.
- 세트별 `기준 기록`은 읽기 전용; `이번 기록`은 수정 가능한 값; `완료`는 사용자가 눌러야만 사실로 저장된다.
- 진행 중량을 직접 탭해서 몰래 수정되지 않도록 잠금 상태를 표현하고, `중량 변경` 명시적 진입을 제공한다.
- 좌우 이전/다음 및 종목 목록에서 현재 세션 내 종목을 선택한다. **종목 편집/교체는 현재 세션에만 적용**한다.
- 기본 기구 세팅 메모는 세트 영역 아래에서 접근한다. 메모 편집 내용은 해당 종목의 기본 메모로 저장한다.
- 모든 세트를 한꺼번에 자동 완료하거나, 이전 기준을 별도 확인 없이 오늘 실적으로 저장하지 않는다.
- 마지막 남은 본세트를 실제 완료하면 현재 종목에 머물러 완료 기록과 하단 `다음 종목으로`를 보여주고 상단으로 스크롤한다. 버튼을 누르면 세션의 현재 순서에서 이후 미완료 종목을 우선하며 필요하면 앞으로 순환한다. 다음 세트는 미완료 상태다. 언제든 이전/다음/목록에서 완료 기록을 확인하고 완료 취소·수정할 수 있다.
- 모든 종목 완료 시 완료 안내와 하단 `운동 종료 및 요약`을 보여준다. 세션과 전체 운동 타이머는 직접 종료할 때까지 유지한다. 자동 종료하지 않으며 탐색이나 복원만으로 자동 이동하지 않는다.
- 세트 행은 특정 세트의 완료/취소, 하단 CTA는 다음 미완료 세트의 빠른 완료를 담당한다. 두 경로를 유지하고 같은 완료 처리와 휴식 중 비활성화 규칙을 적용한다.

### 3.7 휴식 상태와 하단 버튼 — `RestState`

| 상태 | 상단 오른쪽 영역 | 하단 CTA |
|---|---|---|
| 워밍업 | `준비 중` 또는 `—` | `준비운동 완료` |
| 본세트 입력 대기 | `휴식 없음` 또는 `—` | `세트 완료` |
| 중간 세트 완료 직후 | **남은 휴식 03:00** 등 | `휴식 종료` / `+30초` |
| 휴식 자연 종료 | **00:00** 또는 `휴식 완료` | 다음 세트 `세트 완료` 조작 복귀 |
| 종목 마지막 남은 본세트 완료 | **이전 종목 완료 후 00:00부터 증가**, 현재 종목 기록 유지, 휴식 없음 | `다음 종목으로` |
| 버튼으로 다음 종목 이동 후 첫 세트 전 | **동일한 실제 완료 시각 기준 경과시간 유지** | `세트 완료` |
| 다음 종목 첫 세트 완료(중간 세트) | **남은 휴식**으로 재전환 | `휴식 종료` / `+30초` |
| 한 세트뿐인 종목 완료 | 현재 종목 완료 기록 및 경과시간 또는 전체 완료, 휴식 없음 | `다음 종목으로` 또는 `운동 종료 및 요약` |
| 모든 종목 완료 | **모든 종목 완료**, 경과/휴식 타이머 없음 | `운동 종료 및 요약` |

- 상단 왼쪽 **전체 운동 시간은 모든 상태에서 유지**된다.
- 휴식시간은 현재 운동 종목의 **목표 상한 반복 횟수**로 설정한다. 초기 시연용 구간은 추후 설정 가능하도록 한 곳에서 정의한다.
- `+30초`는 저장된 휴식 종료 예정 시각을 30초 연장하며, `휴식 종료`는 즉시 카운트다운을 해제한다.
- **마지막 남은 본세트에는 휴식을 시작하지 않는다.** 실제 완료로 미완료→완료가 된 이벤트에서 경과시간 기준을 저장하고 현재 종목의 기록과 `다음 종목으로`를 표시한다. 이동은 버튼으로 수행하며 기준 시각은 바꾸지 않는다. 모든 종목이 완료되면 오른쪽 보조 타이머를 해제한다.
- 종목 전환 경과시간 기준은 **화면 이동 시점이 아닌 이전 종목의 마지막 완료 세트 시각**이다.
- 수동 탐색은 새 타이머를 만들거나 기존 타이머의 기준 시각을 덮어쓰지 않는다. 다른 종목의 휴식은 해당 종목으로 돌아가면 원래 종료 시각으로 표시한다. 완료 취소/추가로 전환 근거가 사라지면 그 전환 타이머만 해제한다.
- 구 v1 세션에서 완료된 종목의 휴식 상태를 복원해도 카운트다운을 표시하지 않는다. 가장 늦은 실제 완료 시각부터 경과시간을 계산하고, 전체 완료라면 종료 CTA만 제공한다. 이 해석은 최초 로드 시 실제 기록이나 저장값을 덮어쓰지 않는다.
- 화면을 다시 열었을 때는 현재 시각과 저장한 기준 시각을 비교해 시간을 계산한다.
- 운동 화면에서 시간이 실제로 움직이는 상태는 UI 갱신으로 처리하되 저장값이 경과시간 계산의 출처다.

### 3.8 중량 변경 — `WeightChangeSheet`

- 단일 `중량 변경` 메뉴에서 현재 승인 진행 중량을 보여주고, 변경 중량을 입력한다.
- 선택지 두 개:
  - `오늘만 변경` — 오늘 운동 기록에만 새 중량 적용
  - `진행 중량 변경` — 명시적 확인 후 이후 정상 운동에도 적용
- 승인 전에는 진행 중량이 변경되지 않으며, 변경 후에도 과거 실제 기록은 보존한다.
- 새로운 승인 중량에서 기준 기록이 없다면 사용자 입력을 기다린다. **최소 반복 횟수로 자동 초기화하지 않는다.**
- 성공 안내 문구는 `중량 증가를 고려해 보세요`처럼 **권고형**으로 쓴다. 목표 하한 미달 시에는 `중량 감소를 고려해 보세요`.

### 3.9 운동 완료 요약 — `WorkoutSummary`

- 종료 전에 미완료 세트가 있으면 완료 세트만 기록될 것임을 확인한다.
- 종료 화면: 날짜·루틴명·전체 운동 시간·완료 본세트 수·총 볼륨·실제 종목별 수행 기록.
- 제목은 `운동 기록 저장 완료`(저장 실패 시 `운동 기록 요약`)이며 `완료 3/9 본세트`처럼 완료 범위를 표시한다. 계획을 모두 완료한 경우에만 `전체 루틴 완료`를 표시한다. 기존 임시 변경 이력에서 계획 수를 복원할 수 없으면 미확인으로 표시한다.
- 갱신된 기준 기록이 있다면 간단히 표시한다. 실적과 권고를 혼동하지 않게 한다.
- 로컬 저장 상태와 서버 동기화 상태는 다른 개념이다. Task 002는 서버 동기화 완료를 주장하지 않는다.

### 3.10 기록 및 설정 — `History` / `Settings`

- `기록`: 최신순 세션 리스트 → 날짜별 상세로 들어가 실제 중량·횟수·완료한 세트 확인. 차트는 후속 단계.
- `설정`: 반복 목표 상한 범위별 기본 휴식시간. 향후 로컬/서버 동기화 상태, 데이터 내보내기, 알림 설정 자리.

## 5. 반응형·상태 검증 체크리스트

### 기기·시각
- 375px / 390px / 430px 너비에서 가로 스크롤이나 중첩 없음
- 긴 종목명, 중량 소수점, 큰 반복 횟수에도 텍스트·입력칸 줄바꿈 적절
- Safe Area, 키보드, 하단 고정 버튼, 다크 모드 대비 확인

### 실제 사용
- 홈에서 운동 시작 후 가장 먼저 워밍업 화면 진입
- 한 종목 기록 → 휴식 자동 시작 → +30초 → 휴식 조기 종료 → 다음 세트
- 마지막 남은 세트 → 현재 종목 기록 및 다음 종목 버튼(휴식 없음) → 버튼 이동 전후 동일한 완료 시각 기준 경과시간 → 중간 세트 완료 후 휴식 표시
- 전체 완료 후 명시적 종료, 완료된 종목 재진입/취소/세트 추가, 순서 변경·앞쪽 미완료 순환, 버튼 이동 전후 및 구 v1 마지막 세트 휴식 상태의 새로고침 복원
- 종목 메모 스크롤 접근, 운동 종목 이동/원본 루틴 불변
- 완료 전 프리필 값은 실적·볼륨에 반영되지 않음
- 기준 `10/9/7`이 `10/8/6`으로 하락하지 않고 `10/9/8`일 때만 갱신
- 새로고침/앱 재진입 후 진행 화면·타이머 복구

## 6. Task 002에서 의도적으로 가볍게 만들 부분

- 실제 운영 PWA 오프라인 설치/백그라운드 알림/서버 동기화는 구현 완료라고 주장하지 않는다.
- 디로딩 제안·주간 부위 분석·성장 차트는 문서 요구사항으로 유지하되 Task 002 UI 범위에서 제외한다.
- 디자인 애니메이션, 차트 라이브러리, 대규모 컴포넌트 라이브러리는 필수 아님. 가능한 한 현재 Vite/React/TypeScript 환경에서 작은 재사용 컴포넌트로 구현한다.
- 첫 Mock UI는 흐름·사용성을 검증하는 **프로토타입**이며 최종 시각 디자인이나 최종 DB 설계가 아니다.
