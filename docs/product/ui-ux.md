## 1. UX 우선순위

1. 세트를 마친 직후 사용자가 할 일은 가능한 한 **`세트 완료` 한 번**이어야 한다.
2. 현재 운동 중량·기준 반복 횟수·이번 실제 입력·완료 여부를 혼동하지 않는다.
3. 운동 시간은 언제나 보이고, 오른쪽 타이머와 하단 버튼은 현재 상태에 맞춰 전환한다.
4. 기록 화면에서 다른 종목이나 루틴의 상세 설정으로 이동할 필요가 없도록 필요한 조작을 제공한다.
5. 예기치 않은 앱 전환/화면 새로고침 후에도 원래 진행 중이던 단계로 돌아온다.
6. 권고(증량/감량/디로딩)와 상태(완료/미완료)는 색상뿐 아니라 **텍스트**로도 전달한다.

## 2. 정보 구조와 이동

```text
[앱 실행]
 ├─ 진행 중인 세션 있음 → [홈의 '운동 이어하기'] → 저장된 운동 단계 복원
 └─ 진행 세션 없음 → [홈: 오늘의 루틴 자동 선택]
       ├─ [루틴 탭] → 루틴 목록 → 루틴 생성/편집 → 운동 종목 검색/추가
       ├─ [기록 탭] → 운동 현황 / 근육별 통계 / 성장 추적 / 운동 이력 → 세션 상세
       ├─ [설정 탭] → 계정 / 운동 설정 / 데이터 및 앱 / 계정 및 데이터 삭제 / 로그아웃
       └─ [운동 시작] → [워밍업/스트레칭]
                            └─ [준비운동 완료] → [운동 진행: 현재 한 종목]
                                   ├─ 세트 완료 → [세트 사이 휴식]
                                   │                ├─ 휴식 종료
                                   │                └─ +30초
                                   ├─ 마지막 남은 세트 완료 → [현재 종목 완료 기록 + 경과시간]
                                   │                        ├─ 다음 종목으로 → [다음 미완료 종목 / 경과시간 유지]
                                   │                        └─ 남은 종목 없음 → [모든 종목 완료 / 운동 종료 및 요약]
                                   ├─ 종목 목록 → 현재 세션 내 다른 종목 선택/순서 변경
                                   ├─ 중량 변경 → 오늘만 / 진행 중량 변경
                                   ├─ 스크롤 하단 → 기구 세팅 메모
                                   └─ 운동 종료 → 미완료 세트 확인 → [운동 요약]
```

기본 탭바는 **홈 / 루틴 / 기록 / 설정** 네 항목이다. 각 화면은 자체 제목을 사용하고 홈은 3.1의 상태별 헤더를 사용한다. 운동 화면과 루틴 편집에서는 일반 탭바를 숨긴다. 운동의 전체 시간·종목 위치·휴식 시간은 3.6의 공통 헤더에 둔다. 사용자가 의도적으로 종목을 고르는 메뉴는 제공하되 전체 종목을 한 스크롤 화면에 계속 나열하지 않는다.

## 3. 화면별 명세

### 3.1 홈 — `Home`

홈의 본문 순서는 **오늘의 루틴 → 운동 시작 → 오늘만 다른 루틴 선택 → 이번 주 일정 → 최근 운동**이다.

| 홈 상태 | 헤더 |
|---|---|
| 분석 ON · 디로딩 미진행 | 왼쪽 OVERLOAD → 공식 달 아이콘 → n.n/8주 → 짧은 수평 게이지. 날짜는 오늘 카드로 이동한다. |
| 분석 OFF · 디로딩 미진행 | 왼쪽 OVERLOAD, 오른쪽 공식 달 아이콘. 주수/트랙/헤더 날짜는 숨긴다. |
| 디로딩 진행 중 | 왼쪽 녹색 선형 초승달 SVG와 `디로딩 진행 중 · n일차`, 오른쪽 `일반 보기`. 왼쪽 영역에서 진행 상세에 진입한다. 일반 보기에는 읽기 전용 상태와 `디로딩 복귀`를 표시한다. |

- 큰 동기부여 카드, 별도 디로딩 상태 카드, 원형 추천 게이지는 제거한다. 진행 중 헤더에는 날짜와 별도 D1 장식을 표시하지 않는다.
- TODAY'S ROUTINE과 실제 날짜를 오늘 카드 첫 행 좌우에 배치한다. 구획과 핵심 글자 크기·선택 후 자동 닫힘·최근 종목 달성/무수행 필터·선택형 태그 규칙은 [최신 홈 결정](Overload_UI_Decision_Log_v0.9.md#1012--2026-11-06-홈-가독성헤더최근-운동-최종-보완)을 따른다. WEIGHT/CARDIO는 제목과 구분선으로 동등하게 나눈다.
- 오늘만 선택은 두 줄 펼침 목록이다. 첫 줄은 루틴명, 둘째 줄은 배정 요일(미지정 포함)과 저장된 순서의 대표 종목 최대 2개를 표시한다. 긴 이름은 줄임표를 사용한다.
- 주간 일정 칸은 날짜 / 요일 또는 상태 기호 / 루틴명 순서이며 과거 날짜의 기호는 [결정 로그](Overload_UI_Decision_Log_v0.9.md) 10.14.1절을 따른다. 긴 이름은 한 줄로 줄이고 선택하면 전체 이름을 확인할 수 있다. 일반 일정은 월~일, 디로딩 일정은 시작일부터 7일 및 8~10일차 구간이다.

- 요일이 변경되면 해당 요일의 기본 루틴이 나타난다. **자동 시작은 하지 않는다.**
- 일반 예정 휴식일에는 휴식일로 표시하고 당일 루틴 수동 선택을 허용한다. 디로딩의 완전 휴식과 일반 보기 제한은 3.11을 따른다.
- 이미 진행 중인 세션이 있으면 새 시작 대신 `운동 이어하기`를 제공한다. 같은 세션이 새로 생성되는 것을 막는다.
- 이어하기에는 짧은 상태 배지(`준비운동 중 / 운동 중 / 휴식 중 / 종목 전환 중 / 운동 종료 대기`), 전체 운동 시간과 완료 세트 수를 표시한다. 유효한 휴식일 때만 남은 휴식, 전환 타이머일 때만 완료 후 경과시간을 한 줄로 표시한다. 만료된 휴식은 `운동 중`으로 돌아오고 전체 완료는 종료 대기를 우선한다. 수동 종목 탐색 중에도 세션의 유효한 타이머를 기존 해석 함수로 읽으며 표시 자체는 저장을 발생시키지 않는다.
- 일반 홈에서 오늘만 다른 루틴을 선택해도 주간 일정의 원본 매핑은 바꾸지 않는다. 디로딩에서는 미수행 임시 루틴의 날짜를 맞교환한다.
- 라벨은 현재 선택 ID와 오늘 기본 ID를 비교한다. 같으면 `요일 기본 루틴`, 다르면 `오늘만 선택`, 선택 없음은 `REST DAY`다. 임시 선택 후 기본으로 되돌리면 기본 라벨이 즉시 복구된다. 기본이 없는 날의 수동 선택은 임시 선택이다.

### 3.2 루틴 목록 — `RoutineList`

[Decision Log10.14.2~3절](Overload_UI_Decision_Log_v0.9.md#1014--2026-11-07-t02-b-최신-ui-통합-기준)이 기준이다. 기본 가로7요일 타일/세로 한 줄 보기를 단일 아이콘으로 전환하고 요일 선택을 공유한다. 날짜 숫자와 상세 운동명은 타일에 넣지 않는다. 세로 오른쪽 공식18px 아이콘은 등록 종목 수다.

요일을 선택하면 해당 배정 루틴만 표시하고 단일 목록 필터가 요일명으로 잠긴다. 해제하면 전체다. 목록 필터는 전체/최신순/오래된순/배정/미배정이며 태그 필터는 없다. 카드 메타 번호·태그·요일/이름/첫 운동 외 N/⋯ 메뉴를 사용한다. 배정은 배경 그라데이션으로 구분한다. 본문은 읽기 전용 상세로 진입한다.

### 3.3 루틴 생성·편집 — `RoutineEditor`

동일 폼에서 이름·설명 있는 optional 태그 드롭다운·월~일 복수 배정·WEIGHT/CARDIO 계획을 편집한다. API 요일은 **월1~일7**이며 초기 데모의 일요일0을 사용하지 않는다. 미지정 태그를 자동 추정하지 않는다. 이름과 태그 필드44px 높이·라벨·간격·경계·배경을 통일한다.

웨이트는 세트·최소/최대 반복, 최초 중량/현재 승인·명시 새 승인, 장비 입력을 유지한다. 상단 변경, 하단 위로/아래로/제거는 동일 너비다. 최초 중량 불변·승인 사건·배치ID·진행 운동 원본을 보호하며 다른 종목 변경은 새 배치다. 유산소는 기존 `CardioPlanFields`를 재사용한다. 입력 검증은 현재 [루틴 계약](../../../overload-server/docs/api/routine-management.md)을 따른다.

상세는 동일 폼을 읽기 전용으로 사용하며 편집/삭제/닫기만 관리 액션으로 제공한다. 생성·편집 취소는 변경 초안을 확인하고 닫는다. 루틴 CRUD와 일정 PUT의 부분 성공을 구분해 일정만 재확인하며 실패 입력을 유지한다. 삭제는 기존 확인 절차이며 과거 완료 기록을 삭제하지 않는다.

### 3.4 운동 종목 선택 — `ExercisePicker`

추가·변경은 공통 `ExerciseSearch` 인라인 검색을 재사용한다. 이름/별칭·공식32px 아이콘·실제 대분류/PRIMARY 표시, 열 때 스크롤·포커스, 다른 입력 초안 보존을 적용한다. 검색 선택은 원본 카탈로그 ID를 사용하며 새 자동완성 카드 시스템/개인 운동 CRUD를 만들지 않는다. 상세 조회는 설정 경로와 구분한다.

별도 일정 편집은7개 선택창·휴식·복수 배정·단일 즉시 저장이다. 한 줄 후보 필터는 배정 유무/태그/전체 보기3개, 단일 선택이며 후보 변경에도 선택값·선택창 크기는 고정한다. 선택 유지 접미사·예약·사용자 일정 이력 UI는 없다. [주간 일정 계약](../../../overload-server/docs/api/weekly-schedule.md)의 최신 재조회·expectedVersion·ACTIVE 보호를 사용한다. Backend 버전 이력은 보존한다.

### 3.6 운동 진행 — `WorkoutExerciseScreen`

```text
┌──────────────────────────────────────┐
│ [00:42:18] [현재 1 / 5종목] [02:15] │  ← 3열 고정
├──────────────────────────────────────┤
│ PUSH DAY                   [종료 ⋯]  │
│ [◀] 벤치프레스 [종목 목록] [▶]     │
│ 목표: 6~10회 × 3본세트              │
│ 진행 중량: 60 kg 🔒  [중량 변경]     │
│                                      │
│  세트      기준        이번    완료  │
│   1         10          10      ✓    │
│   2          9           9      ○    │
│   3          7           7      ○    │
│                                      │
│ [현재 세션에서 세트/종목 변경]       │
│                                      │
│ 기구 세팅 메모 (아래로 스크롤)       │
│ ┌─────────────────────────────────┐  │
│ │ 높이 3 · 그립 눈금 2 ...          │  │
│ └─────────────────────────────────┘  │
├──────────────────────────────────────┤
│ [      현재 세트 완료        ]       │  ← 하단 고정
└──────────────────────────────────────┘
```

- **한 번에 한 종목만** 메인으로 보여준다. 현재 종목명/순서, 본세트/반복 목표, 승인 진행 중량을 분명히 한다.
- 상단은 **전체 운동 시간 | 현재 x / n종목과 종목 수만큼의 구간 | 휴식 시간**을 표시한다. 중앙은 현재 보고 있는 종목까지 앞쪽 구간을 누적해서 채우는 탐색 위치이며 [결정 로그](Overload_UI_Decision_Log_v0.9.md) 10.11.5절을 따른다. 완료 세트 수의 반복 표시는 제거하고, 탐색 버튼에는 가능한 경우 이전·다음 운동명을 표시한다. 일반/디로딩에서 공통으로 사용하며 운동 진행·결과에는 조회 전환 버튼과 디로딩 일차를 두지 않는다.
- 세트별 `기존 기록`은 읽기 전용; `이번 기록`은 수정 가능한 값; `완료`는 사용자가 눌러야만 사실로 저장된다.
- 각 미완료 본세트의 `이번 기록`은 `[−1] [숫자 입력·회] [+1]`로 제공한다. 중앙은 numeric 키패드용 직접 입력, 16px 이상 텍스트를 유지하며 버튼은 44×44px 이상이다. ±1은 해당 미완료 세트 초안만 변경하고 자동 완료·휴식 시작을 하지 않는다. 1 이상의 안전한 정수만 완료할 수 있으며 목표 상한을 넘어도 된다. 1에서 감소, 최대 안전 정수에서 증가를 막고 빈 값·잘못된 임시 입력은 자동 치환하지 않는다. 완료한 값은 읽기 텍스트·원형 체크로 표시하고 [완료 취소 확인](Overload_UI_Visual_Theme_Spec_v0.9.md#5-세트-완료-컨트롤) 뒤 입력을 복원해 수정한다. 이전에 저장된 0회 실제 기록은 삭제·변환하지 않고 읽는다.
- 진행 중량을 직접 탭해서 몰래 수정되지 않도록 잠금 상태를 표현하고, `중량 변경` 명시적 진입을 제공한다.
- 좌우 이전/다음 및 종목 목록에서 현재 세션 내 종목을 선택한다. **종목 편집/교체는 현재 세션에만 적용**한다.
- 기본 기구 세팅 메모는 세트 영역 아래에서 접근한다. 메모 편집 내용은 해당 종목의 기본 메모로 저장한다.
- 모든 세트를 한꺼번에 자동 완료하거나, 이전 기준을 별도 확인 없이 오늘 실적으로 저장하지 않는다.
- 마지막 남은 본세트를 실제 완료하면 현재 종목에 머물러 완료 기록과 하단 `다음 종목으로`를 보여주고 상단으로 스크롤한다. 버튼을 누르면 세션의 현재 순서에서 이후 미완료 종목을 우선하며 필요하면 앞으로 순환한다. 다음 세트는 미완료 상태다. 언제든 이전/다음/목록에서 완료 기록을 확인하고 완료 취소·수정할 수 있다.
- 모든 종목 완료 시 완료 안내와 하단 `운동 종료 및 요약`을 보여준다. 세션과 전체 운동 타이머는 직접 종료할 때까지 유지한다. 자동 종료하지 않으며 탐색이나 복원만으로 자동 이동하지 않는다.
- 현재 종목이 모두 실제 완료되고 기존 증량 판정을 충족하면 고정 CTA 바로 위에 `증량 가능 · NNkg`와 짧은 권고를 표시한다. 다음 종목 버튼과 전체 종료 버튼 모두 같은 위치 규칙을 사용한다. 중간 세트에는 표시하지 않으며 완료 취소/미달/일시 중량 등 자격 상실 즉시 제거한다. 추가 확인을 요구하지 않고 승인 중량을 바꾸지 않는다. 375px에서도 짧은 두 줄 안내로 CTA 공간을 확보한다.
- 이전에 조건을 충족한 비교 가능한 기준 기록이 있으면, 다음 세션의 중량 카드 아래에 작은 비차단 `현재 기준 기록에서 증량 조건 달성` 안내를 표시한다. 승인 kg와 단일 기준 기록 횟수를 보여주고 `지금 변경`으로 기존 중량 모달의 진행 중량 모드에 진입한다. 확인 전에는 중량을 바꾸지 않고, 안내를 무시해도 완료 버튼을 사용할 수 있다. 직전 운동이라고 표현하지 않는다.
- 이 재안내는 현 세션 완료 직후의 고정 안내와 구분한다. 임시/혼합/미완료/구성 불일치 결과로 기준을 만들지 않으며 중량/목표/세트 변경 시 새 비교 구간을 사용한다. 오늘만 중량이 별도로 있더라도 승인 중량의 유효한 과거 근거는 구분해서 표시한다. 루틴 관리에서 승인 중량을 바꿨지만 진행 세션은 옛 스냅샷인 경우에는 과거 중량의 재안내를 숨긴다.
- 세트 행은 특정 세트의 완료/취소, 하단 CTA는 다음 미완료 세트의 빠른 완료를 담당한다. 두 경로를 유지하고 같은 완료 처리와 휴식 중 비활성화 규칙을 적용한다.

### 3.7 휴식 상태와 하단 버튼 — `RestState`

| 상태 | 상단 오른쪽 영역 | 하단 CTA |
|---|---|---|
| 워밍업 | `준비 중` 또는 `—` | `준비운동 완료` |
| 본세트 입력 대기 | `휴식 없음` 또는 `—` | `세트 완료` |
| 중간 세트 완료 직후 | **남은 휴식 03:00** 등 | `휴식 종료` / `+30초` |
| 휴식 자연 종료 | **00:00** 또는 `휴식 완료` | 다음 세트 `세트 완료` 조작 복귀 |
| 종목 마지막 남은 본세트 완료 | **이전 종목 완료 후 00:00부터 증가**, 현재 종목 기록 유지, 휴식 없음 | `다음 종목으로` |
| 버튼으로 다음 종목 이동 후 첫 세트 전 | **동일한 실제 완료 시각 기준 경과시간 유지** | `세트 완료` |
| 다음 종목 첫 세트 완료(중간 세트) | **남은 휴식**으로 재전환 | `휴식 종료` / `+30초` |
| 한 세트뿐인 종목 완료 | 현재 종목 완료 기록 및 경과시간 또는 전체 완료, 휴식 없음 | `다음 종목으로` 또는 `운동 종료 및 요약` |
| 모든 종목 완료 | **모든 종목 완료**, 경과/휴식 타이머 없음 | `운동 종료 및 요약` |

- 상단 왼쪽 **전체 운동 시간은 모든 상태에서 유지**된다.
- 휴식시간은 현재 운동 종목의 **목표 상한 반복 횟수**와 3.10의 고정 구간별 저장값으로 결정한다.
- `+30초`는 저장된 휴식 종료 예정 시각을 30초 연장하며, `휴식 종료`는 즉시 카운트다운을 해제한다.
- 일반 휴식만 남은 10~6초에 하단 고정 `휴식 종료`/`+30초` 바로 위에 호박색 `다음 세트 준비` 카드와 큰 남은 초를 표시하고, 5~1초에 숫자 배경의 느린 강조 애니메이션을 적용한다. 상단의 전체 운동/휴식 시계와 색상 강조는 유지하며 같은 파생 남은 초를 사용한다. 준비 문구는 하단에 모으고 자동 스크롤이나 포커스 이동을 하지 않는다. 기존 본문 하단 여백과 Safe Area/키보드 inset을 유지한다. 전체 화면 점멸은 사용하지 않는다. reduced-motion에서는 애니메이션을 제거하고 문구·색상·숫자를 유지한다. 0초는 카드를 숨기고 기존 `휴식 완료`/완료 버튼으로 복귀한다. `+30초`로 10초를 넘거나 수동 종료하면 즉시 숨기며 다시 10초 이하가 되면 재표시한다. 종목 전환 경과시간·워밍업·전체 완료에는 경고가 없다. 기존 시계만 재사용하고 준비 신호 자체는 저장하지 않는다.
- **마지막 남은 본세트에는 휴식을 시작하지 않는다.** 실제 완료로 미완료→완료가 된 이벤트에서 경과시간 기준을 저장하고 현재 종목의 기록과 `다음 종목으로`를 표시한다. 이동은 버튼으로 수행하며 기준 시각은 바꾸지 않는다. 모든 종목이 완료되면 오른쪽 보조 타이머를 해제한다.
- 종목 전환 경과시간 기준은 **화면 이동 시점이 아닌 이전 종목의 마지막 완료 세트 시각**이다.
- 수동 탐색은 새 타이머를 만들거나 기존 타이머의 기준 시각을 덮어쓰지 않는다. 다른 종목의 휴식은 해당 종목으로 돌아가면 원래 종료 시각으로 표시한다. 완료 취소/추가로 전환 근거가 사라지면 그 전환 타이머만 해제한다.
- 구 v1 세션에서 완료된 종목의 휴식 상태를 복원해도 카운트다운을 표시하지 않는다. 가장 늦은 실제 완료 시각부터 경과시간을 계산하고, 전체 완료라면 종료 CTA만 제공한다. 이 해석은 최초 로드 시 실제 기록이나 저장값을 덮어쓰지 않는다.
- 화면을 다시 열었을 때는 현재 시각과 저장한 기준 시각을 비교해 시간을 계산한다.
- 운동 화면에서 시간이 실제로 움직이는 상태는 UI 갱신으로 처리하되 저장값이 경과시간 계산의 출처다.

### 3.8 중량 변경 — `WeightChangeSheet`

- 단일 `중량 변경` 메뉴에서 현재 승인 진행 중량을 보여주고, 변경 중량을 입력한다.
- 선택지 두 개:
  - `오늘만 변경` — 오늘 운동 기록에만 새 중량 적용
  - `진행 중량 변경` — 명시적 확인 후 이후 정상 운동에도 적용
- 승인 전에는 진행 중량이 변경되지 않으며, 변경 후에도 과거 실제 기록은 보존한다.
- 새로운 승인 중량에서 기준 기록이 없다면 사용자 입력을 기다린다. **최소 반복 횟수로 자동 초기화하지 않는다.**
- 성공 안내 문구는 `중량 증가를 고려해 보세요`처럼 **권고형**으로 쓴다. 목표 하한 미달 시에는 `중량 감소를 고려해 보세요`.

### 3.9 운동 완료 요약 — `WorkoutSummary`

- 종료 전에 미완료 세트가 있으면 완료 세트만 기록될 것임을 확인한다.
- 결과·과거 상세 공통으로 날짜·루틴명·전체 운동 시간과 하나의 수행 영역을 표시한다. WEIGHT/CARDIO를 제목과 구분선으로 나누고 큰 종목별 카드 중첩을 줄인다.
- 웨이트는 종목명 옆 `3/3세트 · 총 2,160kg`, 세트 행은 `60kg × 12회 · 720kg`처럼 표시한다. 완료 수는 실제, 분모는 당시 계획을 사용하며 하단 총 볼륨 반복은 제거한다. [볼륨 근거](requirements.md#r-07-운동-이력-및-완료)와 미확인 표기를 적용한다. 세트별 당시 제조사·부하 방식, 유산소 실제 시간·거리 출처를 유지한다.
- 제목은 `운동 기록 저장 완료`(저장 실패 시 `운동 기록 요약`)이며 `완료 3/9 본세트`처럼 완료 범위를 표시한다. 계획을 모두 완료한 경우에만 `전체 루틴 완료`를 표시한다. 기존 임시 변경 이력에서 계획 수를 복원할 수 없으면 미확인으로 표시한다.
- 갱신된 기준 기록이 있다면 간단히 표시한다. 실적과 권고를 혼동하지 않게 한다.
- 로컬 저장과 서버 동기화를 구분한다. 서버 반영 표시는 ACK 또는 계약에 따른 서버 확인 이후에만 제공한다.
- 상세 마지막에 `이 운동의 중량 검토 결과`를 둔다. 당시의 일반 본세트 계획을 모두 완료한 정상 단일 중량 기록에만 `당시 증량 가능 / 당시 감량 검토 / 당시 유지`와 중량/횟수/목표를 표시한다. 부분/일시/혼합/구성 변경/계획 미확인은 짧은 제외 이유를 보인다. 나중의 승인 변경으로 당시 판정이나 실적을 다시 쓰지 않는다.

### 3.10 기록 및 설정 — `History` / `Settings`

- `기록`은 이번 주 계획 대비 달성·완료 세트·유산소 요약과 운동 현황/근육별 통계/성장 추적, 최근 세션과 전체 이력으로 연결한다. 같은 날짜의 여러 종료 세션은 별도 카드다. 상세의 `⋮`에서 기록 정정·누락 수행 복구·기록 전체 삭제를 제공한다.
- 운동 현황은 주간/월간, 전체/운동별/근육별, 세트/총중량 선택을 그래프와 합계에 함께 적용한다. 근육별 통계의 기본은 **전체 세부 PRIMARY**이며 전체/가슴/등/하체로 필터링한다. SECONDARY는 펼침에서 별도 표시하고 대분류 중복 합산을 방지한다. 성장 추적은 과거 수행 종목도 검색하며 공식 승인 사건의 배치를 선택한다.
- 세션 리스트 아래 `현재 중량 조정 검토`는 해당 승인 중량/배치/구성의 기준과 가장 최근 비교 가능한 기록을 나란히 설명한다. 증량 근거와 감량 검토가 함께 있으면 둘 다 표시하고 자동 변경하지 않는다. 홈은 선택 루틴의 같은 컴포넌트를 재사용한다. 해당 내용이 없으면 빈 섹션은 숨긴다.
- `진행 중량 변경 내역`은 별도 사건 목록이다. 당시 이름, `60 → 62.5kg`, `증량 완료 +2.5kg` 또는 `감량 완료 −5kg`, 시각, 승인 화면을 표시한다. 루틴 관리에서 나중에 승인한 변경도 포함하며 특정 세션이 원인이라고 추정하지 않는다.
- 최초/루틴 승인/운동 모달의 빠른 입력 모두 조절과 승인을 분리한다. 승인 저장 실패 시 편집 화면/모달에 초안을 유지하며 승인 중량과 사건은 반영하지 않는다. 저장소 재확인 후에도 새 값은 직접 재승인해야 한다. 현재 메모리 입력의 일반 저장 실패 재시도와 구분한다.
- `설정`은 계정 정보, 운동 설정(세트 사이 휴식·운동 종목 보기·디로딩 설정), 데이터 및 앱, 계정 및 데이터 삭제, 보조 정보, **로그아웃** 순이다. 앱 설치·오프라인 준비는 로그인에서 설정 → 데이터 및 앱으로 옮긴다. 초기화·탈퇴·내보내기의 상세 화면은 결정 로그의 검토 범위를 따른다.
- 독립 ON/OFF 설정은 토글을 사용한다. 요일 다중 선택이나 삭제 동의에는 기존 체크/확인을 사용한다. 제목 옆 `?`는 필요한 설명만 표시하고 바깥 터치나 재터치로 닫는다. 미동기화·데이터 유실·삭제·분석 OFF 후 재활성화 시 누적 초기화 안내는 본문이나 확인 단계에서 확인할 수 있게 한다.
- 휴식 설정은 **1~10회 / 11~12회 / 13회 이상**의 시작·끝 경계를 비활성 필드로 표시한다. 각 행의 정수 초만 편집할 수 있고 기본값은 180/120/90초다. 단위 `초`는 입력 오른쪽에 표시한다. 구간 추가·삭제 버튼은 비활성화하고 세 값을 한 번에 저장한다.
- 미전송 기록이 있을 때 [계정 정책](auth-preview.md)의 경고·선택을 유지한다.

### 3.11 디로딩 · 확정 화면 흐름

- 홈 헤더 → 디로딩 상세 → 횟수·분할·요일 선택 → 운동이 배치된 날짜만 있는 비교 미리보기 → `이 일정으로 디로딩 시작`. 날짜를 펼쳐 원본 대비 종목·중량·세트·반복·유산소 목표를 확인한다. 원본과 승인 중량의 보호를 안내한다. 상세에서 자격 미달 이유를 표시하고 시작을 비활성화한다. 미리보기 하단에서 바로 시작을 요청하고, 그 순간 재검사에서 거부되면 최신 이유를 표시한다.
- 진행 중 홈에서만 `일반 보기 / 디로딩 복귀`를 전환한다. 선택한 조회 모드는 루틴·기록 탭 이동에 유지한다. 일반 보기에서는 원본과 일반 기록의 조회만 허용하고 원본 실행·수정·삭제를 제한한다. 조회 전환은 진행 중인 디로딩 기간·세션을 바꾸지 않는다.
- 디로딩 홈에서는 오늘의 임시 루틴과 임시 일정을 표시한다. 전체 임시 목록·편집·삭제 및 빈 날짜로 옮기기는 루틴 탭에서 처리한다. 완전 휴식은 오늘의 루틴에 휴식 안내를 표시하고 시작·다른 루틴 선택을 숨긴다. 경과한 휴식일은 `경과`로 표시한다.
- 진행 상세에서만 완료·조건부 취소를 제공하고 각각 한 번 확인한다. 8~10일차 최초 진입의 권장 기간 경과 안내는 진행 중 운동을 방해하지 않는다. 완료 당일과 다음 날, 무수행 취소의 복귀 차이는 [제품 요구사항 5절](requirements.md#5-디로딩과-기록분석)을 따른다. 완료한 기간 카드는 일반 기록에서 조회한다.

## 7. Task 005 — 유산소 화면과 상태

- 루틴 편집: 웨이트 입력과 별도로 `유산소 계획 추가`를 연다. 종류/목표 시간과 해당 기구의 선택값만 보여주며, 미적용 편집기가 열려 있으면 적용 또는 취소 후 루틴을 저장한다. 웨이트 뒤 유산소끼리 위/아래 순서를 조정한다.
- 운동 진입: 웨이트의 마지막 세트는 현재 기록을 유지하고 `다음 종목으로`로 유산소 준비에 진입한다. 유산소 전용은 워밍업 없이 준비로 진입한다. 진입만으로 타이머를 시작하지 않는다.
- 상단 왼쪽은 전체 세션 시간, 오른쪽은 `유산소 준비 / 진행 중 / 일시정지 / 완료 확인 / 완료 / 건너뜀`과 해당 활동 시간을 표시한다. 홈 이어하기에도 현재 종목·상태·시간을 보인다. 유산소에서는 웨이트 휴식 카운트다운/10초·5초 준비 카드를 표시하지 않는다. 이전 웨이트 휴식의 종료 시각은 유지해 다시 돌아갈 수 있다.
- 본문은 현재 한 종목의 계획과 큰 실제 시간에 집중한다. 하단은 준비 시 `유산소 시작`, 진행 시 `일시정지 / 유산소 완료`, 정지 시 `재개 / 유산소 완료`, 확인 시 `유산소 기록 확정`이다. 목표 도달 안내는 자동 종료하지 않는다.
- 완료 확인은 자동 시간·선택 실제 거리·수동 평균 BPM을 제공한다. 시간 정정 체크 전에는 시간 입력을 숨긴다. 확인 취소는 시간을 재개하지 않고 일시정지와 초안을 유지한다. 확정 전 상태/초안은 홈·새로고침 후에도 복원한다.
- 전체 종료 시 미완료 유산소가 있다면 기록 확인으로 돌아가는 경로와 건너뛰기 종료를 구분한다. 완료/건너뜀 뒤 다른 미완료 종목이 있으면 다음 종목으로 이동한다. 모든 웨이트 완료 후 추가 버튼을 종료 영역에 두며 운동 중에는 세션 편집 안에서만 노출한다. 추가를 강요하는 팝업은 없다.
- 기록 상세는 웨이트 실적·유산소 실적을 별도 카드로 표시한다. 계획과 실측, 자동 시간과 수동 정정, 미시작과 미완료 건너뜀을 텍스트로 구분한다. 두 종류를 모두 완료해야 `전체 루틴 완료`를 표시한다.
- 고정 CTA·스크롤 여백·키보드 inset·Safe Area와 다크 모드를 유지한다. 실제 DOM 검증은 375×812/390×844/430×932에서 진행했고, 실제 iPhone 가상 키보드·잠금·Standalone은 미검증이다.

## 8. Task 005.5 — 계정 UX 프리뷰

인증·계정 UI는 개발 전용 `/auth-preview`로 격리한다. 기존 다크 카드·Dialog·4탭 패턴을 재사용하고 프리뷰 안에서만 빨간색 CTA를 적용한다. 상단 가상 상태 안내와 하단 개발 패널을 제품 UI와 구별한다. OTP는 단일 숫자 입력, 주요 폼 버튼은 문서 흐름에 두어 키보드가 열려도 스크롤로 접근할 수 있게 한다. [상세 화면/시나리오 및 실기기 체크리스트](auth-preview.md)를 따른다. 기존 앱의 파란색 스타일과 실제 운동/설정 화면은 유지한다.

## 9. Task 005.5 계정 UX 인계

정리일: 2026-10-27. 인증·계정 목업은 사용자 1차 검토를 통과했다. 아래는 확정된 제품 흐름으로, 기존 UI를 이번 작업에서 변경하거나 모두 구현됐다고 선언하는 내용이 아니다. 정책 기준은 [인증·계정 정책](auth-preview.md), [완료 기록/저장·다중 기기·충돌 요구사항](requirements.md)의 R-07 및 10절이다.

| 상황 | 필요한 UX |
| --- | --- |
| 재실행/인증 만료 | 정상 재실행 시 자동 로그인 유지. 운동 중 만료는 조작을 막지 않고 완료 후 필요한 재인증으로 연결. 동일 계정 기록만 전송. |
| 로그인 수단 연결/복구 | 기존 계정 재인증 후 새 수단 인증·연결. 같은 이메일 자동 통합 금지. 연결된 수단으로 복구하며 마지막 수단 해제를 제한. |
| 미동기화 로그아웃 | ‘동기화 후 로그아웃’ / ‘로컬 기록 유지 후 로그아웃’ 및 취소. 서버 저장 확인 전 성공 표시 금지. 다른 계정에서 이전 계정 기록 비노출. |
| 수정 제어권 정상 이전 | 다른 기기에서 세션 조회 → 사용자가 명시적 이전 요청 → 기존 기기 최신 상태 동기화 → 새 기기에서 수정. 동기화 실패를 이전 완료로 표시하지 않음. |
| 기존 기기 사용 불가 | 서버의 마지막 저장 상태와 누락 가능성 안내 → 사용자 요청으로 강제 이전. 이전 기기의 나중 전송이 최신 상태를 자동 대체하지 않음. |
| 기록 충돌 | 서버/로컬 차이점만 표시 → 누락·변경 수행 정보 선택 복구 → 하나의 유효 세션으로 통합. 복구 전 동기화 완료 표시 금지. |
| 완료 기록 수정/삭제 | 사용자의 명시적 요청으로 허용. 수정 전 정보·변경 사실/삭제 사실을 추적하고 당시 판단과 수정 후 현재 판단을 구별. 현재 평가는 재계산하되 승인 중량 자동 변경 없음. |
| 새 루틴/전체 초기화/탈퇴 | 새 루틴은 이력 유지. 전체 초기화는 계정 유지·운동 데이터 삭제. 탈퇴는 계정/수단까지 대상으로 구분. 내보내기 안내·재인증·최종 확인 흐름을 유지. |

같은 계정의 한 세션 충돌 복구와 독립 계정 간 운동 데이터 병합을 구별한다. 후자는 후속 과제다. 차이 표시의 세부 단위·복구 검증·수정/삭제 이력 표현·제어권 이전 실패 화면은 [Task 006 설계 대상](../handoff/Overload-Task006-Design-Handoff.md)이며 이번 문서 작업에서 구체적 UI/기술 계약을 확정하지 않는다.
