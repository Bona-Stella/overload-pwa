## 1. UX 우선순위

1. 세트를 마친 직후 사용자가 할 일은 가능한 한 **`세트 완료` 한 번**이어야 한다.
2. 현재 운동 중량·기준 반복 횟수·이번 실제 입력·완료 여부를 혼동하지 않는다.
3. 운동 시간은 언제나 보이고, 오른쪽 타이머와 하단 버튼은 현재 상태에 맞춰 전환한다.
4. 기록 화면에서 다른 종목이나 루틴의 상세 설정으로 이동할 필요가 없도록 필요한 조작을 제공한다.
5. 예기치 않은 앱 전환/화면 새로고침 후에도 원래 진행 중이던 단계로 돌아온다.
6. 권고(증량/감량/디로딩)와 상태(완료/미완료)는 색상뿐 아니라 **텍스트**로도 전달한다.

## 2. 정보 구조와 이동

```text
[앱 실행]
 ├─ 진행 중인 세션 있음 → [홈의 진행 중인 운동 / 운동 이어가기] → 저장된 운동 단계 복원
 └─ 진행 세션 없음 → [홈: 오늘의 루틴 자동 선택]
       ├─ [루틴 탭] → 루틴 목록 → 상세 → 편집, 또는 목록에서 루틴 생성 → 운동 종목 검색/추가
       ├─ [기록 탭] → 운동 현황 / 성장 추적 / 주간 근육 계획 / 주간 근육 통계
       │                └─ 최근 운동 기록의 전체 보기 → 운동 이력 → 세션 상세
       ├─ [설정 탭] → 계정 / 운동 설정 / 데이터 및 앱 / 계정 및 데이터 삭제 / 로그아웃
       └─ [운동 시작] → [워밍업/스트레칭]
                            └─ [준비운동 완료] → [종목 준비] → [운동 시작하기]
                                   ├─ 중간 세트 완료 → [세트 사이 휴식]
                                   │                ├─ 휴식 종료
                                   │                └─ +30초
                                   ├─ WEIGHT → WEIGHT / CARDIO → CARDIO 완료 → [다음 종목 준비]
                                   ├─ 마지막 WEIGHT → CARDIO → [다음 종목으로 / 남은 유산소 건너뛰고 종료]
                                   ├─ 남은 종목 없음 → [모든 종목 완료 / 운동 종료 및 요약]
                                   ├─ 스와이프·종목 목록 → 같은 세션의 다른 종목 탐색
                                   ├─ 중량 변경 → 오늘만 / 진행 중량 변경
                                   ├─ 스크롤 하단 → 기구 세팅 메모
                                   └─ 운동 종료 → 확인·FINISH ACK → [운동 기록 요약 최상단]
```

### 공통 하단 내비게이션

- **구성.** 홈 → 루틴 → 기록 → 설정 순서로 아이콘 전용 버튼 네 개를 동일한 너비로 배치한다. 탭바는 375·393·430·1280px 화면에서 336×56px, 320px에서 296×56px이다. 높이 46px 버튼의 중앙에 24px 아이콘을 둔다.
- **선택.** 확장 상태에서 캡슐 하나가 200ms `ease`로 수평 이동하고 아이콘은 각 탭 가운데에 고정된다. 첫 표시와 빠른 선택, 브라우저 뒤로·앞으로 이동 시 현재 탭을 따른다. 활성 홈·설정은 기존 SVG를 검은색으로 채우며 집의 지붕·문과 기어 중앙 구멍을 유지한다. 루틴·기록의 활성 윤곽선은 검은색 3px이다. 비활성 윤곽선은 모두 1.6px이며 홈은 흰색, 나머지는 중립색이다.
- **자동 접기·펼치기.** 문서의 세로 위치가 같은 방향으로 24px 증가하면 접고, 24px 감소하면 펼친다. 방향을 바꾸면 누적 거리를 새로 센다. 터치와 휠의 실제 스크롤 위치를 사용한다. 페이지 맨 위, 새 탭 진입, 탭바가 다시 나타날 때는 펼친 상태를 기본으로 한다. 내부 목록과 모달의 독립 스크롤은 영향을 주지 않는다.
- **움직임과 색.** 접기 320ms, 펼치기 340ms이며 `cubic-bezier(.32, .08, .26, 1)`을 사용한다. 활성 아이콘은 24px 크기로 중앙에 이동하고, 비활성 아이콘은 중앙으로 이동하며 작아지고 흐려진다. 펼칠 때 각 아이콘은 원래 칸으로 복귀하며 마지막 프레임에서 목표 위치를 지나치거나 다시 정렬되지 않아야 한다. 선택 배경은 `#6C93C6`에서 `#5E82B1`로 짙어졌다가 펼치면 돌아온다. 움직임 줄이기에서는 탭 선택과 접기·펼치기 상태가 즉시 전환된다. [시각 규칙](Overload_UI_Visual_Theme_Spec_v0.9.md#15-공통-하단-내비게이션--2026-11-19)
- **원형 버튼.** 접히면 현재 탭만 46×46px 원형으로 남는다. `하단 메뉴 펼치기`를 누르면 페이지 이동이나 기존 탭 재선택 없이 현재 스크롤 위치에서 네 탭이 펼쳐진다. 접힌 나머지 탭은 키보드 탐색과 접근성 트리에서 제외한다.
- **배치.** 두 상태의 하단 간격은 `env(safe-area-inset-bottom)`이다. 본문은 두 상태 모두 확장 높이 56px에 안전 영역과 콘텐츠 간격 16px을 더해 확보한다. 안전 영역이 0px이면 하단 간격 0px과 본문 여백 72px, 34px이면 하단 간격 34px과 본문 여백 106px이다. 모달과 전체 화면 오버레이는 기존 레이어를 사용한다. 운동 집중 화면의 고정 액션과 휴식 푸터는 운동 프레임이 자체 여백을 확보한다.
- **탐색과 입력.** 실제로 이동한 탭과 하위 화면을 하나의 선형 History에 쌓는다. 홈 → 루틴 → 기록 → 설정을 방문했다면 뒤로 가기도 역순을 따른다. 화면의 뒤로가기와 브라우저 뒤로가기는 같은 부모 항목으로 돌아가며, 탭 재선택은 같은 항목을 추가하지 않는다. 이동 전에 미저장 입력을 보호하고 종료 세션은 ACTIVE 화면으로 복원하지 않는다. 운동 집중 화면과 루틴 상세·편집·생성, 모바일 키보드 표시 중에는 일반 탭바를 숨긴다. 키보드가 닫히면 현재 탭 위치로 복원한다. 각 버튼의 이름·현재 상태와 Tab 포커스 윤곽선, Enter·Space 선택을 제공한다.

각 화면은 자체 제목을 사용하고 홈은 3.1의 상태별 헤더를 사용한다. 운동의 전체 시간·종목 위치·휴식 시간은 3.6의 공통 헤더에 둔다. 사용자가 의도적으로 종목을 고르는 메뉴는 제공하되 전체 종목을 한 스크롤 화면에 계속 나열하지 않는다.

### 저충실도 와이어프레임

HTML 베이스라인은 현재 React UI의 제목·문구·정보 구조·배치·주요 화면 연결을 검토한다. 화면 선택과 이전·다음, 탭·버튼 이동, 모달, 토글과 편집·조회에는 단순한 JavaScript를 사용한다. 입력·저장·로딩·오류는 준비된 예시로 비교한다. 실제 서버에서 제한하는 항목은 검토 자료에도 비활성으로 표현한다.

탭바는 **접힘 상태 보기**를 누르면 원형으로 즉시 전환한다. 원형 버튼은 같은 화면의 확장 탭바를 복원한다. 알림 미리보기는 고정 시간과 예시 상태를 보여 준다. 실시간 스크롤 판정·애니메이션·타이머·오디오·인증·서버 저장·집계는 운영 앱과 검토 앱에서 확인한다. [HTML 베이스라인](Overload_UI_Baseline_Wireframe_v0.9.html)

## 3. 화면별 명세

### 3.1 홈 — `Home`

홈의 본문은 **오늘의 루틴과 운동 시작 → 오늘만 다른 루틴 선택 → 이번 주 일정 → 최근 운동** 순서다. ACTIVE 세션에서는 첫 영역을 진행 중인 운동 카드로 교체한다.

| 홈 상태 | 헤더 |
|---|---|
| 분석 ON · 디로딩 미진행 | 왼쪽 OVERLOAD → 공식 달 아이콘 → n.n/8주 → 짧은 수평 게이지. 날짜는 오늘 카드로 이동한다. |
| 분석 OFF · 디로딩 미진행 | 왼쪽 OVERLOAD, 오른쪽 공식 달 아이콘. 주수/트랙/헤더 날짜는 숨긴다. |
| 디로딩 진행 중 · G6 화면 설계 | 왼쪽 녹색 선형 초승달 SVG와 `디로딩 진행 중 · n일차`, 오른쪽 `일반 보기`. 왼쪽 영역에서 진행 상세에 진입한다. 일반 보기에는 읽기 전용 상태와 `디로딩 복귀`를 표시한다. |

- 큰 동기부여 카드, 별도 디로딩 상태 카드, 원형 추천 게이지는 제거한다. 진행 중 헤더에는 날짜와 별도 D1 장식을 표시하지 않는다.
- TODAY'S ROUTINE과 실제 날짜를 오늘 카드 첫 행 좌우에 배치한다. 구획과 핵심 글자 크기·선택 후 자동 닫힘·최근 종목 달성/무수행 필터·선택형 태그 규칙은 [최신 홈 결정](Overload_UI_Decision_Log_v0.9.md#1012--2026-11-06-홈-가독성헤더최근-운동-최종-보완)을 따른다. WEIGHT/CARDIO는 제목과 구분선으로 동등하게 나눈다.
- 오늘의 기본 루틴은 실제 활성 프리셋의 오늘 배정에서 읽는다. `오늘만 다른 루틴 선택`은 `전체 / 미배정 / 저장된 일정 번호(01~04)`를 제공하며 처음에는 실제 활성 일정 번호를 선택한다. 미배정은 어느 프리셋에도 배정되지 않은 루틴이다. 순환 제외 프리셋도 조회할 수 있고 루틴 ID로 중복을 제거한다. 필터와 임시 선택은 적용 일정을 바꾸지 않는다. 두 줄 목록은 루틴명·배정 요일·대표 종목을 표시한다.
- 이번 주 일정은 날짜·상태·루틴명 순서와 긴 이름 축소·날짜 선택 상세를 유지한다. 운동 현황과 같은 날짜/근거에는 같은 ✓ 전체 완료·△ 부분 달성·× 기준 미달·– 휴식을 표시한다. 미래·검사 대기·등록 전·계획/수행 확인 불가는 중립 또는 미확정으로 남긴다. △의 정확한 50%·종목 최소 세트·유산소 AND·혼합 기준은 10.24.4절을 공통 사용하며 공식 완료율·유효 운동일·G4를 변경하지 않는다. 현재 plannedDays.selectedSessionId의 상세와 공통 display-achievement에 연결됐으며 근거 부족은 미확정으로 유지한다. 대체 슬롯·복수 후보 정책 전체 완료와 구분한다.
- 최근 운동은 실제 수행이 있는 종료 기록을 최신순으로 최대 3건 표시한다. 상세 조회 실패는 달성 미확인으로 구분한다. 달성 수치는 운동 당시 최초 계획 대비 현재 유효 수행을 기준으로 한다. 이 홈 카드의 기존 상한과 아래 기록 메인의 최근 7일 범위는 별개다.
- 최근 카드를 누르면 해당 세션의 [운동 기록 상세](#운동-기록-상세)를 전체 화면으로 열고, 화면·브라우저 뒤로가기로 홈과 이전 목록 위치에 복귀한다. `전체 보기`는 기록 탭의 [전체 운동 이력](#전체-운동-이력)을 연다.

- 요일이 변경되면 해당 요일의 기본 루틴이 나타난다. **자동 시작은 하지 않는다.**
- 일반 예정 휴식일에는 휴식일로 표시하고 당일 루틴 수동 선택을 허용한다. 디로딩의 완전 휴식과 일반 보기 제한은 3.11을 따른다.
- 진행 중 카드의 상단에 `진행 중인 운동`과 현재 종목·상태를 배치한다. 루틴 이름, 전체 경과시간, 웨이트 완료/계획 세트 수, 현재 세션에 적용된 WEIGHT/CARDIO 목록을 보여준다. `운동 이어가기`로 기존 세션을 연다. 같은 기기의 작업 사본이 없으면 서버에서 확인한 계획·수행을 표시하고 현재 종목은 확인 필요로 안내한다. 종료가 확인되면 오늘의 루틴 카드로 돌아간다.
- 일반 홈에서 오늘만 다른 루틴을 선택해도 주간 일정의 원본 매핑은 바꾸지 않는다. 디로딩에서는 미수행 임시 루틴의 날짜를 맞교환한다.
- 임시 루틴을 선택하면 선택 영역이 닫히고 오늘 카드가 바뀐다. `오늘의 원래 일정으로`에서 기본 배정으로 돌아간다. 기본이 없는 날의 선택도 오늘에 한정한다.

### 3.2 루틴 목록 — `RoutineList`

[Decision Log 10.16절](Overload_UI_Decision_Log_v0.9.md#1016--다중-주간-루틴-일정과-자동-순환)을 적용한다. 주간 일정은 최대 4개이며 표시 번호와 내부 ID를 구분한다. 번호는 조회 전용이다. 제목 행 오른쪽에 실제 활성 일정은 `✓ 진행중`, 순환 OFF의 다른 일정은 전환 SVG와 `전환`, 순환 ON의 다른 일정은 눈 아이콘과 `보기`를 표시한다. 전환을 누르면 서버 성공 후 활성 일정이 바뀐다. 가로 7요일 타일과 세로 한 줄 보기에서 배정 루틴을 확인한다.

저장된 루틴의 드롭다운은 `전체 / 최신순 / 오래된순 / 이 일정 배정 / 이 일정 미배정`을 제공한다. 정렬은 생성 시각을 기준으로 하며 배정·요일 필터는 조회 중인 프리셋 기준이다. 요일을 선택하면 해당 요일 배정으로 필터를 잠근다. 저장된 루틴 카드는 상세로 연결되고 프리셋별 배정 요일을 표시한다.

ROUTINE-06의 `주간 일정 편집`은 조회 중인 프리셋의 월~일 드롭다운을 각각 제공한다. 루틴 또는 휴식을 선택하고 변경 내역을 확인한 뒤 한 번에 저장한다. 활성 프리셋 배정은 즉시 적용되며 비활성 편집은 해당 프리셋만 바뀐다. 루틴 후보 필터는 배정 유무·태그·전체 보기다.

`⋯`에서 이름 변경, 전체 편집, 현재 보고 있는 일정 삭제를 선택한다. 이름은 V31에서 저장하며 저장 충돌이나 연결 오류는 기존 확정 이름과 편집 초안을 구분한다. ROUTINE-07에서는 포함·제외 그룹과 각 그룹 내 순서를 편집한다. 핸들을 끌면 카드가 포인터를 따라 이동하고 주변 카드 위치도 바뀐다. 키보드 정렬도 제공한다. 그룹 이동은 추가·제외로 수행하며 초안은 저장을 확인하기 전까지 적용되지 않는다. 순환과 쓰기 제한은 [프리셋 API](../../../overload-server/docs/api/weekly-schedule.md)를 따른다.

### 3.3 루틴 상세·편집·생성

[결정 10.32절](Overload_UI_Decision_Log_v0.9.md#1032--루틴-상세편집생성-리디자인-구현--2026-11-18)과 [시각 규칙 11절](Overload_UI_Visual_Theme_Spec_v0.9.md#11-루틴-상세편집생성--2026-11-18)을 적용한다. 목록에서 저장된 루틴을 선택하면 상세를 열고, 상세의 `편집` 또는 목록 메뉴에서 해당 루틴의 편집을 연다. 목록의 `+ 새 루틴`은 생성 초안을 연다.

#### 루틴 상세

- 기록 하위 화면의 공통 헤더에 뒤로가기, `루틴 상세`, 우측 `편집`을 놓는다. 요약 카드 첫 행 왼쪽에 선택 태그와 루틴명, 오른쪽에 `생성 · YYYY.MM.DD`를 놓는다. 현재 응답의 `createdAt`을 사용하며 일정 시간대 또는 기기 시간대로 표시한다. 값이 없으면 생략한다. 좁은 화면에서는 이름이 줄바꿈되고 날짜는 한 줄을 유지한다.
- 요약은 웨이트 종목 수·총 본세트·유산소 종목 수 3열이다. WEIGHT는 순번과 17px 운동명, 카탈로그 대분류·소분류, 부하 방식과 제조사, 승인 중량·본세트·최소 반복·최대 반복 4열을 표시한다. 화면 메모리에서 참조할 수 있는 기구 세팅 메모에는 `미저장`을 표시한다.
- CARDIO도 순번·17px 운동명 아래 분류를 같은 위치에 둔다. 실제 러닝머신 매핑의 예는 `달리기 · 러닝머신`이다. 레거시에서 기록 설정 참조만 확인되면 대분류를, 매핑을 확인할 수 없으면 `유산소 분류 미확인`을 표시한다. 목표 시간·거리·속도 또는 페이스·경사 또는 기구별 저항은 4열이다. 목표 시간은 60으로 나누어떨어지면 분, 그 외에는 초로 표시한다. 미설정은 `—`이며 0과 구분한다.
- WEEKLY SCHEDULE은 배정된 프리셋의 번호·이름·월`일 요일 칩을 보여 준다. 긴 이름은 말줄임하고 확인된 미배정과 조회 대기·실패를 구분한다. 배정 편집은 3.2의 주간 일정에서 한다.
- `온라인으로 운동 시작`은 선택한 루틴의 기존 START를 호출한다. `루틴 삭제`는 전체 프리셋 배정 해제와 과거 기록 보존을 안내한다. 취소하면 상세에 머무르고 성공하면 목록으로 돌아간다. 상세의 승인 중량은 조회 전용이다. 운동 직후의 증량·감량 수정과 승인은 3.9에 있으며 상세의 권고 태그와 근거 팝업은 보류 상태다.

#### 루틴 편집

- `루틴 편집` 헤더 → 저장된 이름·태그를 채운 기본 정보 → WEIGHT → CARDIO → `제거한 종목 복원` → `취소 / 변경 사항 저장` 순서다. WEIGHT는 순번·운동명·분류·`변경`, 제조사와 부하 방식 2열, 본세트·최소/최대 반복 3열, 설정 중량, 기구 세팅 메모, 위로·아래로·삭제를 제공한다. CARDIO는 `변경`과 목표 시간·거리, 강도 단위와 해당 속도/페이스·경사/저항을 지원 범위에 맞게 배치한다. 현재 편집 CARDIO 제목에는 분류 행이 없다.
- `− / 중량값 / +`에서 원판식·스택식은 2.5kg, 그 외는 1kg씩 조절한다. 가운데 값은 기존 2.5kg 휠과 직접 입력을 연다. 저장 단위는 kg이며 한쪽당 환산 표시는 없다. 조합이 같은 기존 배치는 승인 중량으로 시작한다. 값을 바꾸면 `변경 사항 저장`에서 새 승인값을 확인한 다음 제출한다. 운동·제조사·부하 방식 조합이 바뀐 WEIGHT는 새 배치로 최초 중량을 직접 입력한다.
- 첫 종목의 위로와 마지막 종목의 아래로는 비활성이다. 저장된 배치를 제거하면 저장 시 논리 제외되며, 편집의 `복원 후보 조회`에서 기존 제거 배치를 조회해 복원한다. 새 종목을 제거하면 현재 초안에서 빠진다. 기구 세팅 메모는 계정·데이터 세대의 화면 메모리 초안이다. 루틴 저장과 별개이며 새로고침 시 사라진다.

#### 루틴 생성

- 목록의 `+ 새 루틴`에서 `루틴 생성`을 연다. 이름 입력은 비어 있고 `나의 루틴`은 예시다. 태그는 `미지정`이다. WEIGHT·CARDIO에 등록 종목이 없을 때 각각 점선 안내를 표시한다. 종목을 선택하면 편집 카드가 생기고 마지막 종목을 제거하면 안내가 돌아온다. CARDIO 선택 중에는 빈 상태와 0종목을 유지하며 선택 후에는 카탈로그 분류도 표시한다.
- 편집과 같은 폼·종목 카드·목표 검증을 사용한다. 기존 배치 복원은 편집에만 제공한다. 하단은 `취소 / 루틴 생성`이다. 성공 후 목록에 한 번 `✓ 새 루틴 생성 완료`와 실제 이름이 나온다. `나중에`는 안내를 닫고 `배정하기`는 주간 일정 편집에서 새 루틴을 후보 상단에 표시한다. 자동 요일 배정은 없다.

#### 생성·편집 공통 동작

- 추가와 변경은 기존 검색·선택 UI를 사용한다. **새 종목을 선택해 카드가 추가됐을 때만** 렌더링과 키보드 정리 뒤 카드 상단을 고정 헤더 아래 약 8px에 맞춘다. 입력칸에 자동 포커스하지 않고 움직임 줄이기 설정에서는 애니메이션을 생략한다. 교체·순서 이동·입력·삭제·복원·최초 진입에서는 추가 스크롤을 실행하지 않는다.
- 고정 푸터의 두 버튼은 1:1, 높이 48px이다. 모바일 안전 영역과 텍스트 키보드에 대응한다. 헤더 뒤로가기와 `취소`는 같은 이탈 경로를 사용한다. 변경이 없으면 돌아가고 미저장 변경이 있으면 확인 후 폐기하거나 계속 편집한다. 취소에서 저장 요청은 발생하지 않는다.
- 이름·종목·중량·반복·유산소 목표를 검증한 후 온라인 요청을 보낸다. 중량은 0 이상, 소수점 6자리까지 입력한다. 유산소 시간은 1`86,400초이며 분 입력은 정수 초로 변환할 수 있어야 한다. 선택 목표는 거리 0.001`1,000km, 속도 0.1`100km/h 또는 페이스 0.1`120분/km, 경사 0`50%, 저항 1`100을 지원 종목에서 검증한다. 다른 기기 유형에는 시간만 적용할 수 있다. 실패 시 입력을 유지하고 재시도할 수 있다. 편집 성공 시 목록을 갱신해 복귀한다. 최근 실제 수행 중량 자동 제안과 서버 메모는 후속 정책이다. [연동 계약](../engineering/backend-ui-v0.9.md#루틴-관리-연동--2026-11-18)

### 3.4 운동 종목 선택 — `ExercisePicker`

추가·변경은 공통 `ExerciseSearch` 인라인 검색을 재사용한다. 이름/별칭·공식32px 아이콘·실제 대분류/PRIMARY 표시, 열 때 스크롤·포커스, 다른 입력 초안 보존을 적용한다. 검색 선택은 원본 카탈로그 ID를 사용하며 새 자동완성 카드 시스템/개인 운동 CRUD를 만들지 않는다. 상세 조회는 설정 경로와 구분한다.

조합별 중량·메모 조회는 정규·오늘만 추가·대체에 공통 적용하되 공식 승인 원본은 정규 루틴 배치다. 오늘만 원계획 운동·제조사·중량 방식을 변경·대체한 세션은 다른 정규 종목까지 공식 증감 평가 전체 제외다. 네 분류와 원계획 세트가 일치하는 대체 슬롯은 별도로 완료 인정할 수 있다. 따라서 루틴 완료·주간/G4 반영과 공식 평가 제외를 구분해야 한다. 세부 제품 조건은 Decision Log 10.21절, 날짜 기호와 기록 UI는 10.24절을 적용하며 실제 연결은 후속 구현이다. 단순 추가·초과 수행은 기존 첫 N개 평가와 실제 전체 기록을 유지한다.

### 3.5 스트레칭/워밍업 — `Warmup`

```text
┌──────────────────────────────────────┐
│ 전체 운동 시간          00:07:35     │
│                                      │
│        스트레칭 & 워밍업              │
│        자유롭게 준비하세요            │
│        세트 기록 없음                │
│                                      │
│ 다음 운동: 벤치프레스                │
│                                      │
│       [  준비운동 완료  ]            │
└──────────────────────────────────────┘
```

- 홈의 `오늘의 루틴`에서 요일 기본 또는 오늘만 선택한 루틴으로 `운동 시작`을 누른다. 온라인 START가 확인된 운동은 세션의 시작 시각부터 전체 경과시간을 표시한다. 진행 중인 운동은 `운동 이어가기`로 복귀한다.
- 웨이트가 있으면 다음 종목명·목표·장비가 있는 준비운동에서 `준비운동 완료`를 누른다. 다음 화면은 첫 웨이트의 준비 상태다. 유산소만 있으면 유산소 준비로 바로 진입한다.
- 워밍업 세트, 휴식 카운트, 몸풀기 중량을 입력·저장하지 않는다.
- 새로고침이나 앱 전환 뒤에는 같은 기기에 확인된 단계로 복귀한다.

### 3.6 운동 진행 — `WorkoutFrame` / `LocalWorkoutFlow`

```text
┌──────────────────────────────────────┐
│ [00:42:18] [현재 1 / 5종목] [02:15] │  ← 3열 고정
├──────────────────────────────────────┤
│ ‹ 이전       PUSH DAY       다음 ›  │
│ 이전 운동명                다음 운동명│
│ 01 벤치프레스        [종목 보기/변경]│
│ 목표: 6~10회 × 3본세트              │
│ 진행 중량: 60 kg 🔒  [중량 변경]     │
│                                      │
│  세트      기준        이번    완료  │
│   1         10          10      ✓    │
│   2          9           9      ○    │
│   3          7           7      ○    │
│                                      │
│ [운동·세트 편집]                     │
│                                      │
│ 기구 세팅 메모 (아래로 스크롤)       │
│ ┌─────────────────────────────────┐  │
│ │ 높이 3 · 그립 눈금 2 ...          │  │
│ └─────────────────────────────────┘  │
├──────────────────────────────────────┤
│ [      현재 세트 완료        ]       │  ← 하단 고정
└──────────────────────────────────────┘
```

- **한 번에 한 종목만** 메인으로 보여준다. 현재 종목명/순서, 본세트/반복 목표, 승인 진행 중량을 분명히 한다.
- 상단은 **전체 운동 시간 | 현재 x / n종목과 진행 표시 | 종목 준비·WEIGHT 수행·휴식·유산소 시간 또는 완료 상태**를 같은 폭의 세 열로 표시한다. 중앙의 채운 구간은 탐색 위치다. 웨이트는 루틴명 양옆에서 이전·다음, 제목 옆에서 `종목 보기/변경`을 사용한다. 유산소는 루틴명 행의 `홈 / 종료`와 별도의 이전·목록·다음 행을 사용한다. 목록에서는 WEIGHT/CARDIO 그룹 안에서만 순서를 변경한다.
- 진행 화면에는 하단 탭 대신 `WorkoutFrame`의 상태별 고정 버튼을 표시한다. 상단 시간 바와 하단 버튼의 실제 높이를 측정하여 본문 여백을 예약한다. iOS Safe Area와 키보드 inset을 고려한다.
- 세트별 `기존 기록`은 읽기 전용; `이번 기록`은 수정 가능한 값; `완료`는 사용자가 눌러야만 사실로 저장된다.
- 각 미완료 본세트의 `이번 기록`은 `[−1] [숫자 입력·회] [+1]`로 제공한다. 현재 일반 운동 PWA는 중앙을 터치해 [공통 숫자 입력](#312-공통-숫자-입력) 휠을 열고 직접 입력으로 전환할 수 있다. 16px 이상 텍스트와 44×44px 이상 버튼을 유지한다. ±1은 해당 미완료 세트 초안에만 적용한다. 완료는 [세션 계약](../../../overload-server/docs/api/workout-sessions.md#snapshot-정확한-요청-계약)의 양의 정수 범위를 따르며 목표 상한을 넘어도 된다. 증감은 필드 허용 범위 안에서 처리하고 빈 값·잘못된 임시 입력은 자동 치환하지 않는다. 완료한 값은 읽기 텍스트·원형 체크로 표시하고 [완료 취소 확인](Overload_UI_Visual_Theme_Spec_v0.9.md#5-세트-완료-컨트롤) 뒤 입력을 복원해 수정한다. 이전에 저장된 0회 실제 기록은 삭제·변환하지 않고 읽는다.
- 진행 중량을 직접 탭해서 몰래 수정되지 않도록 잠금 상태를 표현하고, `중량 변경` 명시적 진입을 제공한다.
- 좌우 이전/다음, 종목 목록 또는 [수평 스와이프](#운동-종목-스와이프)로 현재 세션 내 종목을 선택한다. `운동·세트 편집`의 기존 임시 편집·교체와 저장은 현재 세션에 적용한다.
- 세트 아래에는 기구 세팅 메모의 제목 행과 입력을 배치한다. 새 종목 준비에서 펼치고 실제 시작 시 접는다. 진행 중 다시 펼칠 수 있고, 탐색 중에는 조합별 메모 초안을 유지한다. 현재 입력은 **계정·세대에 묶인 마운트 메모리 초안**이며, 새로고침·기기 저장·서버 저장과 최신값 동기화는 별도 [메모 정책](Overload_UI_Decision_Log_v0.9.md#10256-최근-실제-중량과-조합-메모--정책-3-6)을 따른다.
- 모든 세트를 한꺼번에 자동 완료하거나, 이전 기준을 별도 확인 없이 오늘 실적으로 저장하지 않는다.
- 마지막 세트를 로컬에서 확정하면 다음 미완료 웨이트로, 유산소 기록을 확정하면 다음 미완료 유산소로 자동 이동한다. 마지막 웨이트와 첫 유산소 사이에는 `다음 종목으로`와 `남은 유산소 건너뛰고 종료` 선택을 표시한다. 선택해서 들어간 미시작 종목에서 `운동 시작하기`를 누르면 해당 종목의 수행 컨트롤이 활성화된다. 이미 시작한 종목의 완료 세트·입력 초안·휴식·유산소 진행은 그대로 이어간다.
- 모든 종목 완료 시 완료 안내와 하단 `운동 종료 및 요약`을 보여준다. 세션과 전체 운동 타이머는 직접 종료할 때까지 유지한다. 자동 종료하지 않으며 탐색이나 복원만으로 자동 이동하지 않는다.
- 현재 종목이 모두 실제 완료되고 기존 증량 판정을 충족하면 고정 CTA 바로 위에 `증량 가능 · NNkg`와 짧은 권고를 표시한다. 다음 종목 버튼과 전체 종료 버튼 모두 같은 위치 규칙을 사용한다. 중간 세트에는 표시하지 않으며 완료 취소/미달/일시 중량 등 자격 상실 즉시 제거한다. 추가 확인을 요구하지 않고 승인 중량을 바꾸지 않는다. 375px에서도 짧은 두 줄 안내로 CTA 공간을 확보한다.
- 이전에 조건을 충족한 비교 가능한 기준 기록이 있으면, 다음 세션의 중량 카드 아래에 작은 비차단 `현재 기준 기록에서 증량 조건 달성` 안내를 표시한다. 승인 kg와 단일 기준 기록 횟수를 보여주고 `지금 변경`으로 기존 중량 모달의 진행 중량 모드에 진입한다. 확인 전에는 중량을 바꾸지 않고, 안내를 무시해도 완료 버튼을 사용할 수 있다. 직전 운동이라고 표현하지 않는다.
- 이 재안내는 현 세션 완료 직후의 고정 안내와 구분한다. 임시/혼합/미완료/구성 불일치 결과로 기준을 만들지 않으며 중량/목표/세트 변경 시 새 비교 구간을 사용한다. 오늘만 중량이 별도로 있더라도 승인 중량의 유효한 과거 근거는 구분해서 표시한다. 루틴 관리에서 승인 중량을 바꿨지만 진행 세션은 옛 스냅샷인 경우에는 과거 중량의 재안내를 숨긴다.
- 세트 행은 특정 세트의 완료/취소, 하단 CTA는 다음 미완료 세트의 빠른 완료를 담당한다. 두 경로를 유지하고 같은 완료 처리와 휴식 중 비활성화 규칙을 적용한다.

#### 운동 종목 스와이프

- 본문을 왼쪽으로 끌면 다음 종목, 오른쪽으로 끌면 이전 종목이 손가락과 함께 이동한다. 페이지 너비의 35% 또는 빠른 스와이프 기준을 충족하면 약 220ms로 전환하고, 짧은 드래그나 취소는 원래 위치로 돌아간다. 두 페이지 사이의 24px 간격은 전환 거리에 포함하고 35% 기준에는 포함하지 않는다.
- 인접 페이지는 같은 레이아웃의 전체 콘텐츠를 읽기 전용으로 보여 준다. 탐색은 시작·완료 작업이나 History 항목을 만들지 않는다. 세로 스크롤과 입력 컨트롤, 화면 가장자리의 Safari/PWA 기본 제스처를 보호한다. 첫·마지막 종목 밖과 준비운동·종료 사이에는 스와이프하지 않는다.
- 스와이프와 이전·다음 버튼 탐색에서 세로 위치를 유지한다. 목표 종목이 짧으면 도달할 수 있는 가장 가까운 위치로만 보정한다. 운동 기록 요약의 최초 진입은 [3.9절](#39-운동-완료-요약--workoutsummary)을 따른다.

### 3.7 휴식 상태와 하단 버튼 — `RestState`

다음 표는 현행 일반 계정의 웨이트 진행 기준이다.

| 상태 | 상단 오른쪽 영역 | 하단 CTA |
|---|---|---|
| 워밍업 | `운동 상태 / 준비 중` | `준비운동 완료` |
| 첫 종목 또는 다음 미시작 종목 | `종목 준비`와 증가하는 경과시간 | `운동 시작하기` |
| 웨이트 수행 | `WEIGHT 수행`과 확인된 누적 시간 | `n세트 완료` |
| 중간 세트 완료 직후 | `휴식 시간`과 남은 시간 | `휴식 종료` / `+30초` |
| 휴식 자연·수동 종료 | `WEIGHT 수행` 누적 재개 | 다음 `n세트 완료` |
| 마지막 웨이트 완료, 미완료 유산소 있음 | `운동 상태 / 완료` | `다음 종목으로` / `남은 유산소 건너뛰고 종료` |
| 모든 종목 완료 | **모든 종목 완료**, 경과/휴식 타이머 없음 | `운동 종료 및 요약` |

- 상단 왼쪽 **전체 운동 시간은 모든 상태에서 유지**된다.
- 휴식시간은 현재 운동 종목의 **목표 상한 반복 횟수**와 3.10의 고정 구간별 저장값으로 결정한다.
- `+30초`는 저장된 휴식 종료 예정 시각을 30초 연장하며, `휴식 종료`는 즉시 카운트다운을 해제한다.
- 남은 10~1초에는 하단 고정 `휴식 종료`·`+30초` 위에 호박색 `다음 세트 준비` 바와 남은 초를 표시한다. 상단과 하단은 같은 남은 시간을 쓰며 자동 스크롤이나 포커스 이동을 하지 않는다. `+30초`로 10초를 넘거나 자연·수동 종료하면 바를 숨긴다. 선택에 따른 점멸·어둡게·움직임 줄이기 동작은 [휴식 타이머 알림](#휴식-타이머-알림)을 따른다. 기존 본문 여백과 Safe Area·키보드 inset을 유지하며 준비 신호는 저장하지 않는다.
- 마지막 5초 효과음과 점멸의 적용 상태는 [휴식 타이머 알림](#휴식-타이머-알림)과 [P1 결정](Overload_UI_Decision_Log_v0.9.md#1040--p1-개선-정책과-순서)을 따른다.
- **마지막 세트 완료에는 새 휴식이 붙지 않는다.** 첫 `종목 준비`는 준비운동 완료 시각, 다음 준비는 직전 종목의 실제 완료 시각을 기준으로 표시한다. 웨이트·유산소 경계에서 선택에 걸린 시간도 포함한다. 복원된 작업 사본에 기준이 없으면 확인 가능한 선행 완료·준비운동 시각을 우선하고, 마지막 대체값은 세션 시작 시각이다.
- 다른 종목을 탐색하는 동안 기존 휴식의 종료 예정 시각을 유지한다. 휴식 CTA와 완료 제한은 해당 종목의 유효한 휴식에 적용한다. 유산소 시작 뒤 오른쪽은 그 종목의 활동 시간을 표시한다.
- 화면을 다시 열었을 때는 현재 시각과 저장한 기준 시각을 비교해 시간을 계산한다.
- 운동 화면에서 시간이 실제로 움직이는 상태는 UI 갱신으로 처리하되 저장값이 경과시간 계산의 출처다.

### 3.8 중량 변경 — `WeightChange`

- 단일 `중량 변경` 메뉴에서 현재 승인 진행 중량을 보여주고, 변경 중량을 입력한다.
- 선택지 두 개:
  - `오늘만 변경` — 오늘 운동 기록에만 새 중량 적용
  - `진행 중량 변경` — 명시적 확인 후 이후 정상 운동에도 적용
- 운동 중에는 `KgWheel`과 직접 입력을 재사용한다. 진행 중량 변경 선택지는 최초 계획에 있는 종목에서 제공한다. 공식 승인 중량은 서버 적용 확인으로 갱신하며, 현재 운동의 입력·수행 문맥과 완료 당시 실제값은 구분한다.
- 새로운 승인 중량에서 기준 기록이 없다면 사용자 입력을 기다린다. **최소 반복 횟수로 자동 초기화하지 않는다.**
- 성공 안내 문구는 `중량 증가를 고려해 보세요`처럼 **권고형**으로 쓴다. 목표 하한 미달 시에는 `중량 감소를 고려해 보세요`.

#### 유산소 진행과 완료 기록

공통 시간 바 아래에 루틴명과 `홈 / 종료`, CARDIO·상태 태그·종목명, 이전·목록·다음을 배치한다. `당시 계획`은 목표 시간·거리·속도 또는 페이스를 3열로 표시하고, 미설정 값은 `—`로 구분한다. 계획 경사 또는 저항은 값이 있을 때 추가 표시한다.

| 상태 | 타이머와 조작 |
|---|---|
| 준비 | 상단 `종목 준비`에 경과시간을 표시한다. 본문의 `실제 활동 시간`은 00:00:00이며 `시작하면 측정이 진행돼요`를 표시한다. 하단 `운동 시작하기`에서 실제 측정을 시작한다. |
| 진행 | `실제 활동 시간 · 일시정지 제외`와 `측정 중`을 표시한다. 하단은 `일시정지 / 유산소 완료`다. 목표 시간 도달만으로 완료하지 않는다. |
| 일시정지 | 활동 시간이 고정되고 `측정 일시정지`를 표시한다. `재개`는 이전 누적 시간에 새 실행 구간을 이어 붙인다. 일시정지 상태에서도 `유산소 완료`로 진입할 수 있다. |
| 완료 확인 | 자동 측정값을 고정하고 `측정 종료`를 표시한다. 완료 기록 카드에서 실제 시간을 검토·정정하고 선택 값을 입력한 뒤 하단 `유산소 기록 확정`을 누른다. `완료 취소 · 일시정지로 돌아가기`는 누적 시간과 적용된 초안을 유지한다. |
| 확정 후 | 실제 완료 기록과 `유산소 완료 취소`를 표시한다. 취소를 확인하면 진행 세션의 완료 결과를 취소하고 일시정지로 돌아간다. 종료·다음 종목·유산소 추가는 남은 세션 상태에 따른다. |

- 완료 기록의 연필 버튼은 시·분·초 휠과 직접 입력을 연다. 편집 취소는 적용값을 유지한다. `시간 적용`의 초 값이 자동 측정 시간을 반올림한 표시 초와 다르면 기록 시간에 노란색 `수정됨`을 표시한다. 같은 값으로 적용하면 자동 기록으로 복원된다. 확인 중의 타이머 값과 기록용 정정값은 각각 유지한다.
- 선택 항목은 실제 거리(km)·실제 평균 속도(km/h)·평균 심박수(BPM)·실제 경사도(%)의 2열이다. 거리·속도는 러닝머신·자전거·야외 운동에서 입력할 수 있다. 평균 심박수는 선택 정수 20–300이며 실제 경사도는 모든 종목에서 `저장 미지원`으로 비활성이다.
- 직접 입력한 거리가 우선이다. 거리가 비고 실제 평균 속도가 입력되면 유효 활동 시간으로 **거리**를 계산한다. 시간 정정값을 적용했으면 그 시간을 사용한다. 실제 평균 속도는 입력값이며 거리로 역산하지 않는다. 자동 시간·유효 활동 시간·거리 출처를 결과에서 구분한다. [유산소 실제 측정 계약](../../../overload-server/docs/api/cardio-actual-measurements.md)
- `현재 세션에서 종목 변경 · 유산소 추가`는 현재 세션에 적용한다. 측정 중 종목은 먼저 멈추고, 완료한 종목은 완료 기록을 먼저 취소해야 제외할 수 있다.

### 3.9 운동 완료 요약 — `WorkoutSummary`

- 미완료 종목이 남아 있는 일반 세션의 `종료`는 확인창을 연다. 웨이트·유산소 경계에는 명시적인 건너뛰기 종료도 제공한다. 실제 완료한 세트·유산소와 종료 시각을 보존하고 미완료 실적을 생성하지 않는다. 모두 완료된 경우 `운동 종료 및 요약`으로 종료한다. 계정 앱은 서버 FINISH 확인을 기기에 보존한 뒤 요약으로 전환한다.
- 운동 기록 요약은 **운동 화면의 세로 위치를 넘겨받지 않고 최상단에서 시작하는 SPA 페이지**다. 요약이 표시된 뒤 본문 스크롤을 유지한다. 이력의 상위 화면과 과거 운동 상세는 기존 복귀 및 방문 경로를 사용한다.
- **운동 기록 요약 헤더 → 요약 카드 → 조건부 중량 검토 → WEIGHT/CARDIO 실제 수행 카드 → 기록 보존 안내 → 복귀 버튼**을 표시한다. 헤더와 하단 버튼은 기존 홈 또는 루틴 복귀를 실행한다. 요약 카드는 운동 날짜와 시간 범위, 현재 완료 상태, 루틴명, 전체·웨이트·유산소 세 열을 사용한다. 수행·비수행 시간은 기존 기록에서 확인되는 값만 표시한다.
- 수행 카드의 WEIGHT/CARDIO 제목과 총계, 두 자리 종목 번호와 종목 간 구분선은 운동 기록 상세의 배치를 사용한다. 웨이트는 기존 완료/계획 세트 수, 당시 기준·목표, 세트별 중량×반복·제조사와 부하 방식·볼륨을 표시한다. 유산소는 완료/전체 종목 수와 실제 활동 시간, 당시 목표, 저장된 거리·출처·평균 속도·심박을 표시한다. [볼륨 근거](requirements.md#r-07-운동-이력-및-완료)
- 요약에는 `전체 루틴 완료`의 기존 표시 조건을 적용한다. 웨이트 완료 세트의 분모는 종료 직후 요약의 기존 계획 수를 사용한다. 종목별 계획 수가 없는 경우는 실제 완료 세트 수 표기를 유지한다.
- 화면 권고로 공식 기준 기록이 갱신됐다고 선언하지 않는다. 실제 공식 평가는 기록 상세의 평가 변경 이력에서 최초/현재를 구분한다.
- 로컬 저장과 서버 동기화를 구분한다. 서버 반영 표시는 ACK 또는 계약에 따른 서버 확인 이후에만 제공한다.
- 기존 assessment.weightReview는 서버가 지정한 반복 근거로 현재 수행을 읽는 권고이며 최종 종료 요약은 별도 V36 봉인 조회를 사용한다. 미완료 감량은 권고에만 적용하며 공식 기준 자격·최초 평가를 보존한다. [권고 계약](../../../overload-server/docs/api/workout-sessions.md#종료-화면의-중량-검토-권고--공식-평가와-분리)의 현재 응답을 신규 전체/선택 승인 API로 해석하지 않는다.
- **종료 직후의 중량 검토.** 수정·전체/선택 승인은 실제 API에 연결됐다. 봉인된 증량·감량 권고와 추천값이 있고 현재 배치 사용 가능 및 승인 중량 일치 조건을 충족한 후보를 표시한다. 저장은 편집 권한과 서버 세션·루틴 버전 검사를 거친다. `수정` → 운동별 체크·`무게 수정` → `수정 완료` → 전체/선택 승인 및 최종 확인을 구분한다. 취소나 입력 확인만으로 승인 이벤트를 만들지 않는다. 승인 후 서버 이력을 재조회한다. 승인된 후보는 즉시 요약의 편집 목록에서 제외한다. [현행 승인 흐름](#중량-권고종료-후-승인과거-조회)
- **과거 상세.** 같은 헤더·카드·수행 행 표현을 사용한다. `중량 변경 승인 이력`에서 당시 근거와 사건을 조회하고, 상세 메뉴에서 기존 실제 수행 정정·삭제·복구·평가 이력에 접근한다. 헤더와 `기록으로 돌아가기`는 기존 탐색 이력에 따라 복귀한다. [운동 기록 상세](#운동-기록-상세)

### 3.10 기록 및 설정 — `History` / `Settings`

- 기록 상세의 `⋮` 팝오버는 항목별 박스를 제거한 44px 이상 행과 가벼운 구분선으로 구성하고 외부 터치·ESC·화면 이동 시 닫는다. 정정은 종목별 완료 수행과 세트 번호/실적/시각을 분리한다. 같은 종목의 장비가 다르면 세트별로 표시하며 원본 없는 복구·중복 복구·수정 범위 확장은 허용하지 않는다. 평가 변경 이력은 원시 응답 대신 최초/현재 공식 평가와 실제 수행 변경 전후를 표시한다.

- 기록 있는 월~일 주의 첫 카드 위에만 얇은 제목/날짜 범위 구분선을 둔다. 빈 주 제목·주차별 큰 컨테이너·접기는 없으며 월 경계 범위와 선택 월 필터를 유지한다. 날짜순 검색 결과에도 재사용한다. 이 규칙은 이전 무구분 피드 결정을 대체한다.

- 기록 정정은 허용 실제 수행값만 변경하며 공식 승인값·최초 승인 문맥·계획·장비는 보존한다. 최초 평가와 현재 재평가를 구분하고 과거 정정으로 후속 승인 사건을 바꾸지 않는다. 기존 PENDING 해결은 별도 명시 절차로 유지하며 신규 전체/선택 승인과 합치지 않는다. [안전성 경계](Overload_UI_Decision_Log_v0.9.md#10236-기록-정정과-과거-승인-안전성)

- 세션 리스트 아래 `현재 중량 조정 검토`는 해당 승인 중량/배치/구성의 기준과 가장 최근 비교 가능한 기록을 나란히 설명한다. 증량 근거와 감량 검토가 함께 있으면 둘 다 표시하고 자동 변경하지 않는다. 홈은 선택 루틴의 같은 컴포넌트를 재사용한다. 해당 내용이 없으면 빈 섹션은 숨긴다.
- `진행 중량 변경 내역`은 별도 사건 목록이다. 당시 이름, `60 → 62.5kg`, `증량 완료 +2.5kg` 또는 `감량 완료 −5kg`, 시각, 승인 화면을 표시한다. 루틴 관리에서 나중에 승인한 변경도 포함하며 특정 세션이 원인이라고 추정하지 않는다.
- 최초/루틴 승인/운동 모달의 빠른 입력 모두 조절과 승인을 분리한다. 승인 저장 실패 시 편집 화면/모달에 초안을 유지하며 승인 중량과 사건은 반영하지 않는다. 저장소 재확인 후에도 새 값은 직접 재승인해야 한다. 현재 메모리 입력의 일반 저장 실패 재시도와 구분한다.
- 설정 탭의 현행 배치·계정 상태는 아래 설정 메인 및 계정 설정 상세를 따른다.
- 독립 ON/OFF 설정은 토글을 사용한다. 요일 다중 선택이나 삭제 동의에는 기존 체크/확인을 사용한다. 제목 옆 `?`는 필요한 설명만 표시하고 바깥 터치나 재터치로 닫는다. 미동기화·데이터 유실·삭제·분석 OFF 후 재활성화 시 누적 초기화 안내는 본문이나 확인 단계에서 확인할 수 있게 한다.
- [세트 사이 휴식](#세트-사이-휴식)에서 계정의 서버 저장값을 조회·편집하고, [휴식 타이머 알림](#휴식-타이머-알림)에서 현재 브라우저의 운동 알림을 조작한다.
- 미전송 기록이 있을 때 [계정 정책](auth-preview.md)의 경고·선택을 유지한다.

- 제목 없이 `내 계정` 카드로 시작한다. 카드 첫 행은 46px 원형 이니셜·계정명/이메일·이동 화살표, 아래는 `로그인 방식 / 로그인된 기기`의 같은 폭 두 열이다. 넘치는 이메일은 말줄임한다. 제공된 이메일의 앞뒤 공백을 제거하고 첫 문자를 대문자로 표시한다. 운영은 세션에서 이메일·현재 로그인 방식·기기 수를 받지 않아 `—`, `이메일 확인 불가`, `확인 불가`를 사용한다. 검토의 `review@example.test`·`R`·`이메일`·`2대`는 합성 예시다.
- 운동 카드는 `세트 사이 휴식`, `휴식 타이머 알림`, `운동 종목 보기`, `디로딩 설정` 순이다. 앞의 세 항목은 운영에서 열 수 있다. 디로딩 설정, 두 데이터 메뉴(`운동 데이터 상태 / 운동 데이터 내보내기`), 두 위험 작업(`전체 운동 데이터 초기화 / 회원 탈퇴`)은 비활성이다. 그룹 제목은 화면에 표시하지 않는다.
- `앱 설치 · 오프라인 준비`는 데이터 카드 아래의 접이식 카드다. 기존 준비 상태·브라우저별 설치·업데이트 안내를 표시한다. 설치 버튼은 설치 가능 이벤트가 있는 운영 경로에서 표시하며 최초 오프라인 접속과 백그라운드 전송 보장은 지원 범위에 포함되지 않는다. 온라인에서 연 운동을 명시적으로 이어가는 절차는 기존 로컬 보호 규칙을 따른다.
- 하단의 독립 `로그아웃`은 현재 브라우저 세션만 종료한다. 확인 뒤 운동 초안을 보존한 경우 실행하며 저장에 실패하면 보류한다. 카드·행·안전 영역은 [비주얼 명세](Overload_UI_Visual_Theme_Spec_v0.9.md#13-설정-메인과-계정-설정--2026-11-18)를 따른다. 하단 탭 내비게이션 리디자인은 후속 범위다.

#### 세트 사이 휴식

- 공통 뒤로가기 헤더와 같은 크기의 `편집`·`취소` 액션을 사용한다. 키보드 포커스가 표시된다. `반복 구간별 휴식 시간` 카드에서 1~10회, 11~12회, 13회 이상의 계정 저장값을 초로 표시한다. 60초 이상에는 분·초 환산값을 붙인다.
- 편집에서는 `시작 세트`·`끝 세트`·`휴식 (초)` 제목과 값을 같은 3열 중심에 정렬한다. 오른쪽 삭제 아이콘은 별도 열이다. 경계 숫자는 읽기 전용이며 마지막 `이상`은 같은 치수에 차콜 배경과 보조 글자색을 사용한 정적 텍스트다. `+ 구간 추가`와 행별 삭제는 비활성이다. 화면 문구 `세트`와 달리 실제 구간 기준은 **목표 반복 횟수 상한**이다.
- 계정 저장값으로 초안을 열고 `변경 사항 저장`을 누른다. 양의 정수 초를 검증하고, 요청 중 중복 저장을 막으며 성공 뒤 최신 값으로 조회 모드에 복귀한다. 실패 시 초안을 유지한다. `WRITE_CONFLICT`일 때 `최신 설정 다시 확인`으로 서버 값을 조회한 뒤 사용자가 다시 저장한다. 취소·화면 이탈은 미저장 변경 확인을 거치며 취소에는 저장 요청이 없다.

#### 휴식 타이머 알림

- 공통 헤더 아래 하나의 5px 카드에 `화면 어둡게`, `화면 깜빡임`, `효과음`, `중간 알림음`을 배치한다. 화면 방식은 상호 배타이며 둘 다 OFF도 가능하다. 깜빡임 ON일 때 상단(3열 도식)·하단(가로 바 도식) 카드의 ON/OFF를 각각 선택한다. 3·5·10초 시작 시점은 3분할이며 세부 선택은 방식 전환 뒤에도 유지한다.
- 상태 아이콘은 ON에서 푸른색, OFF에서 보조 글자색이다. 화면 어둡게는 세로로 나눈 원을 사용하며 ON에서만 왼쪽 반원을 채운다. 깜빡임은 광선·점 형태, 효과음은 음파·음소거, 중간 알림음은 울리는 종·사선 종으로 바뀐다. 종료 카운트음과 중간 알림음은 각각 켜고 끈다. 둘 중 하나를 켜면 공통 음량 0~100%를 조절할 수 있다. 중간 알림음이 켜져 있으면 **20·30·60초 전** 중 하나를 선택할 수 있다. 선택한 시점에 휴식당 한 번 알리고 같은 소리가 세 번 울린다. 종료 카운트음은 남은 5·4·3·2·1초에 각 한 번 울린다.
- 휴식이 시작될 때 저장한 중간 알림 기준과 종료 예정 시각으로 남은 시간을 계산한다. `+30초`를 누르면 새 종료 예정 시각을 기준으로 계산하고 이미 울린 중간 알림은 반복하지 않는다. `휴식 종료`를 누르면 진행 중인 화면 효과와 예약음이 즉시 해제된다. 앱으로 복귀하거나 새로고침하면 실제 남은 시간에 맞춰 표시하며 지나간 중간 알림은 건너뛴다.
- 실제 운동에서 설정한 위치만 해당 시점부터 점멸한다. 하단 준비 바는 10~1초에 표시된다. 화면 어둡게는 12~1초에 운동 상단과 본문을 덮으며 12·11초는 밝은 글자, 10초 이하는 노란 숫자다. 기존 푸터의 `+30초`와 `휴식 종료`를 사용할 수 있다. 12초를 초과하도록 연장하거나 종료하면 오버레이가 해제된다. 실제 운동의 오버레이에는 X가 없다.
- 설정의 `알림 미리보기`는 운동과 별도의 가상 시간이다. 화면 어둡게는 12초부터 진행하며 X로 닫고 휴식 조작 푸터는 표시하지 않는다. 깜빡임은 3·5·10초 선택보다 2초 앞선 5·7·12초부터 시작한다. 상단 3열과 하단 준비 바 미리보기를 좁은 폭에서도 나란히 유지하며, 해제한 영역은 낮은 밝기와 채도로 표시한다. 종료 또는 이탈 시 가상 타이머와 오디오를 정리한다. 움직임 줄이기에서는 점멸 대신 정적 테두리 강조가 적용된다.
- 전체 미리보기는 종료 카운트 효과음만 사용한다. 제목 옆 미리듣기는 일반 1회·중간 3회이며, 실제 재생과 세 소리 사이 간격에 `Ⅱ`가 표시된다. `Ⅱ`는 예약음까지 즉시 중지한다. 완료 시 `▶`로 복귀하고 다른 미리듣기는 이전 소리를 먼저 정리한다. 계정별로 현재 브라우저에 저장하며 서버·기기 간 동기화는 지원하지 않는다.
- P1-03의 UI-11에서는 마지막 5초 효과음을 복구했다. UI-02·UI-20 후속 작업에서는 계정별 브라우저 설정으로 실제 운동과 미리보기의 효과를 연결하고 운동 복귀·알림 해제를 보완했다. 서버·기기 간 설정 동기화는 후속 범위다. P1-05의 상·하단 점멸은 [시각 규격](Overload_UI_Visual_Theme_Spec_v0.9.md#14-세트-사이-휴식과-휴식-타이머-알림--2026-11-19)을 따른다.

#### 계정 설정 상세

- `내 계정`을 열면 공통 `계정 설정` 헤더 → 로그인 수단 → 대표 재인증 이메일 → 최근 이메일 재인증 → 기기 관리 진입 → `계정 정보 새로 확인` 순서다. 뒤로가기는 설정 메인의 진입 버튼으로 초점과 스크롤을 복원한다.
- 이메일 로그인은 6자리 OTP다. 서버가 반환한 신원으로 이메일·Google별 연결됨·미연결·확인 불가를 표시한다. 이메일 연결 확인, Google 연결·추가 연결과 해제를 기존 경로로 제공한다. 조회 중, 미등록 대표 이메일, 마지막 수단, 여러 동일 제공자 신원의 해제 모호성을 구분해 동작을 제한한다. 허용되는 해제는 대상·영향을 확인한 뒤 요청하며 서버가 재인증과 남은 수단을 검증한다. 합성 검토에서는 이메일만·둘 다·Google만 상태를 비교한다.
- 대표 재인증 이메일에는 마스킹 주소와 등록·미등록·확인 불가를 표시한다. `이메일로 재인증`은 인증 코드 요청과 6자리 확인을 거친다. 등록 후보와 일반 재인증을 구분하고 유효시간·재발송 대기·오류를 표시한다. 최근 재인증 카드는 이 화면에서 확인한 OTP 결과와 `서버 이력 확인 불가`를 구분한다. 대표 이메일 등록이나 Google 로그인은 OTP 성공 표시의 근거가 되지 않는다.
- `계정 정보 새로 확인`은 기존 조회를 다시 실행해 연결 목록·대표 이메일을 갱신한다. 조회 중과 실패를 구분한다. 기기 관리 진입과 API 미지원은 다음 절을 따른다. [인증·계정 연동](../engineering/backend-ui-v0.9.md#설정-메인과-계정-설정-연동)

#### 로그인된 기기 관리

- `설정 → 내 계정 → 로그인된 기기 관리`로 연다. 계정 설정의 진입 행은 `접속 상태 확인 · 원격 로그아웃`과 이동 화살표를 표시한다. 기기 수 태그는 조회 지원 전까지 생략한다. 공통 헤더와 브라우저 뒤로가기에서 계정 설정으로 복귀하며 진입 행의 초점과 스크롤을 복원한다. 계정 설정 헤더에서 설정 메인으로 돌아간다.
- 접속 현황 3열(전체 기기·온라인·오프라인), 현재 기기, 다른 기기 목록, 원격 로그아웃 버튼을 배치한다. 현재 기기는 확인된 ID로 구분해 맨 위에 `이 기기`를 붙인다. 다른 기기는 마지막 접속 내림차순이며 누락 시각은 뒤에 둔다. 기기명·OS와 브라우저·접속 상태·로그인 일시·마지막 접속을 별도로 표시한다. 기준 시각과 비교해 1시간 미만의 마지막 접속은 `방금`이나 분 전으로, 그 외에는 날짜·시각으로 보여 준다.
- 접속 상태와 운동 상태를 별도로 표시한다. 편집 기기가 현재 기기면 `이 기기에서 운동 진행 중` 패널을 표시한다. 다른 기기면 현재 카드에 `현재 운동은 읽기 전용`, 해당 기기 카드에만 `운동 진행 중`을 표시한다. 운동 없음이나 편집 기기 미확인에는 패널을 생략한다.
- 운영은 요약의 세 칸에 `—`와 조회 미지원 안내를 표시한다. 이 경우 현재·다른 기기 카드와 개별 로그아웃 버튼은 나타나지 않으며 두 일괄 버튼은 비활성이다. 조회 중·실패·빈 목록·현재 기기 확인 불가와 구분한다.
- 검토 화면의 `기기 상태 예시`에서 합성 기기 3대·온라인 2대·오프라인 1대, 현재 기기만, 운동 상태 3종, 현재 기기와 접속 상태 미확인, 조회 중·실패·빈 목록·미지원을 비교한다. 확인창은 개별·다른 기기 모두·모든 기기의 종료 범위를 보여 주고 운동 중인 기기가 대상이면 경고를 추가한다. 취소와 `시안 확인` 모두 창을 닫으며 목록과 로그인 상태를 유지한다.
- 긴 기기명과 환경 정보는 줄바꿈한다. 하단 버튼은 본문에 배치하고 기존 탭과 모바일 안전 영역을 유지한다. [UI 결정 10.33절](Overload_UI_Decision_Log_v0.9.md#1033--로그인된-기기-관리-화면-구현--2026-11-18)

#### 운동 기록 상세

- 요약 첫 행은 기존 시간대의 날짜/시작–종료(`MM.DD · 요일 한 글자 · HH:mm–HH:mm`), 기록 메인과 동일한 상태 아이콘·명칭, 세로 `⋮` 메뉴다. 루틴명은 다음 행에서 최대 2줄과 전체 이름 title을 사용한다. 메뉴의 기록 정정·누락 수행 복구·기록 전체 삭제·평가 변경 이력과 비활성 조건·외부 닫기/Escape·기존 이동을 유지한다.
- 3열은 `전체 / 웨이트 / 유산소`이며 각각 `전체 경과 시간 / 비수행 시간`, `수행 시간 / 수행·계획 종목`, `수행 시간 / 수행·계획 종목`의 2단 지표다. 기존 `recordFacts` 값을 사용하고 미확인 시간은 `–`, 확인된 0은 기존 시간 포맷으로 구별한다. 시간 합계 관계 경고·볼륨 미확인 세트 수·미확인 상태를 보존한다.
- `중량 변경 승인 이력`은 종료 당시 저장된 증량·감량 권고와 추천 중량이 있거나 실제 승인 사건이 있을 때 표시한다. 미승인 권고는 미승인으로 구분한다. 유지·판정 근거 부족은 이 카드에 표시하지 않으며 해당 권고와 승인 사건이 모두 없으면 카드 전체를 생략한다. 조회 중과 오류는 별도로 표시하고 현재 수행값으로 과거 판정을 새로 만들지 않는다. 기본 펼침과 오른쪽 chevron을 사용하며 열린/닫힌 상태 모두 앞뒤 간격은 10px다. 카드 세로 패딩은 8px, 접기 터치 영역은 44px다.
- 수행은 운동마다 큰 카드를 만들지 않고 한 카드의 `WEIGHT / CARDIO — 선 — 오른쪽 총계`로 구분한다. 종목별 두 자리 번호·제목/세트 수와 총중량·당시 기준/목표를 표시한다. 세트는 `실제 중량×반복 / 제조사·부하 방식 / 세트 볼륨` 3열이며 긴 보조 정보는 줄바꿈한다. 종목 간 상단 여백·얇은 구분선은 넉넉하게, 세트 행은 촘촘하게 한다. 미수행 원인·기준 미달 색/안내와 완료 세트 없음도 유지한다.
- CARDIO는 번호/이름 왼쪽·실제 시간 오른쪽, 목표와 기존 거리 출처/거리·평균 심박·실제 속도의 압축 문장이다. 첫 섹션이 CARDIO일 때 추가 상단 마진을 적용하지 않아 WEIGHT 단독과 같은 시작 규칙을 사용한다. 혼합일 때만 기존 WEIGHT 다음 CARDIO 간격을 유지한다. `result.corrected`로 확인되는 **시간 바로 앞에만** 노란 `수정` 배지를 붙이고 자동 타이머 원본도 남긴다. 거리·심박·속도는 개별 수정 근거가 없어 배지를 추정하지 않는다. 각 값의 기존 포맷·단위·미입력·출처 미확인 표기는 유지한다.
- `기록 보존 안내`는 기존 `dataNote`를 하단 카드로 옮긴 것이다. 정상 저장·삭제·자동 종료·합성 시연 등 전달받은 문구를 그대로 표시하며 새 저장 정책을 뜻하지 않는다. 하단 복귀 버튼과 탭 내비게이션은 유지한다.

#### 운동 현황

- 헤더 한 줄에 뒤로 가기와 `운동 현황`을 놓는다. 화면 순서는 **통합 기간 카드 → 운동량 요약 → 운동량 추이 → 주간 루틴 달성 → 유산소 현황**이다.
- 기간 카드의 `주간 / 월간`과 추이의 `세트 / 총중량`은 상대적으로 어두운 둥근 트랙 안에서 선택 박스가 200ms 동안 이동한다. 모션 줄이기 설정에서는 즉시 전환한다. 중앙 날짜는 주간 `MM/DD ~ MM/DD`, 월간 `YYYY/MM`이며 한 줄의 높이와 정렬을 공유한다. 이전·다음·달력은 36×36px 외형과 36×44px 조작 영역을 사용한다. 기본 상태의 달력은 일반 버튼과 같고 열린 상태와 키보드 포커스는 구분한다.
- `운동량 요약`과 `선택 기간 전체` 아래에 `완료 세트`·`총중량` 독립 카드 두 개를 같은 너비로 놓는다. `운동량 추이`는 세그먼트 → 검색 → 조건별 가로 스크롤 태그 → 선택 결과와 그래프 순서다. 기간과 지표 전환은 기존 집계에 적용한다.
- 검색 행은 둥근 범위 버튼·입력·원형 검색 버튼으로 구성한다. `전체 / 운동별 / 분류별 / 근육별` 팝오버는 둥근 메뉴와 선택 배경을 사용하며 터치·키보드 선택, Escape, 외부 닫기와 포커스 복귀를 지원한다. 검색 버튼은 활성 상태와 키보드 포커스에서 강조한다. 실제 입력 글자는 16px로 iPhone 입력 포커스 확대를 피하며 후보의 이름·보조 정보·아이콘과 내부 스크롤을 유지한다. 선택값 해제는 전체 통계로 복귀한다. 실제 선택 항목의 일별 추이는 [현행 연결 범위](#기록-탐색정정통계-연결)를 따른다.
- `주간 루틴 달성`은 선택 날짜를 포함하는 주의 달성률·진행 바·계획/완료 운동일·월~일 상태 카드 7개를 보여 준다. 최종 범례는 `– 휴식`, `· 미수행`, `? 미확인`이다. 범례 문구는 화면 표기이며 기존 날짜별 판정과 공식 달성률을 유지한다.
- `유산소 현황`은 누적 유산소 시간·누적 일수 2열과 종류별 아이콘·이름·누적 거리를 배치한다. `상세 보기`를 누르면 같은 카드 안에 계획 대비 시간·거리 출처가 펼쳐지고 `운동 이력`으로 이동할 수 있다. 운영 Overview는 날짜별 전체 시간과 날짜 없는 종류별 합계를 제공하므로 종류별 수행 요일은 생략하며 누적 일수는 `미확인`이다.
- 320·375·393·430px에서 요약 2열, 날짜의 한 줄, 달성 카드 7열과 내부 검색 스크롤을 유지한다. `/routine-preview?tab=history&activity-demo=states`는 직전 주 다양한 상태와 요일·거리 예시를 보여 주는 별도 [합성 시연](../engineering/frontend.md#운동-현황-최종-ui-승인-및-구현-완료--2026-11-17)이다.

#### 성장 추적

- **UI 승인·구현 완료 / `f6ad67d`.** 한 줄 뒤로 가기·제목 아래에 `분석할 운동`, `성장 분석`, `승인 중량 변경 이력` 카드 세 개를 배치한다. 검색은 기존 운동별 후보·태그·목록 스크롤·선택/초기화·빈 상태를 유지하며 화면에 없는 범위 필터를 추가하지 않는다.

- 요약 하단 구분선 아래에 `승인 중량 변경`과 `N건`을 표시한다. API가 전체 건수를 제공하지 않으므로 다음 페이지가 있으면 `불러온 N건`, 아직 확인되지 않은 수는 `—`다. 최신값은 선택 배치·기간에서 조회한 승인 사건을 사용하며 일반 수행 중량이나 현재 루틴 값으로 과거를 보충하지 않는다.
- `중량 변화 그래프`는 날짜·kg 축, 기존 선·점·툴팁과 연결 근거를 유지한다. 꼭짓점별 상시 중량 라벨은 채택하지 않았다. 일반 운동 세트와 디로딩 중량의 제외 설명은 분석 카드 하단에 한 번 표시한다.

- 요약은 `계획 세트 / 운동 예정일` 2열이며 숫자 19px·단위 12px이다. 계획값은 기존 `data.total`, 누락 시 `미확인`이다. 운동 예정일은 기존 집계가 없어 항상 `미확인`이며 새 예정일 계산을 구현한 것이 아니다.
- 두 보기 모두 단일 카드 안에 `그룹명 — 얇은 선 — 오른쪽 합계`와 항목별 수치·막대를 놓는다. 분류는 `전면 / 후면`, `PPL`, `신체 부위`이며 근육은 기존 근육군을 따른다. 두 번째 그룹부터 상단 간격 20px, 항목은 상하 8px, 그룹 제목 14px·항목 13px·수치 12px이다. 카드 패딩은 14px 12px, 모서리는 기존 5px이다.
- 분류 합계는 기존 계획 총세트를 사용하며 해당 분류의 계획이 미확인이면 `합계 확인 불가`다. 근육군 소계는 기존 세부 기여 합으로 상위 독립 분류 합계와 구별한다. 운영 데이터의 부위 분류·전체 근육 목록·권장 범위 누락은 그대로 남긴다. `0세트 포함`은 기존 정확한 0 필터만 제어하며 ▼ 가이드·상한 초과 숫자 보존을 유지한다.

#### 주간 근육 통계

- 공통 헤더 → 달력 모양의 읽기 전용 이번 주 날짜 행/`이번 주` 배지 → 설정 카드 → 압축된 `주간 세트 달성` → 보기별 달성 현황 제목 → 통합 통계 카드 → 필수 상태 안내 순서다. 기간은 기존 이번 주 월~일 API 범위이며 `MM.DD – MM.DD`로 표시한다. 날짜 이동·달력 열기·주간/월간·프리셋·0세트 토글은 없다.
- 설정 카드 안에 `분석 기준`의 `분류별 / 근육별`, `측정 지표`의 `세트 / 총중량`을 세로 배치한다. 계획 페이지의 2분할 트랙·40px 버튼·패딩 4px·모서리 12px·200ms 선택 표시와 모션 줄이기를 재사용한다. 기존 선택 상태·필터·전환 동작을 유지한다.
- 요약 첫 행은 제목과 `미확인`, 둘째 행은 7px 빈 트랙과 `실제 완료 / 미확인 세트`다. 현재 분석에는 주간 전체 당시 계획과 세트 달성률이 없어 채운 비율이나 임의의 0%·100%를 표시하지 않는다. 총중량 선택 중에도 세트 기준 요약이며 일수 기반 루틴 달성률을 전용하지 않는다.
- `분류별 달성 현황 / 근육별 달성 현황` 아래 한 카드의 그룹·구분선·항목·막대는 계획과 같은 디자인을 사용한다. 세트 지표에서 분류별 독립 합계는 `합계 확인 불가`, 근육군 합계는 기존 실제/당시 계획 기여 소계다. 총중량 모드에서는 기존대로 그룹 소계를 숨기고 항목의 실측 kg만 표시한다. 계획 총중량·항목별 퍼센트를 새로 계산하지 않는다.
- 기존 항목 선택/0 필터·소수 기여·계획 없음 `—`·계획 확인 필요·빈 상태·오류를 보존한다. 막대는 기존 수치/최댓값 정규화와 상한 규칙을 사용하며 이번 리디자인에서 달성 비율 막대로 바꾸지 않았다. HTML의 분류·권장 수치는 합성 예시다. 운영 API의 지원 범위는 연결 명세를 따른다.


### 3.11 디로딩 · 확정 화면 흐름

- 홈 헤더 → 디로딩 상세 → 횟수·분할·요일 선택 → 운동이 배치된 날짜만 있는 비교 미리보기 → `이 일정으로 디로딩 시작`. 날짜를 펼쳐 원본 대비 종목·중량·세트·반복·유산소 목표를 확인한다. 원본과 승인 중량의 보호를 안내한다. 상세에서 자격 미달 이유를 표시하고 시작을 비활성화한다. 미리보기 하단에서 바로 시작을 요청하고, 그 순간 재검사에서 거부되면 최신 이유를 표시한다.
- 진행 중 홈에서만 `일반 보기 / 디로딩 복귀`를 전환한다. 선택한 조회 모드는 루틴·기록 탭 이동에 유지한다. 일반 보기에서는 원본과 일반 기록의 조회만 허용하고 원본 실행·수정·삭제를 제한한다. 조회 전환은 진행 중인 디로딩 기간·세션을 바꾸지 않는다.
- 디로딩 홈에서는 오늘의 임시 루틴과 임시 일정을 표시한다. 전체 임시 목록·편집·삭제 및 빈 날짜로 옮기기는 루틴 탭에서 처리한다. 완전 휴식은 오늘의 루틴에 휴식 안내를 표시하고 시작·다른 루틴 선택을 숨긴다. 경과한 휴식일은 `경과`로 표시한다.
- 진행 상세에서만 완료·조건부 취소를 제공하고 각각 한 번 확인한다. 8~10일차 최초 진입의 권장 기간 경과 안내는 진행 중 운동을 방해하지 않는다. ACTIVE 운동 보호는 [디로딩 v1.7 종료 정책](Overload_Deloading_Design_Specification_v1.7.md#3-디로딩-시작취소완료자동-종료), 직접 완료·지연 자동 완료·무수행 취소의 복귀 시점은 [§10.5](Overload_Deloading_Design_Specification_v1.7.md#105-주간-일정-프리셋-연동)를 따른다. 완료한 기간 카드는 일반 기록에서 조회한다.

### 3.12 공통 숫자 입력

- 정책상 루틴·일반/디로딩 세션·기록 정정의 편집 가능한 중량, 세트 수, 반복 횟수와 반복 범위가 공통 입력 대상이다. 현재 일반 운동의 중량·반복 휠은 구현됐으나 종료 기록 정정은 허용된 native 입력을 유지한다. 정책 대상 전체에 휠이 적용됐다고 해석하지 않는다. 구체적인 포함·제외 범위는 [Decision Log 10.19절](Overload_UI_Decision_Log_v0.9.md#1019--공통-숫자-입력-세로-휠-피커)을 따른다.
- `[−] [현재 숫자] [+]`를 유지한다. 가운데는 React PWA의 커스텀 세로 휠을 열며, 중앙값 강조와 스크롤 종료 후 정렬을 적용한다. `− / +`와 휠의 기본 변경 간격은 중량 2.5kg, 세트·반복·반복 범위 1이다. 종료 후 중량 검토의 예정값 수정은 10.23.5절의 PLATE/STACK 2.5kg·기타 1kg을 우선하며 승인 권고 폭 5kg·2kg과 구별한다. `직접 입력`은 휠 안에서 숫자 키보드로 전환한다.
- 기존 값·자동 입력·빈 초안을 보존하고, 허용된 중량을 휠 간격에 맞춰 반올림하거나 자르지 않는다. 사용자가 조절한 값은 초안에 반영한다. 완료·승인·저장·종료는 기존 확정 경로를 사용한다.

### 3.13 기록 하위 페이지 공통 헤더

- [RecordSubpageHeader](../../src/components/RecordSubpageHeader.tsx)와 [전용 CSS](../../src/components/RecordSubpageHeader.module.css)를 **운동 현황·성장 추적·주간 근육 계획·주간 근육 통계·운동 기록 상세·전체 운동 이력**에서 사용한다. 각 화면은 제목·기존 뒤로 가기 핸들러·접근 가능한 버튼 이름(`기록으로` 또는 `루틴으로`)을 전달한다. 마지막 두 화면의 적용은 `3bd64a4`에서 승인됐다.
- 헤더 최소 높이 44px, 버튼 44×44px, 중앙 SVG 24px, 제목 22px·750·줄 높이 1.4다. 공통 내부 그리드 `32px / minmax(0,1fr)`, 간격 2px, 버튼 시작 여백 −12px, 헤더 상하·좌우 패딩/마진 0으로 터치 영역과 시각적 화살표를 분리한다. 같은 화면 너비에서 적용된 6개 페이지의 화살표 중심·제목 시작 좌표·수직 정렬이 일치한다. 페이지별 위치 보정은 두지 않는다.
- 버튼 기본 배경·테두리는 없고 기존 키보드 포커스 표시를 유지한다. 기존 탐색·브라우저/PWA 뒤로 가기·화면 상태 복원을 바꾸지 않으며 본문 카드의 위치·크기·텍스트도 유지한다. 다른 기록 하위 페이지에서도 재사용할 수 있지만 적용 범위를 확대해 설명하지 않는다. [HTML](Overload_UI_Baseline_Wireframe_v0.9.html)은 동일 규격을 밝은 무채색으로 대응한다.

| 예시 | 검토할 동작 |
|---|---|
| 모달과 버튼 | 일반 확인은 Dusty Blue, 삭제·미저장 변경 버리기는 짙은 빨강 채움과 옆의 흰색 윤곽 취소를 사용한다. 위험 작업 진입 버튼은 별도 윤곽 스타일이다. `삭제 확인`과 `버튼 예시`에서 호버·눌림·키보드 포커스·비활성·처리 중을 확인한다. 처리 중인 주요 버튼은 스피너와 문구를 표시하고 재실행을 막는다. |
| 닫기와 안내 | 일반·위험 모달은 취소와 확인, 단일 안내는 확인을 제공한다. 닫기 버튼·Escape·브라우저 뒤로 가기에서는 닫힌 뒤 시작 요소로 포커스를 되돌린다. 토스트는 성공·오류·안내를 한 건씩 표시하며 닫기 버튼과 자동 종료를 제공한다. |
| 스켈레톤 | `스켈레톤 표시`와 `콘텐츠 표시`에서 같은 계정 카드의 위치와 크기를 비교한다. 루틴 태그의 `목록 표시`와 `목록 스켈레톤`도 같은 행·패딩·텍스트 슬롯을 사용한다. 로딩 중 콘텐츠 조작을 잠그고 움직임 줄이기에서는 정적인 자리 표시를 사용한다. |
| 검색 태그 UI | 운동량 추이와 같은 구조로 왼쪽 검색 범위(`전체`·`운동별`·`분류별`·`근육별`), 검색 입력, 범위별 칩과 결과를 표시한다. `운동별`에는 운동 부위 칩, `근육별`에는 근육 분류 칩을 제공한다. 칩 선택을 강조하고 좁은 폭과 긴 칩은 칩 영역 안에서 가로로 스크롤한다. 빈 입력·검색어 변경·지우기·결과 선택은 합성 자료로 시연한다. |
| 루틴 태그 선택 목록 | 각 행에 태그 이름과 보조 설명을 배치하고 한 항목을 선택한다. `미지정`으로 분류를 해제할 수 있다. 방향키·Home·End는 선택 가능한 행으로 이동하고 Enter로 선택한다. Escape는 예시를 닫고 기존 선택을 유지한다. 비활성·빈 목록·스켈레톤 상태도 제공한다. |
| 서브페이지 헤더 | `기본 서브페이지 헤더 보기`에서는 왼쪽 뒤로가기와 제목, 오른쪽 OVERLOAD 이미지를 표시한다. `긴 제목`은 좌측에서 줄바꿈하고 로고의 원본 비율과 우측 정렬을 유지한다. 우측 액션형은 같은 자리에 편집·취소 조작을 제공한다. |
| 기타 피드백 | 인라인 검증 오류는 입력과 연결해 표시한다. 루틴·기록·검색의 빈 상태, 상태 태그·텍스트, 오프라인·동기화 상태 카드를 예시로 확인한다. |

### 3.15 모바일 입력과 키보드

- 검색·텍스트·메모·숫자 직접 입력의 렌더링 글자 크기는 16px 이상을 기준으로 한다. 브라우저 수동 확대와 숫자 휠·검색 결과의 내부 스크롤을 유지한다.
- 일반 화면에서는 보이는 영역과 고정 헤더를 기준으로 필요한 거리만 보정한다. 모달은 내부 스크롤을 사용한다. 보이는 입력을 다시 정렬하거나 사용자의 스크롤과 경쟁하지 않는다.
- 운동 화면 하단 메모는 터치 포커스 전에 스크롤 공간을 확보하고 Safari의 기본 이동을 우선한다. 키보드가 닫혀 뷰포트가 안정된 뒤 현재 위치를 정상 범위에 맞추고 임시 공간을 정리한다. 다른 필드·화면으로 이동하면 이전 보정을 취소한다. 고정 액션과 탭의 키보드 중 숨김·복원은 기존 구조를 사용한다.

## 5. 반응형·상태 검증 체크리스트

**후속 React 구현·검증:** [10.23.7절](Overload_UI_Decision_Log_v0.9.md#10237-디로딩과-공통-ux)에 따라 iOS Safari/PWA 기본 가장자리 뒤로가기와 History·앱 이동의 정합성을 맞추고 초안·취소 보호를 유지한다. 모달 X의 불필요한 자동 포커스 테두리를 방지하되 focus-visible과 닫은 뒤 원래 조작 요소로 포커스 복원을 유지한다. 브라우저 제스처를 재구현하거나 접근성 포커스 표시를 전역 제거하지 않는다.

### 기기·시각
- 375px / 390px / 430px 너비에서 가로 스크롤이나 중첩 없음
- 긴 종목명, 중량 소수점, 큰 반복 횟수에도 텍스트·입력칸 줄바꿈 적절

- 한 종목 기록 → 휴식 자동 시작 → +30초 → 휴식 조기 종료 → 다음 세트

- 종목 메모 스크롤 접근, 운동 종목 이동/원본 루틴 불변

- 실제 iPhone Safari와 홈 화면 설치형 PWA에서 느린 스와이프, 빠른 연속 스크롤, 관성, 중앙 스냅을 확인한다. 의도하지 않은 값 반영과 부모 화면의 세로 스크롤 충돌이 없는지 검증한다.
- 휠에서 `직접 입력`으로 전환할 때 정수·소수 키보드, 작은 화면의 Safe Area와 하단 버튼 가림, VoiceOver에서 현재 값·증감·선택·직접 입력 조작을 확인한다. Android에서도 같은 사용 흐름을 검증한다.
- 간격 밖의 유효 중량과 빈 값을 열기만 했을 때 보존되는지 확인한다. 값 변경 후 취소·복원, 오프라인 초안 저장과 재진입을 검증하고 휠 조작만으로 완료·승인·서버 저장·운동 종료가 발생하지 않는지 확인한다.
- 관성·애니메이션·행 간격·선택 반영 타이밍과 시각 세부는 실기기 검증 결과로 확정한다.

## 7. Task 005 — 유산소 화면과 상태

- P1 이후 진입·시작·자동 이동은 [3.6절](#36-운동-진행--workoutframe--localworkoutflow)을 적용한다.
- 루틴 생성·편집의 CARDIO 목표는 3.3을 따른다. 저장 계획의 시간·거리·강도와 세션에서 확정하는 실제 시간·거리·속도·평균 심박은 별도의 데이터다.
- 운동 진입: 웨이트의 마지막 세트는 현재 기록을 유지하고 `다음 종목으로`로 유산소 준비에 진입한다. 유산소 전용은 워밍업 없이 준비로 진입한다. 진입만으로 타이머를 시작하지 않는다.
- 상단 왼쪽은 전체 세션 시간이다. 오른쪽은 준비 중 `종목 준비` 경과시간, 시작 뒤 유산소 활동시간이다. 본문과 홈 이어가기의 상태 표시에서 진행·일시정지·완료 확인·완료·건너뜀을 구분한다. 유산소에서는 웨이트 휴식 CTA를 표시하지 않고 해당 휴식의 종료 시각을 보존한다.
- 본문은 현재 한 종목의 계획과 실제 시간에 집중한다. 하단은 준비 시 `운동 시작하기`, 진행 시 `일시정지 / 유산소 완료`, 정지 시 `재개 / 유산소 완료`, 확인 시 `유산소 기록 확정`이다. 목표 도달 안내로 자동 종료하지 않는다.
- 완료 확인은 자동 시간·선택 실제 거리·수동 평균 BPM을 제공한다. 시간 정정 체크 전에는 시간 입력을 숨긴다. 확인 취소는 시간을 재개하지 않고 일시정지와 초안을 유지한다. 확정 전 상태/초안은 홈·새로고침 후에도 복원한다.
- 전체 종료 시 미완료 유산소가 있다면 기록 확인으로 돌아가는 경로와 건너뛰기 종료를 구분한다. 완료/건너뜀 뒤 다른 미완료 종목이 있으면 다음 종목으로 이동한다. 모든 웨이트 완료 후 추가 버튼을 종료 영역에 두며 운동 중에는 세션 편집 안에서만 노출한다. 추가를 강요하는 팝업은 없다.
- 기록 상세는 웨이트 실적·유산소 실적을 별도 카드로 표시한다. 계획과 실측, 자동 시간과 수동 정정, 미시작과 미완료 건너뜀을 텍스트로 구분한다. 두 종류를 모두 완료해야 `전체 루틴 완료`를 표시한다.
- 고정 CTA·스크롤 여백·키보드 inset·Safe Area와 다크 모드를 유지한다. 실제 DOM 검증은 375×812/390×844/430×932에서 진행했고, 실제 iPhone 가상 키보드·잠금·Standalone은 미검증이다.

## 8. Task 005.5 — 계정 UX 프리뷰

인증·계정 UI는 개발 전용 `/auth-preview`로 격리한다. 기존 다크 카드·Dialog·4탭 패턴을 재사용하고 프리뷰 안에서만 빨간색 CTA를 적용한다. 상단 가상 상태 안내와 하단 개발 패널을 제품 UI와 구별한다. OTP는 단일 숫자 입력, 주요 폼 버튼은 문서 흐름에 두어 키보드가 열려도 스크롤로 접근할 수 있게 한다. [상세 화면/시나리오 및 실기기 체크리스트](auth-preview.md)를 따른다. 기존 앱의 파란색 스타일과 실제 운동/설정 화면은 유지한다.

## 9. Task 005.5 계정 UX 인계

정리일: 2026-10-27. 인증·계정 목업은 사용자 1차 검토를 통과했다. 아래는 확정된 제품 흐름으로, 기존 UI를 이번 작업에서 변경하거나 모두 구현됐다고 선언하는 내용이 아니다. 정책 기준은 [인증·계정 정책](auth-preview.md), [완료 기록/저장·다중 기기·충돌 요구사항](requirements.md)의 R-07 및 10절이다.

| 상황 | 필요한 UX |
| --- | --- |
| 재실행/인증 만료 | 정상 재실행 시 자동 로그인 유지. 운동 중 만료는 조작을 막지 않고 완료 후 필요한 재인증으로 연결. 동일 계정 기록만 전송. |
| 로그인 수단 연결/복구 | 기존 계정 재인증 후 새 수단 인증·연결. 같은 이메일 자동 통합 금지. 연결된 수단으로 복구하며 마지막 수단 해제를 제한. |
| 미동기화 로그아웃 | ‘동기화 후 로그아웃’ / ‘로컬 기록 유지 후 로그아웃’ 및 취소. 서버 저장 확인 전 성공 표시 금지. 다른 계정에서 이전 계정 기록 비노출. |

| 기존 기기 사용 불가 | 서버의 마지막 저장 상태와 누락 가능성 안내 → 사용자 요청으로 강제 이전. 이전 기기의 나중 전송이 최신 상태를 자동 대체하지 않음. |
| 기록 충돌 | 서버/로컬 차이점만 표시 → 누락·변경 수행 정보 선택 복구 → 하나의 유효 세션으로 통합. 복구 전 동기화 완료 표시 금지. |
| 완료 기록 수정/삭제 | 사용자의 명시적 요청으로 허용. 수정 전 정보·변경 사실/삭제 사실을 추적하고 당시 판단과 수정 후 현재 판단을 구별. 현재 평가는 재계산하되 승인 중량 자동 변경 없음. |
| 새 루틴/전체 초기화/탈퇴 | 새 루틴은 이력 유지. 전체 초기화는 계정 유지·운동 데이터 삭제. 탈퇴는 계정/수단까지 대상으로 구분. 내보내기 안내·재인증·최종 확인 흐름을 유지. |

같은 계정의 한 세션 충돌 복구와 독립 계정 간 운동 데이터 병합을 구별한다. 후자는 후속 과제다. 아래 과거 설계 대상 표시는 당시 기록이며 현재 구현된 정정·누락 복구·버전 충돌 처리는 현행 기능 흐름을 따른다. 차이 표시의 세부 단위·복구 검증·수정/삭제 이력 표현·제어권 이전 실패 화면은 [Task 006 설계 대상](../handoff/Overload-Task006-Design-Handoff.md)이며 이번 문서 작업에서 구체적 UI/기술 계약을 확정하지 않는다.

### 검색 상태와 화면별 범위

공통 구현은 [SearchList](../../src/components/SearchList.tsx)이며 `IDLE → EDITING → SELECTED`를 사용한다. 검색을 열어야 결과와 분류 필터가 함께 나타나고 닫으면 함께 사라진다. 목록 열기 자체는 서버 저장을 발생시키지 않는다.

| 조작 전 상태 | 사용자 조작 | 결과와 데이터 변화 |
|---|---|---|
| 기본 상태 | 입력 또는 검색 열기 | EDITING. 현재 조건의 후보 조회·필터 조작 가능 |
| 입력 중·검색어 있음 | X | 검색어만 지우고 목록·필터·입력 포커스 유지 |
| 입력 중·검색어 없음 | X | 호출 화면의 선택 초기화 실행, IDLE, 목록·필터 닫기, 입력 포커스 해제 |
| 결과 선택됨 | X | 선택·검색어 해제, IDLE. 해당 선택에 종속된 그래프/조회 해제 |
| 입력 중 | 결과 본문 선택 | 호출 화면으로 선택 전달. 선택을 보존하는 화면은 운동명을 입력값으로 표시하고 목록 닫기 |
| 입력 중 | 결과의 상세 조회 | 기존 CatalogDetail/SelectedExercise로 이동. 본문 선택과 별개이며 기록·루틴을 저장하지 않음 |
| 입력 중 | 바깥 누름 또는 Escape | 검색 닫기. Escape는 검색 열기 버튼에 포커스를 돌려주고 호출 화면의 취소 처리도 실행 가능. X와 달리 공통 코드가 검색어·필터 전체를 초기화하지 않음 |

| 호출 화면 | 초기 상태·후보·선택의 용도 | 초기화 범위와 한계 |
|---|---|---|
| 설정의 운동 종목 보기 | 기본 EDITING. 공개 카탈로그 이름·별칭과 부위 필터, 검색 범위 선택 없음. 선택은 UUID 상세 조회이며 루틴 추가가 아님 | ExerciseSearch의 X 초기화는 검색어와 부위 ALL로 복귀. 목록/상세는 기존 조회 화면 재사용 |
| 루틴·진행 운동의 종목 선택 | 일반적으로 닫힌 검색 또는 호출부의 autoFocus로 시작. 신규 선택 가능한 표준 운동만 추가/교체에 사용 | 선택값을 편집 초안/현재 운동으로 전달한다. 모든 호출에서 선택 운동명을 검색창에 계속 남기는 방식은 아님 |
| 운동 현황 | 기본 닫힘. 전체/운동별/분류별/근육별 후보와 해당 범위의 분류 필터 | 선택 해제는 전체 통계로 복귀. 기간·단위·분류 조건은 각 화면 상태로 보존 |
| 성장 추적 | 기본 닫힘. 운동별만 검색하며 선택 기간의 실제 수행/승인 근거가 있는 종목 사용 | 선택 해제 시 배치·성장선 조회를 해제. 부위 태그는 유지하며 다음 검색에 재사용 |

성장 태그는 서버 `groupCode` 검색을 사용한다. 카탈로그/운동 현황 태그는 클라이언트 후보 필터다. 서로 동일한 검색 endpoint라고 문서화하지 않는다. 각 후보의 없는 분류나 미확인 실적을 임의 생성하지 않는다.

### 루틴 저장과 진행 운동의 분리

1. 루틴 생성/편집은 이름·선택 태그·웨이트/유산소 종목, 순서와 목표를 초안에 둔다. 이름·종목 최소 1개·세트/반복 정수·소수 중량·유산소 목표 범위를 검사하고 신규 유산소는 카탈로그 정체성을 요구한다.
2. 기존 웨이트의 승인값과 최초 중량은 별개다. 조합 변경은 기존 배치 제거와 NEW ID로 저장하며 신규 최초 중량은 현재 코드에서 사용자 입력을 요구한다. 최근 실제 중량 자동 제안·없으면 0 자동 초기화는 구현되지 않았다. 목표 조회는 정책 3-6의 정확한 조합·FINISHED만이며 ACTIVE 제외가 확정됐다.
3. 같은 배치의 새 승인값은 변경 사항 저장에서 명시적으로 확인한 후 `weightApprovals`로 제출한다. 숫자 편집이나 모달 확인만으로 서버 승인값은 바뀌지 않는다.
4. 저장 성공 뒤 루틴 조회를 갱신하고 생성 완료 후 일정 배정을 선택할 수 있다. 실패하면 초안과 고정된 생성 요청을 유지한다. 미저장 초안을 닫거나 뒤로가면 폐기 확인한다. 삭제는 서버 확인 후 목록을 갱신하며 과거 기록을 삭제하지 않는다.
5. START는 그 시점의 루틴을 InitialPlan으로 복사한다. 이후 루틴 편집은 이미 시작/종료된 세션의 최초 계획을 바꾸지 않는다. 요일 배정·활성 프리셋 변경은 루틴 저장과 별도 [일정 계약](../../../overload-server/docs/api/weekly-schedule.md)이다.

### 운동 시작·수행·저장·종료

- 인증된 계정·데이터 세대·쓰기 가능 상태에서 홈의 기본 또는 오늘만 선택 루틴으로 START한다. 선택만으로 세션을 만들지 않는다. 시작 요청의 ID/내용을 보존하며 유실 응답 뒤 중복 세션을 새로 만들지 않는다. 활성 일반 세션이 있으면 이어하기/현재 편집권 확인 경로를 사용한다.
- 서버 InitialPlan·현재 AppliedPlan·완료 수행은 서로 다르다. 준비 상태를 거쳐 `운동 시작하기`를 선택한 뒤, 입력 초안의 중량·반복을 검증한 명시적 세트 완료에서만 실제 세트와 완료 시각을 만든다. 반복은 1 이상의 안전한 정수이며 목표 상한 초과를 허용한다. ±/직접 입력과 종목 이동만으로 세트가 완료되지 않는다.
- 세트 취소·허용된 목표/종목 편집은 현재 세션에 적용한다. 완료 사실이 남은 종목의 제외/교체를 막으며 초안 취소는 원래 적용 계획을 보존한다. 종목 이동·휴식 종료/+30초는 실제 세트를 추가하지 않는다.
- 유산소는 준비 → 시작 → 일시정지/재개 → 완료 검토 → 확정이다. 실제 활동 시간·직접 거리 또는 실제 속도 기반 계산 거리·심박수를 저장한다. 계획 시간·계획 속도를 실제 기록으로 채우지 않는다. 건너뜀은 COMPLETED 실적이 아니다.
- 각 변경은 진행 운동의 IndexedDB 원본에 먼저 저장하고 전체 snapshot을 전송한다. 로컬 저장과 서버 ACK를 구별한다. 실패한 입력·고정 요청·종료 요청을 보존하며 재시도/서버 결과 확인을 제공한다. 편집 잠금·writerEpoch·계정/세대·revision 검사를 우회하지 않는다.
- 운동 중 홈/다른 탭으로 이동할 때 초안을 먼저 보존하고 재진입하면 같은 세션을 이어간다. 일반 관리와 신규 START는 온라인 전용이며, 기존 운동의 오프라인 이어하기는 마지막 검증 계정/세대와 기기 저장 원본이 있는 경우에만 명시적으로 허용한다. 브라우저 저장소 삭제나 모든 기기에서의 복구를 보장하지 않는다.
- 미완료가 남은 종료는 확인 후 실제 완료 사실만 최종 snapshot과 endedAt으로 고정한다. 완료 취소는 종료 요청 생성 전까지만 가능하며 종료 저장 중 임의 재편집하지 않는다. FINISH의 ACK 또는 서버 재조회로 종료를 확인한 뒤 실제 요약·승인을 제공한다. 응답 유실은 새 운동 시작이 아니라 기존 종료 결과 확인으로 해결한다.
- 24시간 미동기화 AUTO_CLOSED는 별도 서버 상태다. 실제 endedAt과 최초 명시 종료 평가를 만들지 않는다. 명시적인 ‘운동 취소 후 모든 기록 삭제’ 기능으로 해석하지 않는다. 종료 기록의 삭제·정정·누락 복구는 아래 별도 절차다.

### 시간·수행 합계의 의미

[recordSummary](../../src/features/workout-online/record-summary.ts)를 최근/전체 이력과 상세에 공통 적용한다. 저장 단위와 표시 정밀도를 구별한다.

| 값 | 실제 근거·확인 불가 처리 |
|---|---|
| 전체 경과 시간 | endedAt − startedAt. AUTO_CLOSED처럼 실제 종료가 없으면 미확인 |
| 웨이트 수행 시간 | 명시적으로 시작한 선택 종목이 미완료이고 화면이 보일 때의 관찰 구간 합. 워밍업·종목 준비·휴식·유산소·화면 숨김·완료/종료는 제외한다. 휴식 종료 시 자동으로 재개한다. |
| 유산소 수행 시간 | 현재 유효 COMPLETED 결과의 activeMs 합. timerMs는 정정 전 자동 측정값으로 별도 보존 |
| 비수행 시간 | 위 세 근거가 확인될 때 전체 − 웨이트 − 유산소. 단순 휴식 타이머 합이 아님. 측정 누락이나 수행 합계 초과면 미확인과 확인 안내이며 음수나 임의 0으로 보정하지 않음 |
| 수행/계획 종목 | InitialPlan의 종목별 실제 완료 판정 수 / 원계획 종목 수. 현재 루틴이나 승인 권고를 분모로 쓰지 않음 |
| 총 세트·총중량·거리 | 유효 실제 세트 수, 실제 중량×반복의 합, 기록된 유산소 거리의 합. 맨몸은 명시적 추가 부하만 사용하고 미입력 거리를 만들지 않음 |

**종료 직후 요약과 기록 상세의 계산 차이:** recordSummary의 기록 목록/상세는 InitialPlan 분모와 sessionDisplayStatus를 사용한다. 반면 summaryData가 만드는 종료 직후 요약의 plannedSets는 종목별 AppliedPlan.setCount를 우선하고 없으면 실제 세트 수를 사용한다. 전체 완료 표시는 공식 overallWeightPlanComplete=true 및 유산소 phase가 모두 completed인지를 검사하며 유산소 목표 충족을 재검사하지 않는다. 따라서 계획 편집·유산소 목표 미달·유산소 전용 세션에서 기록 상세의 종목/달성 판정과 달라질 수 있다. 정책 3-1은 모든 화면의 InitialPlan 기준 통일로 확정됐으므로 이 차이는 구현 필요다. 유산소 거리 누락 규칙도 아래 최신 정책대로 함께 연결해야 하며 정책을 다시 선택하지 않는다. [실제 summaryData](../../src/features/workout-online/summary-data.ts)

웨이트 시간 A안은 정책 3-3으로 현행 유지가 확정됐다. 백그라운드/잠금 구간 추정은 현재 요구사항이 아니며 실제 관찰 불가를 임의 보충하지 않는다. 웨이트 구간은 snapshot.weightTiming으로 서버에 보존한다. 중단·복원/기기 인계로 관찰하지 못한 구간은 complete=false이며 과거 데이터에 시간을 백필하지 않는다. 최근 기록의 시간은 기존 분 단위 버림을 유지한 채 `총 42분 / 총 1시간 / 총 1시간 10분`으로 표시하고, 이력/상세는 기존 초 단위 표기를 유지한다. 저장된 밀리초와 거리·중량의 십진 원본은 변경하지 않는다.

### 중량 권고·종료 후 승인·과거 조회

- 진행 중 서버 잠정 평가와 기존 단일 세션 기준 기록의 증량 재안내는 권고다. 현재 루틴/배치·승인값·세트/반복·장비·근거 세션을 대조한다. 완료된 현재 종목의 유효 판정 또는 비교 가능한 최고 단일 세션이 있을 때만 안내한다. 다른 운동일의 최고 세트를 섞지 않는다.
- 권고 숨기기는 현재 마운트의 세션/종목별 안내를 숨길 뿐이다. 서버 거절 사건·승인·루틴 변경을 만들지 않는다. 다음 운동은 여전히 비교 가능한 근거가 있으면 재안내할 수 있다.
- 일반 FINISH에서 서버가 종료 당시 권고를 봉인한다. 수행이 없거나 승인 문맥이 불명확하면 권고를 만들지 않는다. 정상 문맥의 미완료 세트/최소 반복 미달은 감량, 전부 최대 이상이면 증량, 나머지는 유지다. 이는 공식 benchmark 자격 및 전체 달성과 별개다.
- 실제 종료 요약은 GET weight-review에서 frozen/current/approvals를 읽는다. 전체 또는 일부 선택, 무게 수정, 최종 승인 확인의 순서다. 선택 0개는 승인 불가이며 무게 수정 확인은 초안만 바꾼다. 기본 권고 폭은 PLATE/STACK 5kg·기타 2kg, 수동 조절 단위는 2.5kg·1kg이며 유효한 임의 소수 직접 입력도 가능하다.
- 최종 확인에서만 POST weight-review-approvals를 호출한다. 현재 세션·루틴 version과 배치/승인값을 서버가 검사하고 선택 건을 원자 적용한다. 저장 후 다시 GET하여 요청 ID·최종 중량·출처를 확인한다. 실패/유실/충돌은 초안과 오류를 유지하며 성공으로 꾸미거나 자동으로 과거 권고를 덮어쓰지 않는다.
- 실제 승인된 종목은 요약의 남은 승인 대상에서 제외된다. 부분 승인·미승인도 서버 이력에서 구별된다. 다음 START는 최신 루틴 승인값을 복사한다. 예를 들어 기준25·권고30·사용자 초안27.5 중 실제 저장한 승인값은27.5이며, 과거 권고30과 구별한다.
- 과거 기록 상세는 frozen과 실제 승인 사건을 읽는 읽기 전용이다. 새 승인·수정 버튼을 제공하지 않으며 이후 루틴 편집이나 실제 수행 정정으로 과거 승인 여부를 추정하지 않는다. API의 과거 세션 승인 가능성 자체를 날짜만으로 금지하는 정책은 아니다. 서버 충돌 검사가 최종 기준이다.
- 일반 기록 정정과 기존 종료 후 PENDING 해결(KEEP_CURRENT/REAPPROVE)은 서로 다른 계약으로 유지한다. [서버 승인 계약](../../../overload-server/docs/api/workout-sessions.md#종료-후-중량-검토와-명시-승인--v36)

### 달성 판정과 이유

**최신 정책과 현행 코드 구분:** 정책 3-1/ST-19는 종료 직후 요약·이력·상세·홈·운동 현황 모두 InitialPlan 기준이며 실제 거리가 없으면 확인 가능한 실제 시간만 비교한다. 부분 인정도 기존 50% 기준에 같은 거리 선택 규칙을 적용한다. 거리 미입력만으로 미확인으로 만들지 않고 속도/강도·경사/저항 등 다른 보호는 유지한다. 아래 [sessionAchievement](../../src/features/home/achievement.ts)와 [display-achievement](../../src/features/statistics/display-achievement.ts)는 현재 코드 설명이며 아직 거리 미입력을 미확인으로 처리하므로 구현 완료가 아니다. 중량 권고의 INCREASE/DECREASE와 혼동하지 않는다.

- 현재 코드의 전체 달성은 최초 계획 웨이트별 계획 세트 수를 충족하고 유산소 목표를 충족한 경우다. 웨이트 완료 자체는 목표 반복 달성이 조건이 아니다. 유산소는 시간·존재하는 거리/강도를 검사하며 거리/강도/경사·저항의 근거가 불충분하면 미확인일 수 있다.
- 현재 코드의 전체 미완료일 때 부분 달성은 원계획 내 웨이트 세트 비율 ≥50% 및 인정 종목/전체 계획 종목 ≥50%다. 웨이트 인정은 min(2, 계획 세트 수), 유산소는 존재하는 시간·거리 각각 ≥50%다. 혼합은 두 유형을 종목 분모에 포함하며 유산소 전용에는 웨이트 비율 조건이 없다. 추가 종목/초과 세트로 비율을 채우지 않는다.
- 현재 코드에서 판정 가능한 미완료가 위 기준 미달이면 기준 미달, 계획·비교 문맥/거리 등 근거가 부족하면 미확인이다. 날짜 상태의 미래·대기·휴식은 개별 세션 판정과 별도이며 홈과 운동 현황이 같은 근거를 공유한다. 서버 공식 완료율·effectiveDay·G4를 UI 부분 판정으로 덮지 않는다.
- achievementReasons는 기존 판정식의 실패에 실제 기여한 항목만 설명한다. 부분 달성은 전체 완료를 막은 계획 세트/시간/거리/강도 미달, 기준 미달은 부분 기준을 막은 세트 비율 또는 미인정 종목만 표시한다. 전체 달성과 미확인에는 미달 이유를 임의 생성하지 않는다. 별도 서버 이유 목록이나 영구 판정 사건이 아니라 현재 저장 사실의 표시용 파생값이다.
- 대체 운동을 원래 슬롯 완료로 인정하는 연결은 아직 없다. 일반 공식 평가의 세션 전체 조합 제외도 화면/종료 봉인 일부와 서버 공식 evaluate의 적용 범위가 다르다. [확인 필요 범위](../../../overload-server/docs/api/workout-sessions.md#2026-11-13-후속-확정-정책과-구현-경계)를 완료 처리하지 않는다.

### 기록 탐색·정정·통계 연결

- 홈은 실제 수행이 있는 최근 종료 기록 최대3건이다. 기록 메인은 스케줄 시간대의 종료일 기준 오늘 포함 최근7일, 전체 이력은 workoutDate 기준 선택 월이다. 두 범위/정렬이 다르지만 같은 세션의 값은 공통 원본·요약을 사용한다.
- 실제 목록은 GET closed의 20건 cursor와 GET 단건 detail을 사용한다. 이전 기록 더 보기를 누른 범위만 있으며 완전한 월/전체 과거 조회를 보장하지 않는다. 루틴별 검색은 불러온 목록의 이름 검색, 실제 계정 운동별 검색은 연결 대기이며 프리뷰에서만 세션 포함 운동명으로 작동한다. 검색 해제 시 선택 월은 보존된다.
- 상세에서 ⋮ → 기록 정정은 실제 완료 세트의 중량·반복, 유산소 실제 시간·거리/측정·심박 등 허용 필드와 수행 삭제만 처리한다. 최초 계획·종목·장비·승인 문맥·기록 시각·승인 사건·웨이트 측정 구간은 보존한다. 변경 이력은 이전/이후 값, 평가는 최초/현재를 구분한다.
- 누락 복구는 같은 세션의 로컬 완료 원본이 있고 서버에서 미존재·비삭제로 검증된 사실만 선택한다. 전체 세션 논리 삭제는 사용자 복원 대상이 아니며 통계에서 제외한다. 쓰기 실패/유실은 원문과 미확인 상태를 보존하고 재조회·명시 확인으로 해결한다.
- 최근/전체 이력은 세션 ID·version·계정/세대·갱신 문맥에 따라 상세를 다시 읽는다. 인증 재확인 중에는 새 조회를 중단하고 완료 후 재조회한다. 계획이 없는 유형의 종목 수·시간·합계는 목록에서 숨기고, 계획은 있으나 미수행이면 0과 미확인을 구분한다.
- 운동 현황은 공통 주간/월간 기간과 세트/총중량을 적용한다. 전체 일별 추이는 서버 days를 사용한다. 특정 운동/부위/근육 선택의 실제 일별 추이는 미연결이며 기간 합계를 임의로 일별 값으로 나누지 않는다.
- 주간 근육 계획은 선택 프리셋의 배정 루틴을 읽어 월~일 출현마다 합산한다. 전면/후면·PPL 및 세부 근육 계획 기여는 구현, 부위 분류·전체 근육 목록·권장 범위는 미확인이다. 전체 보기 선택은 탭/프리셋 변경 후 유지하며 실제 활성 프리셋을 바꾸지 않는다.
- 주간 근육 통계는 이번 주 실제 기여와 완전한 일정 이력이 있을 때의 당시 계획 기여를 표시한다. PRIMARY 1.0·SECONDARY 0.5는 세부 근육 세트에만 사용한다. 근육 목록의 소계는 세부 기여 합이며 상위 분류의 독립 세트 수가 아니다. 실제 전면/후면·PPL·부위의 독립 집계는 미구현이다.
- 성장 추적은 종목 → 근거 있는 루틴 배치 → 승인 사건의 순서다. 기간/검색/태그 변경 시 후보를 새로 읽고 offset을 초기화한다. 계획값·실제 세트 중량·다른 배치의 승인값을 성장점으로 합치지 않는다. [통계](../../../overload-server/docs/api/statistics.md)와 [성장 API](../../../overload-server/docs/api/approved-weight-growth.md)를 따른다.

### 실제 계정과 시연의 경계

HTML은 합성 수치의 정적 승인 상태 예시를 제공한다. routine-preview의 승인 확인은 메모리에만 남고 새로고침하면 초기화된다. 실제 계정의 승인 완료 표시는 SavedWeightReview가 다시 읽은 승인 사건을 근거로 한다. 메모의 변경 blur/입력 종료 시 온라인 저장·LWW·실패 초안 보호는 정책 3-6으로 확정됐으나 현재 미구현이다. CombinationMemo는 계정/세대에 묶인 마운트 메모리 초안으로, 서버 저장·기기 간 공유·새로고침 복원을 보장하지 않는다. G6 디로딩 편집/START·설정의 미연결 항목·운영 HTTPS/PWA와 실제 iPhone 검증을 1차 일반 운동 구현 완료로 대체하지 않는다.
