# Task 005.5 — 인증·계정 정책 및 UX 프리뷰

정책 정리일: 2026-10-27 (Asia/Seoul). **제품 정책 정리 완료 · 인터랙티브 목업 사용자 1차 검토 통과**. 실제 인증·동기화·계정 관리 기능은 미구현이다. 이번 정리는 문서만 변경하며 목업 UI나 기존 운동 로직을 바꾸지 않는다.

이 문서는 인증·계정 제품 정책의 기준과 기존 개발 프리뷰 사용법을 구분한다. 운동 저장·다중 기기·충돌·완료 기록 수정/삭제 정책은 [제품 요구사항](requirements.md)의 R-07 및 10절을 따른다. Task 006은 [설계 인계 문서](../handoff/Overload-Task006-Design-Handoff.md)에서 시작한다. Task 001–005 인수인계와 Task 005.5 구현 보고서는 각 작업 당시의 기록으로 유지한다.

| 구분 | 확정 정책 |
| --- | --- |
| 가입과 진입 | 신규 사용자는 회원가입 필수. 회원가입/로그인은 하나의 진입 화면에서 시작하고 인증 후 신규/기존 회원 흐름을 구분한다. |
| 인증 수단 | Google SSO와 이메일 6자리 일회용 인증코드를 지원한다. 이메일 비밀번호·Apple 로그인·게스트 모드는 제외한다. |

| 계정 식별 | 동일 이메일만으로 자동 연결·통합하지 않는다. Google은 이메일이 아닌 제공자의 고유 계정 식별자를 기준으로 구분한다. |

| 데이터 관리 | 새 루틴 생성, 운동 데이터 전체 초기화, 회원 탈퇴를 구분한다. 전체 초기화·탈퇴에는 내보내기 안내와 재인증·최종 확인 흐름을 제공한다. |

## 확정된 세션·로그아웃 UX와 잠정 기간

- 정상적인 앱 재실행에서는 자동 로그인을 유지한다. 앱 종료·화면 잠금 자체를 로그아웃 사유로 삼지 않는다. 명시적 로그아웃·탈퇴 또는 재인증이 필요한 경우의 처리는 구별한다.
- 운동 도중 인증이 만료되어도 진행 중 운동의 세트 완료·휴식·유산소 조작을 중단시키지 않는다. 운동 완료 후 필요한 경우 재인증하고 **동일 계정**의 미동기화 기록을 전송한다.
- 운동 완료와 서버 저장 완료를 구분한다. ‘나중에 하기’나 인증 실패만으로 미동기화 기록을 삭제하지 않는다. 로컬 저장 실패와 브라우저 저장소 유실 가능성은 별도로 안내한다.
- 미동기화 기록이 있는 로그아웃은 아래 두 선택과 취소를 제공한다. 모두 동기화된 경우에는 간단하게 로그아웃한다.

| 선택 | 필요한 결과 |
| --- | --- |
| 동기화 후 로그아웃 | 서버 저장 확인 이후 로그아웃. 실패하면 원본을 유지하고 오류를 안내하며 로그아웃을 완료하지 않는다. |
| 로컬 기록 유지 후 로그아웃 | 이전 계정 전용으로 기록을 보존하고 접근을 차단한다. 같은 계정 재로그인 후 전송을 재시도한다. 다른 계정에서는 조회·접근·전송할 수 없다. 브라우저 데이터 삭제·기기 손실 등에 따른 유실 가능성을 안내한다. |
| 취소 | 로그아웃하지 않고 현재 계정과 기록을 유지한다. |

| 기간 | 잠정값 | 상태 |
| --- | --- | --- |
| 짧은 인증 세션 | 30분 | 잠정 |
| 비활동 로그인 유지 | 마지막 실제 사용 후 30일 | 잠정 |
| 절대 재인증 상한 | 최초 인증 후 90일 | 잠정 |
| 중요 계정 작업의 최근 재인증 | 10분 이내 | 잠정 |

위 기간은 운영 계약으로 확정한 값이 아니다. 실제 사용/비활동의 정의, 시간 계산 기준, 세션 발급·자동 갱신·폐기·만료 실패 처리, 안전한 쿠키·CSRF 정책과 재인증 적용 범위는 Task 006에서 확정한다. 목업의 매번 재인증 동작도 실제 운영 세션 정책을 결정하지 않는다.

## 확정된 초기화·탈퇴 구분

| 동작 | 계정/로그인 수단 | 운동 데이터와 확인 흐름 |
| --- | --- | --- |
| 새 루틴으로 시작하기 | 유지 | 기존 운동 이력·루틴별 점진적 과부하 기록 유지. 새 루틴과 중량 기준을 설정하는 일반 흐름. |
| 운동 데이터 전체 초기화 | 유지 | 루틴, 완료 웨이트 이력, 유산소 기록, 진행 중 운동, 중량 승인 이벤트 및 관련 운동 기준을 삭제 대상으로 정의한다. 내보내기 안내 → 본인 재인증 → 최종 확인 필요. |
| 회원 탈퇴 | 탈퇴 대상으로 구분 | 계정·연결 수단과 운동 데이터의 처리 범위를 안내하고 내보내기·본인 재인증·최종 확인 후 탈퇴한다. 미동기화 로컬 기록과의 관계도 안내한다. 실제 파기 범위·시점·보존 의무는 Task 006에서 구체화한다. |

전체 초기화나 탈퇴 이전의 다른 기기·대기열 기록이 재전송되어 데이터를 되살리거나 다른 계정으로 이전되지 않도록 설계해야 한다. 일반적인 과거 운동 기록 수정/삭제는 과거 승인 이벤트를 임의로 바꾸지 않으며, **명시적인 운동 데이터 전체 초기화는 승인 이벤트도 삭제 대상**이라는 범위 차이가 있다. 초기화·탈퇴에 필요한 제한적 감사/충돌 원본의 보존 범위·기간과 부가 설정/메모의 세부 삭제 범위는 후속 결정 사항이다.

## 개발용 데이터와 실사용 전환

현재 Task 001–005의 기존 로컬 데이터는 배포 전 개발용 테스트 데이터다. 사용자 계정으로 이전할 필요가 없다. 다만 **이번 문서 작업은 그 데이터를 삭제하거나 초기화할 권한을 실행하지 않으며**, 기존 `overload.core.v1` 저장·복원 동작을 보존한다. 실제 개발 데이터 폐기 시점·대상·확인 절차 및 실사용 데이터 전환 기준은 Task 006의 설계 대상이다. 향후 실사용 데이터는 유실·중복·계정 간 노출을 방지해야 한다.

## 실행 및 격리

- `overload-pwa`에서 `npm run dev` → `http://localhost:3000/auth-preview`.
- iPhone은 같은 LAN에서 `http://<PC의 LAN IP>:3000/auth-preview`로 접속한다. 기존 `server.host: true`, 포트 3000 설정을 유지한다.
- 기존 앱은 `/`이며 인증으로 잠그지 않는다. 프리뷰 상단의 ‘기존 앱’ 링크로 돌아간다.
- `main.tsx`의 `import.meta.env.DEV` 분기에서만 프리뷰를 지연 import한다. production `/auth-preview`는 개발 전용 안내만 표시하며 앱의 저장 훅도 마운트하지 않는다. 프리뷰 코드·CSS·시나리오는 production 산출물에서 제외한다.
- 모든 계정/운동/동기화 예시는 React 메모리 상태다. `overload.core.v1`, localStorage, sessionStorage, IndexedDB, 쿠키, 토큰, 네트워크 및 기존 운동 모델에 접근하지 않는다. 새로고침 시 목업 상태만 초기화한다.
- 개발 시나리오를 다시 선택하면 가상 예시 전체를 초기화한다. 실제 기존 기록에는 영향이 없다.

## 현재 구현된 목업 화면과 수용 흐름

1. 통합 진입: Google 또는 이메일 6자리 코드. 비밀번호·Apple·게스트 없음. 로그인은 선택된 가상 계정 A/B/신규로 결정되며 입력 이메일이 실제 계정 조회나 매칭에 사용되지는 않는다.
2. 이메일: 전송 중 → 가상 전송 완료 → 단일 numeric/one-time-code 입력 → 확인. 기본 코드 `123456`, 유효기간 5분, 재전송 대기 30초, 전송 최대 3회/검증 최대 5회는 **목업 테스트값**이다. 운영용 제한·해제 정책은 Task 006 이후 정한다. 개발 패널에서 30초 경과/5분 만료를 재현한다.
3. 기존 회원은 가상 홈으로, 신규 회원은 약관 예시 확인과 선택 닉네임 가입 단계로 이동한다. 키/몸무게/성별 수집 없음. 약관은 위치 예시이며 실제 법적 동의나 계정을 생성하지 않는다.
4. Google: 실제 OAuth 창 대신 성공/취소/실패 버튼을 제공한다. 기존 A는 이메일만 연결된 예시다. A의 Google 로그인 성공은 ‘두 수단 연결’ 시나리오에서 로그아웃한 다음 체험하거나 기존 B를 선택한다. 신규 Google 가입은 개발 패널에서 신규 계정 선택 후 진행한다.
5. 로그인 이후 홈/루틴/기록/설정 4탭. 기존 실제 앱과 구별된 가상 탭이다. 설정에서 닉네임(비워두기 가능), 로그인 수단, 동기화, 내보내기, 루틴 시작, 전체 초기화, 로그아웃, 탈퇴, 약관 위치를 체험한다. 내보내기는 가상 JSON의 선택·복사 가능한 미리보기다. 실제 파일 백업 기능은 구현하지 않는다.
6. 수단 연결/해제: 기존 계정의 연결된 수단으로 재인증 → 계속 확인 → 새로운 수단 인증. 마지막 수단은 해제 불가. 동일 이메일 미연결/다른 계정 소유 Google/두 계정 데이터 충돌을 별도 재현하며 자동 연결/병합하지 않는다.
7. 민감 작업은 매번 가상 재인증한다. 검토 중인 세션 기준값은 짧은 세션 30분, 마지막 실제 사용 후 30일 자동 로그인, 최초 인증 후 90일 재인증 상한, 민감 작업 10분 이내 재인증이다. 실제 세션 만료·갱신 타이머는 없다. 자동 복원·만료·갱신 실패는 시나리오로만 표시한다.
8. 운동 중 만료: 별도 가상 운동 화면에서 세트/휴식/유산소 조작을 계속한다. 시계는 고정 예시로 표시한다. 완료 → 재인증 필요 → 같은 계정 재인증 → 동기화 대기 → 가상 전송 결과 확인. 나중에 하기는 현재 프리뷰 메모리 기록을 유지한다. 실제 운동 타이머/저장/판정에는 인증을 주입하지 않는다.
9. 미동기화 로그아웃: 동기화 후 로그아웃 / 로컬 유지 후 로그아웃 / 취소. 성공 결과 확인 전에는 로그아웃하지 않고, 실패하면 원본을 유지한다. 로컬 유지 시 이후 같은 계정으로만 접근 가능하며 다른 계정에서는 표시/전송하지 않는다. 브라우저 데이터 삭제·기기 손실의 유실 가능성을 안내한다.
10. 초기화/탈퇴: 안내 → 삭제 범위 및 내보내기 안내 → 기존 수단 재인증 → 문구(‘초기화’/‘탈퇴’) 입력 → 가상 완료. 초기화는 계정/수단 유지, 탈퇴는 가상 계정 사용 중단과 수단 해제까지 구별한다. 새 루틴은 기존 이력을 유지한다.

## 시나리오 패널

화면 아래 ‘개발 전용 · 시나리오 패널’을 펼친다. 24개 시나리오: 기존/신규 진입, 이메일만/Google만/둘 다 연결, 자동 복원, 인증 만료, 갱신 실패, 운동 중 만료, 9종 저장 상태(모두 동기화됨/중/대기/오프라인/재인증/실패/기기 충돌/초기화 이전 전송 차단/로컬 실패), 코드 오류/만료/제한, 3종 연결 충돌, 기존 계정 재인증 실패. 일부 항목은 같은 화면 안에서 다음 버튼으로 결과를 선택한다.

상태 전환은 네트워크 재시도나 실제 충돌 해결 알고리즘이 아니다. 동기화 중 결과는 ‘가상 서버 저장 성공/실패’로 수동 선택한다. 오프라인은 패널의 ‘가상 인터넷 연결 복원’ 후 재시도한다. 실패/충돌 화면은 원본을 유지하며 충돌 알고리즘은 구현하지 않는다.

## Task 006 인계 요구사항 (구현 전 설계 필요)

설계 착수 기준은 [Task 006 설계 인계 문서](../handoff/Overload-Task006-Design-Handoff.md)에 모았다. ## iPhone 수동 확인
