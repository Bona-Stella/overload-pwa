# Overload UI v0.9 — Visual Theme Specification

**기준일:** 2026-11-07 · v0.9 T02-B 개정 (기존 컬러/토큰 유지)

FRONT 18의 현행 시각 규격은 [18절 메시지](#front18-feedback-visual), [19절 카드](#front18-card-visual), [20절 버튼·입력](#front18-controls-visual), [21절 선택·기능형 모달](#front18-selection-dialog-visual)을 적용한다.

**범위:** React PWA 실제 구현용 시각 스타일 명세. [HTML 베이스라인](Overload_UI_Baseline_Wireframe_v0.9.html)은 밝은 무채색의 저충실도 자료다. 간단한 색조·아이콘과 기본 화면·상태 전환으로 현재 UI의 정보 위계를 검토한다.

**기술 방향:** CSS Custom Properties + CSS Modules, 모드에 따라 `data-theme` 토큰만 변경. 테마 변경으로 데이터/타이머/입력값을 초기화하지 않는다.

테두리 참고 `#3B4453`.

**디로딩 모드** (아래 끝까지 같은 그린그레이 계열):

테두리 참고 `#3B4A40`.

## 3. 상태색과 게이지

- 과거 계획 운동 완료 ✓: `#74A68A` (어두운 초록)
- 과거 확정 예정일의 부분 달성 기준 미달 ×: `#B17B83` (어두운 빨강)
- 과거 확인된 휴식일 `–`: 중립 보조색. 요일 대신 나타나지만 완료 의미가 아니다.
- 세트 완료 원형 체크: 위 완료색 계열을 이용한 얇은 초록 체크와 둥근 테두리. **행 전체를 초록으로 채우지 않음.** 일반과 디로딩에서 동일 규칙. 완전 취소/정정 API 정책과 구분.
- 홈과 운동 현황의 날짜 상태는 10.24.4절의 ✓/△/×/–을 공통 사용한다. 미래·판정 대기·근거 확인 불가는 기존 요일 또는 중립/미확정 표현을 유지하고 ×로 확정하지 않는다. 과거 날짜 숫자·루틴명만 어둡게 하며 상위 `opacity`로 상태 기호를 탈색시키지 않는다. △를 공식 완료율/G4 값으로 해석하거나 새 위험색·HEX를 정의하지 않는다.

**분석 ON 추천 게이지:** 0주부터 항상 가는 수평 트랙을 표시하며 채움 길이는 `clamp(weeks / 8, 0, 1)`. 0~4.0주(포함) Dusty Blue `#6C93C6`, 4.0주 초과는 황→주황→적의 점진 보간. 8주 이상 100% 빨강. 분석 OFF일 땐 게이지 숨김.

| 기준 예시 | 색상 후보 |
|---|---|
| 4.0주 이하 | `#6C93C6` **확정** |
| 4.0주 초과 경고 시작 | `#D6BC65` (후보) |
| 6.0주 | `#D98D55` (후보) |
| 8.0주 | `#C96763` (후보) |

4.0주에서 4.0주를 아주 조금 넘는 순간은 의도적으로 카테고리가 바뀐다. 색 외에도 `n.n/8주` 수치를 유지한다. 경고 세 색의 정확한 HEX는 시안 후보로 취급하고 개발에서 공통 토큰에 집중 관리한다.

## 4. 텍스트 위계 — 중량과 장비

| 콘텐츠 | 권장 표현 및 우선순위 |
|---|---|
| 세트당 **실제 수행 중량 × 반복 횟수** | **밝은 본문** `#F0F1F4`, 12~13px 수준, 600~700 weight; 읽히는 것이 최우선 |
| 세트 오른쪽 **볼륨(kg)** | 일반 본문/보조 사이의 충분한 대비, 축소·투명도 과도 적용 금지 |
| 종목명·세트 수 | 상단 주요 텍스트, 명확한 대비 |
| **제조사·부하 방식·당시 기록** | **작은 보조 글자** 10~11px, normal 400, `#A9ADB7` 또는 한 단계 낮은 중립색, 전 화면 일관 적용. 흰색/굵은 대제목 금지 |
| 레이블 `WEIGHT` · `CARDIO` | 해당 모드 주 강조색을 유지 |
| 물음표 도움말 | 원형 **시각 지름 약 16px**(기존 23px보다 작게), 본문과 균형. **실제 터치 대상은 44×44 CSS px에 가까운 히트영역**으로 보완(선택 UI의 터치 접근성 유지) |

대상 화면: 운동 완료 요약, 기록 상세, 운동 진행 포커스, 임시 편집/장비 선택, 운동별/제조사별 통계, 복구/정정 맥락 등 **장비 메타데이터가 등장하는 전체 화면**. 수정 가능한 입력 필드의 기본 접근성과 구별한다.

## 5. 세트 완료 컨트롤

- 진행 전에는 반복 횟수 값과 `− / +`에 평상시 테두리를 두지 않는다. 세 버튼의 터치 폭과 기존 키보드 포커스 윤곽을 유지한다. [숫자 조작 규격](#front18-number-visual)을 적용한다.
- 완료 후 세트 번호·반복 값은 읽기 전용 `--text-primary`로 표시한다. 완료색은 **원형 테두리 ✓**에 적용하고 진행 막대를 유지한다. 완료 행의 배경은 채우지 않는다.
- `CircleCheck`의 기본 원은 21px, 체크 글리프는 14px다. 중량 검토 행에서는 원 17px와 글리프 11px를 카드 왼쪽에 맞춘다. 두 곳 모두 44×44px 입력 영역과 선택 시 `--status-done`, 미선택 시 `--text-muted` 윤곽을 사용한다. [공통 체크 CSS](../../src/components/common-ui/CircleCheck.module.css) · [검토 행 CSS](../../src/features/workout-flow/WorkoutFlow.module.css)
- 체크 탭: 「완료를 취소하시겠습니까?」 팝업 (`아니요 · 유지` / `완료 취소`). 후자를 선택했을 때만 입력과 `완료` 버튼 복귀. 실제 서버 삭제·정정/오프라인 원본 처리 정책을 준수.

## 6. 구현·검증 지침

- 32px 검색/운동 선택 아이콘은 [아이콘 자산](assets/exercise-icons/README.md)의 기존 원본 PNG를 표시한다. 원본 이미지를 32 CSS px로 렌더링하며 중립 그레이/Onyx 배경, 별도의 파스텔 컬러 원형 배경 금지.
- `data-theme`은 화면 표시 스타일만 바꾸며 서버의 실제 디로딩 상태/쓰기 권한과 동치가 아니다. 일반 보기 읽기 전용 정책 유지.
- 앱의 CSS 토큰 예시:

```css
:root {
  --surface-page: #111216;
  --surface-card: #1B1D22;
  --surface-input: #25282E;
  --text-primary: #F0F1F4;
  --text-muted: #A9ADB7;
  --accent: #6C93C6;
  --on-accent: #111820;
  --status-done: #74A68A;
  --status-missed: #B17B83;
  --hero-gradient: linear-gradient(142deg, #272D37 0%, #222832 50%, #1C212A 100%);
}
[data-theme="deload"] {
  --accent: #78B89A;
  --hero-gradient: linear-gradient(142deg, #28312C 0%, #222B26 50%, #1A231E 100%);
}
```

- WCAG 대비 검토, iPhone 15 Safari 및 홈화면 PWA 실제 렌더링, 재마운트/타이머 리셋 방지, 아이콘 이미지 자산 경로와 캐시 검증은 React 통합 단계에서 수행.
- HTML은 **밝은 무채색 화면과 기본 조작**을 제공하고 위 시각 테마는 CSS Modules 실제 구현에 적용한다. 화면·조작은 [UI/UX](ui-ux.md), 디로딩 제품 정책은 [v1.7](Overload_Deloading_Design_Specification_v1.7.md)을 따른다.

**변경 이력:** 2026-11-05 v0.9 시각 기준 → 2026-11-07 T02-B 공통 표현 보완. 컬러·토큰의 역사적 값과 기존1~6절은 보존했다.

### 2026-11-07 디로딩 정책 표현 정정

신규 계정은 **기본 ON·누적0의 초기 epoch**로 시작한다(2026-11-07 추가 확정). 최초 ON은 OFF→ON 전환이 아니다. OFF→ON은 새 epoch·누적0이며 OFF/활성화 전 기록을 소급 가산하지 않는다. 기존 미설정 계정은 G4의 명시적 이행 경계를 검증한다. HTML 초기 ON·개발용5.2주는 시연이며 실제 서버 설정·누적을 증명하지 않는다. 시작 자격은 최근7일 실제 일반 수행/이전 완료 이후 신규 일반 수행/오늘 수행 없음/ACTIVE 일반 세션 없음의4조건이다. 계획일 수·OFF·게이지0은 gate가 아니다. 이미 ACTIVE인 디로딩 기간은 별도 상태 제약으로 중복 생성하지 않는다. 유산소 실제 수행은 기존 계약의 미삭제 COMPLETED·activeMs>0를 뜻하며 최초 목표 달성과는 구분한다. E≤1 RESET·E>1 min(1,E/N) ADD, 다음 월04시 이후 검사 완료 확정·주중 미가산을 따른다. G4·G5 Backend는 구현했고 G6 PWA 연동은 후속이다. HTML의 누적값은 시연이며, 현행 계정 홈의 분석·기간 읽기 범위는 [Frontend 현황](../engineering/frontend.md#87-v09-적용-범위와-구현-상태)을 참고한다. 기존 DB의 적용 범위는 별도다. 일반 ST-17~23의 예정 루틴 분모를 디로딩에 복사하지 않는다.

## 9. 분석·중량 검토의 최종 UI 적용 — 2026-11-14

[기록 탭 10.24절](Overload_UI_Decision_Log_v0.9.md#1024--기록-탭-최종-개편--2026-11-14)과 유지되는 10.23.5~7절의 당시 설계다. 이후 기록 탭 React 적용은 결정 로그 10.26~10.30절, 홈 운동 화면과 종료 요약은 아래 10절에 기록한다. HTML은 무채색 정적 예시를 제공한다.

- 주간 근육 계획의 제목 우측 전체 보기는 기존 ON/OFF 스위치다. 주간 근육 통계는 이번 주 고정으로 기간/달력을 제거하고 기존 분류/근육·세트/총중량 버튼과 한 카드의 부위명·구분선·가로 막대를 유지한다.
- 운동 현황과 이력 검색은 기존 운동 검색의 입력/범위 선택·이름/보조 설명·스크롤 목록·선택을 공통 사용한다. 독립 검색 디자인·새 토큰을 만들지 않는다. 이력 범위는 루틴별/운동별이며 운동량 범위 네 가지와 구별한다.
- 월간 이력은 기존 기록 카드를 유지하고 기록 있는 주의 첫 카드 위에 얇은 주차 제목·월~일 날짜 범위 구분선만 추가한다. 큰 주차 카드·접기는 없으며 월 경계와 검색 결과에도 같은 표시를 쓴다. 320/375/390/430px에서 검색·구분선·카드가 넘치지 않게 한다.
- 계획 권장 시작은 막대 위의 `▼`이며 최대 초과 시 숫자를 보존하고 막대만 100%로 표시한다. 위험색·경고·강제 제한을 추가하지 않는다. HTML의 권장 수치는 합성 예시이며 제품 기준값이 아니다.
- 중량 검토의 선택 체크·예정값 편집과 명시 승인은 구분한다. 기존 중량 모달의 고정 현재값→실시간 예정값·취소/확인을 재사용하고 수치 단위는 10.23.5절을 따른다.
- 현행 종료 요약의 검토 행은 첫 줄에 원형 체크·이름(14px·650)·`무게 수정`(72×36px)을 두고, 둘째 줄에 중량 변화와 세트·반복 근거를 배치한다. 변경 전 중량과 구분 화살표는 11px·400, 결과 중량은 13px·700, 세트·반복 근거는 12px·400이며 기본 줄 높이는 1.6이다. 결과와 방향 표시는 증량 `--status-done`, 감량 `--status-warning`을 사용한다. 승인과 무게 수정 버튼은 캡슐형이며 활성 승인 버튼은 `--status-done` 배경을 사용한다. 요약과 상세의 승인 이력은 16px·700 제목과 최소 44px 접기 영역, 같은 증감 토큰을 사용한다. [검토 행 CSS](../../src/features/workout-flow/WorkoutFlow.module.css) · [이력 카드 CSS](../../src/features/workout-flow/WorkoutRecordDetail.module.css)
- 후속 React 모달에서는 닫기 X의 불필요한 자동 포커스 테두리를 방지하되 키보드 focus-visible과 원래 조작 요소로의 포커스 복원을 유지한다. 기본 브라우저 뒤로가기·초안 보호와 iOS 실기기 검증은 10.23.7절을 따른다.

## 15. 공통 하단 내비게이션 — 2026-11-19

Onyx 셸의 탭바는 `#08090C` 바탕과 1px `#282C34` 테두리, 안쪽 4px 패딩을 사용한다. 탭바와 선택 캡슐의 모서리는 999px이다. 폭은 `min(calc(100% - 24px), 336px)`이고 높이는 56px이다. 320px에서는 296×56px이며 375·393·430·1280px에서는 336×56px이다. 균등한 버튼 네 개는 높이 46px, 중앙 아이콘은 24px이다.

| 탭 | 활성 | 비활성 |
|---|---|---|
| 홈 | 기존 집 경로를 `#000`으로 채움. 지붕과 문 구조 유지 | `#FFF` 1.6px 윤곽선 |
| 루틴 | 채움 없이 `#000` 3px 윤곽선 | `#D1D5DD` 1.6px 윤곽선 |
| 기록 | 채움 없이 `#000` 3px 윤곽선 | `#D1D5DD` 1.6px 윤곽선 |
| 설정 | 기존 기어 경로를 `#000`으로 채우고 `evenodd`로 중앙 구멍 유지 | `#D1D5DD` 1.6px 윤곽선 |

확장 상태의 Dusty Blue `#6C93C6` 선택 캡슐은 아이콘 아래에서 200ms `ease`로 이동한다. 접히면 하단 중앙에 46×46px 원형과 24px 활성 아이콘만 남는다. 배경은 축소 중 `#5E82B1`로 짙어지고 펼칠 때 원래 색으로 돌아온다. 접기 320ms·펼치기 340ms에 `cubic-bezier(.32, .08, .26, 1)`을 적용한다. 움직임 줄이기에서는 모든 전환을 즉시 적용한다. 키보드 `focus-visible`은 별도의 흰색 윤곽선으로 표시한다.

두 상태 모두 하단 안전 영역에 맞춰 고정한다. 본문은 확장 높이 56px에 안전 영역과 16px을 더해 확보한다. 위 색상·SVG·치수는 앱 셸의 탭바 전용 규칙이다. HTML에서는 밝은 무채색의 확장 캡슐과 원형을 간단한 기호로 표시하며 버튼 선택에 따라 즉시 전환한다. [동작 및 안전 영역](ui-ux.md#공통-하단-내비게이션)

- 숫자와 단위를 한 그룹으로 가운데 정렬한다. 숫자 영역은 기본 48px, 별도 테두리와 배경 없이 숫자를 눌러 휠을 연다. 설정 중량을 포함한 숫자 휠 진입 chevron은 제거했다. 일반 드롭다운과 접기·펼치기의 화살표는 유지한다. 외부 증감은 기본 48×48px이며 압축형 운동 세트 표는 좌우 폭 44px를 사용한다.
- 휠 Dialog의 모서리는 5px, 기존 가용 너비를 유지한다. 52px 행과 배경이 강조된 52px 중앙 선택 띠를 둔다. 표시 높이는 화면에 맞춰 156~260px이다. 하단 액션은 높이 48px의 캡슐형, 너비 1:1, 사이 8px이며 직접 입력은 48px·5px이다. [휠 CSS](../../src/components/NumberWheel.module.css) · [사용자 조작](ui-ux.md#312-공통-숫자-입력)
- 유산소 목표 시간·거리의 기본 정보 행은 각각 전체 너비와 수정 아이콘을 사용한다. 추가 목표는 선택 표기와 균등 2열을 쓴다. 레이블·수치·단위를 가운데에 두고 숫자 영역에 테두리·별도 배경·진입 아이콘을 추가하지 않는다. [유산소 조작과 증감](ui-ux.md#front18-cardio-goals)
