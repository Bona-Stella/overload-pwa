# Overload Deloading Design Specification

**버전:** v1.7
**기준일:** 2026-11-07
**상태:** 최신 확정 정책 통합본 · 2026-11-08 Backend G0~G5-3 구현 완료 · G6 실제 PWA 연동 및 기존 DB V25~V29 적용은 별도
**문서 원칙:** 이 문서를 합의사항의 단일 기준으로 사용한다. 명시된 확정 정책과 미확정 제품 결정을 구분하고, 실제 구현은 별도이며 변경 시 규칙 ID와 변경 이력을 유지한다.

> **요약**
> Overload의 디로딩은 피로도를 진단하거나 강제하는 기능이 아니다. 기존 **저장된 루틴**을 기준으로 적절한 시점에 짧은 회복 기간을 제안하고, 사용자가 선택한 방식에 따라 운동량을 줄여 준다. 원본 루틴 및 승인 중량은 유지하고, 디로딩 임시 루틴·이력은 독립적으로 관리한다. 권장 7일, 최대 10일이며, 10일차 종료 시 정상 완료와 동일하게 자동 종료한다.

**현행 기준:** 이번 사용자 요청의 기록 기반 디로딩 정책과 [통계·추적 v1.4](../../../overload-server/docs/product/Overload_Statistics_and_Tracking_Design_Specification_v1.4.md) §14, [최종 구현 계획](../../../overload-server/docs/tasks/weekly-schedule-immediate-implementation-plan.md) §2·3·7.1을 통합했다. [v1.6](Overload_Deloading_Design_Specification_v1.6.md)은 역사 원본으로 보존한다. 실제 구현 근거와 미구현 범위는 [Backend 현황 분석](../tasks/deload-v17-backend-readiness-analysis.md)을 따른다.

## 0. 문서 관리 방법

- **[DOC-01 · 확정/v1.7]** v1.7을 현재 디로딩 정책 기준으로 사용한다. 기존 v1.6과 서버의 v1.1~v1.3은 역사 자료다. 규칙 ID를 재번호하지 않고 유지·교체 내역은15절에 기록한다.
- **[DOC-02 · 확정]** 본문에서 **확정**은 대화에서 합의된 제품 정책, **구현 확인**은 정책은 정해졌으나 실제 코드/스키마 점검이 필요한 사항, **미결정**은 추가 판단이 필요한 사항이다.
- **[DOC-03 · 확정]** 서로 충돌한 이전 제안보다 **가장 나중에 명시적으로 합의한 정책**을 우선한다. 이 문서는 기능 구현 완료를 뜻하지 않는다.

## 1. 제품 철학 및 범위

- **[DL-01 · 확정] 루틴 우선:** 운동일 수, 계획 종목, 종목 순서, 세트·반복·중량 목표와 임시 루틴의 출발점은 기존에 저장된 원본 루틴이다. 실제 수행량으로 원본 루틴을 자동 재설계하지 않는다.
- **[DL-02 · 확정/v1.7]** 디로딩은 권장: 실제 일반 운동 기록을 이용한 간접 훈련 주기 분석이며 직접적인 피로도·회복도·의료 위험 측정이 아니다. 권장 목표는8유효주이며 강제 시작하지 않는다. 피로 점수·주관적 강도 입력·AI 최적화는 추가하지 않는다.
- **[DL-03 · 확정] 완전 휴식 허용:** 디로딩은 운동을 해도 되고 전혀 하지 않아도 되는 회복 기간이다. 권장 운동 계획을 전부 완료할 의무가 없다.
- **[DL-04 · 확정] 독립성:** 디로딩 시작 시 원본 루틴을 참조하여 임시 루틴을 만든 이후에는 두 루틴이 서로 영향을 주지 않는다. 디로딩 진행 중 일반 화면은 **읽기 전용**이므로 원본 루틴을 조회할 수 있지만 수정·삭제·실행할 수 없으며, 변경 사항이 진행 중인 디로딩 임시 루틴으로 자동 전파되지 않는다.

## 2. 기록 기반 유효 훈련 주수 및 추천 게이지

### 2.1 분석 ON/OFF와 표시

**2026-11-07 추가 확정:** 신규 계정은 디로딩 분석 **기본 ON·최초 누적0주**로 시작한다. 최초 ON은 초기 epoch이며 OFF→ON 전환이 아니다. 계정 생성과 함께 서버가 초기 상태를 보장하는 방법, 기존 미설정 계정의 적용 시각·시간대 및 비소급 이행은 [G4 분석 API](../../../overload-server/docs/api/deload-analysis.md)를 따른다. 신규 기본 ON을 근거로 기존 계정의 과거 기록을 소급 가산하지 않는다. HTML의 초기 ON과 개발용5.2주는 시연 상태이며 실제 서버 설정·누적을 증명하지 않는다.

- **[DL-05 · 확정/v1.7]** 신규 계정은 **기본 ON·누적0의 초기 epoch**로 생성하며 이를 OFF→ON으로 기록하지 않는다. ON은 주간 누적 계산과 추천 표시를 활성화한다. OFF는 누적 분석·게이지·추천 알림을 중단하지만 일반 실제 기록·G3 미수행 검사·일반 통계는 유지한다. 실제 OFF→ON은 누적0의 **새 epoch**다. 이전 OFF 기간과 활성화 이전 기록을 새 epoch에 소급 가산하지 않는다. 기존 미설정 계정도 G4의 명시적 이행 경계 이전 기록을 가산하지 않는다. OFF에서도 DL-80 네 조건을 충족하면 수동 시작할 수 있고, 진행 기간은 토글로 종료되지 않는다.
- **[DL-06 · 교체/v1.7]** 현재 템플릿의 계획 운동일 수와 분석 누적은 독립이다. **계획2일 이상 gate·계획1일 이하 자동 초기화·다음 월요일 빈도 변경 예약은 폐기**한다. 일정은 즉시 적용하되 과거 평가의 계획/수행을 새 템플릿으로 재분류하지 않는다. 기록 기반 RESET은 DL-10을 따른다.
- **[DL-07 · 확정/v1.7]** 목표8유효주, 채움 clamp(누적/8,0,1). ON은0주부터5px 수평 트랙, OFF는 주수/트랙 없음.0~4.0주는 Dusty Blue #6C93C6,4.0주 초과 노랑→주황→빨강,8주 이상100% 빨강 유지. 경고색 후보 #D6BC65/#D98D55/#C96763은 미세 조정값이다. 숫자/채움은 서버의 마지막 확정 누적을 표시하고 **주중에 증가시키지 않는다**. UNKNOWN/재계산 중 상태를 실제0이나 OFF로 바꾸지 않는다. 헤더는 DL-70/86과 최신 UI10.12·10.14를 따른다.

### 2.2 하루 유효 운동일과 후보

**[DL-08 · 확정/v1.7]** 각 적격 실제 일반 세션의 **불변 InitialPlan**에 대해 다음을 계산한다.

`세션 달성률 = 완료한 InitialPlan 종목 수 / 전체 InitialPlan 종목 수`

- 웨이트는 InitialPlan의 계획 세트 전체를 수행해야 해당 종목 완료1개다.4세트 중3세트는0종목이며 실제3세트 기록은 보존한다.
- 유산소는 InitialPlan의 등록된 최초 목표를 달성해야1개다. 실제 목표 비교 근거가 부족하면 미확인이지 임의 완료/미완료가 아니다. 계획 축소·현재 루틴 수정으로 분모/목표를 바꾸지 않는다.
- InitialPlan 밖 추가 종목은 실제 운동량에는 포함하지만 완료 분자에는 넣지 않는다. 계획이0개/손상된 세션을0/0=1로 평가하지 않는다.
- 예정과 다른 루틴·휴식일을 포함한 **실제 일반 세션**을 각자 자기 InitialPlan으로 평가한다. 실제 수행이 없는 START만으로 훈련 날짜를 만들지 않는다. 부분 세트/목표 미달의 양의 실제 유산소가 있으면 실제 수행일 후보이며 달성값0도 가능하다.
- 같은 날짜의 적격 세션 중 **최고 단일 달성률**만 선택한다. 두 세션의 서로 다른 절반을 합쳐1로 만들지 않으며 하루 최대1이다. 더 좋은 후보의 미확인 목표가 최고값에 영향을 줄 수 있으면 보류한다.
- 일반 계획 이행률 **ST-17~23의 예정 루틴 후보 제한은 그대로**다. 디로딩 후보만 넓힌다. 업로드일 대신 저장된 수행일/workoutDate를 사용하고 기존 세션 날짜/시간대를 다시 쓰지 않는다.

### 2.3 주간 E/N·확정·재계산

**[DL-09 · 교체/v1.7]** 주는 월요일~일요일 고정이다.

- N = 실제 일반 수행 또는 확정 자동 미수행이 있는 **서로 다른 평가 날짜 수**.
- E = 각 평가 날짜의 최고 단일 세션 유효값 합계. 실제 수행 없는 확정 MISSED의 값은0.
- 실제 수행과 최초 MISS 근거가 같은 날짜에 함께 있어도 N은1이다. 실제 후보를 평가하고 MISS를 별도 날짜/실패 횟수로 더하지 않는다. 휴식일의 실제 수행은 후보이나 수행 없는 휴식일은 평가 날짜를 추가하지 않는다.
- 일반 일정의 계획일 수를 분모로 쓰지 않으며 현재 일정 변경으로 과거 E/N을 바꾸지 않는다. 실제 기록 정정·삭제·복구에 따른 파생 결과 재평가는 허용하고 원래 계획/최초 MISS 사실은 보존한다.

**[DL-10 · 교체/v1.7]** 정상적으로 평가 완료된 분석ON 일반 주는 **E≤1이면 누적 RESET0**, **E>1이면 min(1,E/N)을 ADD**한다. 반드시 E 임계값을 먼저 검사한다.1/1을 먼저1주로 계산하지 않는다. 검사 완료된 N0/E0의 전체 휴식 주도 RESET이며0/0 나눗셈은 하지 않는다. 등록 전/epoch 전/분석OFF/전체 정지/UNKNOWN·검사 미완료를 정상 N0주로 둔갑시키지 않는다.

**[DL-11 · 교체/v1.7]** 일반 일정 변경은 저장 즉시 적용한다. 과거 수행·첫 예정 START/최초 MISS·해당 날짜 종료 직전 계획 근거는 유지한다. 현재 계획일0/1/2/6이라는 이유만으로 누적을 변경하지 않는다. 주간 결과는 **다음 월요일04시 이후**, 해당 주의 필요한 일별 검사와 후보 평가가 완료된 뒤 확정한다. 월요일03:59:59·주중에는 새 주간 값을 가산하지 않는다. 일요일 ACTIVE/UNKNOWN이 남으면 보류한다.

**[DL-12 · 확정/v1.7]** 실제 디로딩 기간에는 일반 누적/주간 RESET과 일반 미수행 평가를 정지한다. 날짜 당시의 기간 이력을 사용하며 현재 상태만 보고 과거 정지일을 MISS로 만들지 않는다. 정상/자동 완료는 누적0의 새 일반 분석 경계, 무수행 취소는 기존 누적과 epoch를 유지한다. 취소로 인한 정지 구간/정지 보호 주를 소급 RESET하지 않는다. 보호 때문에 E≤1 RESET을 억제하더라도 양의 ADD를 만들지 않는다. 전체 정지 주와 정상 검사 N0주는 다르다.

**[DL-13 · 교체/v1.7]** 완료 다음 날부터 일반 훈련을 재개한다. 완료 뒤 남은 일반 날짜를 **같은 월~일 주의 새로운 분석 구간**에서 E/N으로 평가하고 다음 월요일04시 이후 확정한다. 완료 전 실적을 새 구간에 다시 더하지 않는다. 옛 '전체 계획일 분모'나 '완료 주 전체 제외/다음 주까지 유예'를 사용하지 않는다.

**[DL-14 · 확정/v1.7]** 늦은 동기화·정정·논리 삭제·명시 복구로 원본이 바뀌면 영향받은 가장 이른 주부터 **같은 epoch의 후속 주를 순서대로 재계산**한다. 수행 원본/InitialPlan/최초 평가·MISS는 보존한다. 주간 RESET은 바뀔 수 있는 파생 결과이며 새 epoch를 만들지 않는다. 재ON/정상·자동 완료의 hard reset 경계와 구분한다. E와 기여는 정확한 유리수로 비교·계산하고 UI 반올림 문자열을 재입력하지 않는다. 주별 revision·ruleVersion·보류/마지막 확정값을 구분하며 같은 주 재실행으로 중복 가산하지 않는다.

### 2.4 정확한 예와 경계

| 해당 주의 서로 다른 날짜별 유효값 | E | N | 결과 |
|---|---:|---:|---|
| [1] |1|1|RESET0 |
| [1,1] |2|2|ADD1 |
| [1,1,1,0(MISSED)] |3|4|ADD0.75 |
| [1,0.5] |1.5|2|ADD0.75 |
| [1,0(MISSED)] |1|2|RESET0 |
| [0.5,0.5] |1|2|RESET0 |
| [1,1,1,0.5,0(MISSED)] |3.5|5|ADD0.7 |
| [1,1,1,1,0(MISSED)] |4|5|ADD0.8 |
| 정상 검사 완료·실제/미수행 날짜0 |0|0|RESET0, 나눗셈 없음 |
| UNKNOWN/일요일 ACTIVE/검사 미완료 |미확정|미확정|보류, 마지막 확정값과 구분 |

계획0일이어도 실제 일반 세션을 서로 다른2일 완전 수행하면 E2/N2=1주다. 예정PUSH 대신 PULL 완전 수행은 일반 계획PUSH 달성률을 채우지 않지만 디로딩에서는 PULL 자기 InitialPlan1이다. 두 반쪽 세션은0.5 하나로 선택한다.

누적3 → RESET주 → 다음 주ADD1이면 현재1이다. 늦은 기록으로 RESET주가0.75 ADD로 바뀌면 **3+0.75+1=4.75**다. 현재1에0.75만 더하는1.75는 잘못이다. ON을 주중에 재개해도 달력 주를 수~화로 바꾸지 않으며 활성화 전 세션을 쪼개 새 구간에 넣지 않는다.

월요일 완료 뒤 화~토5일 완료는 E5/N5=1주, 수요일 완료 뒤 목·금2일 완료는 E2/N2=1주, 완료 후1일만 완료하면 E1이라 RESET0이다.

## 3. 디로딩 시작·취소·완료·자동 종료

- **[DL-15 · 확정/v1.7]** 시작 제한: DL-80의 실제 일반 수행 기반 네 조건을 확인한다. 현재 계획2일 조건은 없다. 오늘 실제 수행이나 ACTIVE 일반 세션이 있으면 시작하지 않는다. 접속 기기가 아는 미동기화 완료 수행/고정 요청을 먼저 확인하며 숨은 타 기기 상태를 알 수 있다고 가정하지 않는다. 서버 검증과 로컬 원본 보호를 함께 적용한다.
- **[DL-16 · 확정] 무수행 세션:** 시작만 하고 웨이트 세트·유산소 수행이 전혀 없는 세션은 취소 시 운동 이력으로 남기지 않고 정리한다. 오프라인 미동기화 수행을 잘못 삭제하지 않아야 한다. 실제 수행이 하나라도 있으면 해당 사실을 보존한다.
- **[DL-17 · 확정/v1.7]** 진행 중 구분: 동일 사용자에게 ACTIVE 디로딩 기간은 하나만 존재할 수 있다. 신규 기간 생성은 서버 상태 재확인·멱등 재요청·동시성 보호로 중복을 막는다. 이는 DL-80 네 운동 자격과 별도의 **기간 생성 상태 제약**이며 다섯 번째 자격 조건이 아니다. 일반/디로딩 운동은 단일 ACTIVE 세션 원칙을 공유하고 세션 유형을 바꾸거나 임의 종료하지 않는다. 진행 중 원본 루틴·일반 기록은 읽기 전용이며 실행·수정·삭제를 막고 공통 계정·휴식 설정은 유지한다.
- **[DL-18 · 확정] 기간:** DL-17의 단일 기간 제약을 적용하며, 시작일을 1일차로 하는 **권장 7일**. 8·9·10일차까지 연장되며 **10일차의 종료 시점에 자동 정상 완료**한다. 11일차부터 원본 루틴을 다시 실행할 수 있다. 7일차에 자동 종료하지 않는다.
- **[DL-19 · 확정] 직접 완료:** 사용자는 7일을 채우지 않았거나 운동을 전혀 하지 않았어도 언제든 완료를 선택할 수 있다. 완료한 **당일까지 디로딩 기간**이며 그날 일반 운동으로 전환하지 않는다. 완료 시 누적 유효 주수는 0, 운동/디로딩 이력은 보존, 임시 루틴은 비활성화한다.
- **[DL-20 · 확정] 취소:** 디로딩 운동을 **한 번도 실제 수행하지 않았을 때만** 취소할 수 있다. 완전 휴식으로 며칠을 보낸 경우에도 실제 수행이 없으면 취소 가능하다. 웨이트 1세트 또는 유산소의 실제 수행이 한 번이라도 있으면 취소 불가이며 완료로 종료한다. 취소 시 누적 유효 주수 유지.
- **[DL-21 · 확정] 방식 변경:** 3일형↔2일형↔휴식 등 디로딩 방식 교체는 실제 수행 **전까지만** 가능하다. 0세트 세션을 취소·정리했다면 변경 가능. 수행 후에는 방식 고정; 미수행 운동의 일정/종목/중량 등 임시 루틴 수정은 계속 허용한다.
- **[DL-22 · 확정] 자동 완료:** 10일차 종료 시 사용자 직접 완료와 **동일한 상태 전이 및 효과**를 적용한다. 별도의 확인창은 없고, 11일차 일반 루틴으로 돌아간다.

- **[DL-24 · 확정] 기존 루틴 유지:** 기존 운동 요일·분할·운동 종목을 유지한 상태에서 디로딩 중량/세트/반복/유산소 목표만 낮춘다. 기존 루틴에서 여러 날 반복되는 같은 운동도 그대로 유지할 수 있다.
- **[DL-25 · 확정] 주 3회 압축:** 등록 운동을 Push / Pull / Legs로 분리할 수 있으면 그 구조로 생성한다. 어느 한 영역이 비어 정상 분할이 불가능하면 **3일 균등 분배**로 대체하며 3일형 선택 자체를 막지 않는다. **v1.4 UI 정책:** 사용자에게 펼침 선택을 제공하여 PPL 가능 시 기본값 PPL 또는 자발적 균등 분배를 선택할 수 있다. PPL 불가능 시 비활성화 사유를 보여주고 균등 분배를 기본 선택한다.
- **[DL-26 · 확정] 주 2회 압축:** 전면 / 후면 분리가 가능하면 그 구조로 생성한다. 불가능하면 **2일 균등 분배**로 대체한다. **v1.4 UI 정책:** 전면·후면이 가능하면 기본값으로 보여주되 사용자가 균등 분배를 선택할 수 있다. 불가능하면 비활성화 사유를 보여주고 균등을 선택한다.
- **[DL-27 · 확정] 완전 휴식:** 운동 루틴을 생성하지 않고 휴식 기간만 관리한다. 운동 0회여도 정상 완료할 수 있다.
- **[DL-28 · 확정]** 주 3일·2일형의 가능 여부는 **원본 루틴의 계획 운동일 수**로만 판단한다. 특정 분할이나 운동 종목 수가 부족하다는 이유로 선택을 추가 제한하지 않는다. 원본에 없는 운동은 절대 자동 추가하지 않는다.

### 4.1 분할별 근육 구분

| 분할 | 포함되는 대표 영역 |
|---|---|
| Push | 가슴, 전면·측면 어깨, 삼두 |
| Pull | 등, 후면 어깨, 이두 |
| Legs | 대퇴사두근, 햄스트링, 둔근, 종아리 |
| 전면 | 가슴, 전면·측면 어깨, 삼두, 대퇴사두근, 복근 |
| 후면 | 등, 후면 어깨, 이두, 햄스트링, 둔근, 종아리 |

※ 이 구분은 자동 편성 기준이다. 하나의 운동이 여러 `PRIMARY` 근육을 가질 수 있으며, 복합 운동은 더 적절한 **한 날짜에만** 배치한다.

## 5. 운동 종목 자동 선정 및 정렬

- **[DL-29 · 확정] 출처 제한:** 원본 주간 루틴에 실제 등록되어 있는 표준 운동만 사용한다. 비어 있는 분할을 채우기 위해 새 운동을 발명하거나 외부 추천을 추가하지 않는다.
- **[DL-30 · 확정] 대표 운동 선정:** `exercise_muscle`의 세부 `PRIMARY` 근육을 기준으로 아직 포함되지 않은 근육의 대표 운동을 우선한다. 일반 가슴과 윗가슴처럼 서로 다른 세부 PRIMARY라면 모두 고려할 수 있다. `SECONDARY`만으로 PRIMARY 커버를 대체하지 않는다.
- **[DL-31 · 확정] 메인 우선:** 같은 주동근의 운동 후보에서는 원본 루틴에서 **먼저 배치된 운동**을 우선한다. 세트 수나 반복 수가 많다는 이유로 보조 운동을 메인보다 우선하지 않는다.
- **[DL-32 · 확정] 다관절 우선 정렬:** 주동근 커버를 고려해 종목을 선정한 뒤 **다관절(COMPOUND) → 단관절(ISOLATION)** 순서로 정렬한다. 같은 분류 안에서는 기존 루틴의 우선순위를 유지한다. 다관절이라는 이유만으로 동일 PRIMARY의 중복 운동을 무조건 선정하지 않는다.
- **[DL-33 · 확정] 다중 PRIMARY:** 한 운동이 대퇴사두근·둔근 등 여러 PRIMARY를 가지면 선택 시 해당 근육을 모두 커버한 것으로 본다. 서로 다른 분할에 걸쳐도 가장 적절한 한 날에만 배치하고, 다른 날에 동일한 웨이트 종목을 재배치하지 않는다.
- **[DL-34 · 확정] 3일형 분할의 순서:** 기존 주간 루틴의 요일별 **첫 메인 운동**을 원본 요일 순서로 보며, Push·Pull·Legs의 최초 등장 순서대로 3일형 순서를 정한다. 중복 분할은 건너뛴다. 예: 등·등·가슴·하체·가슴·하체 → Pull·Push·Legs.
- **[DL-35 · 확정] 균등 분배 대안:** 정규 분할이 안 되면 선정된 메인 운동부터 **1일차→2일차(→3일차)→1일차…** 라운드로빈 배치한다. A·B·C·D 우선순위의 2일형은 `A,C` / `B,D`다. `A,B` / `C,D`처럼 뒤쪽 날에 보조 운동만 몰아넣지 않는다.
- **[DL-36 · 확정] 커버와 운동량의 균형:** 부위별 대표성을 확보하되 하루 종목·세트 상한을 넘기지 않는다. 상한을 채우려고 종목을 억지로 추가하지 않는다. 선택 이후 사용자가 임시 루틴을 수정할 수 있다.

### 5.1 예시: 원본 주 6일의 Push 통합

| 원본 월요일 Push | 원본 목요일 Push |
|---|---|
| 벤치프레스(가슴) | 인클라인 벤치프레스(윗가슴) |
| 숄더프레스(전면 어깨) | 사이드 레터럴 레이즈(측면 어깨) |
| 트라이셉스 익스텐션(삼두) | 체스트 플라이(가슴) |

**추천 Push:** ① 벤치프레스 → ② 인클라인 벤치프레스 → ③ 숄더프레스 → ④ 사이드 레터럴 레이즈 → ⑤ 트라이셉스 익스텐션. 같은 세부 PRIMARY를 이미 대표하는 체스트 플라이는 우선순위가 낮아진다. 실제 결과는 표준 운동별 정확한 PRIMARY 매핑과 상한에 따라 달라진다.

jointType은 Backend V18/StandardExercise에 존재한다. G5-1 자동 편성은 이 값과 세부 PRIMARY를 사용한다. 운영 카탈로그의 종목별 분류 품질은 별도 검증 대상이다.

- **[DL-37 · 확정/v1.7]** 현재 Backend V18의 standard_exercise.joint_type 컬럼과 StandardExercise.JointType enum은 **이미 구현되어 있다**. 지원값은 COMPOUND/ISOLATION/OTHER이며 NULL은 미분류, OTHER는 명시적 해당 없음이다. 새 컬럼을 다시 추가하지 않는다. 종목별 분류 정확성과 디로딩 자동 편성 엔진 검증은 별개다. 근육 개수·운동명·부하 방식으로 jointType을 추정하지 않는다.

## 6. 웨이트 운동량 감량

- **[DL-40 · 확정] 중량:** 승인 중량이 있으면 그 값을, 없으면 원본 루틴에 설정된 초기 중량을 기준으로 **85%** 적용한다. **PLATE·STACK = 5kg, DUMBBELL = 2kg, 장비 구분 없음 = 1kg** 단위로 **내림**한다. BODYWEIGHT는 중량 조절 없이 세트·반복으로 조절한다.
- **[DL-41 · 확정] 0kg 방지:** 소중량 운동에서 장비 단위 내림으로 0kg가 되면 0kg로 만들지 말고 원래 소중량을 유지한 채 세트·반복을 줄인다. 장비 단위 탓에 중량 감량폭이 커지면 반복까지 과도하게 중복 감량하지 않도록 한다.
- **[DL-42 · 확정] 세트:** 기존 세트 수의 **50%를 정수 반올림(0.5는 올림)**하고 **최소 1세트** 유지한다. 예: 1→1, 2→1, 3→2, 4→2, 5→3, 6→3.
- **[DL-43 · 확정] 반복:** **짝수 세트**는 세트만 절반으로 줄여 반복 횟수를 기본 유지한다. **홀수 세트**는 세트를 반올림한 뒤 **반복 횟수를 낮춰 전체 수행 횟수가 약 50%**가 되도록 보정한다. 정확한 50%는 의무가 아니다. 예: 3×10→2×8(약 53%), 5×10→3×8(48%), 3×8→2×6(50%), 1×10→1×5.
- **[DL-44 · 확정] 압축형 종목 상한:** 주 3일형은 `min(원본 루틴 하루 평균 웨이트 종목 수 + 1, 6)`을 상한으로, 주 2일형은 `min(평균 + 2, 7)`을 상한으로 삼는다. 평균이 정수가 아닐 때 최종 정수화 방법은 구현 전 확인 항목이다. **상한은 목표 종목 수가 아니다.**
- **[DL-45 · 확정] 압축형 세트 상한:** 하루 전체 계획 세트는 원본 루틴의 하루 평균 세트 수의 **약 70%를 넘기지 않는 방향**으로 조정한다. 주간 총세트의 절반은 참고치이고, 압축형에서 약 20~40%로 줄어도 무방하다. 당일 운동이 원래보다 과중해지지 않는 것이 우선이다.
- **[DL-46 · 확정] 자동 적용 시점:** 감량은 임시 루틴을 **최초 생성할 때만** 적용한다. 이후 사용자가 수정한 중량·세트·반복은 자동으로 덮어쓰지 않는다. 실제 운동 수행 전 방식 변경으로 새 루틴을 다시 생성하는 경우에만 새 추천값을 적용한다.

### 6.1 세트·반복 예시

| 원본 세트 × 반복 | 디로딩 세트 × 반복 | 총 반복 비율 |
|---|---|---:|
| 4 × 10 | 2 × 10 | 50% |
| 6 × 10 | 3 × 10 | 50% |
| 3 × 10 | 2 × 8 | 약 53% |
| 5 × 10 | 3 × 8 | 48% |
| 1 × 10 | 1 × 5 | 50% |

## 7. 유산소 자동 편성과 감량

- **[DL-47 · 확정]** 기존 루틴에 등록된 유산소만 디로딩에 포함한다. 계획에 없던 종목을 자동 추가하지 않는다. 유산소를 포함해도 수행 여부는 사용자 선택이다.
- **[DL-48 · 확정] 목표:** 등록된 **속도는 85%**로 줄이고 **소수점 첫째 자리**까지 반올림한다(예: 7.5km/h→6.4km/h). **시간은 50%**로 줄이고 **1분 단위 반올림(0.5분 올림)**한다(35분→18분, 45분→23분). 속도가 없으면 시간만 감량하고 없는 목표는 새로 만들지 않는다.
- **[DL-49 · 확정] 기존 루틴 유지:** 유산소 요일/종목 구성은 원본 그대로 두고 해당 목표만 낮춘다.
- **[DL-50 · 확정] 압축형 하루 상한:** 유산소는 웨이트 종목 수와 **별개**로 하루 **최대 1종목**이다. 원본 주간 루틴에 여러 종류가 있으면 **먼저 등록된 유산소**를 기본 추천하며 사용자가 변경할 수 있다.
- **[DL-51 · 확정] 3일형:** 원본 유산소가 주 **2일 이상**이면 Legs를 제외한 두 분할일에 유산소 1종목씩 배치한다. 원본 유산소가 주 **1일**이면 하체가 아닌 **첫 운동일**에만 배치, **0일**이면 추가하지 않는다.
  - **Legs 구분이 없는 3일 균등 분배 대안:** 원본 유산소가 주 **1일**이면 **첫 운동일**, 주 **2일 이상**이면 **앞의 두 운동일**에 하루 1종목씩 배치한다. 원본 유산소가 **0일**이면 추가하지 않는다. 원본에 등록된 유산소만 사용하며 DL-50의 하루 상한·우선 종목과 DL-53의 유산소 중복 예외를 유지한다. 이 예외는 Legs 구분이 없는 3일 균등형에만 적용한다.
- **[DL-52 · 확정] 2일형:** 원본 유산소가 주 **2일 이상**이면 두 운동일 모두 배치, **1일**이면 첫 운동일에만 배치, **0일**이면 추가하지 않는다.
- **[DL-53 · 확정] 중복 예외:** 압축형에서 **웨이트 종목은 서로 다른 날짜에 중복 선정하지 않지만**, 유산소는 위 배치 규칙에 따라 동일 종목이 여러 날짜에 한 번씩 나타날 수 있다.

## 8. 요일 자동 배치·수정·연장

- **[DL-54 · 확정]** 기존 루틴 유지형은 **원본 운동 요일**을 따른다.
- **[DL-55 · 확정]** 3일형은 **시작일 / 시작일+2 / 시작일+4**, 2일형은 **시작일 / 시작일+3**으로 최초 제안한다. 예: 월요일 시작 → 3일형 월·수·금, 2일형 월·목. 7일은 월~일 고정이 아닌 **실제 시작일부터 7일**이다.
- **[DL-56 · 확정]** 사용자는 권장 7일 안에서 미수행 운동의 날짜를 자유롭게 변경할 수 있고 **연속된 운동일도 허용**한다. 자동 추천은 처음 한 번이며 사용자가 수정한 날짜는 자동 재배치하지 않는다. **v1.4 변경:** 방식 선택 화면에서 시작 전에 추천 요일을 직접 변경할 수 있으며, 시작 후에도 미수행 일정 수정은 유지한다.
- **[DL-57 · 확정]** 이미 수행한 날짜·실제 기록은 고정한다. **미수행 운동만** 날짜를 바꿀 수 있다. 놓친 운동도 앱이 자동 완료·삭제·이동하지 않고 사용자가 직접 수정한다.
- **[DL-58 · 확정]** 디로딩 도중 방식 변경은 수행 전이라는 조건뿐 아니라 **남은 기간 내 실제 배치 가능한 운동일 수**도 고려한다. 남은 날짜가 3일이면 최대 3회형, 2일이면 최대 2회형, 1일이면 새 자동 생성을 권장하지 않고 종료를 안내한다. **7일이 지난 뒤에는 새 디로딩 루틴을 자동 생성하지 않는다.**
- **[DL-59 · 확정]** 8~10일차까지 이어지면 메인 하단 루틴 UI는 새로운 주차처럼 이동하고 **8일차·9일차·10일차**를 표시한다. **미수행 운동을 8~10일차로 이동하거나 기존 임시 루틴을 수정하는 것은 가능**하지만, **새 디로딩 루틴의 생성은 불가**하다. 완료된 운동의 날짜·실적은 고정한다. 10일차 종료 후 자동 완료.

## 10. 운동 이력, 통계, 원본 루틴 보호

- **[DL-65 · 확정]** 디로딩 중 수행한 세트·중량·유산소의 실제 기록은 정상 운동 이력에 남기고 **디로딩 운동임을 구분**한다. 수행 당시의 운동 계획(스냅샷)도 유지한다. 나중에 임시 루틴을 수정해도 과거 수행 기록은 바뀌지 않는다.
- **[DL-66 · 확정]** 디로딩 실적은 **근육별 주간 통계와 운동 이력에 포함**한다. 디로딩 전용 기록 화면에서는 **현재 디로딩 기간에 연결된 실적만** 조회하고, 일반 기록(디로딩 중에는 읽기 전용)은 기존 전체 수행 통계와 당시 기록을 조회한다. 그러나 일반 중량 **증량·유지·감량 평가 및 승인 중량 변경**에서는 제외한다. 디로딩 중 수동 중량/세트 조정도 일반 성과 평가에 반영하지 않는다.
- **[DL-67 · 확정]** 완료 후 임시 루틴은 **비활성화하여 일반 루틴 목록에 노출하지 않음**. 수행 세션의 기록과 당시 계획, 디로딩 시작/종료 날짜·방식은 조회할 수 있게 보존한다. 완전 휴식으로 운동 기록이 0건이어도 디로딩 자체 이력은 남긴다.
- **[DL-68 · 구현 확인]** 기존 `InitialPlan`·`AppliedPlan`, 운동 세트의 장비/중량 스냅샷, FINISH/AUTO_CLOSED, 사후 수정·삭제·복구, 오프라인 IndexedDB 및 서버 동기화 흐름을 재사용한다. 일상 운동과 디로딩 세션에 동일한 단일 활성 세션 원칙을 적용한다.

- **[DL-79 · 구현 확인] 수행 이력 및 활성 세션 보호:** 세션 수행 세트가 한 번이라도 실제 저장되면 이후 표시용 수행 기록의 정정·논리 삭제와 별개로 **디로딩 취소 불가 판단에 필요한 수행 사실을 보존**해야 한다. 디로딩 운동 세션이 아직 진행 중일 때는 모드 완료·취소·방식 변경으로 그 세션을 임의 종료하거나 유실시키지 않는다. 특히 10일차 자동 종료와 날짜 경계·오프라인 미전송이 겹치는 경우 데이터 전이 원자성과 시간 처리 규칙을 코드에서 확인해야 한다. 이는 DL-17/20/22 및 완료 원본 보호 원칙의 구현 검증이며 새로운 사용자의 필수 입력을 요구하지 않는다.

## 10.2 v1.7 · 시작 자격 (v1.5 식별자 유지)

- **[DL-80 · 확정/v1.7]** 분석ON/OFF와 무관하게 다음 **네 조건**을 모두 만족해야 시작할 수 있다. ① 오늘 제외 직전7개 로컬 달력 날짜에 실제 일반 운동 수행 존재, ② 이전 완료 디로딩이 있다면 그 완료 이후 새 일반 실제 수행 존재, ③ 오늘 실제 일반 운동 수행 없음, ④ 현재 ACTIVE 일반 운동 세션 없음. 이전 완료가 없다면②는 적용할 이전 경계가 없다. **현재 주간 계획2일 이상 조건은 폐기**하며 게이지0/계획0~1일/OFF 자체는 차단 사유가 아니다.
- **[DL-81 · 확정/v1.7]** 최근 실제 운동: 계정 로컬 달력 기준 오늘 제외 직전7개 날짜다(11월4일이면10월28일~11월3일). 실제 웨이트 수행 세트 또는 현재 유효한 미삭제 실제 유산소 결과(COMPLETED, activeMs>0)가 있어야 한다. START만 있음·SKIPPED·결과 없음·실제 활동0·기록 없는 예정 운동·디로딩 세션은 인정하지 않는다. activeMs는 기존 WorkoutSnapshotRequests.cardioNumbers와 WorkoutRecordRequests의 실제 활동량 필드이며 새 최소 운동시간·거리·속도 기준을 추가하지 않는다. 최초 목표 달성 여부와 무관한 실제 수행의 존재 검사이며 DL-08의 종목 완료 판정과 구분한다. 수행일을 사용하고 업로드일로 바꾸지 않는다.
- **[DL-82 · 확정/v1.7]** ON/OFF는 추천 누적만 제어한다. OFF라도 일반 수행 기록·G3 미수행 검사·일반 통계·수동 시작 자격 조회는 유지한다. 재ON은0의 새 epoch다. 진행 기간은 토글과 독립이고 실제 수행/미수행을 분석 설정으로 삭제하거나 변경하지 않는다.
- **[DL-83 · 확정] 자격 미달 UI:** **홈 헤더의 디로딩 진입 영역**(ON: 수평 게이지 / OFF: 초승달)을 통해 기존 상세로 접근한다. 상세에서 시작 자격 충족 여부를 알리고 미충족 시 `디로딩 시작`을 비활성화하며 구체적 이유를 제공. **미리보기의 최종 시작 버튼을 누르는 순간 동일 조건을 재검사**한다. 별도 자격 설정/입력 페이지나 별도 최종 확인 화면은 만들지 않는다.
- **[DL-84 · 확정/v1.7]** 날짜·오프라인·재시작 검증: 저장된 달력/세션 시간대와 수행일, 즉시 일정의 불변 과거 근거, 최근7일/오늘 실제 수행, 이전 완료 이후 새 수행 및 ACTIVE를 서버에서 확인한다. 접속 기기의 미전송 원본·고정 요청도 보호하되 타 기기 미지 상태를 추적하는 새 전역 잠금을 만들지 않는다. 판정 조회와 시작 확정 사이 경쟁은 owner 잠금·버전·최종 재검증으로 막는다. HTML의 자격 스위치는 서버 검증이 아니다.

**현재 기준:** DL-05~14는 v1.7의 기록 기반 E/N·epoch·주간 확정 규칙을 적용한다. DL-18~22의 7~10일 종료 규칙, DL-69~79의 UI/취소/완료/완전 휴식 원칙은 유지한다. 시작에 자격이 필요하더라도 시작 후 운동 수행을 강요하지 않고, 모든 미수행 임시 루틴을 삭제해도 디로딩 기간은 유효하다.


## 10.3 v1.6 · v0.9 UI 심플화 합의와 기존 정책의 관계

> **적용 우선순위:** DL-07/60/61/63/64/69/70/83의 최신 문구 및 아래 DL-85~90은 v1.5의 홈 원형 추천 버튼, 전역 상단 `일반 보기`, 별도 시작 최종 확인 화면 규칙을 명시적으로 대체한다. 그 밖의 v1.6 회복·분할·기록·기간 정책은 유지하되, 훈련 누적/자격은 v1.7의2절·3절·DL-80~84가 우선한다.

- **[DL-85 · 확정] 홈 최우선 정보:** 홈의 큰 동기부여 카드·별도 디로딩 상태 카드를 제거. 일반 모드/디로딩 모드 모두 기존 `오늘의 루틴 → 운동 시작 → 오늘만 다른 루틴 선택 → 이번 주 일정 → 최근 운동` 순서를 유지한다. 홈 헤더는 간결하게, 오늘의 루틴에서 WEIGHT/CARDIO 목록은 동등한 구획으로 표시한다.
- **[DL-86 · 확정/v1.7]** 헤더: 분석ON/OFF 미진행은 DL-70과 UI10.12의 공식 달·브랜드 고정·오늘 카드 날짜를 따른다. 브랜드18px/700/자간0.06em, 달22~24px Dusty Blue, ON만 주수/게이지다. 진행 중은 Mint Sage 공식 달+디로딩 진행 중·n일차/일반 보기, 날짜·D배지·클로버 없음. 공식 SVG/PNG 원본 형태를 보존하며 문자/Lucide 대체 금지. 조회 상태를 실제 기간/권한으로 사용하지 않는다.
- **[DL-87 · 확정] 일반 보기의 탐색 경계:** 홈에서만 `일반 보기/디로딩 복귀` 전환, 루틴/기록의 조회 데이터에 적용; 일반 보기 읽기 전용 및 일반 운동 실행 금지. 운동 수행 중에는 모드 전환·일차를 표시하지 않으며 실제 세션은 계속 진행된다.
- **[DL-88 · 확정] 시작 미리보기에서 즉시 확정:** 횟수/분할/요일을 정해 운동 날짜와 원본 대비 감량 목표를 본 뒤 **미리보기 하단에서 바로 시작**한다. 별도 시작 확인 화면은 만들지 않는다. DL-15/80 자격 재검사는 필수이며 원본 루틴/승인 중량 불변 안내를 간결하게 남긴다. **디로딩 완료·취소의 단일 확인창은 유지**한다.
- **[DL-89 · 확정] 공통 운동 진행 시각화:** 일반/디로딩 운동 모두 상단에 `전체 운동 시간 | 현재 x / n종목 + 종목 구간형 표시 | 휴식 시간`을 재사용한다. 이 구간은 **종목 탐색 위치**이고 세트 완료율이 아니다. **현재 종목까지 처음부터 누적 채움**(4종목 중 2번째 `[■ ■ □ □]`, 3번째 `[■ ■ ■ □]`)이며 현재 칸 하나만 점등하지 않는다. 이전 종목 탐색 시 위치에 맞게 줄어든다. `기존 기록/이번 기록`의 원래 배치와 미완료 세트의 반복 횟수 입력 `−/+`를 유지한다. 완료 후 읽기 표시·원형 체크·취소 확인은 [Visual Theme Spec 5절](Overload_UI_Visual_Theme_Spec_v0.9.md#5-세트-완료-컨트롤)을 따른다. 완료 세트 취소/재완료와 실제 수행 사실 보존, 공식 중량 평가 제외는 기존 규칙 유지. 기록 상세의 수행 볼륨은 종목 요약·세트별 표시를 제공하되 중복 요약 카드를 추가하지 않는다.
- **[DL-90 · 확정] 8~10일·휴식·조회 지속:** 홈에서 진행일 차 표시를 간결히 했더라도 7일 권장·최대10일, 8일차 종료 안내 1회, 완료 당일 일반 운동 불가, 완전 휴식 및 임시 루틴 전부 삭제 허용, 완료 후 일반 기록과 디로딩 이력 보존 규칙은 변경하지 않는다. UI에서 날짜/진행 정보를 덜 보인다는 이유로 기간 계산이나 필수 자격을 생략하지 않는다.

## 10.4 2026-11-05 · UI v0.9 시각 기준 보존

2026-11-07 현재 홈 헤더·날짜·주간 상태의 후속 보완은 DL-70/86과 UI Decision Log10.12·10.14가 우선한다. 아래는 유지되는 시각 토큰과 이전 표현의 이력이며 분석/자격의 권위는 v1.7의2절·DL-80이다.

> **우선순위:** DL-07과 DL-89의 최신 개정, 본 절의 구체적인 시각 규칙이 이 문서의 이전 초록 게이지/중립색 게이지 표현보다 우선한다. 계산·시작 자격·수행기록 판정과 서버 상태 불변 조건은 변경하지 않는다. 배치·행동은 [UI 결정 로그 10.11절](Overload_UI_Decision_Log_v0.9.md#1011--2026-11-05-최종-디자인-보완--onyx-완료-상태-누적-진행), 실제 컬러·테마·완료 컨트롤 표현은 [Visual Theme Spec](Overload_UI_Visual_Theme_Spec_v0.9.md)을 따른다. [HTML 와이어프레임](Overload_UI_Baseline_Wireframe_v0.9.html)은 무채색 UI/UX 시뮬레이션으로 유지하며 아래 실제 테마 색상을 적용하지 않는다.

- **테마:** 공통 페이지 Onyx `#111216`, 보조 카드 `#1B1D22`, 내부/입력 `#25282E`. 일반 강조 Dusty Blue `#6C93C6`, 디로딩 강조 Mint Sage `#78B89A`.
- **오늘의 루틴 강조 카드:** 일반 `linear-gradient(142deg, #272D37 0%, #222832 50%, #1C212A 100%)`; 디로딩 `linear-gradient(142deg, #28312C 0%, #222B26 50%, #1A231E 100%)`. 두 경우 오른쪽 아래도 동일 색 계열의 저채도 어두운 면이며, 화면 전체에 유색 틴트를 적용하지 않는다.
- **강조 텍스트:** `WEIGHT`/`CARDIO`, CTA, 활성 탭/상태, 오늘 날짜 등 모드별 강조색; 일반 본문은 중립색. 오늘의 루틴은 WEIGHT/CARDIO 각각 `총 N종목`, `1. 운동명` 왼쪽 + 저장 계획 수치 오른쪽 한 줄(가변 반복은 범위로 표시).
- **지난 주간 날짜(최신 UI10.14 우선):** 판정 전에는 요일 문자, 확정 완전✓/부분·미수행X/휴식-이다. 다음 날04시 검사와 전환 이전 비소급을 적용한다. 아래 v1.6 표현은 이력이다: 날짜/요일 또는 상태/루틴명 3층. 과거 완료 ✓ `#74A68A`, 과거 미수행 × `#B17B83`, 과거 휴식 - (중립 회색)로 **요일을 교체**. 오늘·미래는 요일 유지. 과거 텍스트는 개별적으로 어둡게 하되 상태 색상에 상위 opacity를 적용하지 않는다. ✓/×는 확정 운동 판정, -는 지난 휴식 계획 표시이지 수행 완료를 뜻하지 않는다.

## 10.5 주간 일정 프리셋 연동 (정책 확정 · 구현 전)

일반 주간 일정 프리셋의 [제품·UI 기준](Overload_UI_Decision_Log_v0.9.md#1016--다중-주간-루틴-일정과-자동-순환)을 적용한다. 프리셋 연동은 후속 개발이며 기존 G5 기간, 네 시작 자격, 감량 비율, 편성, 기록 소속, 완료·취소 조건을 유지한다.

- 디로딩 시작 시 일반 활성 프리셋과 순환 위치를 보존하고 순환을 일시 정지한다. 실제 운동에는 디로딩 임시 계획을 사용한다. 달력의 월~일 주차와 G3/G4의 기존 보호 및 분석 경계는 유지한다.
- 정상 완료 당일은 기존 보호일이며 다음 날 A의 해당 요일 배정으로 복귀한다. 그날이 월요일이어도 A로 시작한다. 무수행 취소는 즉시 A로 복귀하고 기존 분석 누적은 보존한다. 10일차 자동 완료가 지연되면 기존 ACTIVE 보호를 적용한 뒤 실제 완료 처리로 일반 접근이 가능해지는 시점에 A로 복귀한다. 종료 보호 날짜와 실제 처리 시각은 구별한다.
- 자동 ON이면 세 경우 모두 **실제 복귀 날짜보다 뒤의 첫 월요일**에 다음 순서를 진행한다. OFF이면 복귀한 A를 유지한다. 디로딩 중 지난 월요일은 소비하지 않으며, 누락된 순환을 보충하거나 소급 적용하지 않는다.
- 일반 프리셋과 순환 목록 조회는 허용한다. ACTIVE와 완료 당일의 기존 보호가 적용되는 동안 프리셋 생성·배정 수정·삭제·순서·포함 여부·순환 ON/OFF·수동 적용을 제한한다. ACTIVE 중 임시 계획은 기존 권한으로 편집한다.
- 미리보기·시작의 디로딩 원본 프리셋은 기본 활성이다. 사용자가 다른 프리셋이나 순환 제외 프리셋을 고를 수 있다. 선택한 배정과 원본 운동 루틴 구성으로 기존 편성·감량 계산을 수행하고 시작 당시 원본과 근거를 보존한다. 미리보기 뒤 실제 START에서 선택한 원본을 재검증한다. 원본이 바뀌었거나 유효하지 않으면 시작을 거절하고 최신 미리보기를 안내한다. 일반 활성 A에서 원본 B를 골라도 임시 계획은 B, 멈춘 순환과 복귀는 A다. [G5 후속 계약 경계](../../../overload-server/docs/api/deload-periods.md#주간-일정-프리셋-연동-검토--미구현)

- **v1.4 최신 합의:** 이전 `가능하면 PPL/전후면 아니면 자동 균등`만 하던 방식 대신 사용자에게 **가능한 두 방식의 직접 선택**을 제공. 이전 `디로딩 중 원본 루틴 편집 가능`은 **일반 조회 읽기 전용**으로 변경. 기존 7일 미리보기의 휴식일 카드 표시를 폐기하고 운동일만 보여준다.

### 2026-11-07 v1.7 정정 이력
