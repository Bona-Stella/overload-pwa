[ST-19](../../../overload-server/docs/product/Overload_Statistics_and_Tracking_Design_Specification_v1.4.md#31-하루-종목-완료-기준)
- Benchmark 동점은 현재 서버의 최신 종료 시각 우선 방식을 채택했다. 웨이트 시간은 확인 가능한 활성 수행 화면 구간의 A안을 유지하며 백그라운드 추정은 요구하지 않는다.
- 최근 실제 중량은 정확한 사용자/세대/조합의 FINISHED만 대상이며 ACTIVE는 제외한다. 메모는 변경 blur/입력 종료 시 온라인 저장·서버 최종 반영값 우선 LWW·실패 초안 보호로 확정됐다. HTTP/DTO나 새로고침 뒤 미저장 초안 보장은 별도 검토이며 정책 재선택 대상이 아니다.
- 조합 변경 NEW·대체의 세션 전체 공식 제외와 별도 슬롯 인정·전체 과거 서버 필터/페이지 검색·독립 분류 집계와 선택 대상 실제 일별 추이를 유지한다. 현재 부족한 범위를 미정 정책이나 완료 기능으로 바꾸지 않는다.

## 1. 제품 원칙

1. 운동하는 동안 기록 입력과 화면 조작을 최소화한다.
2. **원본 루틴**, **요일별 일정**, **승인된 진행 중량**, **실제 운동 기록**, **다음 운동 기준 기록**을 구분한다.
3. 앱은 성과·증량·감량·디로딩을 **안내**하지만, 중량 또는 훈련 계획을 사용자의 승인 없이 바꾸지 않는다.
4. 운동 이력에는 성공·실패·중도 종료 여부와 무관하게 **실제 완료한 세트의 사실**을 보존한다. 자동 입력된 값은 세트를 완료하기 전까지 실적으로 보지 않는다.
5. 현재 운동은 로컬에 우선 저장하고 재진입 시 복원한다. 실제 계정의 동기화와 복원 범위는 R-08을 따른다. 운영용 백업은 별도 범위다.
6. 초기 UI는 **다크 모드 고정**, 한 번에 **한 운동 종목에 집중하는 화면(A안)**, iPhone 모바일 퍼스트를 기준으로 한다.
7. HTML 베이스라인은 밝은 무채색의 저충실도 검토 자료다. 현재 앱의 배치·문구·정보·사용 흐름을 기준으로 그리고 화면 이동, 모달, 토글 등 기본 조작에 JavaScript를 허용한다. 복잡한 움직임과 데이터 처리 규칙은 Markdown에 기록하고 실제 동작은 운영 앱 또는 검토 앱에서 확인한다. [와이어프레임 작성 기준](ui-ux.md#저충실도-와이어프레임)

### 공통 UI 검토와 적용 범위

- 공통 UI를 재사용 가능한 React 부품으로 구현하고, 독립 Preview에서 예시 데이터로 상태와 조작을 검토한다. 구현, Preview 검토, 서비스 적용은 각각의 상태로 기록한다. 현재 공통 UI는 구현 및 Preview 검토 단계까지 진행했으며 서비스 화면별 적용은 별도 작업이다. [프런트엔드 구현 현황](../engineering/frontend.md#공통-ui-컴포넌트와-독립-preview--2026-11-19)
- 삭제·버리기를 확정하는 주요 버튼에는 짙은 빨강 채움과 밝은 글자를, 옆의 취소에는 흰색 윤곽을 사용한다. 스켈레톤은 로딩 전후 카드와 행의 크기·배치를 유지한다.
- 목록은 검색 입력·분류 드롭다운·태그 칩을 묶은 **검색 태그 UI**와 **루틴 태그 선택 목록**을 제공한다. 로고를 지정한 기본형 서브페이지 헤더에는 오른쪽에 원본 비율의 OVERLOAD 이미지를 표시한다. [사용자 조작](ui-ux.md#314-공통-ui-preview)

## 2. 개발 우선순위와 범위

현행 일반 운동 API/UI 적용 범위는 [UI/UX 기능 흐름](ui-ux.md#1차-기능의-실제-동작과-연결-범위--2026-11-16)을 따른다. 아래 P0/P1의 Mock·초기 로드맵과 메모 개념은 당시 계획이며 서버 연동 미구현 현황으로 해석하지 않는다. 메모 서버 저장 목표와 현재 마운트 메모리 초안은 구분한다.

- 한 종목 집중형 기록 화면에서 기준 기록 사전 입력, 실제 반복 횟수 수정, 세트 완료·취소/수정
- 목표 반복 범위 상한에 따른 휴식시간 자동 설정, 중간 세트 완료 시 타이머 자동 시작, `휴식 종료`·`+30초`

- 모든 작업 세트가 목표 상한 달성 시 증량 고려 표시, 목표 하한 미달 시 감량 고려 안내. **자동 중량 수정 금지**
- 중량 변경의 두 용도: `오늘만 변경` / `진행 중량 변경(다음 정상 운동에도 적용)`
- 사용자·데이터 세대·표준 운동·제조사·중량 방식 조합의 최신 기구 세팅 메모를 저장·전환한다. 루틴별 분리·메모 이력·기록별 스냅샷은 만들지 않는다. 현재 서버 미연동과 후속 목표는 [최신 확정 정책](Overload_UI_Decision_Log_v0.9.md#1021--루틴-중심-중량메모대체-정책--2026-11-13-후속-확정)을 구분한다.

- 운동 종료 요약, 완료 세트 기준 운동 이력, 날짜별 상세 조회

## 4. 기능 상세

### R-01. 요일별 루틴

- 기본 내비게이션은 `홈 / 루틴 / 기록 / 설정` 순서의 아이콘 전용 캡슐형 탭바다. 하나의 Dusty Blue 선택 캡슐이 현재 탭으로 200ms `ease`로 이동한다. 활성 홈·설정은 검은색 채움, 활성 루틴·기록은 검은색 3px 윤곽선으로 표시한다. 네 버튼은 높이 46px로 균등 배치하고 좁은 화면에서 탭바 폭을 줄인다.
- 문서의 세로 스크롤 위치가 같은 방향으로 24px 증가하면 탭바를 접고, 24px 감소하면 펼친다. 새 탭 진입과 페이지 최상단에서는 펼친 상태를 기본으로 표시한다. 모달과 내부 목록의 독립 스크롤은 접기·펼치기에서 제외한다.
- 접히면 현재 탭의 46×46px 원형 버튼 하나를 하단 중앙에 표시한다. `하단 메뉴 펼치기`를 선택하면 현재 화면과 스크롤 위치를 유지하며 네 탭이 복원된다. 접힌 나머지 탭은 키보드 탐색과 접근성 트리에서 제외한다.
- 각 탭의 접근성 이름과 현재 페이지 상태를 제공한다. Tab으로 포커스를 이동하고 Enter·Space로 선택하며, 움직임 줄이기 설정에서는 캡슐이 즉시 전환된다. 하단 안전 영역과 본문 스크롤 여백을 확보하고 텍스트 입력 중 키보드가 화면을 가리면 탭바를 숨겼다가 현재 탭 위치로 복원한다.
- 기존 탭 이동·재선택·브라우저 이력과 상세 화면의 표시 정책을 유지한다. 운동 진행과 루틴 상세·편집·생성에서는 일반 탭바를 숨긴다. 공통 브랜드/설정 아이콘 헤더는 생략하며 운동 타이머 헤더와 화면별 제목을 사용한다. [하단 내비게이션 명세](ui-ux.md#공통-하단-내비게이션)
- 홈은 상태별 헤더 아래에 오늘의 루틴, 운동 시작, 오늘만 다른 루틴 선택, 이번 주 일정, 최근 운동을 이 순서로 제공한다. 오늘의 루틴은 WEIGHT와 CARDIO를 동등한 영역으로 나눈다.
- 오늘만 선택 목록은 루틴명과 배정 요일 및 저장 순서의 대표 운동 최대 2개를 두 줄로 보여 준다. 주간 일정은 날짜·요일·루틴명을 표시한다. 디로딩에서의 날짜 맞교환과 일반 홈의 당일 선택은 5절에서 구분한다.
- 표준 운동 검색·선택은 [추출 원본 아이콘 6종](assets/exercise-icons/README.md)을 재사용해 32 CSS px로 표시한다. 임의 대체·추가 매핑은 하지 않으며 중립 플레이스홀더와 표준 분류의 구분은 [UI/UX 종목 선택](ui-ux.md#34-운동-종목-선택--exercisepicker)을 따른다.
- 설정의 독립 ON/OFF는 토글로 표시하고 필요한 항목에만 도움말을 제공한다. 데이터 유실·미동기화·삭제 등 필수 안내는 확인 단계나 본문에 표시한다.
- 앱 설치·오프라인 준비는 설정 메인의 독립 접이식 카드에서 제공한다. 로그아웃은 설정 메인 마지막에 둔다. 자세한 화면과 필수 경고는 [설정 UI](ui-ux.md#설정-메인) 및 [계정 정책](auth-preview.md)을 따른다.
- 루틴 이름, 운동 종목 목록과 순서, 종목별 본세트 수, 목표 최소·최대 반복 횟수, 최초 중량을 설정한다.
- 목표는 예를 들어 `6~10회 × 3세트`, `8~12회 × 3세트` 등으로 지정한다. 최소=최대도 입력할 수 있다.
- 하나의 루틴을 여러 요일에 연결할 수 있다. 초기 정책으로 한 요일에 기본 루틴은 하나만 두며 충돌 시 사용자에게 교체 확인을 요청한다.
- 루틴 미지정 요일은 기본적으로 휴식일로 표시하되, 사용자가 임의의 루틴을 선택해 시작할 수 있다.
- 현재 선택 ID가 오늘의 기본 루틴 ID와 같으면 `요일 기본 루틴`, 다른 루틴이면 `오늘만 선택`, 선택이 없으면 `REST DAY`로 표시한다. 임시 변경 후 기본 루틴을 다시 고르면 즉시 기본 라벨로 돌아오며, 선택 이력이나 주간 일정 변경으로 판정하지 않는다. 기본 루틴이 없는 날의 수동 선택은 `오늘만 선택`이다.
- 화면 진입 시 오늘의 기본 루틴을 표시할 뿐, **운동 시작 버튼을 누르기 전에는 세션·운동 타이머를 시작하지 않는다.**
- 루틴 편집은 앞으로 시작할 세션에 반영한다. 이미 저장된 과거 세션은 변경하지 않는다.
- 저장된 루틴의 상세에서 태그·이름·실제 생성일, 웨이트 종목 수·총 본세트·유산소 종목 수, 종목별 계획과 배정된 주간 일정을 확인한다. 상세는 편집, 온라인 운동 시작, 삭제 확인 및 목록 복귀를 제공한다. 루틴 삭제는 주간 배정을 해제하며 과거 운동 기록을 보존한다.
- 생성은 이름·태그·종목이 비어 있는 초안으로 시작하며 편집은 저장값을 불러온다. 두 모드에서 웨이트와 유산소의 추가·변경·삭제·그룹 내 순서 이동 및 계획 검증을 지원한다. 서버에서 제거한 기존 종목의 복원은 편집에서 제공한다. 유산소는 필수 목표 시간과 지원 종목별 선택 목표를 입력하며 실제 수행값은 세션에서 기록한다.
- 새 종목을 추가하면 추가된 카드로 이동한다. 변경한 초안을 취소하거나 뒤로 갈 때는 폐기를 확인한다. 저장 실패 시 초안을 유지한다. 생성과 변경은 별도 요청이며 생성 성공 후 일정 배정을 선택할 수 있다.
- 같은 조합의 기존 승인 중량 변경은 저장 전에 명시적으로 확인한다. 조합이 바뀌면 새 배치와 최초 중량으로 저장하며 기존 평가와 승인을 옮기지 않는다. 수동 입력이 현행이며, 최근 유효 실제 수행의 마지막 완료 세트 중량 제안 및 기록이 없을 때 0kg 자동 입력은 후속 정책이다. 조회 실패와 기록 없음은 구분한다. 화면과 상태별 상세는 [루틴 UI/UX](ui-ux.md#33-루틴-상세편집생성)를 따른다.
- 최초 중량·승인 초안·운동 중 입력의 공통 휠/±·직접 입력은 [10.19절](Overload_UI_Decision_Log_v0.9.md#1019--공통-숫자-입력-세로-휠-피커)을 따른다. 종료 후 중량 검토의 승인 예정값 수정은 [10.23.5절](Overload_UI_Decision_Log_v0.9.md#10235-중량-검토와-명시-승인)의 PLATE/STACK 2.5kg·기타 1kg을 적용한다. 기본 승인 권고 폭 5kg·2kg과 구분하며 유효한 임의 소수를 간격에 맞춰 반올림하지 않는다. 빈/잘못된 입력은 조절하지 않고 초안 조절만으로 승인·세트 완료하지 않는다.
- 루틴 관리의 진행 중량 변경은 다음 새 세션부터 적용한다. 이미 진행 중인 세션의 승인/작업 중량, 실제 완료, 미완료 초안, 타이머는 유지한다. 운동 화면의 오늘만/진행 중량 변경은 기존 명시적 확인 흐름을 유지하고 승인 결과는 루틴 관리에서도 표시한다.
- 요일은 홈 일정과 편집 화면 모두 월→일 순으로 표시한다. 현재 API의 dayOfWeek는 월1~일7이다. 초기 데모의 일요일0 매핑을 계정 API에 사용하지 않는다.

### R-02. 운동 시작 및 워밍업

- 홈의 요일 기본 또는 오늘만 선택한 루틴에서 `운동 시작`을 누르면 온라인 START로 세션을 생성한 뒤 기기에서 보존한다. 전체 경과시간은 START의 시작 시각을 기준으로 표시한다. 이미 진행 중인 세션은 `운동 이어가기`로 연다. [홈 및 준비운동 UI](ui-ux.md#35-스트레칭워밍업--warmup)
- 웨이트가 있는 루틴의 첫 화면은 스트레칭/워밍업이다. 시간 제한이나 세트/중량/휴식 입력은 없다. 유산소만 있는 루틴은 유산소 준비 화면으로 바로 진입한다.
- `준비운동 완료`를 누르면 첫 종목의 본세트 화면으로 이동한다.
- 준비운동 화면에서 앱을 다시 열면 그 상태와 전체 경과시간을 복원한다.
- 진행 중인 세션은 홈의 운동 시작 대신 이어하기 카드로 표시한다. 전체 운동 시간/완료 세트 수를 유지하고 `준비운동 중`, `운동 중`, 유효한 `휴식 중`과 남은 시간, `종목 전환 중`과 완료 후 경과시간, `운동 종료 대기`를 구분한다. 기존 타이머 해석과 저장 시각에서 계산하며 표시 갱신을 위해 타이머를 새로 만들거나 매초 저장하지 않는다.

### R-03. 최고 수행 기준 기록(Benchmark)

- 실제 운동 이력은 모든 완료 세트의 결과를 보존하고, **다음 운동의 사전 입력값**은 `다음 운동 기준 기록`을 사용한다.
- 예: 벤치프레스 60kg, 목표 6~10회, 3본세트

| 실제 운동 | 다음 운동에 불러올 기준 기록 |
|---|---|
| 1회: `10/9/7` | `10/9/7` |
| 2회: `10/8/6` | `10/9/7` 유지 |
| 3회: `10/9/8` | `10/9/8` 갱신 |
| 4회: `10/8/6` | `10/9/8` 유지 |
| 5회: `10/10/10` | `10/10/10`, 증량 고려 안내 |

- 각 기준 기록은 **단 한 번의 실제 운동에서 모두 완료한 세트 조합**이어야 하며, 여러 날의 세트별 최고값을 섞어 만들지 않는다.
- **Task 002 비교 규칙(초기 구현 가정):** 동일 루틴 내 종목 설정·승인 진행 중량·본세트 수·목표 반복 범위에서, 모든 해당 본세트를 완료한 정상 세션만 비교한다. 반복 횟수 **총합이 기존 기준보다 커졌을 때만** 갱신한다. 동점일 때는 이전 기준을 유지한다는 초기 가정이었다. **2026-11-16 변경 확정 / 구현 확인:** 사용자가 현재 Backend의 첫 N개 총 반복 내림차순 → 종료 시각 최신순 → UUID 오름차순을 채택했다. 초기 동점 유지 정책을 대체하며 여러 운동일의 세트별 최고를 혼합하지 않는다.
- 이 비교 규칙은 예시를 만족하는 최초의 명시적 규칙이며, 특정 세트의 수행 저하를 얼마나 반영할지는 후속 사용성 검토에서 조정할 수 있다. 세트 수/목표/승인 중량이 바뀌면 비교 구간을 구분한다.
- 이미 입력된 기준 숫자를 보더라도 세트는 **미완료** 상태로 시작한다. 완료하지 않은 세트는 이력·볼륨·기준 갱신에서 제외한다.
- 비교 가능한 완료 결과가 아직 없다면 새 중량/구성에서의 반복 횟수는 사용자가 직접 지정하게 한다. **목표 하한으로 자동 초기화하지 않는다.**
- 각 본세트 반복 횟수는 중앙 직접 입력과 ±1 버튼으로 초안만 수정한다. 1 이상의 안전한 정수만 실제 완료할 수 있고 목표 상한 초과는 허용한다. 빈 값·잘못된 임시 값은 자동 치환하지 않으며 1에서 감소, 최대 안전 정수에서 증가를 막는다. 완료 및 휴식 시작은 기존 명시적 완료 조작에서만 발생한다. 과거 v1의 0회 실제 기록은 읽기·보존하되 새 완료는 허용하지 않는다.

### R-04. 더블 프로그레션 및 중량

- 예: 승인 진행 중량 60kg, 6~10회 × 3본세트. 동일 중량에서 실제 완료한 세트가 모두 `10/10/10` 이상이면 `증량 고려` 안내를 표시한다.
- 본세트 하나라도 최대 목표 미달이면 증량 안내를 띄우지 않는다. 목표 최소 횟수 미달이면 `감량 고려`를 안내할 수 있지만 의무 조치는 아니다.
- 어떤 안내도 자동으로 중량을 바꾸지 않는다.
- 증량을 승인하지 않고 보류했다면 다음 운동에서도 비교 가능한 최고 단일 세션 기준 기록으로 증량 조건을 재안내한다. 현재 루틴 배치·승인 중량·세트 수·반복 범위의 기준 기록이 모든 목표 상한을 달성했을 때만 `현재 기준 기록에서 증량 조건 달성 · 승인 NNkg · 10/10/10회`처럼 근거를 표시한다. 직전 운동이라고 단정하지 않으며 필수 선택 없이 운동을 계속할 수 있다. `지금 변경`은 기존 진행 중량 변경 확인 흐름으로 연결한다.
- 재안내는 임시/혼합 중량, 부분 완료, 임시 계획 변경 등 기존 기준 기록 비대상 결과를 새 근거로 사용하지 않는다. 서로 다른 세션의 세트별 최고값을 합치지 않는다. 승인 중량이나 비교 구성이 바뀌면 해당 구간의 기준으로 다시 판정하며 예전 기록은 보존한다. 현재 운동의 오늘만 중량을 쓰더라도 유효한 과거 승인 중량의 근거는 구분해 표시할 수 있으며 임시 중량을 자동 승인하지 않는다.
- 현재 종목을 실제로 모두 완료하고 기존 더블 프로그레션 판정이 증량 고려인 경우, 하단 고정 `다음 종목으로` 바로 위에 짧은 비차단 `증량 가능` 안내를 표시한다. 모든 종목 완료 상태에서는 `운동 종료 및 요약` 바로 위에 표시한다. 중간 세트, 목표 미달, 오늘만/혼합 중량 등 기존 판정에서 제외되는 경우에는 표시하지 않으며, 완료 취소/재수정 시 즉시 다시 판정한다. 승인 중량은 자동 변경하지 않는다.
- `오늘만 변경`: 그 세션에만 다른 중량을 적용한다. 실제 기록은 그 중량으로 보존하지만 승인 진행 중량이나 정상 기준 기록을 변경하지 않는다.
- `진행 중량 변경`: 사용자가 확인하면 승인 중량을 바꾸고 이후 정상 운동의 기준 중량으로 사용한다. 종전 중량 기록과 이력은 유지한다.
- 중량 증가 후 `6/6/6` 같은 반복 횟수 초기화는 하지 않는다. 새 중량에서 처음 수행할 횟수는 사용자가 직접 설정한다.
- 디로딩 시 적용되는 임시 중량도 승인 중량·정상 기준 기록을 덮어쓰지 않는다.

### R-05. 운동 시간·휴식 시간·종목 전환

- 전체 운동 시간은 `운동 시작`부터 종료까지 경과시간을 나타내며, 운동 진행 중 상단에 계속 표시한다.
- 오른쪽 상단 타이머 영역은 상태별로 재사용한다: `휴식 대기/없음` → `세트 사이 남은 휴식(카운트다운)` → `종목 전환 시 이전 종목 마지막 세트 완료 후 경과시간(카운트업)`.
- 운동 진행 상단은 전체 운동 시간, 현재 종목 위치와 구간 표시, 상태별 보조 타이머의 3열이다. 웨이트는 휴식 또는 전환 시간을, 유산소는 현재 종목의 활동 시간을 표시한다. 현재 종목까지의 누적 채움은 탐색 위치이며 수행 완료율과 구분한다. [운동 진행 UI](ui-ux.md#36-운동-진행--workoutframe--localworkoutflow)
- 휴식 기본값은 **목표 반복 범위의 상한**으로 고른다. 쓰기는 고정 세 구간(1~10회 180초, 11~12회 120초, 13회 이상 90초)의 시간만 한 번에 갱신하는 계약을 따른다. 현재 설정 화면은 저장 시간을 조회한다(R-10).
- 중간 본세트 완료 시 휴식 자동 시작, 하단 조작은 `휴식 종료` / `+30초`로 바뀐다. 휴식이 끝났다고 다음 본세트 완료에 별도 확인 버튼을 요구하지 않는다.
- 일반 본세트 사이 휴식은 종료 예정 시각과 현재 시각의 차이를 올림한 초로 표시한다. 하단 `다음 세트 준비`는 10~1초에 유지한다. 설정에 따라 상단 상태·하단 준비 영역을 각각 3·5·10초 전부터 깜빡이거나, 12~1초에 본문과 상단을 어둡게 한다. 두 화면 효과는 상호 배타이며 모두 끌 수 있다. 중앙 카운트다운은 10초 이하에서 노란색이다. 실제 운동의 `+30초`·`휴식 종료`는 가려지지 않으며, 연장 후 12초를 초과하거나 휴식이 종료되면 오버레이가 해제된다. 움직임 줄이기에서는 정적 강조를 사용한다.
- 현재 세션의 마지막 남은 본세트를 실제 완료하면 휴식을 시작하지 않고 현재 종목에 머물며 완료 기록과 `다음 종목으로` 버튼을 표시한다. 버튼을 누르면 현재 이후 순서의 다음 미완료 종목으로 이동하고, 앞쪽 종목만 남았으면 그쪽으로 이동한다. 이동한 종목의 세트를 자동 완료하지 않는다.
- 현행 계정의 오른쪽 시간 칸은 완료된 웨이트에서 다음 미완료 종목으로 이동하기 전에 가장 늦은 실제 세트 완료 시각부터 `이전 종목 완료`를 표시한다. 미완료 웨이트에서 유효한 휴식이 없으면 `휴식 없음`이다. 첫 세트가 중간 세트이면 해당 목표 반복 설정의 휴식을 시작한다.
- 모든 종목을 완료하면 보조 타이머 대신 `모든 종목 완료`와 `운동 종료 및 요약` CTA를 표시한다. 세션과 전체 운동 타이머를 유지하며, 사용자가 종료하기 전에는 이력 확정이나 자동 종료를 하지 않는다.
- 완료 판정은 세션에서 변경한 세트/종목 구성과 순서를 기준으로 한다. 화면 탐색·새로고침·이어하기·완료된 종목 열기는 이동이나 새 타이머를 발생시키지 않는다. 수동 탐색은 다른 종목의 휴식 시각을 보존한다.
- 완료 취소나 세트 추가로 전환 타이머의 원본 종목이 다시 미완료가 되면 해당 타이머를 해제한다. 다른 종목의 유효한 휴식은 유지한다. 이전 종목·목록으로 돌아가 기록을 확인·수정할 수 있다.
- 이전 v1 세션에 완료된 종목의 휴식이 남아 있으면 실제 완료 기록 중 가장 늦은 시각을 기준으로 경과시간을 표시한다. 화면 표시를 위해 저장된 실제 기록이나 최초 로드 데이터를 덮어쓰지 않는다. 전체 완료 세션에서는 보조 타이머를 표시하지 않는다.
- 화면이 백그라운드로 가거나 새로고침해도 타이머 계산이 이어지도록 시작 시각과 휴식 종료 예정 시각을 저장한다. 1초 간격 UI 업데이트 자체를 정답 데이터로 쓰지 않는다.

### R-06. 운동 중 변경과 메모

**현재 적용 구분(코드 확인 2026-11-16):** 조합별 최신 서버 메모 정책은 [10.21.5절](Overload_UI_Decision_Log_v0.9.md#10215-조합별-최신-기구-세팅-메모)로 확정했다. 현재 CombinationMemo는 계정/세대에 묶인 마운트 메모리 초안이며 새로고침 복원·기기 저장·서버 저장/다른 기기 조회는 미구현이다. 변경 blur/화면·조합 이동 시 온라인 저장, 실패 초안/재시도 보호, 서버 최종 반영값 우선 LWW는 [10.25.6절](Overload_UI_Decision_Log_v0.9.md#10256-최근-실제-중량과-조합-메모--정책-3-6)로 확정됐고 구현 필요다. HTTP/DTO·저장 구조와 새로고침 뒤 미저장 초안은 별도 구현 검토다. [현재 UI·계약 경계](ui-ux.md#일반-운동-현행-구현과-시연-경계--2026-11-13)


- 세트 수/종목 추가·삭제·교체·순서 변경은 **현재 세션의 복사본에만** 적용한다. 원본은 유지된다.
- 현재 종목은 단일 화면에 집중해 표시하고, 종목 목록/이전·다음 탐색으로 이동한다.
- 기본 기구 세팅 메모는 사용자·데이터 세대·표준 운동·제조사·중량 방식 조합의 최신 값으로 저장한다. 조합 선택 시 전환하고 수정·삭제할 수 있다. 빈 메모와 조회 실패를 구분하고 최신 초안을 보호한다. 메모 이력·세션별 스냅샷은 만들지 않고 루틴 승인값·버전도 바꾸지 않는다.
- 운동 도중 종목을 바꾸거나 앱을 닫아도 입력·완료 세트는 남아 있어야 한다.

### R-07. 운동 이력 및 완료

**현행 표시.** 종료 직후 `운동 기록 요약`은 과거 상세의 헤더·요약 카드·수행 목록 표현을 공유한다. 기존 조건부 중량 검토와 기록 보존 안내를 표시하고 홈으로 복귀한다. 전체 과거 검색·독립 집계·현재 조정 검토는 [1차 개발 확인 범위](#1차-개발의-확인-범위--2026-11-16)를 함께 적용한다. [운동 완료 요약 UI](ui-ux.md#39-운동-완료-요약--workoutsummary)


- 완료 결과와 과거 상세는 한 기록 영역 안에 WEIGHT/CARDIO를 나누고, 웨이트 종목별 완료 세트 수·총 수행 볼륨과 각 세트의 수행 볼륨을 표시한다. 미완료 세트는 실적에서 제외한다. 당시 장비와 유산소 실제 시간·거리 출처를 보존한다.
- 기록 분석은 `운동 현황 / 성장 추적 / 주간 근육 계획 / 주간 근육 통계`의 2×2다. 계획은 선택 프리셋의 현재 월~일 반복 계획, 근육 통계는 이번 주 월~일 실제/당시 계획 고정이다. 계획에는 날짜 UI가 없고 근육 통계의 기간 이동·월간·달력은 제거한다. 기존 집계·전체 보기·기여·권장 표시 규칙은 유지한다.
- 운동 현황의 주간/월간·이전/다음·달력은 요약·추이·달성·유산소에 공유한다. 기존 분리 탭 대신 공통 검색 목록과 전체/운동별/분류별/근육별 범위를 사용한다. 후보 검색과 선택 항목 통계 조회를 분리하고 기간·세트/총중량을 함께 적용한다.
- 기록 메인은 오늘 포함 최근 7일 유효 완료 세션을 최신순 개별 카드로 표시한다. 이번 주나 최근 3건과 다르며 같은 날짜 여러 기록·빈 상태·전체 보기를 유지한다.
- 전체 운동 이력은 현재 월 기본의 월간 피드다. 월 이동·달력을 유지하며 루틴별/운동별 이름 검색의 요구 범위는 전체 과거 기간이며 현행은 로드된 페이지의 루틴명만 검색한다. 실제 운동명 검색은 미연결이고 해제 시 이전 선택 월로 복귀한다. 기록 있는 월~일 주의 첫 카드 위에만 얇은 주차 제목·실제 날짜 범위를 표시하고 빈 주/큰 컨테이너/접기는 만들지 않는다. 선택 월 바깥 기록은 더하지 않는다. 상세에서는 기존 실제 중량·반복·일시 변경과 당시 문맥을 확인한다.
- 홈·운동 현황 날짜 표시는 ✓ 전체 완료 우선, 미완료일의 △/×, 확인된 휴식 –을 공통 판정한다. 웨이트 세트 비율과 전체 종목 인정 비율이 각각 50% 이상이고 웨이트 인정 최소치는 min(2, 원계획 세트 수)다. 유산소는 실제 거리 미입력이면 시간50%만, 실제 거리가 있으면 존재하는 최초 시간/거리 목표 각각50%(둘 다 있으면 AND)를 비교한다. 혼합은 전체 종목에 두 종류를 포함하고 웨이트 비율은 웨이트만 계산한다. 유산소 전용에는 세트 조건을 적용하지 않는다. 정확히 50%를 포함하고 추가분으로 부풀리지 않는다. 미래·대기·확인 불가는 중립/미확정이며 공식 완료율·유효 운동일·G4·중량 평가와 분리한다. 상세 경계와 확인 필요는 10.24.4절을 따른다.
- 진행 중 미완료 종목이 있는 상태에서 `종료`를 누르면 확인 후 완료한 수행과 실제 종료 시각을 보존한다. 종료를 취소하면 운동을 이어갈 수 있다. 모든 종목의 처리가 끝난 경우 `운동 종료 및 요약`으로 종료를 요청한다. 기기 종료 의도와 서버 FINISH 확인은 구분한다.
- 기록의 일부만 수행했더라도 원본 루틴의 목표 세트 수는 다음 운동에 남아 있어야 한다.
- 수행 볼륨은 완료 세트의 실제 중량 × 실제 반복 횟수다. BODYWEIGHT는 [명시적으로 기록된 추가 중량](../../../overload-server/docs/api/bodyweight-additional-load.md)만 사용한다. 근거가 없는 세트는 볼륨 미확인으로 구분한다. 유산소 활동 시간과 종류별 거리는 별도로 표시한다.
- 종료 요약은 실제 완료 세트 수와 저장 확인 상태를 표시한다. `전체 루틴 완료`는 현재 구현의 조건을 사용하며 아래의 정책 3-1 전환 과제가 남아 있다.
- V36 FINISH에서 봉인한 권고 중 유효한 증량·감량 후보는 종료 직후 요약에서 예정값 수정과 명시적 전체/선택 승인을 할 수 있다. 현재 루틴 배치와 승인 중량 일치, 편집 권한 및 서버 버전의 기존 검사를 적용한다. 과거 상세에서는 봉인 근거와 승인 사건을 조회하며 실적 정정·삭제·복구는 별도 기능이다. 미완료 감량 권고는 공식 평가·Benchmark 자격과 독립이다. [종료 후 명시 승인 계약](../../../overload-server/docs/api/workout-sessions.md#종료-후-중량-검토와-명시-승인--v36)
- 기록 목록은 세션 탐색을 유지하면서, 적용 가능한 경우 `현재 중량 조정 검토`와 `진행 중량 변경 내역`을 제공한다. 현재 검토는 현 배치/승인 중량/구성의 기준 기록과 최근 비교 가능한 완료 기록을 구분해 보여준다. 최고 기준의 증량 근거와 최근 약한 수행의 감량 검토가 공존할 수 있으며 하나가 다른 사실을 덮어쓰지 않는다. 홈에서도 현재 선택 루틴에 한해 같은 파생 검토를 재사용한다.
- 실제 승인 변경은 당시 루틴/종목 이름, 배치 ID, 변경 전/후 중량, 발생 시각, 루틴/운동 화면의 출처를 별도 사건으로 보존한다. 양수는 `증량 완료 +Nkg`, 음수는 `감량 완료 −Nkg`다. 루틴 이름 변경/삭제 후에도 사건의 이름은 유지한다. 명시적 연결 없는 루틴 편집 사건을 특정 세션의 결정이었다고 추정하지 않는다.
- 실제 기록 목록/상세의 공통 recordSummary는 InitialPlan 세트 수를 분모로 쓴다. 종료 직후 summaryData는 AppliedPlan 우선·없으면 실제 세트 수이며 전체 완료 조건도 기록 상세와 다르다. [계산 차이](ui-ux.md#시간수행-합계의-의미)는 정책 3-1에 따라 통일할 구현 필요 사항이며 모든 요약이 같은 판정이라고 완료 처리하지 않는다.

#### 완료 기록 정정·논리 삭제·누락 복구

- 사용자는 과거 완료 운동 기록을 명시적으로 수정하거나 삭제할 수 있다. 수정 전 정보와 변경 사실을 이력으로 관리한다. 삭제 사실도 이력과 재동기화 차단에 필요한 범위에서 관리한다. 보존 범위/기간과 구체적인 변경 모델은 Task 006에서 설계한다.
- 수정·삭제 후 **현재 유효한 기록**을 기준으로 기준 기록과 현재 점진적 과부하 평가를 재계산한다. 삭제되거나 수정으로 더 이상 유효하지 않은 과거 버전을 현재 평가의 유효 수행으로 사용하지 않는다.
- 기존 비교 조건(루틴/배치/구성/승인 중량/예정 세트 및 반복 범위), 비교 가능한 한 세션의 실제 수행만 사용한다는 원칙, 부분·임시·혼합 기록의 제외 기준은 유지한다. 여러 세션의 최고 세트를 조합하거나 유산소를 웨이트 평가에 섞지 않는다.
- 재계산은 **승인된 진행 중량을 자동 변경하지 않는다.** 과거 중량 승인 이벤트를 임의로 삭제·수정하거나 새 승인으로 꾸미지 않는다. 근거 세션이 수정/삭제되더라도 당시 사용자가 승인한 사건과 현재 재평가 결과는 별개다.
- 수정 전 당시 수행 정보·판단과 수정 후 현재 판단을 구별한다. 과거의 판단을 새 결과로 조용히 대체하지 않는다. 판정 버전/근거 보존 및 재구성이 불가능한 과거 데이터의 표현 방식은 Task 006에서 설계한다.
- 삭제된 기록이 과거 기기의 재전송으로 되살아나지 않아야 한다. 같은 기록의 중복 생성과 동시 수정도 10절의 버전/충돌 정책을 따른다.
- 실제 계정은 [세션 API](../../../overload-server/docs/api/workout-sessions.md)의 종료 후 정정·논리 삭제·누락 수행 선택 복구를 사용한다. 복구는 같은 세션의 로컬 완료 원본과 서버 기록을 대조하며, 전체 삭제한 세션은 사용자 복원 대상에서 제외한다. 최초 계획·봉인 평가·이미 확정된 승인 사건과 현재 유효 수행·재평가를 구분한다.

### R-08. 저장·복원·오프라인(단계적)

- Task 002에서는 서버와 독립적으로 운동 입력을 로컬에 저장하고, 새로고침/재진입 후 진행 상태를 복원한다.
- v1의 선택 필드 `progressChanges`가 없는 구 저장값은 빈 변경 내역으로 해석하되 최초 로드에서 다시 쓰거나 과거 사건을 추정하지 않는다. 승인 변경과 사건은 한 저장 성공에서만 반영한다. 동일 값/오늘만/취소/초안/검증 오류에는 사건을 생성하지 않는다.
- 승인 저장이 실패하면 승인 중량/사건을 반영하지 않고 입력 초안을 유지한다. `저장소 재확인`은 저장소 상태만 확인하며 거부된 승인을 자동 적용하지 않는다. 복구 후 사용자가 다시 승인/루틴 저장해야 한다. 일반 반복 횟수 등의 쓰기 실패는 기존 메모리 입력 보존과 다시 저장 경로를 유지한다. 다중 탭 충돌 차단을 우회하지 않는다.
- 실제 계정의 진행 운동은 IndexedDB에 먼저 보존하고 서버 ACK와 구분한다. 온라인에서 이미 시작한 운동은 오프라인에서 명시적으로 이어갈 수 있다. 재연결·재인증 시 기존 세션의 권한과 버전을 확인한 뒤 고정 요청을 처리한다. [로컬 보호 및 복원](../engineering/frontend.md#12-진행-운동의-로컬-보호-및-복원)을 따른다.
- 로컬 저장만으로 데이터가 영구 백업되었다고 표시하지 않는다.

### R-09. 로그인된 기기 관리

- **화면 구현 완료.** 설정의 `내 계정 → 로그인된 기기 관리`로 진입한다. 운영에서는 기기 조회 미지원을 표시한다. [화면과 조작](ui-ux.md#로그인된-기기-관리)
- **연동 요구사항.** 고유 기기 수와 세션 수를 구분한다. 서버 근거로 현재 기기, 온라인 여부, 로그인 일시와 마지막 접속을 확인한다. 접속 상태와 운동 편집 권한은 독립적이다. 로그인 기기와 실제 편집 기기를 매칭할 수 있을 때만 기기별 운동 상태를 표시한다.
- **원격 종료 요구사항.** 개별 다른 기기, 현재 기기를 제외한 모든 기기, 현재 기기를 포함한 전체 기기의 종료 범위를 각각 확인한다. 서버가 종료를 확인한 뒤 목록을 갱신해야 한다. 현행 API는 현재 브라우저 로그아웃을 지원하며 운영의 원격 작업은 비활성이다.
- **정책 미확정.** 운동 중인 기기를 원격 종료할 때의 기록 보존, 운동 중단, 편집 권한 해제, 다른 기기에서의 재개는 후속 정책이다. [서버 연동 범위](../engineering/backend-ui-v0.9.md#로그인된-기기-관리-연동-경계)

### R-10. 설정 및 계정 관리

- 설정 메인은 제목 없이 `내 계정` 요약 → 운동 메뉴 → 데이터 메뉴 → 접이식 PWA 안내 → 위험 작업 → 현재 브라우저 `로그아웃` 순으로 제공한다. 요약에 이메일이 들어오면 첫 글자를 대문자 이니셜로 쓴다. 운영에서 이메일·현재 로그인 방식·기기 수를 확인할 수 없으면 미확인으로 표시한다.
- 운동 메뉴에서 두 휴식 설정과 표준 운동 열람을 사용할 수 있다. 디로딩 설정, 데이터 상태·내보내기, 초기화·탈퇴는 운영에서 비활성이다. 앱 설치 안내와 오프라인 이어가기는 [기존 지원 범위](../engineering/frontend.md#12-진행-운동의-로컬-보호-및-복원)를 따른다.
- **세트 사이 휴식.** 목표 반복 횟수 상한 기준 1~10회·11~12회·13회 이상에서 휴식 초만 조회·수정한다. 편집 화면의 `시작 세트`·`끝 세트`는 표시 문구다. 경계값과 구간 추가·삭제는 고정이다. 계정의 서버 설정에 양의 정수 초 세 값을 저장하며 성공 응답 뒤 반영한다. 취소 시 저장 요청이 없고, 실패 시 초안을 보존한다. 쓰기 충돌 시 최신값을 다시 조회한 뒤 명시적으로 재시도한다.
- **휴식 타이머 알림.** 화면 방식·위치·시점, 효과음·볼륨, 중간 알림음·시점을 계정별로 현재 브라우저에 저장한다. 화면 설정과 소리는 별도로 조작하며, 효과음 OFF는 중간 알림도 끈다. 운동 중 5~1초에 종료 효과음을 사용하고, 활성화된 중간 알림은 20·30·60초 중 선택한 시점에 같은 소리를 3회 재생한다. 전체 미리보기에는 화면 효과와 종료 카운트 효과음이 포함된다. 개별 미리듣기는 일반 1회·중간 3회이며 `Ⅱ`로 재생과 예약음을 중지한다. ON/OFF는 아이콘과 토글로 표현한다. 서버 저장·기기 간 동기화는 미지원이다. [두 휴식 설정의 화면 규칙](ui-ux.md#세트-사이-휴식)
- 계정 상세에서 이메일 6자리 OTP와 Google 연결을 관리한다. 마지막 수단의 해제는 화면에서 막고 서버가 남은 수단의 실제 가용성과 재인증을 최종 검사한다. 대표 이메일은 서버의 마스킹된 조회값을 표시하며 재인증은 기존 OTP 절차를 따른다.
- 최근 재인증 표시는 현재 화면에서 확인된 OTP 결과에 한정한다. 서버 이력 조회는 미지원이다. `계정 정보 새로 확인`은 세션 소유권을 확인하고 연결 수단·대표 이메일을 다시 읽는다. 기기 관리 진입과 원격 작업의 범위는 R-09를 따른다. [설정 화면](ui-ux.md#설정-메인)

## 5. 디로딩과 기록·분석

### 디로딩과 훈련 사이클

G4·G5 Backend를 구현했다. G6 실제 PWA 연동과 기존 DB V25~V29 적용은 별도다.

- [디로딩 v1.7](Overload_Deloading_Design_Specification_v1.7.md)의 DL-15/80~84를 적용한다. 오늘을 뺀 직전7개 달력 날짜의 실제 일반 운동 수행, 이전 디로딩을 완료했다면 그 이후의 신규 일반 수행, 오늘 실제 수행 없음, 활성 일반 세션 없음이 필요하다. 미동기화 수행도 보호하며, 분석 OFF 또는 게이지 0% 자체는 시작 차단 사유가 아니다.
- 분석 ON은 각 실제 일반 세션의 InitialPlan을 평가하고 날짜별 최고 단일 값과 확정MISS의 서로 다른 날짜로 E/N을 계산한다. E≤1 RESET, E>1 min(1,E/N) ADD이며 다음 월요일04시 이후 필요한 일별 평가가 끝나야 확정하고 주중에는 가산하지 않는다. 일반 ST-17~23의 계획 분모와 디로딩 후보는 구분한다. 추천 게이지의 0~4.0주 포함 경계와 이후 경고색 표시는 [결정 로그](Overload_UI_Decision_Log_v0.9.md) 10.11.4절 및 [Visual Theme Spec 3절](Overload_UI_Visual_Theme_Spec_v0.9.md#3-상태색과-게이지)을 따른다. OFF는 계산·게이지·추천 알림을 멈추며 재활성화하면 소급 없이 0부터 시작한다. 진행 중에는 누적을 정지하고, 완료 시 초기화하며 무수행 취소 시 기존 누적값을 보존한다. 세부 분모·초기화 기준은 DL-05~14를 따른다. 신규 계정은 **기본 ON·누적0의 초기 epoch**로 시작한다(2026-11-07 추가 확정). 최초 ON은 OFF→ON 전환이 아니다. OFF→ON은 새 epoch·누적0이며 OFF/활성화 전 기록을 소급 가산하지 않는다. 기존 미설정 계정은 G4의 명시적 이행 경계를 검증한다. HTML의 초기 ON·5.2주는 배치를 설명하는 정적 예시다. 이미 ACTIVE인 디로딩 기간의 중복 생성은 별도 상태 제약이며 운동 자격을5개로 늘리지 않는다.
- 사용자가 고른 방식과 요일에 따라 저장된 원본에서 독립된 임시 루틴을 생성한다. 유지형, 가능한 압축형 또는 완전 휴식을 제공한다. 웨이트·유산소 감량과 분할 정책은 [디로딩 v1.7](Overload_Deloading_Design_Specification_v1.7.md)의 4~8절, 서버의 편성·미리보기는 [기간 API](../../../overload-server/docs/api/deload-periods.md#자동-편성-경계)를 따른다. 미리보기에서 원본과 감량 목표를 비교하고 시작 버튼에서 자격을 재검사한다. 원본 루틴과 승인 중량을 보호한다.
- 시작일 포함 권장 7일이며 8~10일차 최초 진입에 한 번 안내한다. 10일차 종료에 자동 완료 대상이 된다. 무수행 조기 완료와 조건부 취소·방식 변경, ACTIVE 운동 보호, 실제 종료와 일반 운동 복귀 시점은 [디로딩 v1.7의 종료 정책](Overload_Deloading_Design_Specification_v1.7.md#3-디로딩-시작취소완료자동-종료)과 [기간 API](../../../overload-server/docs/api/deload-periods.md#완료취소자동-종료--g5-3)를 따른다.
- 일반 보기는 홈에서 전환하는 읽기 전용 조회 모드다. 원본 루틴과 일반 과거 기록의 수정·삭제 및 일반 운동 실행은 제한된다. 임시 루틴의 미수행 일정은 수정할 수 있고, 디로딩에서 오늘만 다른 임시 루틴 선택은 미수행 날짜 맞교환이다. 완전 휴식이나 미수행 임시 루틴 전체 삭제 뒤에도 회복 기간을 유지한다.
- 실제 디로딩 수행과 당시 계획은 운동 이력·근육 통계에 포함한다. 기간 이력은 운동 0건이어도 정상 완료 시 남긴다. 디로딩 실적은 일반 중량 증량·유지·감량 평가, 승인 중량 및 공식 성장선에서 제외한다.

### 운동 현황·근육 통계·성장 추적

- 기간·대상·단위를 바꾸면 운동 현황의 범위를 일관되게 적용한다. 네 수준(전면/후면·PPL·부위·세부 근육)은 원본 계획/실제 세트에서 독립 계산한다. 세부 근육에만 PRIMARY 1.0 / SECONDARY 0.5를 적용하며 참여·물리적 전체 정수와 기여 소수를 구별한다. 복수 PRIMARY를 유지하고 하위 합으로 상위를 만들지 않는다. 기존 PRIMARY 기본·SECONDARY 펼침은 종전 UI 기록이며 새 디자인은 후속으로 정한다.
- 조회·선택한 활성/비활성 프리셋의 월~일 현재 계획을 분석하며 같은 루틴의 반복 요일은 각각 포함한다. 프리셋에는 운동·중량을 복제하지 않는다. 실제 수행·과거 적용 이력·디로딩 임시 계획과 별개이며 분류 누락은 임의 생성하지 않는다. 현행은 선택 프리셋 분석과 전면/후면·PPL·세부 근육 계획 기여 일부를 구현했다. 부위 계획·네 수준 전체 독립 집계·전체 근육/권장 범위는 미완성이며 [통계 API의 실제 구현 경계](../../../overload-server/docs/api/statistics.md)를 따른다.
- 성장 추적은 과거 수행 종목도 검색할 수 있고, 배치별 실제 승인 사건을 근거로 표시한다. 계획·실제·승인과 자료 미확인을 구별한다. [통계 제품 기준 v1.4](../../../overload-server/docs/product/Overload_Statistics_and_Tracking_Design_Specification_v1.4.md)과 [성장 조회](../../../overload-server/docs/api/approved-weight-growth.md)를 따른다.

## 6. 대표 수용 테스트

1. `10/9/7` 이후 `10/8/6`을 수행해도 다음 세션 기준 기록은 `10/9/7`이다.
2. 이어 `10/9/8`을 수행하면 다음 세션 기준 기록은 `10/9/8`로 갱신된다.
3. 저조한 실제 기록도 이력에서 조회된다. 여러 운동일의 최고 세트를 임의로 조합하지 않는다.
4. 동일 승인 중량으로 6~10회 × 3본세트를 모두 10회 수행하면 증량을 안내하되 중량은 자동 변경되지 않는다.
5. 사용자가 진행 중량을 62.5kg으로 승인해도 반복 횟수를 6/6/6으로 자동 초기화하지 않는다.
6. `오늘만 변경` 75kg 세션이 끝나도 승인 중량 80kg은 다음에 유지된다.
7. 시작 즉시 운동 시간이 측정되고 준비운동 화면에서는 워밍업 세트 입력이 없다.
8. 중간 본세트 완료 시 휴식이 자동 시작되며 `+30초`와 `휴식 종료`가 동작한다.
9. 마지막 남은 세트 완료 시 현재 종목에서 **마지막 실제 세트 완료 시각**부터 경과시간과 `다음 종목으로`를 표시한다. 버튼 이동 후에도 같은 경과시간 기준을 유지한다. 전체 완료 시에는 사용자가 `운동 종료 및 요약`을 누를 때까지 기록 검토 상태를 유지한다.
10. 루틴의 종목을 운동 중 임시로 변경해도 다음에 같은 루틴을 시작하면 원래 종목 구성으로 복원된다.
11. 새로고침 시 워밍업/완료 세트/미완료 입력/타이머 상태가 복원된다.
12. 운동 종료 시 완료 세트만 이력·볼륨에 포함되며 미완료는 자동 완료되지 않는다.
13. 요일별 기본 루틴은 홈에 표시되지만 `운동 시작`을 누르지 않는 한 세션을 생성하지 않는다.
14. 기존 Full-Stack Health Check 기능 및 테스트가 훼손되지 않는다.

## 8. Task 005 — 유산소 V1

**현행 계정 화면과 저장.** 운동 중 유산소는 준비·측정·일시정지·완료 확인·기록 확정을 구분한다. 완료 확인에서는 연필 버튼으로 시간 정정 휠을 열고, 자동 기록 원본과 적용한 정정값을 보존한다. 거리·평균 속도·심박은 선택 항목이다. 거리·속도는 지원 종목에 한해 입력할 수 있으며 실제 경사도는 저장 미지원으로 표시한다. 직접 입력 거리가 우선이고 빈 거리는 입력한 평균 속도와 유효 활동 시간으로 계산한다. 실제 평균 속도는 거리에서 역산하지 않는다. [유산소 화면별 동작](ui-ux.md#유산소-진행과-완료-기록) · [실제 측정 API](../../../overload-server/docs/api/cardio-actual-measurements.md)

아래는 초기 Task 005 개발 데모의 구현 이력이다. 당시 체크박스·저장 키·입력 범위 및 종료 문구는 현행 계정 UI나 API 계약으로 사용하지 않는다.

- 하나의 루틴/세션에 웨이트와 유산소를 함께 기록한다. 웨이트 목록 뒤에 별도 유산소 목록을 순서대로 배치한다. 유산소끼리 추가·편집·제거·순서 변경이 가능하고, 유산소만 있는 루틴도 요일 기본/오늘만 선택으로 시작한다.
- 러닝머신·실내 자전거·야외 러닝·계단 운동·자유 이름의 기타 유산소를 제공한다. 계획에는 필수 목표 시간, 선택 목표 거리·속도 또는 페이스 한 모드, 러닝머신 경사도 또는 자전거 저항을 기록한다. 거리/강도는 러닝머신·자전거·야외 러닝에서만 입력한다. 시간은 분(소수 허용)을 초로 반올림하여 저장한다.
- 입력 방어 범위: 목표 시간 1–86400초, 거리 0.001–1000km, 속도 0.1–100km/h, 페이스 0.1–120분/km, 경사 0–50%, 저항 1–100. 실제 평균 BPM은 정수 20–300, 정정 시간은 정수 1–86400초다. 이는 V1의 유한값 입력 제한이며 운동 처방이 아니다. 미입력은 `null`이며 0 실적으로 대체하지 않는다.
- 운동 중 상단에 상시 유산소 추가 버튼을 두지 않는다. 세션 편집 메뉴에서 오늘만 추가하거나, 웨이트 완료 후 하단 종료 영역에서 추가한다. 원본 루틴은 바꾸지 않는다. 추가하지 않고 웨이트를 종료할 때 유산소 권유 모달을 띄우지 않는다.
- 유산소 준비 화면은 자동 측정하지 않는다. `유산소 시작` 후 별도 활동 시간을 측정하고 일시정지/재개를 지원한다. `누적 활동 ms + 실행 구간 시작 시각과 현재 시각의 차이`를 사용한다. 일시정지·확인 화면은 시간을 늘리지 않으며 목표 초과로 자동 완료하지 않는다. 전체 세션 시간은 계속 흐른다.
- `유산소 완료`는 타이머를 멈추고 확인 단계로 간다. 실제 시간은 자동 입력하고 실제 거리와 수동 평균 BPM만 선택 입력한다. 특별한 사유의 시간 정정은 체크박스로 열고, 자동 시간·정정 시간을 모두 보존한다. 확인 취소 시 일시정지로 돌아가고 입력 초안을 유지한다. 확정 후 중복 완료는 무시한다.
- 미완료 상태에서 전체 종료하면 `기록하고 완료`(미시작은 준비 화면)와 `미완료 유산소 건너뛰고 종료`를 구분한다. 건너뛴 종목에는 실제 결과를 만들지 않는다. 시작 여부로 미시작/수행 중 미완료를 구분한다. 다른 미완료 종목이 있으면 다음 종목 버튼을 제공하고 최종 종료는 사용자가 직접 실행한다.
- 이력/홈은 웨이트 세트와 유산소 완료 종목 수를 따로 표시한다. 전체 완료 표시는 두 계획을 모두 완료한 경우에만 사용한다. 웨이트 볼륨·단일 완료 세션 기준 기록·증량/감량 판정은 웨이트만 사용한다. 유산소를 건너뛰어도 완전히 수행한 웨이트의 기존 자격을 바꾸지 않는다. 유산소만 수행한 세션은 웨이트 기준 기록을 만들지 않는다.
- `overload.core.v1`와 `version: 1`을 유지한다. 구 데이터의 없는 `cardio`는 읽을 때 빈 목록으로 해석하며 로드 자체는 원문을 변경하거나 다시 저장하지 않는다. 새 필드가 있으면 종류·범위·상태·시각·결과·식별자를 검증한다. 손상 데이터는 편집 차단으로 보호한다. 기존 저장 실패 안내/재시도/다른 탭 충돌 차단을 그대로 사용한다.
- 식별자: 루틴 유산소 계획 배치 `CardioPlan.id`와 세션 실제 활동 `CardioActivity.id`는 별개다. 세션에는 당시 계획을 복사하고, 결과에는 활동 ms·자동 타이머 ms·정정 여부·선택 실제 거리/BPM·완료 시각을 담는다. 후속 서버 설계의 참고 모델이며 API/DB 계약을 확정한 것은 아니다.
- 로그인·계정 이전·API/PostgreSQL·서버 동기화·Service Worker·오프라인 재실행·GPS/웨어러블/Health·칼로리·차트·디로딩·드랍/슈퍼세트는 이번 범위에 포함하지 않는다. 실제 iPhone Safari 잠금/백그라운드·키보드·설치 검증은 별도로 필요하다.

## 9. Task 005.5 — 개발 전용 인증 UX 목업

`/auth-preview`에서 계정/인증/동기화/데이터 관리 흐름을 가상 데이터로 시연한다. 목업은 사용자 1차 검토를 통과했다. 실제 앱 진입과 운동 기능은 유지한다. [인증·계정 확정 정책/잠정 세션 기간/프리뷰 사용법](auth-preview.md)을 기준으로 하고, [Task 006 인계](../handoff/Overload-Task006-Design-Handoff.md)에서 후속 설계를 시작한다. 실제 인증·동기화·데이터 삭제·기존 데이터 이전은 미구현이며 production 빌드에 프리뷰를 포함하지 않는다.

## 10. Task 005.5 — 저장·동기화·다중 기기 확정 정책

아래는 당시 합의와 후속 과제의 기록이다. 실제 계정의 전송 단위·재시도·권한 이전·종료 후 복구는 [Task 009 v1.0](../../../overload-server/docs/tasks/task-009-redesign-v1.0.md) 및 [로컬 보호 및 복원](../engineering/frontend.md#12-진행-운동의-로컬-보호-및-복원)을 따른다.

### 10.1 로컬 우선 저장과 동기화

- Task 001–005의 로컬 저장·복원 동작을 보호한다. 중요한 상태 변경을 로컬에 저장한 후 서버와 동기화한다. 로컬 쓰기 실패와 서버 전송 실패를 구별하고, 실패한 값을 저장 완료로 표시하지 않는다.
- 세트 완료, 중량 승인과 승인 이벤트, 유산소 시작/일시정지/재개/완료 등의 상태 전환을 주요 동기화 대상으로 검토한다. 전송 단위·빈도·순서는 Task 006에서 설계한다. **유산소 타이머를 매초 서버에 전송하지 않는다.**
- 승인 중량과 승인 이벤트의 일관된 저장, 일반 입력 실패 시 메모리 초안 보존, 손상 저장소와 다중 탭 충돌 차단 등 현재 보호 동작을 유지한다.
- 운동 완료, 로컬 저장 완료, 서버 저장 완료를 구별한다. 미동기화 기록은 서버 저장 확인 전까지 보호하고 전송 실패·인증 만료만으로 삭제하지 않는다.
- 동일 기록의 재전송·응답 유실 후 재시도는 중복 기록을 만들지 않아야 한다. 사용자 소유권·변경 버전·삭제 및 전체 초기화 경계를 검증한 **충돌 없는 변경은 자동 동기화**한다.
- 로그아웃과 계정 전환 후에는 이전 계정의 로컬 기록·메모리·전송 대기열에 다른 계정이 접근하거나 전송할 수 없어야 한다. 로그인/복구와 세션 UX는 [계정 정책](auth-preview.md)을 따른다.
- 브라우저 저장소를 영구 백업으로 간주하지 않는다. 현재 계정의 저장·재시도 계약은 R-08을 따르며 실기기 검증은 별도다.

### 10.2 진행 중 운동의 수정 제어권

- **하나의 진행 중 운동 세션은 한 기기에서만 수정**한다. 다른 기기에서는 같은 사용자의 해당 세션을 조회할 수 있다. 조회 가능은 다른 사용자의 데이터 접근 허용을 뜻하지 않는다.
- 수정 제어권 이전은 사용자의 명시적 요청으로 수행한다. 앱 실행·조회·연결 복원만으로 제어권을 자동 이동하지 않는다.
- 정상 이전은 현재 수정 기기의 최신 기록을 동기화한 뒤 진행한다. 최신 상태 동기화에 실패하면 정상 이전이 완료됐다고 표시하지 않는다.
- 기존 기기를 사용할 수 없으면 **서버의 마지막 저장 상태와 미전송 정보가 빠져 있을 수 있음을 안내**하고 강제 이전할 수 있다. 강제 이전으로 서버가 받지 못한 기록까지 복원됐다고 표시하지 않는다.
- 이전 기기의 오래된 제어권과 미동기화 기록이 새 제어 기기의 최신 상태를 덮어쓰지 못하도록 한다. 이전 기기가 다시 연결되면 기록은 필요에 따라 충돌 비교/복구 대상으로 다루고 자동 재전송으로 최신 상태를 대체하지 않는다.
- 제어권 식별·검증·회수, 동시 이전 요청, 오프라인/잠금/연결 끊김, 같은 기기의 여러 탭 관계 등 기술 계약은 Task 006에서 정한다. 이 제품 규칙의 대상은 진행 중 세션이며, 완료 기록의 동시 수정에도 별도의 버전/충돌 검증이 필요하다.

### 10.3 충돌 비교와 선택적 복구

- 같은 데이터를 서로 다르게 수정했다면 자동 덮어쓰지 않는다. 단순히 클라이언트 시각이 더 최신이라는 이유로 한쪽을 채택하지 않는다.
- 서버 기록과 로컬 기록의 **차이점만 표시**한다. 사용자가 누락·변경된 수행 정보를 선택적으로 복구하고 최종적으로 **하나의 유효한 운동 세션**으로 통합한다.
- 이 복구는 동일 계정·동일 세션의 변경을 정리하는 흐름이다. 독립된 두 사용자 계정의 운동 데이터 병합을 허용하는 정책이 아니다.
- 충돌 원본은 복구 검증에 필요한 범위에서 보존하고 복구가 확인되기 전에는 정상 동기화 완료로 표시하지 않는다. 충돌 원본을 별도의 완료 운동 실적으로 중복 집계하지 않는다.
- 원본 보존 범위/기간, 차이 비교 단위, 선택 복구의 검증, 복구 도중 재충돌·취소·실패의 처리는 Task 006 설계 대상이다.

### 10.4 삭제·전체 초기화와 실사용 전환

- 개별 완료 기록 삭제 후 오래된 기기의 재전송으로 해당 기록이 다시 생성되지 않도록 한다. 전체 운동 데이터 초기화 이후에도 과거 기기의 미동기화 기록이 되살아나면 안 된다.
- 전체 초기화는 계정을 유지하고 루틴·완료 운동/유산소 이력·진행 중 운동·중량 승인 이벤트 및 관련 운동 기준을 삭제 대상으로 한다. 삭제 전 내보내기 안내, 본인 재인증, 최종 확인이 필요하다. 일반적인 새 루틴 생성과 구별한다.
- 일반 완료 기록 수정/삭제에서 승인 이벤트를 보존하는 원칙과, 사용자가 명시적으로 **전체 운동 데이터 초기화**를 요청해 승인 이벤트도 삭제 대상으로 포함하는 흐름은 범위가 다르다.
- 계정 유지 초기화와 회원 탈퇴의 구별 및 세부 보존/파기 결정 사항은 [계정 정책](auth-preview.md)을 따른다. 삭제·초기화·탈퇴의 서버 검증과 오래된 요청 차단 방식은 Task 006에서 설계한다.
- 기존 데이터는 배포 전 개발용 테스트 데이터이므로 사용자 계정으로 이전할 필요가 없다. 실제 폐기와 실사용 전환 기준은 설계 대상으로 분류하되 **이번 작업에서는 로컬 데이터를 삭제·마이그레이션하지 않는다.** 향후 실사용 데이터는 유실·중복·계정 간 노출을 방지한다.
