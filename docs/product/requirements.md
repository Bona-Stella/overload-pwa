# Overload — 제품 요구사항 v1.0

- 작성일: 2026-10-26
- 상태: **핵심 제품 방향과 초기 UI/UX 합의** / 세부 알고리즘 및 운영 정책 일부 추후 확정
- 대상: iPhone 홈 화면 설치를 목표로 하는 모바일 퍼스트 웨이트 트레이닝 PWA
- 구현 관련 주의: 본 문서는 **제품의 기준**이며 Git 저장소·코드의 현재 상태를 검증한 문서가 아니다. 구현 전 Codex가 실제 저장소와 각 `AGENTS.md` 및 엔지니어링 문서를 확인해야 한다.

## 1. 제품 원칙

1. 운동하는 동안 기록 입력과 화면 조작을 최소화한다.
2. **원본 루틴**, **요일별 일정**, **승인된 진행 중량**, **실제 운동 기록**, **다음 운동 기준 기록**을 구분한다.
3. 앱은 성과·증량·감량·디로딩을 **안내**하지만, 중량 또는 훈련 계획을 사용자의 승인 없이 바꾸지 않는다.
4. 운동 이력에는 성공·실패·중도 종료 여부와 무관하게 **실제 완료한 세트의 사실**을 보존한다. 자동 입력된 값은 세트를 완료하기 전까지 실적으로 보지 않는다.
5. 현재 운동은 로컬에 우선 저장하고 재진입 시 복원한다. 네트워크 동기화와 운영용 백업은 이후 단계에서 구현·검증한다.
6. 초기 UI는 **다크 모드 고정**, 한 번에 **한 운동 종목에 집중하는 화면(A안)**, iPhone 모바일 퍼스트를 기준으로 한다.

## 3. 핵심 용어와 데이터 경계

| 개념 | 의미 | 변경 범위 |
|---|---|---|
| `ExerciseDefinition` | 벤치프레스 등 종목 정의, 추후 주요·보조 부위 확장 | 종목 관리 |
| `Routine` | 루틴 이름과 종목 구성/순서/세트 수/반복 범위 | 명시적인 루틴 편집에서만 변경 |
| `WeeklySchedule` | 요일별 기본 루틴 지정 | 일정 편집에서 변경. 오늘만 다른 루틴 선택 가능 |
| `ExerciseProgress` | 루틴 내 종목별 **승인된 현재 진행 중량** 및 기준 수행 기록 | 사용자가 명시적으로 승인한 중량 변경 또는 유효한 기준 기록 갱신 |
| `WorkoutSession` | 특정 날짜에 시작한 운동의 독립적인 복사본, 워밍업·진행·종료 상태 | 현재 운동에만 적용 |
| `WorkoutSet` | 해당 세트의 입력값, 실제 완료 여부/시각, 실제 중량·반복 횟수 | 실제 세트 기록으로 저장 |
| `ExerciseMemo` | 해당 운동/기구를 위한 기본 세팅 메모 | 편집 시 이후 운동에도 유지 |
| `TrainingCycle` / `DeloadPlan` | 훈련 주기, 임시 디로딩 계획 | 후속 구현 대상 |

> DB 테이블/엔티티명을 확정하는 규정은 아니다. 다만 서로 다른 의미의 데이터를 하나로 덮어쓰지 않는 것은 필수다. 동일 종목을 서로 다른 루틴/세트 구성에서 사용할 수 있으므로 기준 기록을 종목 이름만으로 묶지 않는다.

## 4. 기능 상세

### R-01. 요일별 루틴

- 공통 브랜드/설정 아이콘 헤더를 두지 않고, 기본 내비게이션은 `홈 / 루틴 / 기록 / 설정` 네 탭으로 제공한다. 운동 진행 화면과 루틴 편집에서는 일반 탭바를 숨긴다. 운동 타이머 헤더와 화면별 제목은 유지한다.
- 설정은 휴식시간, 로컬 저장 안내, 서버 연결 진단의 메뉴 목록으로 제공한다. 미구현 계정·백업·디로딩 메뉴를 동작하는 기능처럼 표시하지 않는다.
- 루틴 이름, 운동 종목 목록과 순서, 종목별 본세트 수, 목표 최소·최대 반복 횟수, 최초 중량을 설정한다.
- 목표는 예를 들어 `6~10회 × 3세트`, `8~12회 × 3세트` 등으로 지정한다. 최소=최대도 입력할 수 있다.
- 하나의 루틴을 여러 요일에 연결할 수 있다. 초기 정책으로 한 요일에 기본 루틴은 하나만 두며 충돌 시 사용자에게 교체 확인을 요청한다.
- 루틴 미지정 요일은 기본적으로 휴식일로 표시하되, 사용자가 임의의 루틴을 선택해 시작할 수 있다.
- 현재 선택 ID가 오늘의 기본 루틴 ID와 같으면 `요일 기본 루틴`, 다른 루틴이면 `오늘만 선택`, 선택이 없으면 `REST DAY`로 표시한다. 임시 변경 후 기본 루틴을 다시 고르면 즉시 기본 라벨로 돌아오며, 선택 이력이나 주간 일정 변경으로 판정하지 않는다. 기본 루틴이 없는 날의 수동 선택은 `오늘만 선택`이다.
- 화면 진입 시 오늘의 기본 루틴을 표시할 뿐, **운동 시작 버튼을 누르기 전에는 세션·운동 타이머를 시작하지 않는다.**
- 루틴 편집은 앞으로 시작할 세션에 반영한다. 이미 저장된 과거 세션은 변경하지 않는다.
- 새 종목은 최초 중량을 입력한다. 승인된 진행 중량이 있는 기존 종목은 `현재 진행 중량: NN kg` 옆 `변경`에서 새 중량을 입력하고 `루틴 저장`으로 명시적으로 승인한다. 저장 전 입력과 변경 취소/루틴 취소는 승인 중량을 바꾸지 않는다. 같은 종목명이 다른 루틴에 있어도 해당 배치 ID에만 적용한다. 최초 중량과 과거 기록/기준 기록은 덮어쓰지 않는다.
- 최초 중량/승인 변경 초안/운동 중 중량 모달은 중앙 직접 입력과 좌우 `−2.5 / +2.5`를 함께 제공한다. 중앙을 누르면 소수 키패드를 위한 입력에 포커스한다. 버튼은 현재 유효한 초안에서 2.5kg만 조절하고, 61.3 같은 임의 소수를 배수로 반올림하지 않는다. 빈/잘못된 입력의 버튼은 비활성화하며, 2.5kg 미만에서 감소는 비활성화한다. 초안 조절은 승인이나 세트 완료가 아니다.
- 루틴 관리의 진행 중량 변경은 다음 새 세션부터 적용한다. 이미 진행 중인 세션의 승인/작업 중량, 실제 완료, 미완료 초안, 타이머는 유지한다. 운동 화면의 오늘만/진행 중량 변경은 기존 명시적 확인 흐름을 유지하고 승인 결과는 루틴 관리에서도 표시한다.
- 요일은 홈 일정과 편집 화면 모두 월→일 순으로 표시한다. 저장 ID는 일요일 0, 월요일 1 등 기존 매핑을 유지한다.

### R-02. 운동 시작 및 워밍업

- `운동 시작` 시 세션을 생성·로컬 보존하고, 전체 운동 시간 측정을 즉시 시작한다.
- 첫 화면은 무조건 스트레칭/워밍업 화면이다. 시간 제한이나 세트/중량/휴식 입력은 없다.
- `준비운동 완료`를 누르면 첫 종목의 본세트 화면으로 이동한다.
- 준비운동 화면에서 앱을 다시 열면 그 상태와 전체 경과시간을 복원한다.
- 진행 중인 세션은 홈의 인사보다 앞에 이어하기 카드로 표시한다. 전체 운동 시간/완료 세트 수를 유지하고 `준비운동 중`, `운동 중`, 유효한 `휴식 중`과 남은 시간, `종목 전환 중`과 완료 후 경과시간, `운동 종료 대기`를 구분한다. 기존 타이머 해석과 저장 시각에서 계산하며 표시 갱신을 위해 타이머를 새로 만들거나 매초 저장하지 않는다.

### R-03. 최고 수행 기준 기록(Benchmark)

- 실제 운동 이력은 모든 완료 세트의 결과를 보존하고, **다음 운동의 사전 입력값**은 `다음 운동 기준 기록`을 사용한다.
- 예: 벤치프레스 60kg, 목표 6~10회, 3본세트

| 실제 운동 | 다음 운동에 불러올 기준 기록 |
|---|---|
| 1회: `10/9/7` | `10/9/7` |
| 2회: `10/8/6` | `10/9/7` 유지 |
| 3회: `10/9/8` | `10/9/8` 갱신 |
| 4회: `10/8/6` | `10/9/8` 유지 |
| 5회: `10/10/10` | `10/10/10`, 증량 고려 안내 |

- 각 기준 기록은 **단 한 번의 실제 운동에서 모두 완료한 세트 조합**이어야 하며, 여러 날의 세트별 최고값을 섞어 만들지 않는다.
- **Task 002 비교 규칙(초기 구현 가정):** 동일 루틴 내 종목 설정·승인 진행 중량·본세트 수·목표 반복 범위에서, 모든 해당 본세트를 완료한 정상 세션만 비교한다. 반복 횟수 **총합이 기존 기준보다 커졌을 때만** 갱신한다. 동점일 때는 이전 기준을 유지한다.
- 이 비교 규칙은 예시를 만족하는 최초의 명시적 규칙이며, 특정 세트의 수행 저하를 얼마나 반영할지는 후속 사용성 검토에서 조정할 수 있다. 세트 수/목표/승인 중량이 바뀌면 비교 구간을 구분한다.
- 이미 입력된 기준 숫자를 보더라도 세트는 **미완료** 상태로 시작한다. 완료하지 않은 세트는 이력·볼륨·기준 갱신에서 제외한다.
- 비교 가능한 완료 결과가 아직 없다면 새 중량/구성에서의 반복 횟수는 사용자가 직접 지정하게 한다. **목표 하한으로 자동 초기화하지 않는다.**
- 각 본세트 반복 횟수는 중앙 직접 입력과 ±1 버튼으로 초안만 수정한다. 1 이상의 안전한 정수만 실제 완료할 수 있고 목표 상한 초과는 허용한다. 빈 값·잘못된 임시 값은 자동 치환하지 않으며 1에서 감소, 최대 안전 정수에서 증가를 막는다. 완료 및 휴식 시작은 기존 명시적 완료 조작에서만 발생한다. 과거 v1의 0회 실제 기록은 읽기·보존하되 새 완료는 허용하지 않는다.

### R-04. 더블 프로그레션 및 중량

- 예: 승인 진행 중량 60kg, 6~10회 × 3본세트. 동일 중량에서 실제 완료한 세트가 모두 `10/10/10` 이상이면 `증량 고려` 안내를 표시한다.
- 본세트 하나라도 최대 목표 미달이면 증량 안내를 띄우지 않는다. 목표 최소 횟수 미달이면 `감량 고려`를 안내할 수 있지만 의무 조치는 아니다.
- 어떤 안내도 자동으로 중량을 바꾸지 않는다.
- 증량을 승인하지 않고 보류했다면 다음 운동에서도 비교 가능한 최고 단일 세션 기준 기록으로 증량 조건을 재안내한다. 현재 루틴 배치·승인 중량·세트 수·반복 범위의 기준 기록이 모든 목표 상한을 달성했을 때만 `현재 기준 기록에서 증량 조건 달성 · 승인 NNkg · 10/10/10회`처럼 근거를 표시한다. 직전 운동이라고 단정하지 않으며 필수 선택 없이 운동을 계속할 수 있다. `지금 변경`은 기존 진행 중량 변경 확인 흐름으로 연결한다.
- 재안내는 임시/혼합 중량, 부분 완료, 임시 계획 변경 등 기존 기준 기록 비대상 결과를 새 근거로 사용하지 않는다. 서로 다른 세션의 세트별 최고값을 합치지 않는다. 승인 중량이나 비교 구성이 바뀌면 해당 구간의 기준으로 다시 판정하며 예전 기록은 보존한다. 현재 운동의 오늘만 중량을 쓰더라도 유효한 과거 승인 중량의 근거는 구분해 표시할 수 있으며 임시 중량을 자동 승인하지 않는다.
- 현재 종목을 실제로 모두 완료하고 기존 더블 프로그레션 판정이 증량 고려인 경우, 하단 고정 `다음 종목으로` 바로 위에 짧은 비차단 `증량 가능` 안내를 표시한다. 모든 종목 완료 상태에서는 `운동 종료 및 요약` 바로 위에 표시한다. 중간 세트, 목표 미달, 오늘만/혼합 중량 등 기존 판정에서 제외되는 경우에는 표시하지 않으며, 완료 취소/재수정 시 즉시 다시 판정한다. 승인 중량은 자동 변경하지 않는다.
- `오늘만 변경`: 그 세션에만 다른 중량을 적용한다. 실제 기록은 그 중량으로 보존하지만 승인 진행 중량이나 정상 기준 기록을 변경하지 않는다.
- `진행 중량 변경`: 사용자가 확인하면 승인 중량을 바꾸고 이후 정상 운동의 기준 중량으로 사용한다. 종전 중량 기록과 이력은 유지한다.
- 중량 증가 후 `6/6/6` 같은 반복 횟수 초기화는 하지 않는다. 새 중량에서 처음 수행할 횟수는 사용자가 직접 설정한다.
- 디로딩 시 적용되는 임시 중량도 승인 중량·정상 기준 기록을 덮어쓰지 않는다.

### R-05. 운동 시간·휴식 시간·종목 전환

- 전체 운동 시간은 `운동 시작`부터 종료까지 경과시간을 나타내며, 운동 진행 중 상단에 계속 표시한다.
- 오른쪽 상단 타이머 영역은 상태별로 재사용한다: `휴식 대기/없음` → `세트 사이 남은 휴식(카운트다운)` → `종목 전환 시 이전 종목 마지막 세트 완료 후 경과시간(카운트업)`.
- 휴식 기본값은 운동 종목 이름이 아닌 **목표 반복 범위의 상한** 구간으로 결정한다. 구체 구간과 시간은 설정 가능하게 하고 Task 002에서 예시값은 `가정`으로 표시한다.
- 중간 본세트 완료 시 휴식 자동 시작, 하단 조작은 `휴식 종료` / `+30초`로 바뀐다. 휴식이 끝났다고 다음 본세트 완료에 별도 확인 버튼을 요구하지 않는다.
- 일반 본세트 사이 휴식에서 남은 10~6초는 상단 타이머 색상 강조와 함께 하단 고정 `휴식 종료`/`+30초` 바로 위의 호박색 카드에 `다음 세트 준비`와 남은 초를 표시한다. 5~1초는 숫자 부분만 부드럽게 강조한다. 상·하단은 같은 올림된 남은 초를 사용하고 자동 스크롤·포커스 이동을 하지 않는다. 본문 하단 여백과 Safe Area/키보드 inset을 유지해 CTA와 본문 접근을 보호한다. 11초 이상·0초·종목 전환·워밍업·전체 완료에는 이 경고를 표시하지 않는다. reduced-motion에서는 정적인 강조만 유지한다. 기존 종료 예정 시각과 현재 시각을 사용하며 새로운 타이머·저장 필드를 만들거나 매초 저장하지 않는다. `+30초`, 수동 종료, 화면 복귀·복원도 같은 시각 기준을 따른다.
- 현재 세션의 마지막 남은 본세트를 실제 완료하면 휴식을 시작하지 않고 현재 종목에 머물며 완료 기록과 `다음 종목으로` 버튼을 표시한다. 버튼을 누르면 현재 이후 순서의 다음 미완료 종목으로 이동하고, 앞쪽 종목만 남았으면 그쪽으로 이동한다. 이동한 종목의 세트를 자동 완료하지 않는다.
- 오른쪽은 직전 종목의 마지막 실제 완료 시각부터 `이전 종목 완료 후` 경과시간을 표시한다. 다음 종목 첫 세트 완료 시 중간 세트라면 해당 설정의 휴식으로 전환한다. 한 세트뿐이면 다음 종목/전체 완료 규칙을 적용한다.
- 모든 종목을 완료하면 보조 타이머 대신 `모든 종목 완료`와 `운동 종료 및 요약` CTA를 표시한다. 세션과 전체 운동 타이머를 유지하며, 사용자가 종료하기 전에는 이력 확정이나 자동 종료를 하지 않는다.
- 완료 판정은 세션에서 변경한 세트/종목 구성과 순서를 기준으로 한다. 화면 탐색·새로고침·이어하기·완료된 종목 열기는 이동이나 새 타이머를 발생시키지 않는다. 수동 탐색은 다른 종목의 휴식 시각을 보존한다.
- 완료 취소나 세트 추가로 전환 타이머의 원본 종목이 다시 미완료가 되면 해당 타이머를 해제한다. 다른 종목의 유효한 휴식은 유지한다. 이전 종목·목록으로 돌아가 기록을 확인·수정할 수 있다.
- 이전 v1 세션에 완료된 종목의 휴식이 남아 있으면 실제 완료 기록 중 가장 늦은 시각을 기준으로 경과시간을 표시한다. 화면 표시를 위해 저장된 실제 기록이나 최초 로드 데이터를 덮어쓰지 않는다. 전체 완료 세션에서는 보조 타이머를 표시하지 않는다.
- 화면이 백그라운드로 가거나 새로고침해도 타이머 계산이 이어지도록 시작 시각과 휴식 종료 예정 시각을 저장한다. 1초 간격 UI 업데이트 자체를 정답 데이터로 쓰지 않는다.

### R-06. 운동 중 변경과 메모

- 세트 수/종목 추가·삭제·교체·순서 변경은 **현재 세션의 복사본에만** 적용한다. 원본은 유지된다.
- 현재 종목은 단일 화면에 집중해 표시하고, 종목 목록/이전·다음 탐색으로 이동한다.
- 기본 기구 세팅 메모 하나를 해당 종목에 저장한다. 세션별 메모를 만들지 않는다.
- 운동 도중 종목을 바꾸거나 앱을 닫아도 입력·완료 세트는 남아 있어야 한다.

### R-07. 운동 이력 및 완료

- `운동 종료` 시 완료한 세트와 운동 시간, 완료 본세트 수, 총 볼륨을 요약한다. 미완료 세트는 실제 수행으로 저장하지 않는다.
- 운동 이력은 날짜/세션별로 조회하고, 각 종목의 세트별 실제 중량·반복 횟수 및 일시 변경 여부를 확인할 수 있다.
- 종료 전 미완료 세트가 남았다면 확인 메시지를 표시한다. 운동 종료를 취소해 이어 할 수 있다.
- 기록의 일부만 수행했더라도 원본 루틴의 목표 세트 수는 다음 운동에 남아 있어야 한다.
- 총 볼륨의 초기 정의는 `완료한 본세트 각각의 중량(kg) × 실제 반복 횟수`의 합계다. 부위별 기여도/맨몸운동 특별 규칙은 향후 확장한다.
- 종료 요약은 `운동 기록 저장 완료` 등 중립 표현과 `완료 3/9 본세트`처럼 실제 완료 범위를 표시한다. 현재 세션의 계획을 모두 완료한 경우에만 `전체 루틴 완료`를 표시한다.
- 세션 상세 하단 `이 운동의 중량 검토 결과`는 저장된 당시 중량/실제 세트/목표/계획에서만 `당시 증량 가능 / 당시 감량 검토 / 당시 유지`를 재현한다. 현재 승인 중량을 대입하지 않는다. 미완료·일시/혼합 중량·세션 구성 변경·계획 미확인은 판정 제외 이유를 표시한다.
- 기록 목록은 세션 탐색을 유지하면서, 적용 가능한 경우 `현재 중량 조정 검토`와 `진행 중량 변경 내역`을 제공한다. 현재 검토는 현 배치/승인 중량/구성의 기준 기록과 최근 비교 가능한 완료 기록을 구분해 보여준다. 최고 기준의 증량 근거와 최근 약한 수행의 감량 검토가 공존할 수 있으며 하나가 다른 사실을 덮어쓰지 않는다. 홈에서도 현재 선택 루틴에 한해 같은 파생 검토를 재사용한다.
- 실제 승인 변경은 당시 루틴/종목 이름, 배치 ID, 변경 전/후 중량, 발생 시각, 루틴/운동 화면의 출처를 별도 사건으로 보존한다. 양수는 `증량 완료 +Nkg`, 음수는 `감량 완료 −Nkg`다. 루틴 이름 변경/삭제 후에도 사건의 이름은 유지한다. 명시적 연결 없는 루틴 편집 사건을 특정 세션의 결정이었다고 추정하지 않는다.
- 새 이력은 미완료 초안을 제외하기 전에 종목별 최종 계획 세트 수를 선택 필드 `plannedSetCount`로 보존한다. v1 데이터는 변환 없이 읽는다. 이 필드가 없는 기존 이력은 수정되지 않은 구성의 `setCount`만 사용하며, 임시 변경된 과거 구성은 `당시 계획 수 미확인`으로 표시한다.

### R-08. 저장·복원·오프라인(단계적)

- Task 002에서는 서버와 독립적으로 운동 입력을 로컬에 저장하고, 새로고침/재진입 후 진행 상태를 복원한다.
- v1의 선택 필드 `progressChanges`가 없는 구 저장값은 빈 변경 내역으로 해석하되 최초 로드에서 다시 쓰거나 과거 사건을 추정하지 않는다. 승인 변경과 사건은 한 저장 성공에서만 반영한다. 동일 값/오늘만/취소/초안/검증 오류에는 사건을 생성하지 않는다.
- 승인 저장이 실패하면 승인 중량/사건을 반영하지 않고 입력 초안을 유지한다. `저장소 재확인`은 저장소 상태만 확인하며 거부된 승인을 자동 적용하지 않는다. 복구 후 사용자가 다시 승인/루틴 저장해야 한다. 일반 반복 횟수 등의 쓰기 실패는 기존 메모리 입력 보존과 다시 저장 경로를 유지한다. 다중 탭 충돌 차단을 우회하지 않는다.
- 운영용 목표는 **로컬 쓰기 성공과 서버 동기화 성공을 명확히 구별**하는 것이다. 오프라인/전송 실패 시 대기 후 재전송하고, 서버에서는 요청 ID/멱등성으로 중복 기록을 방지한다.
- 실서비스 단계에서는 적합한 로컬 스토리지(예: IndexedDB), 데이터 스키마 버전 관리, 저장 실패/용량 부족 대응, 백업·복원 전략을 검증한다.
- 로컬 저장만으로 데이터가 영구 백업되었다고 표시하지 않는다.

## 5. 향후 기능의 제품 요구사항(이번 구현 범위 아님)

### 디로딩과 훈련 사이클

- 주기 안내는 **5주차부터 안내를 시작해 8주차까지 단계적으로 강하게** 보이되, 실제 생리학적 피로 `%`로 단정하지 않는다.
- 사용자가 동의하면 1주일 디로딩 계획을 생성한다. 수행할 요일을 직접 지정하고 종목·세트 수·중량을 일시 조정한다.
- 예시: 주간 본세트 총 100개 → 50개, 중량은 평소의 80~90%. 이 수치는 **설정 예시일 뿐 확정 처방이 아님**.
- 장래에는 주요/보조 부위 분류를 통해 부위별 배분을 조절한다.
- 운동을 쉬었던 날짜와 주간 일정의 예정 휴식일을 구별해야 한다. 3일/7일 연속 휴식과 사이클 초기화, 운동 횟수 기반 계산 공식은 **미확정**으로 별도 기획한다.
- 디로딩 세션·중량·반복 횟수는 정상 기준 기록과 진행 중량에 영향을 주지 않는다.

### 성장 차트

- 실제 운동 이력을 유지하고 운동별 작업 중량, 동일 중량에서의 반복 횟수, 주간 볼륨, 장래 부위별 세트 수 등을 추이로 표현한다.
- 디로딩 구간은 성능 하락과 혼동하지 않도록 구분해서 표시한다.

## 6. 대표 수용 테스트

1. `10/9/7` 이후 `10/8/6`을 수행해도 다음 세션 기준 기록은 `10/9/7`이다.
2. 이어 `10/9/8`을 수행하면 다음 세션 기준 기록은 `10/9/8`로 갱신된다.
3. 저조한 실제 기록도 이력에서 조회된다. 여러 운동일의 최고 세트를 임의로 조합하지 않는다.
4. 동일 승인 중량으로 6~10회 × 3본세트를 모두 10회 수행하면 증량을 안내하되 중량은 자동 변경되지 않는다.
5. 사용자가 진행 중량을 62.5kg으로 승인해도 반복 횟수를 6/6/6으로 자동 초기화하지 않는다.
6. `오늘만 변경` 75kg 세션이 끝나도 승인 중량 80kg은 다음에 유지된다.
7. 시작 즉시 운동 시간이 측정되고 준비운동 화면에서는 워밍업 세트 입력이 없다.
8. 중간 본세트 완료 시 휴식이 자동 시작되며 `+30초`와 `휴식 종료`가 동작한다.
9. 마지막 남은 세트 완료 시 현재 종목에서 **마지막 실제 세트 완료 시각**부터 경과시간과 `다음 종목으로`를 표시한다. 버튼 이동 후에도 같은 경과시간 기준을 유지한다. 전체 완료 시에는 사용자가 `운동 종료 및 요약`을 누를 때까지 기록 검토 상태를 유지한다.
10. 루틴의 종목을 운동 중 임시로 변경해도 다음에 같은 루틴을 시작하면 원래 종목 구성으로 복원된다.
11. 새로고침 시 워밍업/완료 세트/미완료 입력/타이머 상태가 복원된다.
12. 운동 종료 시 완료 세트만 이력·볼륨에 포함되며 미완료는 자동 완료되지 않는다.
13. 요일별 기본 루틴은 홈에 표시되지만 `운동 시작`을 누르지 않는 한 세션을 생성하지 않는다.
14. 기존 Full-Stack Health Check 기능 및 테스트가 훼손되지 않는다.

## 7. 후속으로 결정할 항목

- Task 005 이후 드랍세트는 설계 대기 기능이다. 현재 기록/기준/증량 판정은 일반 본세트 기준이며, 향후 드랍세트의 감량 구간을 정상 기준 기록에 섞지 않아야 한다. 이번에는 드랍세트·슈퍼세트의 데이터 구조나 UI를 추가하지 않는다.
- 동률과 동일 총합·다른 세트 분포에 대한 기준 기록 비교 규칙의 장기 정책(현재 Task 002는 동률 유지).
- 최초 운동 또는 승인 중량 변경 직후의 반복 횟수 입력 UX(현재는 사용자 직접 입력, 자동 하한 초기화 금지).
- 목표 상한별 정확한 휴식시간, 휴식 종료 뒤 알림 수단.
- 동일 종목을 여러 루틴에서 사용할 때 기준 기록의 공유 여부(초기에는 루틴 내 종목 설정 단위로 격리).
- 운동을 건너뛴 기간의 디로딩 주기 반영, 부위별 세트 계산, 실제 서버 동기화 충돌 처리.
