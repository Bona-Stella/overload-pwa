| 상태 | 의미 |

## 2. 내비게이션과 전체 범위

- 하단 탐색: **홈 / 루틴 / 기록 / 설정**.
- 사용자가 조각 단위로 확정한 것을 한 문서에 축적. 화면별 실제 배치나 조작을 확인하기 전에는 이전 `/demo`를 완성형 UI로 간주하지 않음.
- v0.4에서 제작한 홈, 준비·웨이트·유산소, 루틴 목록·편집, 기록·분석과 정정·복구 화면은 v0.8에서도 보존. v0.5의 설정·표준 운동 상세를 유지하면서, v0.6은 **루틴 검색·장비 설정·운동 진행 임시 편집·완료 기록·제조사별 참고 통계·휴식 초 입력 위치**를 1차 수정으로 반영.

## 3. 홈 — 현재까지 합의한 방향

- 오늘의 루틴이 우선; 해당 루틴이 *요일 기본 루틴*인지 *오늘만 선택*인지 명시. 오늘만 바꿔도 원래 주간 배정은 바뀌지 않음.
- 월~일 주간 루틴 일정, 최근 운동, 하단 네비게이션 포함.
- 실제 서버에서 루틴/주간 계획을 조회할 때 신규 가입에는 시연용 PUSH/PULL/LEGS가 자동 생성되어 있지 않음.
- 원본 `/demo`의 텍스트·수치·예시 루틴은 설명용이며 실운영 데이터가 아님.

## 4. 루틴 — 현재까지 합의한 방향

- 상단 월~일 주간 일정과 비어 있는 요일 명시. 요일당 루틴 최대 1개, 루틴은 요일 미지정으로도 저장 가능.
- 루틴 카드: 이름, 요일, 웨이트 세트·종목 개수, 유산소 개수, 종목 요약, 편집/삭제.
- 생성/편집: 하나의 세로 화면; **WEIGHT**와 **CARDIO** 영역을 구분하고 각각 별도의 01부터 번호. 저장/취소 위치 고정. 월~일 복수 요일 선택, 중복되면 저장 전 교체 확인.
- 사용자 루틴 삭제는 과거 완료 기록이나 진행 중 운동을 삭제하지 않음.
- 원래 루틴을 수정해도 진행 중인 운동의 당시 계획을 자동으로 덮어쓰지 않음.
- **최신 카탈로그 정책:** 사용자가 직접 운동 종목 정의를 추가·이름 변경·삭제하지 않음. 모든 종목은 **관리자 관리 표준 운동 DB**에서 선택. 표준 UUID를 기준으로 식별하며 이름이 같아도 다른 UUID를 자동 병합하지 않음.
- **v0.6 1차 수정 반영:** `ROUTINE-02`, `WORKOUT-06`의 표준 운동 검색은 행의 부위 이모지 + `가슴 · 대흉근`처럼 PRIMARY 근육만 간결히 표시. 검색 행에는 별도 `>` 상세보기 경로를 두지 않고 클릭하면 운동 설정으로 이동. 검색은 표준명과 별칭을 이용하며 관리자 등록 운동만 선택. 자세/GIF 상세는 설정의 읽기 전용 종목 상세에서 확인.

## 5. 운동 진행 — 기존 합의 유지 + v0.6 장비 표시·임시 편집

- 준비운동 → 웨이트 종목 집중 → 휴식 카운트다운/세트 완료 → 이후 유산소/운동 종료 및 기록.
- 세트 완료는 원자적 로컬 저장 성공 후에만 확정. 서버 ACK 전과 후를 구분. 인증 만료·오프라인일 때 기존 계정의 진행 운동 원본을 보호.
- 시작 당시 계획(InitialPlan)과 도중 편집되는 현재 계획(AppliedPlan)을 구분. 완료 후 원래 계획·당시 장비·완료 사실의 문맥을 소급 변경하지 않음.
- 중량 변경에서 *오늘만 변경*과 *진행 중량 변경*을 구분. 승인 중량 사건과 실제 수행 중량을 혼동하지 않음.
- 운동 종료 후 추가 완료 확인 없이 기록 상세로 진입하기로 합의한 기존 시안 유지.
- 유산소 실제 활동 시간·거리·평균 심박, 건너뛰기/완료, 계획 대비 실제 수행을 구분.
- **v0.6:** `WORKOUT-02` FOCUS 제목의 왼쪽 아래에 `하체 · 대퇴사두근`처럼 대분류와 PRIMARY 근육을 간결히 표시, 오른쪽 남는 공간에 저장된 `제조사 / 부하 방식`을 *읽기 전용* 표시. `목표 6–10회 × 3세트`로 표기하며 `3본세트`는 사용하지 않음.
- 장비 설정 자체를 상단에서 눌러 수정하게 만들지 않음. 기존 `세트 기록 / 임시 편집`(`WORKOUT-05`)에서 제조사·부하 방식 선택을 제공하고 **오늘만 적용**. 이후 완료 세트에 사용하고 이미 완료한 세트의 장비 원본 및 원본 루틴은 바꾸지 않음.

## 6. 기록·분석 — v0.4에서 확정된 구조 보존

- 기록 대시보드: `운동 기록·분석` 제목, 이번 주(월~일) 계획 대비 달성·완료 웨이트 세트·달성률, 유산소 시간, **운동 현황 / 근육별 통계 / 성장 추적**, 최근 운동 세션 3개와 전체 보기.
- 운동 현황: 주간/월간, 세트/총중량, 전체·운동별·근육별, 운동량 막대 그래프; **예정일·실제 달성**을 별도 탭 대신 여기에 통합. 유산소 요약에서 유산소 상세로 진입.
- 유산소 상세: 기간별 실제 누적 활동 시간, 날짜별 차트, 종류별 거리와 거리 출처; 종류가 다른 거리 km를 전체 거리로 무조건 합산하지 않음.
- 근육별 통계: 가슴/등/하체/어깨/팔/코어 → 세부 근육; **PRIMARY/SECONDARY는 분리**, 동일 세트를 대분류 안에서 중복 합산하지 않음. 계획이 없으면 `계획 없음`, 확인할 수 없는 과거 계획이면 `확인 불가`.
- 성장 추적: 종목 검색(현 루틴에서 빠진 과거 종목 포함), 1/3/6개월/전체, **공식 승인 중량** 사건 중심. 디로딩과 임시 실제 수행 중량은 공식 중량 추이에 섞지 않음.
- 운동 이력: 달력 날짜가 아닌 **완료 세션 단위** 카드. 같은 날짜의 여러 세션은 별개. 상세에는 원래 수행·유산소·당시 평가와 수정 후 현재 평가 분리.
- 상세 상단 오른쪽 **⋮ 아이콘만** 사용(‘기록 관리’ 텍스트 노출 금지). 메뉴: 기록 정정 / 누락 수행 복구 / 기록 전체 삭제.
- 기록 정정은 실제 수행값만 허용, 기존 계획·종목/ordinal·문맥 불변. 개별 수행 논리 삭제 가능. 전체 삭제는 확정 경고 후 이력·통계·평가에서 제외되지만 일반 사용자 복원 불가.
- 누락 복구는 본인 기기에 남아 있는 **진짜 완료 원본**에서 선택하는 특별 경로. 사용자가 임의로 완료 세트를 생성하거나 전체 삭제된 세션을 되살리는 기능이 아님.
- 미동기화 세션을 서버 통계에 포함된 것처럼 표시하지 않음. 일정이 없는 날과 확인 불가한 과거 날을 숫자 0으로 혼동하지 않음.
- **v0.6 세트별 장비:** `RECORD-01` 운동 종료 후 상세와 `RECORD-03` 과거 기록 상세에 각 완료 세트의 `제조사 · 부하 방식`을 실제 수행 당시 정보로 표시. 한 종목의 장비가 도중 변경되어도 종목은 하나로 묶고 세트별로 구별. `RECORD-04` 정정에서는 실제 중량·반복 수만 수정하고 장비는 정정할 수 없는 원본. 누락 수행 복구에서도 원본 장비 보존.
- **v0.6 STATS-06 운동별 제조사별 참고 통계:** `운동 현황 → 운동별`에서 운동 상세 통계로 들어가 **전체 보기 / 제조사별 보기** 전환. 완료 세트 수와 총중량을 분리·합산하고 제조사 미지정은 별도 분류하되 전체에는 포함. 제조사별 최고 실제 중량 그래프는 시안용 예시 산식으로, **공식 승인 중량 성장 추적과 분리**. 제조사가 달라도 실제 중량 자체를 동일한 공식 근력 기준으로 비교하지 않음. 제조사+부하 방식의 추가 하위 필터는 후속 확장 후보로만 두고 지금은 만들지 않음.

## 7. 설정 메인 — 새롭게 합의한 정보 구조

**상단부터 다음 순서**. 최상단에 계정 정보를 둔다는 것은 사용자 확정 의견.

1. **계정 정보:** 로그인 계정 요약 → 계정 설정 상세.
2. **운동 설정:** 세트 사이 휴식 / **운동 종목 보기**(읽기 전용) / 디로딩 설정.
3. **데이터 및 앱:** 운동 데이터 상태 / 운동 데이터 내보내기(JSON) / 앱 설치·오프라인 준비.
4. **계정 및 데이터 삭제:** 전체 운동 데이터 초기화 / 회원 탈퇴.
5. 앱 버전 등 보조 정보.

`운동 종목 관리` 메뉴명 및 사용자 개인 종목 CRUD는 **폐기**. `주간 루틴 일정 편집`은 루틴, 일반 운동 통계는 기록, `세트 사이 휴식`은 설정에 위치. 일반 설정에 필요 없는 중복 메뉴를 만들지 않음.

### 7.1 계정 설정 상세 — 사용자 제공 실제 화면 참조

- 로그인 수단: 이메일 로그인 연결 상태, 대표 이메일 로그인 연결 확인/해제, Google 로그인 연결/해제.
- 대표 재인증 이메일: 등록 VERIFIED 상태, 마스킹된 주소, 이메일 OTP 재인증 버튼. **대표 재인증 이메일과 로그인 수단은 별도**.
- 최근 이메일 재인증 상태: 최근 인증 여부/시간 판단을 등록 VERIFIED 상태와 구별.
- 계정 정보 새로 확인, 로그아웃.
- 서로 다른 사용자 계정 자동 병합 금지. 마지막 로그인 수단 해제 불가. 민감 작업 최근 **10분 이내 재인증** 기준.
- 이전 실제 계정 화면 하단의 `앱 설치·오프라인 준비`는 설정 메인의 데이터·앱 영역으로 이동.
- 제공된 화면의 구성은 현재 참고 기준으로 사용하지만, 실제 UI 세부 버튼 동작은 별도 구현 규칙을 따라야 함.

### 7.2 세트 사이 휴식 — 구조 합의

- 휴식 목표는 **계획 반복 상한** 기준. 10회 이하 180초, 11~12회 120초, 13회 이상 90초는 **운영 초기값**.
- 실제 화면에서 계정별 저장값 조회. 세 값을 한 편집 화면에서 변경하고 **한 번에 저장**. 양의 정수 초만 허용, 저장/취소, 온라인 요청.
- **v0.6 단위 위치 확정:** 각 행 왼쪽 레이블은 `10회 이하`, `11~12회`, `13회 이상`으로만 표시하고 **각 숫자 입력칸 바로 오른쪽에 `초`**를 배치. 따라서 `10회 이하 (초)` 같은 혼동 유발 표현은 사용하지 않음.
- 시안에서 값이 바뀌어도 실제 서버에 저장한 것으로 표현하지 않음.

### 7.3 디로딩 설정 — 구조 합의

- **디로딩 추천 분석 ON/OFF만 사용자 변경 허용**. OFF여도 디로딩 기능 자체, 수동 시작 및 이미 진행 중인 디로딩은 유지. OFF 기간의 과거 기록을 재활성화할 때 소급 계산하지 않으며 ON 때 누적값 0부터.
- **중량 적용률 85%, 세트 적용률 50%는 읽기 전용 안내**. 사용자가 직접 비율 편집하는 것은 향후 별도 개발 후보, 이번 UI에서 입력/저장 버튼 금지.
- 설계 기준 `Overload_Deloading_Design_Specification_v1.3.md`의 상세 산식 유지: 중량은 승인 중량 또는 시작 중량의 85%를 바탕으로 장비별 내림, PLATE/STACK 5kg·DUMBBELL 2kg·미지정 1kg; BODYWEIGHT 중량 조절 없음; 작은 중량 0kg 방지; 세트는 50% 정수 반올림(0.5 올림) 최소 1세트; 홀수 세트 등의 반복 횟수 보정. 원래 루틴·승인 중량은 그대로 보존.

### 7.4 데이터·앱 메뉴 — 기존 정책, 상세 UI 검토 예정

- 운동 데이터 상태: 네트워크 연결, 서버 ACK, 로컬 보존·전송 대기, 기기 제어권/동기화 오류를 같은 의미로 혼동하지 않음.
- JSON 내보내기: 계정 운동 데이터 다운로드. **가져오기/복원은 별도 승인되지 않음**.
- 전체 운동 데이터 초기화: JSON 내보내기 안내 → 최근 10분 재인증 → 최종 확인 → 온라인 완료 응답. 계정과 로그인 수단은 유지, 운동 데이터와 휴식은 운영 초기 상태로 재구성. **표준 운동 카탈로그는 관리자 공용 데이터**이므로 종전 개인 종목 20개를 새로 만드는 예전 seed 문구는 현행 정책과 불일치. `dataGeneration` 증가, 구 세대 미전송 자료를 새 세대로 자동 이관하지 않음.
- 회원 탈퇴: 초기화와 구분. 계정/인증 수단/운동 데이터 파기 대상; 온라인 재인증/최종 확인/서버 성공 응답 이후에만 완료로 표시.
- PWA·오프라인: 지원 기기 설치 안내, 계정별 로컬 저장 주의와 미동기화 기록 유실 가능성; 백그라운드 자동 동기화 보장 금지.
- 내보내기·초기화·탈퇴 각 확인 화면의 실제 문구/단계/버튼은 **현재 와이어프레임 초안**이며 후속 사용자 검토 필요.

## 8. 표준 운동 목록·상세 — 사용자 새 결정

### 8.1 표준 운동 DB 실제 연결 상태

- `standard_exercise`: 표준 운동 UUID/명칭/활성 상태.
- `exercise_alias`: 표준 운동 UUID별 이름 검색용 별칭.
- `muscle`: 세부 근육명, 대분류 CHEST/BACK/SHOULDERS/ARMS/LEGS/CORE.
- `exercise_muscle`: 해당 표준 운동의 PRIMARY 또는 SECONDARY 세부 근육 연결. 복수 PRIMARY 허용.
- `manufacturer`: 장비 제조사의 공용 목록이며 특정 표준 운동에 고정 연결되지 않음.
- **웨이트 신규 선택**은 `GET /api/v1/standard-exercises/search-data`를 사용한다. `schemaVersion=1`의 각 운동은 `id`, `name`, `aliases`, `muscles`를 반환한다. 근육 항목은 `id`, `groupCode`, `name`, `role`이다. 활성 상태이며 근육 타겟과 분할 검수가 완료된 `SETS_REPS`가 대상이다.
- **설정의 표준 운동 목록 조회**는 `GET /api/v1/standard-exercises/catalog`를 사용한다. 활성 상태와 두 검수를 충족한 운동을 기록 방식과 관계없이 조회하며, 이름·별칭·근육 외에 `exerciseType`, `recordMethod`, nullable `instructionsKo`와 `equipmentDescription`을 반환한다.
- **유산소 신규 선택**은 `GET /api/v1/standard-exercises/cardio-choices`를 사용한다. 공개된 `recordMethod=CARDIO` 중 활성 기록 설정에 연결되고 표준명이 100자 이하인 운동이 대상이다. 응답의 `id`는 표준 운동 UUID, `activityId`는 유산소 기록 설정 UUID다.
- 조회 가능 범위와 신규 선택 가능 범위는 구분한다. 검수 취소나 비활성화로 신규 선택에서 제외돼도 이미 저장된 루틴·세션 참조는 기존 계약을 따른다. `GET /api/v1/manufacturers`는 별도 제조사 ID·이름 목록이다. [현행 카탈로그 API](../../../overload-server/docs/api/standard-exercise-catalog.md)
- `routine_weight_placements`의 `manufacturerId`·`loadType`은 **사용자가 해당 루틴에서 지정한 값**(미지정 null 허용). 지원 부하 방식: **PLATE(원판), STACK(핀/스택), DUMBBELL(덤벨), BODYWEIGHT(맨몸)**. 세트 수행 시 당시 제조사/부하 방식을 불변 원본으로 보존.
- **V16/V17 당시 기록(2026-11-02).** 당시 검색 응답은 ID·이름·별칭을 제공했다. V17 및 프론트 표준 카탈로그 전환에서 개인 종목 신규 쓰기 차단과 표준 UUID 사용을 구현·검증했다. **기존 개인 종목 직접 관리 정책은 구 버전 문구**이므로 UI에 가져오지 않음. [당시 개발 환경 전환 보고서](../../../overload-server/docs/tasks/standard-exercise-catalog-dev-phase-4-report.md)

### 8.2 운동 목록 조회 UI — 2026-11-11 1차 디자인 확정

- `설정 → 운동 종목 보기`는 표준 운동명·별칭 검색 및 상세 조회 전용. `표준 운동 DB`와 **조회 전용**, 등록·편집·삭제는 관리자가 수행한다는 안내를 유지. 관리자는 현재 사용자 UI/HTTP 관리자 기능의 구현 대상이 아님.
- 검색창 아래 **한 줄 가로 스크롤** 필터: `전체 / 가슴 / 등 / 어깨 / 팔 / 하체 / 코어 / 유산소 / 기타`. 아이콘 없는 기존 알약형 디자인, **높이 27px**, 좌우 크기를 억지로 줄여 한 화면에 모두 넣지 않는다. 이름/별칭 검색과 필터를 조합하고 즉시 결과 갱신.
- 결과: 공식 **32 CSS px** 원형 대분류 아이콘(기존 가슴·등·하체·유산소 자산 + 사용자가 제공한 어깨·팔·코어의 무채색 테마 맞춤), 운동명과 `대분류 · 첫 PRIMARY 근육` 2줄, 우측 `›`, **행 전체 클릭으로 CATALOG-02 상세**. 기타는 텍스트 대체 가능. 결과 없음 안내.
- **CATALOG-01은 검색·필터·목록 항상 펼침**, 닫기 버튼 없음. 다른 화면과는 동일 검색 UI 배치/컴포넌트 규칙을 재사용하되 각 화면의 목적과 펼침/접힘을 구분한다(10.18절).

### 8.3 운동 상세 UI — 2026-11-11 1차 디자인 확정 / 데이터 연동 대기

2026-11-12 사용자가 CATALOG-02 UI를 최종 승인했다. 미디어 제목은 **동작 시연**, 표시 영역은 콘텐츠 너비의 **1:1 정사각형**, 이미지는 `object-fit: contain`으로 원본 비율을 보존한다. 머신 하이 로우의 개발 전용 시연은 원본 GIF의 흰색 배경·프레임·재생 속도·무한 반복을 그대로 사용한다. 투명화·APNG 변환은 취소했다. 실제 UUID 상세 API와 회원용 보호 미디어 연동은 별도 후속 작업이다.

1. 상단 제목 카드에는 `STANDARD EXERCISE`, 운동 표준명, 있으면 별칭, 우측 태그를 **PPL 값 → 전면/후면 값 → 조회 전용** 순서로 한 줄에 둔다. `PPL`, `전면/후면` 등의 설명 라벨은 태그 안에 쓰지 않는다. 분할 값이 없으면 해당 태그를 **그리지 않는다**.
2. GIF 섹션은 미제공 회원에게 **`GIF를 제공하지 않습니다` 안내 이미지**를 표시하는 상태와, 해당 운동 GIF 사용·전송이 허용된 회원에게 **실제 GIF**를 표시하는 상태로 구분한다. 현재 HTML은 미제공 이미지의 **임시 안내 영역**이며 최종 이미지는 추후 제작. GIF 파일 자체나 보호 URL을 허위 삽입하지 않는다. 권한·파일 부재·로드 실패·차단 처리는 연동 구현 단계에서 설계/검증한다.
3. **운동 자세 및 방법**은 기본 접힘, 우측 `∨`로 펼침. 순서 있는 `instructionSteps`를 보여주며 없으면 `등록된 운동 방법 정보가 없습니다.` 안내. 실제 API 값 연결은 이후.
4. **PRIMARY 주요 자극 근육 / SECONDARY 보조 자극 근육**을 별도 카드로 표시. 각 행은 `광배근   등`처럼 **근육명과 대분류를 같은 줄**에 둔다. PRIMARY **정렬상 첫 번째 근육만 `핵심` 태그**를 오른쪽에 표시. 실제 데이터 검수에서도 첫 PRIMARY는 운동의 핵심 타겟을 의미해야 한다. SECONDARY에는 순서/핵심 강조가 없다. 리스트가 없으면 해당 정보가 없다는 안내를 표시.
5. 표준 상세는 **조회 전용**이다. **장비 제조사·머신/부하 방식 및 개인 루틴의 기록 방식 선택 UI는 넣지 않는다.** 제조사·부하 방식은 사용자가 루틴 배치 또는 현재 세션에서 선택하며, 수행 당시 실제 설정값은 수행/기록 문맥에서 다룬다. 서버의 공용 카탈로그 레코드에 있는 기술/검수용 분류와 사용자 루틴 입력 UI를 혼동하지 않는다.
6. 화면 샘플의 운동 방법·근육·분할은 합성 배치 예시다. **Backend 구현 완료.** 인증된 `GET /api/v1/standard-exercises/{exerciseId}`는 ID·이름·별칭·운동 유형·기록 방식·기구 설명·관절 분류와 `primaryMuscles`, `secondaryMuscles`, nullable `pplSplit`·`frontBackSplit`, `instructionSteps`, `selectableForRoutine`을 제공한다. 목록은 PRIMARY를 저장된 순서대로 반환하며 상세 PRIMARY는 `primaryOrder`를 명시한다. `핵심` 태그는 Backend 순서의 첫 PRIMARY에만 표시한다. `selectableForRoutine`은 신규 선택 가능 여부다.
7. **확정 정책 / PWA 연동 미구현.** React 상세 화면과 UUID 상세 요청 연결은 후속 작업이다. 실제 GIF 표시는 별도의 보호 경로 전달 계약과 파일 제공 조건을 충족한 뒤 연결한다. [상세 API](../../../overload-server/docs/api/standard-exercise-catalog.md#get-apiv1standard-exercisesexerciseid) · [PWA 연결 상태](../engineering/backend-ui-v0.9.md#표준-운동-사용자-ui의-v35-연결-경계)

> v0.6 당시 API 설명(2026-11-05). 현행 계약은 위 6~7항을 따른다.
>
> 실제 근육 매핑은 DB에 있으나 현재 검색 조회 API에는 포함되지 않아 **상세 읽기 API 연동 대기**.

### 8.4 루틴·운동 진행에서 해당 종목 상세 사용 — 정책 합의, 기존 UI 자료 대기

- **사용 중인 루틴의 운동을 열거나, 새 루틴 생성·기존 루틴 편집 중에 선택한 운동의 상세 정보 확인** 가능.
- 동일한 표준 운동 정보(GIF/자세/근육)를 재활용하고, 이 문맥에서는 **해당 루틴에 저장된 제조사/부하 방식**을 보여주거나 편집할 수 있음.
- 상세 화면에서 장비 정보를 수정해도 **표준 운동 DB 자체를 수정하는 것이 아님**. 최초 계획/수행 당시의 장비 원본을 소급 변경하지 않음.
- **v0.6 1차 결정:** 루틴 생성/수정의 운동 검색은 이름·별칭+부위 이모지+대분류·PRIMARY 근육만 표시. 별도 `>` 상세 진입을 만들지 않고 직접 운동을 선택해 같은 루틴 편집 화면에서 제조사·부하 방식·세트·반복·초기 중량을 설정. 이미 저장한 운동은 저장된 제조사·부하 방식을 다시 표시·편집하되 배치·공식 승인 중량을 보존. 자세/GIF는 설정 > 운동 종목 상세에서 조회. `CATALOG-03`은 루틴 장비 설명 참고 시안일 뿐 독립 진입이 필수인 화면이 아님.

## 10. v0.7 — 디로딩 UI 통합 결정 (기존 v1.3 정책에 대한 최신 UX 변경 포함)

### 10.1 디로딩 진입 전 — 홈 원형 버튼

- 기존 `HOME-01` 상단의 **작은 원형 버튼**을 디로딩 진입점으로 사용. 별도 홈 배너나 별도 `디로딩 시작` 바로가기 없음. 버튼 → 상세(유효 주수·권장 기간 안내) → **상세 하단 `디로딩 시작`**.
- 유효 훈련 누적은 1주 정수로 증가하지 않고 `0.5`, `0.67`, `0.775` 유효 주처럼 **연속값**. 8칸/주별 구획 게이지는 폐기. 8주를 100%로 상한 표시.
- 4주 미만은 중립색 작은 아이콘/최소 강조, **4주부터 초록 → 노랑 → 주황 → 적색**으로 서서히 변화. 더 높은 수치가 우수한 성취라는 뜻이 아니라 회복 시기를 점검하는 안내. 실제 피로/건강 위험 점수가 아님.
- 분석 OFF여도 수동 진입 버튼 유지. 자동 누적값을 계산/보여주지 않으며 다시 ON하면 누적 0부터 시작하는 원래 정책 유지.

### 10.2 방식/분할/요일 → 원본 비교 → 시작 최종 확인

- 기존 루틴 주간 운동일 수에 따라 기존 유지 / 주 3일 / 주 2일 / 완전 휴식의 **가능한 횟수만** 제공(DL-23의 제약 유지).
- `주 3일 운동` 행의 **˅** 확장 → `PPL 방식` / `균등 분배`. 기본은 PPL이지만 원본 운동의 세부 PRIMARY 분할이 불가능하면 비활성화 및 이유 표기, 균등 자동 선택. PPL이 가능해도 사용자가 **균등을 직접 선택**할 수 있음.
- `주 2일 운동` → `전면·후면 방식` / `균등 분배`에 동일 원칙 적용. 기본 전면·후면, 불가능하면 비활성화 후 균등 선택. 분할 가능 여부는 표준 운동의 정확한 근육 매핑/자동 편성 검증에 의존.
- 방식 카드 **하단에서 시작 전에 요일 선택**. 3회는 3일, 2회는 2일 선택. 첫 제안은 시작일/+2/+4 또는 시작일/+3이며 사용자가 변경한 요일 유지, 연속 운동일 가능, 실제 시작일로부터 7일 범위.
- 상세 미리보기는 **운동일 카드만 표시**하여 휴식일 목록은 생략. 각 운동일 펼치기 → 종목별 `원본 루틴` vs `디로딩 추천` **중량·세트·반복** 비교. 상단에 선택한 PPL/전후면/균등 분배 결과 표시. 자동 추천값은 실제 원본을 기준으로 계산; 시연 수치는 가상. 원본에 없는 운동 자동 추가 금지.
- 시작 확정 화면은 선택 방식·요일·7일 권장/10일 최대·원본 보존만 요약. **시작 직전** 진행 중인 일반 세션이나 당일 실제 수행 기록(오프라인 원본 포함) 존재 검사 후 시작 허용. 목업은 서버 검사 성공을 주장하지 않음.

### 10.3 디로딩 시작 후 앱 전체 운동 환경 전환

- 사용자 의도: **기존 홈/루틴/기록/운동 진행/설정 UI를 최대한 재사용**. 디로딩 전용 기능/안내가 필요하면 추가 허용.
- 앱의 실제 상태(`IDLE`, `DELOAD_ACTIVE`, `DELOAD_COMPLETED_TODAY`)와 **조회 모드**(`DELOAD_VIEW`, `GENERAL_READ_ONLY`)를 분리. 헤더의 작은 `일반 보기` / `디로딩 복귀` 버튼은 **조회 전환만** 하며 실제 디로딩을 종료하지 않음. 일반 운동 기간에는 이 전환 버튼 숨김.
- 디로딩 화면에서는 **차분한 녹색 계열**을 상태/활성 탭/주요 버튼 등 소수 요소에 적용. 추천 게이지의 초록→적색 경고 변화는 **진입 전**에만 적용하고 진입 후에는 진행 일차(`D3` 등) 표시로 교체. 원형 버튼은 디로딩 상세/관리로 연결.
- 일반 화면 조회에서는 기존 데이터 조회만 허용. **원본 루틴 편집·삭제·실행 및 과거 일반 수행 기록 정정·삭제를 잠금.** 다만 공통 계정/세트 사이 휴식/카탈로그/디로딩 분석 등 설정은 잠그지 않음. 이 결정은 디로딩 v1.3의 `DL-04` 및 `DL-17` 중 원본 루틴 수정 허용과 **정책 충돌**하며 최신 사용자 합의가 우선.

### 10.4 홈 원형 버튼 + 기존 다섯 영역 재사용

- 기본 `HOME-01`의 메인 문구/① 오늘의 루틴/② 운동 시작/③ 오늘만 다른 루틴 선택/④ 주간 일정/⑤ 최근 운동/하단 네 탭 순서 **유지**. 별도 전체 임시 루틴 목록을 홈에 중복하지 않음. 전체 관리 목록은 **루틴 탭**에만 위치.
- ①~②: 오늘의 디로딩 임시 루틴을 표시하고 감량된 중량/세트 적용. 휴식일에는 `오늘은 휴식일`, 완전 휴식형에는 `완전 휴식`을 표시하며 운동 시작 숨김.
- ③: **아직 수행하지 않은 다른 임시 루틴**을 선택하면 현재 날짜에 배치된 루틴과 **기존 배정 날짜를 맞교환**. 원래 계획을 삭제하거나 중복 생성하거나 임시 목록에 남겨두지 않음. 완료된 루틴/날짜는 교환 대상 제외. 일반 운동의 기존 `오늘만 선택` 정책을 자동 수정하지 않음(디로딩과 구분).
- ④: **실제 디로딩 시작일부터 7일간**의 일정을 기존 주간 일정 UI로 표시. 오늘은 강조, 완료한 수행일은 ✓ 완료, 이미 지난 휴식일은 경과, 과거 미수행 예정일은 미수행, 미래는 예정/휴식. 날짜가 지났다고 무조건 운동 완료 처리하지 않음. 8~10일차는 기존 주간 일정의 다음 페이지처럼 표시(새 자동 루틴 생성 불가).
- ⑤: 현재 디로딩 기간의 최근 실제 운동 기록만 표시.

### 10.5 임시 루틴 탭·운동 진행·운동 종료

- 디로딩 중 `루틴` 탭에서만 **임시 루틴 전체 목록**. 기존 루틴 카드/상세/편집을 재사용하되 `편집`, `일정 변경`, `⋮ → 삭제` 제공.
- **미수행 임시 루틴 삭제 허용**, 삭제 날짜는 휴식일로 변경. 삭제한 종목/루틴 자동 보충/다른 날짜 자동 이동 없음. **전체 삭제도 허용**하고 디로딩 기간은 유지. 이미 수행한 루틴·실제 기록은 삭제나 일정 재배치에서 보호. 최초 선택 방식 기록은 유지하면서 남은 예정 건수만 달라짐.
- 일정을 빈 날로 이동할 수 있고 다른 미수행 루틴이 있는 날을 고르면 서로 날짜를 교환. 완료 계획과 실제 기록은 고정. 원본 루틴·공식 승인 중량은 불변.
- 기존 `WORKOUT-01/02/05` 준비·세트 기록·휴식·임시 편집을 재사용. 진입 후에는 `디로딩 n일차`, 감량 목표와 원본 목표 비교를 보조 표시. 당시 장비(제조사·부하 방식) 세트별 스냅샷을 보존.
- **계획 세트/종목이 남아 있어도 다음 종목으로 이동하거나 운동 종료** 가능. 수행한 세트만 실제 기록으로 남기고 `실패` 판정/디로딩 달성 강요 없음. **일반 승인 중량 및 증량·유지·감량 평가를 갱신하지 않음.** 운동 한 회차의 완료와 디로딩 전체 완료는 별개.

### 10.6 기록 탭과 과거 디로딩 이력

- 디로딩 중 `기록` 탭은 **현재 활성 디로딩 기간에 연결된 실제 세션**만 조회. 기존 기록 대시보드/운동 현황/근육 통계/운동 이력·세트별 상세/정정 기능 UI를 재사용. 이때 승인 중량 성장 추적은 제외.
- 일반 화면(읽기 전용)은 기존 전체 운동 이력과 통계를 조회. 디로딩 수행값도 **실제 전체 운동량·근육별 통계**에는 포함하되 **승인 중량/증감 평가**에서는 제외. 단순 날짜 필터가 아니라 **디로딩 기간 ID/세션 종류**로 기록 문맥 구분.
- 디로딩 수행 기록은 정정 가능하되 원래 계획·당시 장비·완료 시간 원본은 변경 불가. 일반 기록은 디로딩 중 읽기 전용. 미동기화 완료를 서버 확정 기록으로 가장하지 않음.
- 디로딩 완료 후 **기존 `기록 → 운동 이력`**에 기간 카드 추가. 시작/종료 날짜, 선택 운동 방식, 분할, 완료/자동 완료, 실제 세션과 당시 계획 보존. **완전 휴식 0회도 기간 이력 보존**. 완료된 임시 루틴을 일반 루틴 목록에 다시 나타내거나 재실행하지 않음.

### 10.7 종료·취소·7일 경과·완전 휴식

- 상단 작은 원형 버튼 → **디로딩 상세 하단**의 `디로딩 완료`(항상 가능)와 `디로딩 취소`(실제 수행 0회일 때만 가능)를 배치. 홈에 종료 버튼 없음. `일반 보기`는 종료 기능이 아님.
- 완료 시 **확인창 1회**: 실적/이력 보존, 유효 훈련 주수 0, 당일까지 디로딩 상태, **다음 날** 일반 운동 재개. 취소는 0세트·유산소 실제 수행 0건일 때만 허용, 기존 누적 주수 유지하며 즉시 일반 모드 복귀. 무수행 세션은 실제 이력으로 만들지 않음. **진행 중 운동이 있다면 먼저 세션 종료/취소를 요구**하며, 과거 실제 수행 기록을 나중에 정정·삭제해도 한때 수행한 사실이 있다면 디로딩 취소 허용으로 변경하지 않음.
- 7일차 자동 완료 금지. **8일차 이후 첫 앱 진입 시(운동 기록 도중 제외) 종료/계속 선택 팝업 1회**, `계속하기`는 기존 디로딩 상태 지속일 뿐 기간을 새로 생성하지 않음. 재팝업 없음. 9일차는 작게 권장 기간 경과 안내, **10일차 종료 시 자동 완료**, 11일차부터 원본 루틴 실행.
- 완전 휴식형은 ① 운동 시작/③ 다른 임시 루틴 선택 숨김, ④ 휴식일 경과 표시, 기록 0을 실패로 표현하지 않음, 별도 이력에 기간 보존. 기존 설정 탭은 그대로 재사용.

### 10.8 현재 구현 여부 및 보류

- **본 버전은 인터랙티브 HTML 저충실도 화면 시안이며, 앱/계정/서버/IndexedDB/DB를 수정하지 않음**. 실제 날짜/성공 동기화/서버의 편성 분석은 연결되지 않은 시연 데이터.
- 자동 분할 가능성 판단의 세부 PRIMARY/`jointType`/분할 실패 처리, 동기화/오프라인 중 상태 전환 원자성, 8일차 팝업 1회 확인 기록의 계정/기간 단위 보존, 완료 후 날짜 경계와 기록 정정 영향, 디로딩 재시작 제한/임시 루틴 편집 유효성 등은 **실제 구현 검증 대상**.
- 이번 UI 확정과 무관하게 기존 디로딩 계산·중량·세트·유산소 산식은 `Overload_Deloading_Design_Specification_v1.3.md`에 따라 유지하되, v0.7 대화에서 **명시적으로 변경한 UI/제품 정책만 최신 합의 우선**. 별도 v1.4 정책 통합본에 변경점 반영.

## 10.9 v0.8 · 통계 UI 개선 및 디로딩 시작 자격 (2026-11-04 당시 기록)

> 아래 다섯 조건/계획2일 gate는 폐기 이력이다. 현재 자격·분석은10.15절과 디로딩v1.7을 따른다.

### 운동 현황 그래프와 필터

- 기존 v0.7의 `운동 현황` 상단 **운동량 요약은 기간 전체 값**으로 보존한다. 하단 `운동량 상세` 카드의 필터를 **운동량 추이 차트 위**로 옮기고, 중복 합계 카드는 차트 카드 내부로 통합한다.
- `전체 / 운동별 / 근육별`과 `세트 / 총중량`, 조회 기간을 바꾸면 **선택한 범위의 실제 완료 세트 막대그래프와 선택 합계가 동시에 변경**된다. 총중량은 실제 중량×실제 반복 횟수 합계. 실제 수행 데이터가 없다면 `실제 수행 기록 없음`을 보여주되 ‘계획 없음’과 혼동하지 않는다.
- `운동별`은 해당 기간에 실제 수행한 표준 운동을 선택한다. 과거 루틴에서 삭제된 종목도 실제 수행 이력이 있으면 대상이며 표준 UUID 기반. 운동별 제조사 상세는 기존 경로를 재사용한다.
- `근육별`은 **가슴·등·어깨·팔·하체·코어의 대분류만** 필터로 선택한다. 세부 근육 PRIMARY/SECONDARY는 `근육별 통계`에서 확인한다. 동일 세트가 한 대분류 내 여러 세부 PRIMARY에 연결되어도 대분류 합계에서 중복 집계하지 않는다. 유산소는 기존 독립 통계를 유지한다.
- **와이어프레임 한계:** 주간/월간 수치, 운동 선택 목록, 그래프는 UI 반응을 보기 위한 예시이며 실제 DB·날짜 이력을 조회하지 않는다. 운영 화면은 실제 수행 데이터로 필터 조건을 계산해야 한다.

### 성장 추적의 종목 검색

- **검색 가능한 종목 목록**과 공통 검색 UI를 사용한다. 검색·선택 범위는 현행 성장 추적 계약과 10.18.2절을 따른다.
- 종목을 바꾸면 **해당 표준 운동의 공식 승인 중량 이력**만 표시한다. 승인 중량이 없으면 빈 상태를 표시하고 일반 세트 실제 중량이나 디로딩 중량으로 차트를 채우지 않는다.
- 기존 1/3/6개월/전체, 공식 승인 이력 차트·기록 구조 유지.

### 근육별 SECONDARY 상세

- 기존 대분류/PRIMARY 세부 근육 레이아웃 유지. `SECONDARY · 보조근 참여`를 펼치면 세부 보조근별 **참여 완료 세트 수**를 조회한다.
- 보조근 참여 세트는 PRIMARY 합계에 합산하지 않으며, 같은 세트가 여러 보조근에 참여해도 모두 더한 수를 총 운동 세트라고 부르지 않는다. 실제 집계는 관리자 표준 운동 카탈로그 매핑을 따른다.

### 디로딩 시작 자격: 분석 ON/OFF와 독립

- **모든 디로딩 시작(분석 ON/OFF 동일)**에 다섯 가지 검사를 적용한다: ① 현재 적용되는 주간 원본 운동 계획 **2일 이상**, ② **오늘을 제외한 직전 7일**에 실제로 수행한 일반 웨이트 세트 또는 유산소 기록 **1건 이상**, ③ 이전 디로딩을 완료한 적이 있다면 **그 이후 새로운 일반 운동 수행**, ④ 오늘 실제 운동 수행 없음, ⑤ 활성 일반 운동 세션 없음.
- ‘최근 7일’은 오늘을 제외한 이전 **7개 현지 달력 날짜**를 뜻한다(예: 2026-11-04 시작이라면 2026-10-28~11-03). 운동을 시작만 했지만 실제 수행이 0건인 세션은 근거가 되지 않는다. 디로딩 세트 자체는 일반 운동 자격 기록으로 세지 않는다.
- 기존 누적 유효 훈련 주수 0%는 자격 거절 이유가 아니다. **추천 게이지는 시점 안내, 시작 자격은 실제 운동 기록의 최소 조건**으로 분리. 4~8주 유효 주수 계산, 분석 OFF의 자동 계산·게이지·알림 비노출 및 ON 재활성화 시 0에서 시작 정책은 변경하지 않는다.
- 디로딩 상세에서 5개 조건을 확인하도록 표시한다. 미충족이면 `디로딩 시작` 버튼 비활성화, 이유 안내. 최종 시작 확정 순간 동일 조건을 다시 검사한다. 별도 새 페이지는 만들지 않는다.
- 실제 서비스에서는 현재 주간 일정 **적용일과 시간대**, 지난 7일의 **수행일(동기화 날짜 아님)**, **오프라인 미동기화 완료 원본**, 이전 디로딩 종료 시점과 현재 활성 세션을 검증해야 한다. 초기 상태/일정이 없는 사용자는 시작할 수 없고, 운동 계획 2일 이상과 실제 최근 수행이 필요하다. 앱/서버 구현 완료를 의미하지 않는다.
- 이미 시작한 디로딩에서 모든 임시 루틴을 삭제하거나 0회 운동해도 정상 진행/완료 가능하다는 기존 원칙은 그대로다. 진행 중인 디로딩을 분석 OFF로 바꿔도 유지된다.

### 부가 UX·현재 시안의 범위

- 디로딩 중 오늘이 **빈 휴식일**인 경우, 홈에서 `디로딩 일정 변경` 링크를 통해 기존 루틴 탭으로 이동하게 한다. 완전 휴식형에는 해당 링크가 없다. 새로운 루틴 생성/자동 추가 기능이 아니다.
- 신규 사용자, 기록 없음, 승인 중량 없음, 계획 없는 근육의 **빈 상태**는 기존 정책을 유지하며 확인 가능한 화면에서 예시를 보강한다. 오프라인 저장·동기화 상태는 기존 데이터 상태 UI를 유지하고 실제 저장/ACK 구분은 구현 검증 대상이다.
- v0.8 HTML은 **기존 47개 화면을 그대로 유지**하고 필요한 컴포넌트만 변경. 디로딩 시작 조건의 다양한 사례는 오른쪽 **시연 패널**에서 테스트할 수 있으며, 이는 사용자가 앱에서 직접 설정하는 항목이 아니다.
- 사용자는 v0.8 HTML 전체를 직접 클릭해 본 뒤 v0.9 수정안을 전달한다. 이때 검토 피드백으로 합의가 변경되지 않는 한 추가 임의 변경은 하지 않는다.

### 10.10.5 기존 정책과 충돌하지 않아야 할 내용

1. 디로딩 추천 분석 ON/OFF는 **권장 주수·게이지 계산**에만 영향. 분석 OFF에서도 **주간 계획 2일 이상 + 오늘 제외 직전 7일 내 일반 실제 수행 + 이전 종료 후 신규 일반 수행 + 당일 수행 없음 + 활성 일반 세션 없음**을 검사해 수동 시작 가능(DL-80~84); 0% 숫자만으로 시작 차단하지 않음.
2. 디로딩 기간은 권장 7일, 10일차 종료 시 자동 완료; 완료한 당일 일반 운동 시작 불가, 다음 날 복귀. 전부 쉬거나 미수행 임시 루틴을 전부 삭제해도 디로딩 지속·정상 완료 가능.
3. 실제 디로딩 세트는 운동 이력/근육 통계에는 포함하되 **일반 공식 승인 중량 평가에서는 제외**. 각 세트의 실제 수행 당시 제조사·부하 방식/계획은 불변 원본으로 보존.
4. 통계 v0.8의 범위 필터 연동, 성장 추적 검색, 보조근 펼침도 보존. 유산소 시간·거리와 웨이트 볼륨을 무분별하게 합치지 않음.
5. 본 HTML의 고정 날짜·예시 수치·시연용 자격 패널은 **제품 정책 또는 실데이터가 아니다**. 독립 HTML에는 API·인증·IndexedDB/서버 ACK가 연결되어 있지 않다.

### 10.11.3 홈 '이번 주 일정'의 지난 날짜 상태

- 7열은 **날짜 숫자 / 요일 또는 수행상태 / 루틴명**의 3단 구조.
- **과거 예정 운동 완료일**: 요일을 제거하고 해당 자리에 어두운 초록 `✓` (`#74A68A`).
- **과거 예정 운동 미수행일**: 요일을 제거하고 해당 자리에 어두운 빨강 `×` (`#B17B83`).
- **과거 휴식일**: 요일을 제거하고 같은 자리에 어두운 중립색 `-` 표시. 이 기호는 완료 판정이 아니다.
- 오늘/미래 날짜는 기존 **요일 글자** 유지; 오늘은 모드 메인 컬러로 테두리/배경 등을 강조. 과거 날짜 숫자와 루틴명은 각각 어둡게 하되, 상위 `opacity`로 ✓/×까지 흑백·희미하게 만들지 않는다.
- 상태는 **해당 날짜의 승인/확정된 계획과 실제 수행 기록의 제품 판정**에 근거한다. 단순 지난 날짜/세트 일부/세션 시작만으로 완료로 판단하지 않는다. 서버 연동 전 목 시나리오(11/02 ✓, 11/03 ×, 11/04 -, 11/05 목)는 표시 예시에 불과. 정상/디로딩은 각자 해당하는 일정·수행 기록에 따라 판정한다.
- 날짜 선택 시 전체 루틴명과 수행 상태 표시 동작 유지. 7열/모바일 터치 간격 보존.

### 10.11.4 홈 분석 ON — 디로딩 누적주 게이지 (기존 초록→노랑 규칙 대체)

- 분석 ON·미진행 헤더에서 **0주부터 항상 가늘고 긴 수평 트랙**을 표시한다. `0/8주`일 때는 트랙만 보이고 채움 길이는 0. 분석 OFF일 때만 게이지 미노출.
- 채움 길이 `clamp(유효 훈련 주수 / 8, 0, 1)`; 8주 이상 100% 유지. 이 게이지는 피로도/의료적 위험 점수가 아닌 **디로딩 추천 누적 유효주**다.
- **0 ~ 4.0주(4.0 포함): Dusty Blue `#6C93C6`**. 회색/초록이 아니라 일반 모드 메인 컬러.
- **4.0주 초과부터** 노랑 → 주황 → 빨강 계열로 점진 변화하여 8주에서 빨강 고정. 실제 UI의 경고색 후보는 노랑 `#D6BC65`, 주황 `#D98D55`, 빨강 `#C96763`. *이 세 HEX는 미세 조정 가능한 경고색 후보*이며 시작 경계(4.0 포함)와 변화 방향은 확정.
- 4주 이하의 게이지를 숨기는 과거 결정, 4주부터 초록색으로 바꾸는 과거 규칙, 단순 모드 주 강조색만 고정 표시하는 Spike 시안은 **채택하지 않는다**.

### 10.11.5 운동 진행 — 종목 구간 **누적** 채움

- 상단 중앙은 `현재 x / n종목`과 **n개 구간**. 1기반 `index`에서 `i < index`, 0기반 `position`에서 `i <= position`인 칸이 모두 채워진다.
- 예: 4종목 중 2번째 **`[■ ■ □ □]`**, 3번째 **`[■ ■ ■ □]`**. 해당 종목 한 칸만 켜지는 `[□ ■ □ □]` 시안은 잘못된 표시다.
- 이전 종목으로 탐색하면 채워진 칸도 위치에 맞춰 감소. **완료한 세트/종목 수나 수행률이 아니라 현재 탐색 위치** 표시다.
- 일반·디로딩 공통이며 전체 운동 시간/휴식 시간 3열, `기존 기록 | 이번 기록`, 반복 ±/입력 구조 유지.

### 10.11.6 운동 검색 아이콘 자산 분리

### 10.14.4 생성·편집·상세 공통 폼

- `RoutineForm` 하나의 생성/편집/읽기 전용 모드다. 이름·태그 라벨/간격/44px 입력 높이/경계/배경을 통일한다. 태그는 미지정+10종 중 optional 하나, 기존 승인 설명이 있는 드롭다운이다. 선택 후 태그명만 표시하며 칩 목록·자동 분류를 사용하지 않는다.
- 웨이트 카드 상단은 이름/변경, 하단은 동일 너비 **위로 / 아래로 / 제거**. 세트·최소·최대 3열, 최초 중량/승인 문맥·장비 입력은 현재 계약을 따른다. 유산소도 기존 공통 `CardioPlanFields`와 하단 3개 조작을 재사용한다.
- 웨이트 추가·변경은 같은 `ExerciseSearch` 인라인 목록을 사용한다. 기존 검색 라벨·이름/별칭 검색·32px 공식 아이콘·대분류/PRIMARY 표시를 유지한다. 새 자동완성 카드 시스템은 도입하지 않는다. 열 때 검색 영역으로 스크롤·포커스하며 다른 입력 초안은 유지한다.
- 다른 표준 운동으로 변경하면 새 배치이며 기존 승인/최초 중량을 새 운동에 전이하지 않는다. 같은 종목 재선택은 원배치를 유지한다. 최초 계획·완료 기록/고정 요청을 재작성하지 않는다.
- 상세는 동일 폼의 읽기 전용 모드로 입력·추가·변경·제거를 막고 **편집 / 삭제 / 닫기**를 제공한다. 삭제 확인은 기존 절차를 사용한다. 별도 펼침 상세 영역을 추가하지 않는다.

### 10.14.5 주간 일정 편집과 저장

- 목록과 별도 편집 보기. 월~일 7개 선택창, 휴식, 동일 루틴 복수 요일, **단일 저장·즉시 적용**이다. 사용자용 일정 변경 이력은 표시하지 않는다. Backend 버전 이력/과거 판정 근거는 보존한다.
- 후보 필터는 `배정 유무 ▾ / 태그 ▾ / 전체 보기` **정확히 3개를 320px에서도 한 줄**에 둔다. 배정 하위는 배정 완료/미완료, 태그 하위는 조회한 루틴에 실제 존재하는 태그다. 하위 선택은 기존 버튼형 디자인, 선택한 PUSH는 접두어 없이 PUSH만 표시한다.
- 필터는 단일 선택이며 필터·팝오버 전환 시 7개 배정 초안을 변경하지 않는다. 후보에서 제외된 선택도 원래 이름으로 유지하고 `· 선택 유지`를 붙이지 않는다. 선택창 너비/높이/말줄임 위치는 고정한다.
- 실제 저장은 [immediate-v1 계약](../../../overload-server/docs/api/weekly-schedule.md)의 expectedVersion/dataGeneration/timeZone/assignments를 사용한다. 저장 전 최신 version 확인, 저장 응답과 최신 GET의 version/assignments/appliedAt을 검증한다. 조용한 버전 병합·예약 저장은 없다.
- 루틴 CRUD와 일정 PUT은 별도다. 충돌 요일·기존 루틴을 확인하고 교체하며, 루틴만 성공하면 부분 성공을 알리고 일정만 재확인한다. ACTIVE/미동기화 운동·인증·계정/세대·IndexedDB·snapshot/ACK/writerEpoch 보호를 유지한다.

## 10.15 · 2026-11-07 디로딩 v1.7 표현 정정

이 절은 디로딩 정책 안내를 정리하며 T02-A/T02-B 레이아웃을 변경하지 않는다. 과거10.9/10.10의 계획2일·다섯 조건·원형 게이지/전역 전환 표현과 구버전 변경 이력은 당시 기록으로 보존한다.

- 현재 자격은 최근7일 실제 일반 수행/이전 완료 이후 새 수행/오늘 수행 없음/ACTIVE 일반 세션 없음의4조건이다. 계획0~1일·OFF·게이지0도 다른 네 조건을 충족하면 시작 가능하다.

- 신규 계정은 **기본 ON·누적0의 초기 epoch**로 시작한다(2026-11-07 추가 확정). 최초 ON은 OFF→ON 전환이 아니다. OFF→ON은 새 epoch·누적0이며 OFF/활성화 전 기록을 소급 가산하지 않는다. 기존 미설정 계정은 G4의 명시적 이행 경계를 검증한다. HTML 초기 ON·개발용5.2주는 시연이며 실제 서버 설정·누적을 증명하지 않는다.

- 디로딩은 자기InitialPlan의 최고 단일 후보를 날짜별로 고른 E/N·E≤1 RESET·월요일04시 이후 확정·주중 미가산이다. 일반ST-17~23은 별도다. OFF도 G3/일반통계를 중단하지 않는다. 정지·완료/취소 경계와 기존 감량/편성 수치는v1.7을 따른다.
- 이 절 작성 당시에는 G0~G3를 구현했고 G4/G5는 미구현이었다. 2026-11-08에는 G0~G5-3 Backend 구현을 확인했으며 G6 실제 PWA 연동과 기존 DB 적용은 후속이다. 최신 HTML의 자격 시연은4조건과 기간 상태 제약으로 정정하며 서버 결과를 생성하지 않는다.

## 10.16 · 다중 주간 루틴 일정과 자동 순환

**확정 UX · V30·V31 연동.** 아래는 신규 프리셋의 화면과 조작 기준이다. 서버의 적용·순환·복구·쓰기 제한은 [주간 일정 계약](../../../overload-server/docs/api/weekly-schedule.md), 디로딩 원본과 복귀는 [G5 기간 계약](../../../overload-server/docs/api/deload-periods.md#주간-일정-프리셋과-순환-복귀)에서 확인한다. [HTML](Overload_UI_Baseline_Wireframe_v0.9.html)은 합성 시연이다. 기존 단일 일정 UI는 10.14절에 기록돼 있다.

### 운동 루틴과 주간 일정 프리셋

- **운동 루틴**은 운동 종목·세트·반복·중량과 기존 수행·기록·성장·승인 흐름을 담당한다. **주간 일정 프리셋**은 월~일에 배정한 기존 운동 루틴 ID만 관리한다. 여러 프리셋에서 같은 루틴을 서로 다른 요일에 참조할 수 있다. 운동 구성 편집은 요일 배정을 바꾸지 않고, 프리셋 편집은 운동 구성·수행 기록·성장·승인에 영향을 주지 않는다. 프리셋 자체에 별도 성장·승인 사이클은 없다.
- 최대 4개다. 신규 계정은 요일 배정이 비어 있는 **1번 프리셋 하나**와 **자동 순환 OFF** 상태로 시작한다. 자동 순환의 초기 OFF는 별도 G4 분석 설정과 독립적이다. 표시 번호는 현재 정렬 결과다. 내부 데이터는 표시 번호와 독립적인 안정적인 ID를 사용한다.
- 기존 계정과 데이터의 전환 범위는 [V1 출시 전 전환](../../../overload-server/docs/api/weekly-schedule.md#v1-출시-전-전환)을 따른다.
- `+`는 월~일 배정이 없는 빈 프리셋을 생성한다. 새 프리셋은 자동 순환에서 기본 제외하며, 생성만으로 활성 프리셋과 순환 위치는 바뀌지 않는다.
- 현재 활성 프리셋과 마지막 1개는 삭제할 수 없다. 자동 ON에서 삭제 후 포함 프리셋이 2개 미만이 되거나 디로딩 보호 중이면 삭제할 수 없다. 서버에서 실제 활성·보호·포함 상태를 검증한다. 삭제해도 과거 적용 이력·세션·확정 근거는 유지한다.

### 적용과 자동 순환

| 동작 | 적용 결과 |
| --- | --- |
| 번호 선택 | ON/OFF 모두 조회 중인 프리셋만 바뀐다. 가능한 범위에서 기존 조회 결과를 활용해 로컬로 전환한다. |
| 자동 OFF에서 `전환` 선택 | 보고 있는 프리셋의 적용 요청을 보낸다. 성공 후 활성으로 표시한다. |
| ON → OFF | 자동 순환을 멈추고 현재 활성 프리셋을 유지한다. |
| OFF → ON | 포함 2개 이상일 때 첫 번째 포함 프리셋을 즉시 적용한다. 이후 월~일 고정 주차를 기준으로 순서대로 돌고 마지막 다음에 첫 번째로 돌아간다. |
| 활성 프리셋의 요일 배정 저장 | 기존 즉시 적용 정책으로 반영한다. 순환 위치는 유지한다. |
| 비활성 프리셋의 요일 배정 저장 | 해당 프리셋만 바뀐다. 현재 적용 일정과 순환 위치는 유지한다. |
| 전체 편집 저장 | 포함 여부 또는 전체 순서가 달라지면 ON에서 첫 포함 프리셋부터 다시 시작한다. 제외 그룹 내 순서 변경도 포함한다. OFF는 활성 프리셋을 유지하고, 무변경 저장은 순환 위치를 유지한다. [서버 기준](../../../overload-server/docs/api/weekly-schedule.md#자동-순환-설정) |

수요일에 적용하면 적용 가능한 수요일 이후에 새 배정이 반영된다. 월·화의 당시 계획과 기록, 기존 START·최초 MISS·InitialPlan 등 고정 근거는 보호한다. 순환 ON/OFF는 G4 분석 설정과 별개다. 매주 로컬 월요일 00:00부터 전환 대상이며 실제 적용 시각부터 효력이 발생한다. ACTIVE 보류와 서버 중단 복구는 [자동 순환 적용과 세션 보호](../../../overload-server/docs/api/weekly-schedule.md#자동-순환-적용과-세션-보호)를 따른다.

### 루틴 탭과 전체 편집

- **변경 이력**. 초기 다중 일정안의 채운 별·빈 별과 공통 상태 슬롯, 이후 조작 아이콘 옆 상태 태그를 거쳐, 2026-11-09~10 사용자 피드백 반영으로 제목 행 오른쪽 태그를 확정했다. 실제 활성은 `✓ 진행중`, OFF의 다른 일정은 위쪽 오른쪽·아래쪽 왼쪽 화살표가 겹쳐진 SVG와 `전환`, ON의 다른 일정은 눈 SVG와 `보기`다. `보기`의 접근성 이름에는 조회 전용임을 표시한다.
- 다음 행은 번호·이름, 순환 → 가로/세로 → 메뉴 아이콘 순서다. 아이콘에 보이는 사각 배경과 테두리를 제거하고 기존 터치 영역·포커스를 유지한다. 세로 보기의 요일과 루틴 사이에 여백을 두고 오른쪽 종목 수와 긴 이름의 줄임표를 유지한다. 원형 조회 번호와 `+`는 카드 아래 중앙에 둔다.
- **ROUTINE-06**은 루틴을 먼저 고르고 요일을 일괄 교체하던 초기안을 대체한다. 조회 중인 프리셋의 월~일 독립 드롭다운에서 루틴 또는 휴식을 고른다. 배정 유무·태그·전체 보기 필터와 변경 전후 확인을 제공한다. 루틴 저장 성공 후 한 번 `✓ 새 루틴 생성 완료`, 실제 루틴 이름, `주간 일정에 배정할까요?`를 표시하고 `나중에`와 `배정하기`를 제공한다. 배정 편집에서만 새 루틴을 `✦ 새 루틴 · 이름`으로 상단에 강조하며 요일은 직접 선택한다.
- 메뉴의 이름 편집은 처음에 시연 전용이었고, V31에서 `이름 변경`의 실제 저장이 추가됐다. 이름 변경으로 조회·적용 일정과 배정·순환을 바꾸지 않는다. 전체 편집과 삭제는 기존 메뉴에 둔다. 삭제와 순환 재시작의 조건은 [서버 계약](../../../overload-server/docs/api/weekly-schedule.md#자동-순환-설정)을 따른다.
- **ROUTINE-07**의 포함·제외 목록은 두 줄 정보 왼쪽에 32px 정사각형 번호를 가운데 정렬한다. 작은 `추가`·`제외` 버튼은 다른 그룹의 끝으로 옮긴다. 위아래 버튼 대신 핸들을 사용한다. 마우스·터치로 끄는 동안 카드가 따라오고 주변 카드가 이동한다. 키보드 순서 조작을 유지한다. 취소는 초안을 폐기하고 저장은 구성 전체를 한 번에 보낸다. ON에서 포함 2개 미만은 저장할 수 없다.
- 저장된 루틴 목록에는 `전체 / 최신순 / 오래된순 / 이 일정 배정 / 이 일정 미배정`을 제공한다. 배정과 요일 필터는 조회 일정 기준이다. 루틴 구성의 변경과 요일 배정은 각각 저장한다. 루틴 삭제 시 모든 프리셋의 배정을 해제하고 과거 기록을 보존한다. [현행 화면 명세](ui-ux.md#32-루틴-목록--routinelist)

### 홈과 디로딩

- 초기안의 `현재 주차` 필터와 루틴 검색은 사용자 피드백 이후 제거했다. 최종 구성은 `전체 / 미배정 / 저장된 일정 번호(01~04)`다. 기본 선택은 실제 활성 일정 번호이며, 미배정은 모든 프리셋 기준이다. 제외 프리셋도 조회할 수 있고 루틴 ID로 중복을 제거한다. 선택은 오늘 카드만 바꾸며 기존 START·InitialPlan·기록 정책을 사용한다.
- 디로딩 보호 중 일반 프리셋과 순환 목록은 조회할 수 있다. 관리·활성화·순환 변경은 잠기고 기존에 허용된 임시 계획 편집은 유지한다. 미리보기·시작에서 디로딩 원본 프리셋을 선택할 수 있으며 기본은 활성 프리셋이다. 제외된 프리셋도 원본으로 선택할 수 있다. 정지·복귀와 원본 선택의 도메인 규칙은 [디로딩 v1.7의 프리셋 연동](Overload_Deloading_Design_Specification_v1.7.md#105-주간-일정-프리셋-연동)을 따른다.

## 10.17 · 휴식 타이머 시각·효과음 알림

**정책 확정 · v0.9 HTML 시연 · T03.5 구현 예정.** 웨이트 본세트 사이의 휴식 종료가 가까워졌음을 화면과 소리로 알린다. 기존 휴식 카운트다운, 세트·운동 기록과 저장 방식은 유지한다.

### 시각 알림 범위와 동작

- 색상 반전 범위는 최상단 개발 데모·상태 표시 아래, `홈 / 루틴명 / 운동 종료` 탐색 영역 위에 있는 **3열 시간 정보 바 전체**다. 전체 운동 시간·운동 진행·휴식 시간의 배경과 내부 텍스트를 함께 반전하고, 진행 바의 채움·트랙도 구분할 수 있는 대비를 유지한다. 상태 표시, 탐색, 운동 종목, 세트 카드, 하단 고정 버튼 및 나머지 화면은 기본 색을 유지한다.
- **B 방식**으로 매초 한 번 짧게 반전한 뒤 같은 초 안에서 원래 색으로 돌아온다. 5초 전 설정에서는 5·4·3·2·1초, 10초 전 설정에서는 10초부터 1초까지 적용한다. 0초 또는 수동 `휴식 종료`에 즉시 기본 색으로 돌아온다. `+30초` 뒤에는 새 종료 시각에서 계산한 실제 남은 초로 다시 판단한다. HTML에서 선택한 짧은 반전 시간은 시연값이다.
- `prefers-reduced-motion`에서는 반복 반전을 정적인 테두리 등으로 대체한다. 카운트다운과 기존 10초 이하 `다음 세트 준비` 안내는 계속 표시하며 색만으로 종료 임박 상태를 전달하지 않는다. 반전이 자동 스크롤이나 포커스 이동을 유발하지 않게 한다.

### 효과음과 설정

- **설정 → 운동 설정 → 휴식 타이머 알림**에서 **화면 깜빡임 ON**, **시작 시점 5초 전**, **효과음 ON**이 기본이다. 시작 시점은 10초 전 또는 5초 전이며 화면 깜빡임이 OFF이면 선택을 비활성화한다.
- 효과음 ON은 시각 알림과 독립적으로 **5·4·3·2·1초에 한 번씩** 짧게 재생한다. 시각 알림을 10초 전으로 바꿔도 효과음 시작은 5초 전이다. 재생 실패와 운동 기록 저장은 분리한다. [과거 핸드오프](../handoff/Overload-Project-Handoff-Task001-005.md)의 무음 정책은 이 효과음 설정으로 대체한다. 진동 금지와 전체 화면 플래시 금지는 유지한다.
- 실제 앱에서는 변경값을 앱 재실행 후에도 유지한다. 180·120·90초 등의 기존 `세트 사이 휴식` 값과 분리하고, 필요한 경우 기기 로컬 설정을 사용한다. 전용 Backend API나 DB 변경을 전제하지 않는다.
- T03.5에서 사용자 조작에 따른 오디오 활성화, 브라우저 자동 재생 제한, 음악 앱과 동시 재생, 화면 잠금 및 백그라운드 복귀를 iPhone Safari와 설치형 PWA에서 확인한다. 현재 [HTML 시연](Overload_UI_Baseline_Wireframe_v0.9.html)은 탭 안에서만 설정과 카운트다운을 바꾸고, 효과음은 예정 시점을 텍스트로 표시한다. **실제 PWA 구현과 iPhone 실기기 검증은 예정 상태다.** [Frontend 구현 지침](../engineering/frontend.md#t035-휴식-타이머-시각효과음-알림)

## 10.18 · 2026-11-11 공통 운동 검색 UI·CATALOG-02 1차 확정

**적용 범위:** 이번에 독립 HTML 두 종류(CATALOG-01 전체 펼침, STATS-02 접이식 운동별 필터)를 사용자 피드백으로 조정하고, 통합 무채색 HTML에 적용한 UI 결정. **실제 Backend API 연결·운영 DB 마이그레이션·원본 GIF 제공 권한 승인은 포함하지 않는다.**

### 10.18.1 공통 검색 외형

- 검색 라벨은 `표준 운동 검색 · 이름 또는 별칭`, 입력 예시는 `예: 벤치, barbell`. 운동명·별칭에 입력을 적용한다.
- `전체·가슴·등·어깨·팔·하체·코어·유산소·기타`의 27px 높이 둥근 텍스트 태그를 한 줄로 유지하고 가로로 스크롤한다. 태그에는 아이콘을 사용하지 않는다.
- 32px 원형 공식/확장 아이콘, **운동명 + `대분류 · 핵심 PRIMARY`** 2줄, 구분선과 오른쪽 `›`를 동일 간격/타이포그래피로 사용한다. 선택형 목록의 `›`는 해당 항목이 눌린다는 의미이며 설정 목록에서만 상세 페이지로 이동한다.
- 새 어깨·팔·코어 아이콘은 사용자가 제공한 그림을 기존 회색 아이콘 테마로 변환해 사용한다. 유산소는 원래 걷기 아이콘을 재활용한다. 기타는 자산 미제공 시 `ETC` 문자 표시를 허용한다.
- 검색 결과가 없거나 해당 필터에 데이터가 없으면 `검색 결과가 없습니다.`. 실제 운동명/별칭/PRIMARY/아이콘 매핑은 서버 연동 시 검증해야 한다.

### 10.18.2 화면별 펼침/닫힘과 선택 범위

| --- | --- | --- | --- |
| **CATALOG-01 설정 → 운동 종목 보기** | 항상 펼침 | 없음 | 행 전체를 누르면 CATALOG-02 상세 |

- 닫기 버튼은 **검색 입력 옆이 아니라 펼친 검색 UI의 `운동 종목` 제목 오른쪽 끝**이다. 닫으면 선택값은 유지하고 검색·태그·목록을 접는다. 결과 선택 시에도 자동으로 닫는다. 팝업 검색은 기존 오버레이를 닫는다.
- 접이식 목록은 열린 동안 필터를 좌우 스크롤하고 결과 목록만 최대 높이 범위 안에서 세로 스크롤하여 아래 그래프를 과도하게 가리지 않는다.
- STATS-02는 `전체/운동별/근육별`, `세트/총중량`, 조회 기간을 유지한다. 운동별 선택에는 접이식 공통 검색 UI를 적용한다. Backend가 기존 완료 운동 기록을 현행 정책으로 집계하고 PWA는 선택한 범위의 집계 결과를 표시한다. HTML의 그래프와 합계는 UI 시연용 예시다.
- 성장 추적은 검색 UI와 펼침·닫힘 동작을 변경하고 [현행 성장 추적 계약](../../../overload-server/docs/api/approved-weight-growth.md)의 조회 범위를 유지한다. 선택 기간에 유효한 완료 웨이트 세트 또는 공식 승인 중량 변경 이력이 있는 운동을 검색한다. 공식 승인 이력만 있는 종목, 비활성·미공개 종목 및 삭제된 루틴·배치의 과거 이력도 기존 계약에 따라 조회한다.
- 운동 현황의 운동별 검색에는 해당 기간의 실제 수행 종목을 사용한다. 화면마다 기존 데이터 소스와 선택 조건을 유지한다.
- 루틴·운동 진행 화면은 기존 세트 목표, 장비 제조사, 부하 방식, 임시 변경 등의 폼/선택·복귀 절차를 변경하지 않는다.

### 10.18.3 표준 상세·Backend 후속 정리

- CATALOG-02의 분할 태그/핵심 PRIMARY/미제공 GIF/접힌 방법/빈 상태 기준은 8.3절을 적용한다.
- 제조사·머신·부하 방식 선택은 사용자 루틴 배치와 진행 운동에서 제공한다.
- **확정 정책 / 실제 GIF 표시 미구현.** 인증·인가는 [Spring Security 세션 계약](../../../overload-server/docs/engineering/security-session.md#http-보안-계약)과 [V35 보호 전송 계약](../../../overload-server/docs/api/standard-exercise-catalog.md#보호-gif-전송과-ui-계약)을 적용한다. 회원별 권한, 현재 대표 출처, 파일 유무와 보호 미디어 미캐시 정책을 따른다. 표준 운동 UUID로 원본 ID나 GIF URL을 추정하지 않는다. 현재 GIF 안내 UI를 유지하며, 보호 경로 전달·권한 및 파일 부재·전송 실패 표시와 최종 안내 이미지는 후속 연동에서 처리한다. 실제 파일 권리·배포 조건 충족 전에는 기능을 활성화하지 않는다.
- **확정 정책 / PWA 공통 검색·상세 연동 미구현.** 10.18절의 검색·선택 UI와 첫 PRIMARY의 `핵심` 표시는 후속 PWA 작업이다. 기존 조회·선택 API와 정렬·검수 계약을 유지한다.

### 10.18.4 운동 진행 중 종목 교체

**확정 정책 / 미구현.** 현행 PWA에는 종목 추가와 제외가 있다. 교체 조건과 초기값은 아래를 적용한다. HTML WORKOUT-06의 즉시 교체·0kg 설명은 이전 시안 기록이다.

- 유효한 완료 세트가 없는 종목만 교체할 수 있다. 완료 세트가 있으면 교체할 수 없으며, 사용자가 완료 기록을 명시적으로 취소해 유효한 완료 세트가 모두 없어지면 교체할 수 있다.
- 교체는 현재 세션에만 적용한다. 원본 루틴과 공식 승인 중량을 보존한다. 취소하거나 저장에 실패하면 기존 세션 상태와 로컬 스냅샷을 유지한다. [세션 보존 계약](../../../overload-server/docs/api/workout-sessions.md#교체삭제정정)
- 교체 전 운동의 중량·반복값을 새 운동에 복사하지 않는다. 새 운동의 과거 기록이 있으면 기존 시스템이 지원하는 중량·반복 등의 초기값 자동 입력 로직을 우선 재사용한다. 해당 로직의 존재 여부는 구현 단계에서 확인하며, 장비·부하 방식별 초기값 계약이 있다면 유지한다. 자동 입력값은 사용자가 수정할 수 있다. 새 운동의 과거 기록이 없으면 입력값을 비워 둔다.

### 10.18.5 성장 추적 검색 메타데이터

**확정 정책 / 공통 검색과 메타데이터 보강 미구현.** 검색 대상, 기간, 조회 자격과 승인 중량 그래프·기록은 10.18.2절과 기존 성장 추적 API를 따른다. 이름·별칭·부위 검색은 기존 이력 접근 범위에서 제공한다.

- 근육 정보가 없는 과거 운동은 기존 자격을 충족하면 `전체`에서 조회할 수 있다. 부위별 필터에는 포함하지 않는다.
- 해당 결과에 공통 기본 아이콘과 `근육 정보 없음` 보조 문구를 표시한다. 조회 자격이나 기존 승인 이력 표시를 변경하지 않는다.

### 10.18.6 운동량 추이와 디로딩 표시

**확정 정책 / 선택 범위의 날짜별 집계·디로딩 그래프 표시 미구현.** Backend는 기존 완료 운동 기록을 집계하고 PWA는 집계 결과를 표시한다. 선택 종목·근육의 날짜별 완료 세트·총중량은 기존 통계 설계에 따라 후속 구현한다. 날짜 귀속, 정정·삭제·복구, 디로딩 중 실제 수행 포함, 맨몸 추가 부하 규칙은 현행 계약을 유지한다. [현행 통계 API](../../../overload-server/docs/api/statistics.md#statistics-응답과-실제-집계)

- **디로딩 표시 B안.** 주간·월간 운동량 그래프에서 디로딩 날짜와 구간을 시각적으로 구분하고 시작일과 종료일을 확인할 수 있게 표시한다. 조회 기간과 일부만 겹치면 겹치는 구간을 표시한다.
- [기존 디로딩 기간 조회 API](../../../overload-server/docs/api/deload-periods.md#인증읽기쓰기)를 우선 재사용한다. 이 결정은 통계 설계 ST-45의 그래프 표시 방식을 구체화한다.

## 10.19 · 공통 숫자 입력 세로 휠 피커

**확정 UI 정책 / 구현·실기기 검증 대기.** 운동 중 숫자를 빠르게 조절할 수 있도록 `[−] [현재 숫자] [+]` 구조에 세로 휠을 연결한다. React PWA에서 구현하는 커스텀 컴포넌트이며 iOS 숫자 휠의 조작 방식을 참고한다. 10.10.2절 08항의 반복 입력 배치와 1회 증감을 이어받고, 적용 대상의 중앙 터치와 키보드 진입은 이 절을 따른다.

### 10.19.1 적용 범위

- **입력값:** 편집 가능한 운동 중량(최초·작업·실제 중량, 명시 승인·재승인, 기존 선택형 맨몸 추가 중량 포함), 세트 수, 반복 횟수, 최소·최대 반복 등 반복 범위.
- **화면:** 루틴 생성·편집, 일반 운동 진행·세트별 기록, 운동 중 임시 루틴·세트 편집, 운동 기록 정정, 디로딩 임시 루틴 생성·편집, 디로딩 운동 진행 및 수행 기록 정정. 진행 중·종료 후 기존 승인 해결에서 사용자가 직접 입력하는 재승인 중량도 포함한다. 디로딩 임시 루틴에는 기존 흐름에서 허용된 수동 입력에 적용하며, 자동 편성·감량과 기간·편집 권한은 현행 계약을 따른다.
- **제외:** 모든 유산소 수치, 휴식 시간·휴식 타이머 설정, 자동 운동 시간 측정·타이머, 인증번호·OTP, 통계 그래프·기록 요약·복구 원본 등 읽기 전용 수치, 디로딩 기간·진행일 등 표시값, 개발·검증 전용 입력. 이 항목은 기존 조작을 사용한다. 읽기 전용 데이터와 자동 계산 결과는 새 입력 필드로 만들지 않는다.

### 10.19.2 조작과 값 보존

- `− / +`는 즉시 현재 초안을 조절하고, 가운데 숫자 영역을 터치하면 휠을 연다. 기본 증감 간격은 두 방식 모두 **중량 2.5kg**, **세트 수·반복 횟수·최소 및 최대 반복 각각 1**이다. 필드별 유효 범위와 별도 확정 도메인 규칙을 우선한다.
- 휠은 숫자를 상하로 스와이프한다. 중앙 선택값을 강조하고 주변 값은 흐리게 표시하며, 스크롤을 멈추면 가장 가까운 선택 항목에 정렬한다. 기존 값이 있으면 해당 값에서 시작한다. 사용자가 선택한 값은 별도 확인 없이 현재 초안에 반영한다.
- `직접 입력`은 휠 안에서만 제공한다. 선택하면 숫자 키보드로 전환해 기존 값을 수정하고 초안에 반영할 수 있다. 최솟값·최댓값·소수 자릿수·정수 여부·최소/최대 관계는 각 필드의 기존 검증 계약을 따른다. 2.5kg 간격은 조절 기준이므로 허용된 `52.3kg`을 `52.5kg`으로 반올림하거나 잘라내지 않는다.
- 기존 숫자와 과거 기록 기반 자동 입력을 보존한다. 빈 값은 휠을 열기만 해서는 그대로 유지되며, 값을 선택하거나 입력하는 등 명시적으로 조절할 때만 변경한다. 10.18.4절의 종목 교체에서 새 운동의 과거 기록이 없으면 초안은 빈 상태로 시작한다. 정상적인 0kg 수행 기록과 맨몸 추가 부하의 입력·계산 규칙을 유지한다.
- 휠 선택과 직접 입력은 초안에만 적용한다. 세트 완료·휴식 시작, 공식 승인 변경, 서버 저장, 운동 종료는 기존 확정 동작과 검증을 따른다. 디로딩의 일반 승인 제외와 기존 오프라인 초안·복구 경계를 적용한다. [루틴 수치 계약](../../../overload-server/docs/api/routine-management.md#수치-계약--이번-사용자-승인으로-확정) · [세션 계약](../../../overload-server/docs/api/workout-sessions.md#snapshot-정확한-요청-계약) · [맨몸 추가 부하](../../../overload-server/docs/api/bodyweight-additional-load.md)

### 10.19.3 구현 및 실기기 검증 대상

- 실제 iPhone Safari와 홈 화면 설치형 PWA에서 스와이프·관성·중앙 스냅, 빠른 연속 스크롤, 스크롤 중 의도치 않은 값 반영, 화면 세로 스크롤 충돌을 확인한다.
- 직접 입력 전환 시 숫자 키보드, 작은 화면과 Safe Area, VoiceOver와 보조 입력, Android 동작을 검증한다. 값 변경 후 취소·복원과 오프라인 초안 보존을 함께 확인한다.
- 관성, 애니메이션, 행 간격, 선택 반영 타이밍과 휠의 구체적인 디자인은 실제 iPhone 검증 후 확정한다. [실기기 검증 체크리스트](ui-ux.md#공통-숫자-입력-실기기-검증)
