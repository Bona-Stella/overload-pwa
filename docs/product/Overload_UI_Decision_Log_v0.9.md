## 1. 상태 표기

| 상태 | 의미 |
| --- | --- |
| **합의** | 사용자가 방향이나 제품 규칙을 결정함. 코드 구현 완료를 뜻하지 않음 |
| **와이어프레임 초안** | 사용자 검토를 위한 섹션·동선·표시 제안. 레이아웃/정확한 조작은 변경 가능 |

## 2. 내비게이션과 전체 범위

- 하단 탐색: **홈 / 루틴 / 기록 / 설정**.
- 사용자가 조각 단위로 확정한 것을 한 문서에 축적. 화면별 실제 배치나 조작을 확인하기 전에는 이전 `/demo`를 완성형 UI로 간주하지 않음.
- v0.4에서 제작한 홈, 준비·웨이트·유산소, 루틴 목록·편집, 기록·분석과 정정·복구 화면은 v0.8에서도 보존. v0.5의 설정·표준 운동 상세를 유지하면서, v0.6은 **루틴 검색·장비 설정·운동 진행 임시 편집·완료 기록·제조사별 참고 통계·휴식 초 입력 위치**를 1차 수정으로 반영.

## 3. 홈 — 현재까지 합의한 방향

- 오늘의 루틴이 우선; 해당 루틴이 *요일 기본 루틴*인지 *오늘만 선택*인지 명시. 오늘만 바꿔도 원래 주간 배정은 바뀌지 않음.
- 월~일 주간 루틴 일정, 최근 운동, 하단 네비게이션 포함.
- 실제 서버에서 루틴/주간 계획을 조회할 때 신규 가입에는 시연용 PUSH/PULL/LEGS가 자동 생성되어 있지 않음.
- 원본 `/demo`의 텍스트·수치·예시 루틴은 설명용이며 실운영 데이터가 아님.

## 4. 루틴 — 현재까지 합의한 방향

- 상단 월~일 주간 일정과 비어 있는 요일 명시. 요일당 루틴 최대 1개, 루틴은 요일 미지정으로도 저장 가능.
- 루틴 카드: 이름, 요일, 웨이트 세트·종목 개수, 유산소 개수, 종목 요약, 편집/삭제.
- 생성/편집: 하나의 세로 화면; **WEIGHT**와 **CARDIO** 영역을 구분하고 각각 별도의 01부터 번호. 저장/취소 위치 고정. 월~일 복수 요일 선택, 중복되면 저장 전 교체 확인.
- 사용자 루틴 삭제는 과거 완료 기록이나 진행 중 운동을 삭제하지 않음.
- 원래 루틴을 수정해도 진행 중인 운동의 당시 계획을 자동으로 덮어쓰지 않음.
- **최신 카탈로그 정책:** 사용자가 직접 운동 종목 정의를 추가·이름 변경·삭제하지 않음. 모든 종목은 **관리자 관리 표준 운동 DB**에서 선택. 표준 UUID를 기준으로 식별하며 이름이 같아도 다른 UUID를 자동 병합하지 않음.
- **v0.6 1차 수정 반영:** `ROUTINE-02`, `WORKOUT-06`의 표준 운동 검색은 행의 부위 이모지 + `가슴 · 대흉근`처럼 PRIMARY 근육만 간결히 표시. 검색 행에는 별도 `>` 상세보기 경로를 두지 않고 클릭하면 운동 설정으로 이동. 검색은 표준명과 별칭을 이용하며 관리자 등록 운동만 선택. 자세/GIF 상세는 설정의 읽기 전용 종목 상세에서 확인.

## 5. 운동 진행 — 기존 합의 유지 + v0.6 장비 표시·임시 편집

- 준비운동 → 웨이트 종목 집중 → 휴식 카운트다운/세트 완료 → 이후 유산소/운동 종료 및 기록.
- 세트 완료는 원자적 로컬 저장 성공 후에만 확정. 서버 ACK 전과 후를 구분. 인증 만료·오프라인일 때 기존 계정의 진행 운동 원본을 보호.
- 시작 당시 계획(InitialPlan)과 도중 편집되는 현재 계획(AppliedPlan)을 구분. 완료 후 원래 계획·당시 장비·완료 사실의 문맥을 소급 변경하지 않음.
- 중량 변경에서 *오늘만 변경*과 *진행 중량 변경*을 구분. 승인 중량 사건과 실제 수행 중량을 혼동하지 않음.
- 운동 종료 후 추가 완료 확인 없이 기록 상세로 진입하기로 합의한 기존 시안 유지.
- 유산소 실제 활동 시간·거리·평균 심박, 건너뛰기/완료, 계획 대비 실제 수행을 구분.
- **v0.6:** `WORKOUT-02` FOCUS 제목의 왼쪽 아래에 `하체 · 대퇴사두근`처럼 대분류와 PRIMARY 근육을 간결히 표시, 오른쪽 남는 공간에 저장된 `제조사 / 부하 방식`을 *읽기 전용* 표시. `목표 6–10회 × 3세트`로 표기하며 `3본세트`는 사용하지 않음.
- 장비 설정 자체를 상단에서 눌러 수정하게 만들지 않음. 기존 `세트 기록 / 임시 편집`(`WORKOUT-05`)에서 제조사·부하 방식 선택을 제공하고 **오늘만 적용**. 이후 완료 세트에 사용하고 이미 완료한 세트의 장비 원본 및 원본 루틴은 바꾸지 않음.

## 6. 기록·분석 — v0.4에서 확정된 구조 보존

- 기록 대시보드: `운동 기록·분석` 제목, 이번 주(월~일) 계획 대비 달성·완료 웨이트 세트·달성률, 유산소 시간, **운동 현황 / 근육별 통계 / 성장 추적**, 최근 운동 세션 3개와 전체 보기.
- 운동 현황: 주간/월간, 세트/총중량, 전체·운동별·근육별, 운동량 막대 그래프; **예정일·실제 달성**을 별도 탭 대신 여기에 통합. 유산소 요약에서 유산소 상세로 진입.
- 유산소 상세: 기간별 실제 누적 활동 시간, 날짜별 차트, 종류별 거리와 거리 출처; 종류가 다른 거리 km를 전체 거리로 무조건 합산하지 않음.
- 근육별 통계: 가슴/등/하체/어깨/팔/코어 → 세부 근육; **PRIMARY/SECONDARY는 분리**, 동일 세트를 대분류 안에서 중복 합산하지 않음. 계획이 없으면 `계획 없음`, 확인할 수 없는 과거 계획이면 `확인 불가`.
- 성장 추적: 종목 검색(현 루틴에서 빠진 과거 종목 포함), 1/3/6개월/전체, **공식 승인 중량** 사건 중심. 디로딩과 임시 실제 수행 중량은 공식 중량 추이에 섞지 않음.
- 운동 이력: 달력 날짜가 아닌 **완료 세션 단위** 카드. 같은 날짜의 여러 세션은 별개. 상세에는 원래 수행·유산소·당시 평가와 수정 후 현재 평가 분리.
- 상세 상단 오른쪽 **⋮ 아이콘만** 사용(‘기록 관리’ 텍스트 노출 금지). 메뉴: 기록 정정 / 누락 수행 복구 / 기록 전체 삭제.
- 기록 정정은 실제 수행값만 허용, 기존 계획·종목/ordinal·문맥 불변. 개별 수행 논리 삭제 가능. 전체 삭제는 확정 경고 후 이력·통계·평가에서 제외되지만 일반 사용자 복원 불가.
- 누락 복구는 본인 기기에 남아 있는 **진짜 완료 원본**에서 선택하는 특별 경로. 사용자가 임의로 완료 세트를 생성하거나 전체 삭제된 세션을 되살리는 기능이 아님.
- 미동기화 세션을 서버 통계에 포함된 것처럼 표시하지 않음. 일정이 없는 날과 확인 불가한 과거 날을 숫자 0으로 혼동하지 않음.
- **v0.6 세트별 장비:** `RECORD-01` 운동 종료 후 상세와 `RECORD-03` 과거 기록 상세에 각 완료 세트의 `제조사 · 부하 방식`을 실제 수행 당시 정보로 표시. 한 종목의 장비가 도중 변경되어도 종목은 하나로 묶고 세트별로 구별. `RECORD-04` 정정에서는 실제 중량·반복 수만 수정하고 장비는 정정할 수 없는 원본. 누락 수행 복구에서도 원본 장비 보존.
- **v0.6 STATS-06 운동별 제조사별 참고 통계:** `운동 현황 → 운동별`에서 운동 상세 통계로 들어가 **전체 보기 / 제조사별 보기** 전환. 완료 세트 수와 총중량을 분리·합산하고 제조사 미지정은 별도 분류하되 전체에는 포함. 제조사별 최고 실제 중량 그래프는 시안용 예시 산식으로, **공식 승인 중량 성장 추적과 분리**. 제조사가 달라도 실제 중량 자체를 동일한 공식 근력 기준으로 비교하지 않음. 제조사+부하 방식의 추가 하위 필터는 후속 확장 후보로만 두고 지금은 만들지 않음.

## 7. 설정 메인 — 새롭게 합의한 정보 구조

**상단부터 다음 순서**. 최상단에 계정 정보를 둔다는 것은 사용자 확정 의견.

1. **계정 정보:** 로그인 계정 요약 → 계정 설정 상세.
2. **운동 설정:** 세트 사이 휴식 / **운동 종목 보기**(읽기 전용) / 디로딩 설정.
3. **데이터 및 앱:** 운동 데이터 상태 / 운동 데이터 내보내기(JSON) / 앱 설치·오프라인 준비.
4. **계정 및 데이터 삭제:** 전체 운동 데이터 초기화 / 회원 탈퇴.
5. 앱 버전 등 보조 정보.

`운동 종목 관리` 메뉴명 및 사용자 개인 종목 CRUD는 **폐기**. `주간 루틴 일정 편집`은 루틴, 일반 운동 통계는 기록, `세트 사이 휴식`은 설정에 위치. 일반 설정에 필요 없는 중복 메뉴를 만들지 않음.

2026-11-12 실제 계정의 SETTING-01 전체 메뉴를 사용자 승인했다. 운동 설정에는 휴식 타이머 알림을 포함하고 마지막에 로그아웃을 둔다. 기존 계정 정보·휴식 조회·카탈로그·PWA 상태·로그아웃은 실제 동작에 연결한다. 나머지 설정 메뉴는 미구현 표시와 함께 비활성으로 제공한다. [구현 범위](../engineering/frontend.md#catalog-0102--setting-01-실제-계정-마감)

### 7.1 계정 설정 상세 — 사용자 제공 실제 화면 참조

- 로그인 수단: 이메일 로그인 연결 상태, 대표 이메일 로그인 연결 확인/해제, Google 로그인 연결/해제.
- 대표 재인증 이메일: 등록 VERIFIED 상태, 마스킹된 주소, 이메일 OTP 재인증 버튼. **대표 재인증 이메일과 로그인 수단은 별도**.
- 최근 이메일 재인증 상태: 최근 인증 여부/시간 판단을 등록 VERIFIED 상태와 구별.
- 계정 정보 새로 확인, 로그아웃.
- 서로 다른 사용자 계정 자동 병합 금지. 마지막 로그인 수단 해제 불가. 민감 작업 최근 **10분 이내 재인증** 기준.
- 이전 실제 계정 화면 하단의 `앱 설치·오프라인 준비`는 설정 메인의 데이터·앱 영역으로 이동.
- 제공된 화면의 구성은 현재 참고 기준으로 사용하지만, 실제 UI 세부 버튼 동작은 별도 구현 규칙을 따라야 함.

### 7.2 세트 사이 휴식 — 구조 합의

- 휴식 목표는 **계획 반복 상한** 기준. 10회 이하 180초, 11~12회 120초, 13회 이상 90초는 **운영 초기값**.
- 실제 화면에서 계정별 저장값 조회. 세 값을 한 편집 화면에서 변경하고 **한 번에 저장**. 양의 정수 초만 허용, 저장/취소, 온라인 요청.
- **v0.6 단위 위치 확정:** 각 행 왼쪽 레이블은 `10회 이하`, `11~12회`, `13회 이상`으로만 표시하고 **각 숫자 입력칸 바로 오른쪽에 `초`**를 배치. 따라서 `10회 이하 (초)` 같은 혼동 유발 표현은 사용하지 않음.
- 시안에서 값이 바뀌어도 실제 서버에 저장한 것으로 표현하지 않음.

### 7.3 디로딩 설정 — 구조 합의

- **디로딩 추천 분석 ON/OFF만 사용자 변경 허용**. OFF여도 디로딩 기능 자체, 수동 시작 및 이미 진행 중인 디로딩은 유지. OFF 기간의 과거 기록을 재활성화할 때 소급 계산하지 않으며 ON 때 누적값 0부터.
- **중량 적용률 85%, 세트 적용률 50%는 읽기 전용 안내**. 사용자가 직접 비율 편집하는 것은 향후 별도 개발 후보, 이번 UI에서 입력/저장 버튼 금지.
- 설계 기준 `Overload_Deloading_Design_Specification_v1.3.md`의 상세 산식 유지: 중량은 승인 중량 또는 시작 중량의 85%를 바탕으로 장비별 내림, PLATE/STACK 5kg·DUMBBELL 2kg·미지정 1kg; BODYWEIGHT 중량 조절 없음; 작은 중량 0kg 방지; 세트는 50% 정수 반올림(0.5 올림) 최소 1세트; 홀수 세트 등의 반복 횟수 보정. 원래 루틴·승인 중량은 그대로 보존.

### 7.4 데이터·앱 메뉴 — 기존 정책, 상세 UI 검토 예정

- 운동 데이터 상태: 네트워크 연결, 서버 ACK, 로컬 보존·전송 대기, 기기 제어권/동기화 오류를 같은 의미로 혼동하지 않음.
- JSON 내보내기: 계정 운동 데이터 다운로드. **가져오기/복원은 별도 승인되지 않음**.
- 전체 운동 데이터 초기화: JSON 내보내기 안내 → 최근 10분 재인증 → 최종 확인 → 온라인 완료 응답. 계정과 로그인 수단은 유지, 운동 데이터와 휴식은 운영 초기 상태로 재구성. **표준 운동 카탈로그는 관리자 공용 데이터**이므로 종전 개인 종목 20개를 새로 만드는 예전 seed 문구는 현행 정책과 불일치. `dataGeneration` 증가, 구 세대 미전송 자료를 새 세대로 자동 이관하지 않음.
- 회원 탈퇴: 초기화와 구분. 계정/인증 수단/운동 데이터 파기 대상; 온라인 재인증/최종 확인/서버 성공 응답 이후에만 완료로 표시.
- PWA·오프라인: 지원 기기 설치 안내, 계정별 로컬 저장 주의와 미동기화 기록 유실 가능성; 백그라운드 자동 동기화 보장 금지.
- 내보내기·초기화·탈퇴 각 확인 화면의 실제 문구/단계/버튼은 **현재 와이어프레임 초안**이며 후속 사용자 검토 필요.

## 8. 표준 운동 목록·상세 — 사용자 새 결정

### 8.1 표준 운동 DB 실제 연결 상태

- `standard_exercise`: 표준 운동 UUID/명칭/활성 상태.
- `exercise_alias`: 표준 운동 UUID별 이름 검색용 별칭.
- `muscle`: 세부 근육명, 대분류 CHEST/BACK/SHOULDERS/ARMS/LEGS/CORE.
- `exercise_muscle`: 해당 표준 운동의 PRIMARY 또는 SECONDARY 세부 근육 연결. 복수 PRIMARY 허용.
- `manufacturer`: 장비 제조사의 공용 목록이며 특정 표준 운동에 고정 연결되지 않음.
- **웨이트 신규 선택**은 `GET /api/v1/standard-exercises/search-data`를 사용한다. `schemaVersion=1`의 각 운동은 `id`, `name`, `aliases`, `muscles`를 반환한다. 근육 항목은 `id`, `groupCode`, `name`, `role`이다. 활성 상태이며 근육 타겟과 분할 검수가 완료된 `SETS_REPS`가 대상이다.
- **설정의 표준 운동 목록 조회**는 `GET /api/v1/standard-exercises/catalog`를 사용한다. 활성 상태와 두 검수를 충족한 운동을 기록 방식과 관계없이 조회하며, 이름·별칭·근육 외에 `exerciseType`, `recordMethod`, nullable `instructionsKo`와 `equipmentDescription`을 반환한다.
- **유산소 신규 선택**은 `GET /api/v1/standard-exercises/cardio-choices`를 사용한다. 공개된 `recordMethod=CARDIO` 중 활성 기록 설정에 연결되고 표준명이 100자 이하인 운동이 대상이다. 응답의 `id`는 표준 운동 UUID, `activityId`는 유산소 기록 설정 UUID다.
- 조회 가능 범위와 신규 선택 가능 범위는 구분한다. 검수 취소나 비활성화로 신규 선택에서 제외돼도 이미 저장된 루틴·세션 참조는 기존 계약을 따른다. `GET /api/v1/manufacturers`는 별도 제조사 ID·이름 목록이다. [현행 카탈로그 API](../../../overload-server/docs/api/standard-exercise-catalog.md)
- `routine_weight_placements`의 `manufacturerId`·`loadType`은 **사용자가 해당 루틴에서 지정한 값**(미지정 null 허용). 지원 부하 방식: **PLATE(원판), STACK(핀/스택), DUMBBELL(덤벨), BODYWEIGHT(맨몸)**. 세트 수행 시 당시 제조사/부하 방식을 불변 원본으로 보존.
- **V16/V17 당시 기록(2026-11-02).** 당시 검색 응답은 ID·이름·별칭을 제공했다. V17 및 프론트 표준 카탈로그 전환에서 개인 종목 신규 쓰기 차단과 표준 UUID 사용을 구현·검증했다. **기존 개인 종목 직접 관리 정책은 구 버전 문구**이므로 UI에 가져오지 않음. [당시 개발 환경 전환 보고서](../../../overload-server/docs/tasks/standard-exercise-catalog-dev-phase-4-report.md)

### 8.2 운동 목록 조회 UI — 2026-11-11 1차 디자인 확정

- `설정 → 운동 종목 보기`는 표준 운동명·별칭 검색 및 상세 조회 전용. `표준 운동 DB`와 **조회 전용**, 등록·편집·삭제는 관리자가 수행한다는 안내를 유지. 관리자는 현재 사용자 UI/HTTP 관리자 기능의 구현 대상이 아님.
- 검색창 아래 **한 줄 가로 스크롤** 필터: `전체 / 가슴 / 등 / 어깨 / 팔 / 하체 / 코어 / 유산소 / 기타`. 아이콘 없는 기존 알약형 디자인, **높이 27px**, 좌우 크기를 억지로 줄여 한 화면에 모두 넣지 않는다. 이름/별칭 검색과 필터를 조합하고 즉시 결과 갱신.
- 결과: 공식 **32 CSS px** 원형 대분류 아이콘(기존 가슴·등·하체·유산소 자산 + 사용자가 제공한 어깨·팔·코어의 무채색 테마 맞춤), 운동명과 `대분류 · 첫 PRIMARY 근육` 2줄, 우측 `›`, **행 전체 클릭으로 CATALOG-02 상세**. 기타는 텍스트 대체 가능. 결과 없음 안내.
- **CATALOG-01은 검색·필터·목록 항상 펼침**, 닫기 버튼 없음. 다른 화면과는 동일 검색 UI 배치/컴포넌트 규칙을 재사용하되 각 화면의 목적과 펼침/접힘을 구분한다(10.18절).

### 8.3 운동 상세 UI — 디자인 확정 및 실제 계정 검토 완료

2026-11-12 사용자가 CATALOG-01·02와 SETTING-01의 실제 계정 화면을 직접 확인하고 최종 승인했다. 공개 운동 목록과 UUID 상세를 연결했다. 미디어 제목은 **동작 시연**, 표시 영역은 콘텐츠 너비의 **1:1 정사각형**, 이미지는 `object-fit: contain`으로 원본 비율을 보존한다. 내부 검토 계정의 머신 하이 로우는 보호 경로에서 받은 흰색 배경 원본 GIF를 12프레임·3초 주기로 무한 반복한다. 정식 서비스의 미디어 제공은 별도다. [검증과 마감](../engineering/frontend.md#catalog-0102--setting-01-실제-계정-마감)

1. 상단 제목 카드에는 `STANDARD EXERCISE`, 운동 표준명, 있으면 별칭, 우측 태그를 **PPL 값 → 전면/후면 값 → 조회 전용** 순서로 한 줄에 둔다. `PPL`, `전면/후면` 등의 설명 라벨은 태그 안에 쓰지 않는다. 분할 값이 없으면 해당 태그를 **그리지 않는다**.
2. GIF 섹션은 미제공 회원에게 **`GIF를 제공하지 않습니다` 안내 이미지**를 표시하는 상태와, 해당 운동 GIF 사용·전송이 허용된 회원에게 **실제 GIF**를 표시하는 상태로 구분한다. 현재 HTML은 미제공 이미지의 **임시 안내 영역**이며 최종 이미지는 추후 제작. GIF 파일 자체나 보호 URL을 허위 삽입하지 않는다. 권한·파일 부재·로드 실패·차단 처리는 연동 구현 단계에서 설계/검증한다.
3. **운동 자세 및 방법**은 기본 접힘, 우측 `∨`로 펼침. 실제 상세 응답의 `instructionSteps`를 순서대로 보여주며 없으면 `등록된 운동 방법 정보가 없습니다.`를 안내한다.
4. **PRIMARY 주요 자극 근육 / SECONDARY 보조 자극 근육**을 별도 카드로 표시. 각 행은 `광배근   등`처럼 **근육명과 대분류를 같은 줄**에 둔다. PRIMARY **정렬상 첫 번째 근육만 `핵심` 태그**를 오른쪽에 표시. 실제 데이터 검수에서도 첫 PRIMARY는 운동의 핵심 타겟을 의미해야 한다. SECONDARY에는 순서/핵심 강조가 없다. 리스트가 없으면 해당 정보가 없다는 안내를 표시.
5. 표준 상세는 **조회 전용**이다. **장비 제조사·머신/부하 방식 및 개인 루틴의 기록 방식 선택 UI는 넣지 않는다.** 제조사·부하 방식은 사용자가 루틴 배치 또는 현재 세션에서 선택하며, 수행 당시 실제 설정값은 수행/기록 문맥에서 다룬다. 서버의 공용 카탈로그 레코드에 있는 기술/검수용 분류와 사용자 루틴 입력 UI를 혼동하지 않는다.
6. 화면 샘플의 운동 방법·근육·분할은 합성 배치 예시다. **Backend 구현 완료.** 인증된 `GET /api/v1/standard-exercises/{exerciseId}`는 ID·이름·별칭·운동 유형·기록 방식·기구 설명·관절 분류와 `primaryMuscles`, `secondaryMuscles`, nullable `pplSplit`·`frontBackSplit`, `instructionSteps`, `selectableForRoutine`을 제공한다. 목록은 PRIMARY를 저장된 순서대로 반환하며 상세 PRIMARY는 `primaryOrder`를 명시한다. `핵심` 태그는 Backend 순서의 첫 PRIMARY에만 표시한다. `selectableForRoutine`은 신규 선택 가능 여부다.
7. **PWA 연동 완료.** 실제 계정 화면에서 선택 UUID로 상세를 조회한다. 내부 하이 로우 시연은 기존 보호 경로를 사용한다. 정식 서비스의 대표 미디어 주소 전달과 제공 조건은 후속 범위다. [상세 API](../../../overload-server/docs/api/standard-exercise-catalog.md#get-apiv1standard-exercisesexerciseid) · [PWA 연결 상태](../engineering/backend-ui-v0.9.md#표준-운동-사용자-ui의-v35-연결-경계)

> v0.6 당시 API 설명(2026-11-05). 현행 계약은 위 6~7항을 따른다.
>
> 실제 근육 매핑은 DB에 있으나 현재 검색 조회 API에는 포함되지 않아 **상세 읽기 API 연동 대기**.

### 8.4 루틴·운동 진행에서 해당 종목 상세 사용 — 정책 합의, 기존 UI 자료 대기

## 10. v0.7 — 디로딩 UI 통합 결정 (기존 v1.3 정책에 대한 최신 UX 변경 포함)

### 10.1 디로딩 진입 전 — 홈 원형 버튼

- 기존 `HOME-01` 상단의 **작은 원형 버튼**을 디로딩 진입점으로 사용. 별도 홈 배너나 별도 `디로딩 시작` 바로가기 없음. 버튼 → 상세(유효 주수·권장 기간 안내) → **상세 하단 `디로딩 시작`**.
- 유효 훈련 누적은 1주 정수로 증가하지 않고 `0.5`, `0.67`, `0.775` 유효 주처럼 **연속값**. 8칸/주별 구획 게이지는 폐기. 8주를 100%로 상한 표시.
- 4주 미만은 중립색 작은 아이콘/최소 강조, **4주부터 초록 → 노랑 → 주황 → 적색**으로 서서히 변화. 더 높은 수치가 우수한 성취라는 뜻이 아니라 회복 시기를 점검하는 안내. 실제 피로/건강 위험 점수가 아님.
- 분석 OFF여도 수동 진입 버튼 유지. 자동 누적값을 계산/보여주지 않으며 다시 ON하면 누적 0부터 시작하는 원래 정책 유지.

### 10.2 방식/분할/요일 → 원본 비교 → 시작 최종 확인

- 기존 루틴 주간 운동일 수에 따라 기존 유지 / 주 3일 / 주 2일 / 완전 휴식의 **가능한 횟수만** 제공(DL-23의 제약 유지).
- `주 3일 운동` 행의 **˅** 확장 → `PPL 방식` / `균등 분배`. 기본은 PPL이지만 원본 운동의 세부 PRIMARY 분할이 불가능하면 비활성화 및 이유 표기, 균등 자동 선택. PPL이 가능해도 사용자가 **균등을 직접 선택**할 수 있음.
- `주 2일 운동` → `전면·후면 방식` / `균등 분배`에 동일 원칙 적용. 기본 전면·후면, 불가능하면 비활성화 후 균등 선택. 분할 가능 여부는 표준 운동의 정확한 근육 매핑/자동 편성 검증에 의존.
- 방식 카드 **하단에서 시작 전에 요일 선택**. 3회는 3일, 2회는 2일 선택. 첫 제안은 시작일/+2/+4 또는 시작일/+3이며 사용자가 변경한 요일 유지, 연속 운동일 가능, 실제 시작일로부터 7일 범위.
- 상세 미리보기는 **운동일 카드만 표시**하여 휴식일 목록은 생략. 각 운동일 펼치기 → 종목별 `원본 루틴` vs `디로딩 추천` **중량·세트·반복** 비교. 상단에 선택한 PPL/전후면/균등 분배 결과 표시. 자동 추천값은 실제 원본을 기준으로 계산; 시연 수치는 가상. 원본에 없는 운동 자동 추가 금지.
- 시작 확정 화면은 선택 방식·요일·7일 권장/10일 최대·원본 보존만 요약. **시작 직전** 진행 중인 일반 세션이나 당일 실제 수행 기록(오프라인 원본 포함) 존재 검사 후 시작 허용. 목업은 서버 검사 성공을 주장하지 않음.

### 10.3 디로딩 시작 후 앱 전체 운동 환경 전환

- 사용자 의도: **기존 홈/루틴/기록/운동 진행/설정 UI를 최대한 재사용**. 디로딩 전용 기능/안내가 필요하면 추가 허용.
- 앱의 실제 상태(`IDLE`, `DELOAD_ACTIVE`, `DELOAD_COMPLETED_TODAY`)와 **조회 모드**(`DELOAD_VIEW`, `GENERAL_READ_ONLY`)를 분리. 헤더의 작은 `일반 보기` / `디로딩 복귀` 버튼은 **조회 전환만** 하며 실제 디로딩을 종료하지 않음. 일반 운동 기간에는 이 전환 버튼 숨김.
- 디로딩 화면에서는 **차분한 녹색 계열**을 상태/활성 탭/주요 버튼 등 소수 요소에 적용. 추천 게이지의 초록→적색 경고 변화는 **진입 전**에만 적용하고 진입 후에는 진행 일차(`D3` 등) 표시로 교체. 원형 버튼은 디로딩 상세/관리로 연결.
- 일반 화면 조회에서는 기존 데이터 조회만 허용. **원본 루틴 편집·삭제·실행 및 과거 일반 수행 기록 정정·삭제를 잠금.** 다만 공통 계정/세트 사이 휴식/카탈로그/디로딩 분석 등 설정은 잠그지 않음. 이 결정은 디로딩 v1.3의 `DL-04` 및 `DL-17` 중 원본 루틴 수정 허용과 **정책 충돌**하며 최신 사용자 합의가 우선.

### 10.4 홈 원형 버튼 + 기존 다섯 영역 재사용

- 기본 `HOME-01`의 메인 문구/① 오늘의 루틴/② 운동 시작/③ 오늘만 다른 루틴 선택/④ 주간 일정/⑤ 최근 운동/하단 네 탭 순서 **유지**. 별도 전체 임시 루틴 목록을 홈에 중복하지 않음. 전체 관리 목록은 **루틴 탭**에만 위치.
- ①~②: 오늘의 디로딩 임시 루틴을 표시하고 감량된 중량/세트 적용. 휴식일에는 `오늘은 휴식일`, 완전 휴식형에는 `완전 휴식`을 표시하며 운동 시작 숨김.
- ③: **아직 수행하지 않은 다른 임시 루틴**을 선택하면 현재 날짜에 배치된 루틴과 **기존 배정 날짜를 맞교환**. 원래 계획을 삭제하거나 중복 생성하거나 임시 목록에 남겨두지 않음. 완료된 루틴/날짜는 교환 대상 제외. 일반 운동의 기존 `오늘만 선택` 정책을 자동 수정하지 않음(디로딩과 구분).
- ④: **실제 디로딩 시작일부터 7일간**의 일정을 기존 주간 일정 UI로 표시. 오늘은 강조, 완료한 수행일은 ✓ 완료, 이미 지난 휴식일은 경과, 과거 미수행 예정일은 미수행, 미래는 예정/휴식. 날짜가 지났다고 무조건 운동 완료 처리하지 않음. 8~10일차는 기존 주간 일정의 다음 페이지처럼 표시(새 자동 루틴 생성 불가).
- ⑤: 현재 디로딩 기간의 최근 실제 운동 기록만 표시.

### 10.5 임시 루틴 탭·운동 진행·운동 종료

- 디로딩 중 `루틴` 탭에서만 **임시 루틴 전체 목록**. 기존 루틴 카드/상세/편집을 재사용하되 `편집`, `일정 변경`, `⋮ → 삭제` 제공.
- **미수행 임시 루틴 삭제 허용**, 삭제 날짜는 휴식일로 변경. 삭제한 종목/루틴 자동 보충/다른 날짜 자동 이동 없음. **전체 삭제도 허용**하고 디로딩 기간은 유지. 이미 수행한 루틴·실제 기록은 삭제나 일정 재배치에서 보호. 최초 선택 방식 기록은 유지하면서 남은 예정 건수만 달라짐.
- 일정을 빈 날로 이동할 수 있고 다른 미수행 루틴이 있는 날을 고르면 서로 날짜를 교환. 완료 계획과 실제 기록은 고정. 원본 루틴·공식 승인 중량은 불변.
- 기존 `WORKOUT-01/02/05` 준비·세트 기록·휴식·임시 편집을 재사용. 진입 후에는 `디로딩 n일차`, 감량 목표와 원본 목표 비교를 보조 표시. 당시 장비(제조사·부하 방식) 세트별 스냅샷을 보존.
- **계획 세트/종목이 남아 있어도 다음 종목으로 이동하거나 운동 종료** 가능. 수행한 세트만 실제 기록으로 남기고 `실패` 판정/디로딩 달성 강요 없음. **일반 승인 중량 및 증량·유지·감량 평가를 갱신하지 않음.** 운동 한 회차의 완료와 디로딩 전체 완료는 별개.

### 10.6 기록 탭과 과거 디로딩 이력

- 디로딩 중 `기록` 탭은 **현재 활성 디로딩 기간에 연결된 실제 세션**만 조회. 기존 기록 대시보드/운동 현황/근육 통계/운동 이력·세트별 상세/정정 기능 UI를 재사용. 이때 승인 중량 성장 추적은 제외.
- 일반 화면(읽기 전용)은 기존 전체 운동 이력과 통계를 조회. 디로딩 수행값도 **실제 전체 운동량·근육별 통계**에는 포함하되 **승인 중량/증감 평가**에서는 제외. 단순 날짜 필터가 아니라 **디로딩 기간 ID/세션 종류**로 기록 문맥 구분.
- 디로딩 수행 기록은 정정 가능하되 원래 계획·당시 장비·완료 시간 원본은 변경 불가. 일반 기록은 디로딩 중 읽기 전용. 미동기화 완료를 서버 확정 기록으로 가장하지 않음.
- 디로딩 완료 후 **기존 `기록 → 운동 이력`**에 기간 카드 추가. 시작/종료 날짜, 선택 운동 방식, 분할, 완료/자동 완료, 실제 세션과 당시 계획 보존. **완전 휴식 0회도 기간 이력 보존**. 완료된 임시 루틴을 일반 루틴 목록에 다시 나타내거나 재실행하지 않음.

### 10.7 종료·취소·7일 경과·완전 휴식

- 상단 작은 원형 버튼 → **디로딩 상세 하단**의 `디로딩 완료`(항상 가능)와 `디로딩 취소`(실제 수행 0회일 때만 가능)를 배치. 홈에 종료 버튼 없음. `일반 보기`는 종료 기능이 아님.
- 완료 시 **확인창 1회**: 실적/이력 보존, 유효 훈련 주수 0, 당일까지 디로딩 상태, **다음 날** 일반 운동 재개. 취소는 0세트·유산소 실제 수행 0건일 때만 허용, 기존 누적 주수 유지하며 즉시 일반 모드 복귀. 무수행 세션은 실제 이력으로 만들지 않음. **진행 중 운동이 있다면 먼저 세션 종료/취소를 요구**하며, 과거 실제 수행 기록을 나중에 정정·삭제해도 한때 수행한 사실이 있다면 디로딩 취소 허용으로 변경하지 않음.
- 7일차 자동 완료 금지. **8일차 이후 첫 앱 진입 시(운동 기록 도중 제외) 종료/계속 선택 팝업 1회**, `계속하기`는 기존 디로딩 상태 지속일 뿐 기간을 새로 생성하지 않음. 재팝업 없음. 9일차는 작게 권장 기간 경과 안내, **10일차 종료 시 자동 완료**, 11일차부터 원본 루틴 실행.
- 완전 휴식형은 ① 운동 시작/③ 다른 임시 루틴 선택 숨김, ④ 휴식일 경과 표시, 기록 0을 실패로 표현하지 않음, 별도 이력에 기간 보존. 기존 설정 탭은 그대로 재사용.

### 10.8 현재 구현 여부 및 보류

- **본 버전은 인터랙티브 HTML 저충실도 화면 시안이며, 앱/계정/서버/IndexedDB/DB를 수정하지 않음**. 실제 날짜/성공 동기화/서버의 편성 분석은 연결되지 않은 시연 데이터.
- 자동 분할 가능성 판단의 세부 PRIMARY/`jointType`/분할 실패 처리, 동기화/오프라인 중 상태 전환 원자성, 8일차 팝업 1회 확인 기록의 계정/기간 단위 보존, 완료 후 날짜 경계와 기록 정정 영향, 디로딩 재시작 제한/임시 루틴 편집 유효성 등은 **실제 구현 검증 대상**.
- 이번 UI 확정과 무관하게 기존 디로딩 계산·중량·세트·유산소 산식은 `Overload_Deloading_Design_Specification_v1.3.md`에 따라 유지하되, v0.7 대화에서 **명시적으로 변경한 UI/제품 정책만 최신 합의 우선**. 별도 v1.4 정책 통합본에 변경점 반영.

## 10.9 v0.8 · 통계 UI 개선 및 디로딩 시작 자격 (2026-11-04 당시 기록)

> 아래 다섯 조건/계획2일 gate는 폐기 이력이다. 현재 자격·분석은10.15절과 디로딩v1.7을 따른다.

### 운동 현황 그래프와 필터

- 기존 v0.7의 `운동 현황` 상단 **운동량 요약은 기간 전체 값**으로 보존한다. 하단 `운동량 상세` 카드의 필터를 **운동량 추이 차트 위**로 옮기고, 중복 합계 카드는 차트 카드 내부로 통합한다.
- `전체 / 운동별 / 근육별`과 `세트 / 총중량`, 조회 기간을 바꾸면 **선택한 범위의 실제 완료 세트 막대그래프와 선택 합계가 동시에 변경**된다. 총중량은 실제 중량×실제 반복 횟수 합계. 실제 수행 데이터가 없다면 `실제 수행 기록 없음`을 보여주되 ‘계획 없음’과 혼동하지 않는다.
- `운동별`은 해당 기간에 실제 수행한 표준 운동을 선택한다. 과거 루틴에서 삭제된 종목도 실제 수행 이력이 있으면 대상이며 표준 UUID 기반. 운동별 제조사 상세는 기존 경로를 재사용한다.
- `근육별`은 **가슴·등·어깨·팔·하체·코어의 대분류만** 필터로 선택한다. 세부 근육 PRIMARY/SECONDARY는 `근육별 통계`에서 확인한다. 동일 세트가 한 대분류 내 여러 세부 PRIMARY에 연결되어도 대분류 합계에서 중복 집계하지 않는다. 유산소는 기존 독립 통계를 유지한다.
- **와이어프레임 한계:** 주간/월간 수치, 운동 선택 목록, 그래프는 UI 반응을 보기 위한 예시이며 실제 DB·날짜 이력을 조회하지 않는다. 운영 화면은 실제 수행 데이터로 필터 조건을 계산해야 한다.

### 성장 추적의 종목 검색

- **검색 가능한 종목 목록**과 공통 검색 UI를 사용한다. 검색·선택 범위는 현행 성장 추적 계약과 10.18.2절을 따른다.
- 종목을 바꾸면 **해당 표준 운동의 공식 승인 중량 이력**만 표시한다. 승인 중량이 없으면 빈 상태를 표시하고 일반 세트 실제 중량이나 디로딩 중량으로 차트를 채우지 않는다.
- 기존 1/3/6개월/전체, 공식 승인 이력 차트·기록 구조 유지.

### 근육별 SECONDARY 상세

- 대분류/PRIMARY와 SECONDARY 펼침은 당시 UI 기록이다. 실제 참여 세트와 기여 세트를 구분하며, 후속 10.22절·ST-24~31의 세부 근육 기여는 계획/실제 각각 PRIMARY 1.0 / SECONDARY 0.5를 적용한다. 이 요구사항으로 새 레이아웃을 확정하지 않는다.
- 같은 근육의 기여는 관리자 매핑과 확정 기여식을 사용한다. 여러 근육의 기여 합계를 총 운동 세트·상위 분류·루틴 달성률로 표시하지 않는다. 실제 참여 정수는 보존한다.

### 디로딩 시작 자격: 분석 ON/OFF와 독립

- **모든 디로딩 시작(분석 ON/OFF 동일)**에 다섯 가지 검사를 적용한다: ① 현재 적용되는 주간 원본 운동 계획 **2일 이상**, ② **오늘을 제외한 직전 7일**에 실제로 수행한 일반 웨이트 세트 또는 유산소 기록 **1건 이상**, ③ 이전 디로딩을 완료한 적이 있다면 **그 이후 새로운 일반 운동 수행**, ④ 오늘 실제 운동 수행 없음, ⑤ 활성 일반 운동 세션 없음.
- ‘최근 7일’은 오늘을 제외한 이전 **7개 현지 달력 날짜**를 뜻한다(예: 2026-11-04 시작이라면 2026-10-28~11-03). 운동을 시작만 했지만 실제 수행이 0건인 세션은 근거가 되지 않는다. 디로딩 세트 자체는 일반 운동 자격 기록으로 세지 않는다.
- 기존 누적 유효 훈련 주수 0%는 자격 거절 이유가 아니다. **추천 게이지는 시점 안내, 시작 자격은 실제 운동 기록의 최소 조건**으로 분리. 4~8주 유효 주수 계산, 분석 OFF의 자동 계산·게이지·알림 비노출 및 ON 재활성화 시 0에서 시작 정책은 변경하지 않는다.
- 디로딩 상세에서 5개 조건을 확인하도록 표시한다. 미충족이면 `디로딩 시작` 버튼 비활성화, 이유 안내. 최종 시작 확정 순간 동일 조건을 다시 검사한다. 별도 새 페이지는 만들지 않는다.
- 실제 서비스에서는 현재 주간 일정 **적용일과 시간대**, 지난 7일의 **수행일(동기화 날짜 아님)**, **오프라인 미동기화 완료 원본**, 이전 디로딩 종료 시점과 현재 활성 세션을 검증해야 한다. 초기 상태/일정이 없는 사용자는 시작할 수 없고, 운동 계획 2일 이상과 실제 최근 수행이 필요하다. 앱/서버 구현 완료를 의미하지 않는다.
- 이미 시작한 디로딩에서 모든 임시 루틴을 삭제하거나 0회 운동해도 정상 진행/완료 가능하다는 기존 원칙은 그대로다. 진행 중인 디로딩을 분석 OFF로 바꿔도 유지된다.

### 부가 UX·현재 시안의 범위

- 디로딩 중 오늘이 **빈 휴식일**인 경우, 홈에서 `디로딩 일정 변경` 링크를 통해 기존 루틴 탭으로 이동하게 한다. 완전 휴식형에는 해당 링크가 없다. 새로운 루틴 생성/자동 추가 기능이 아니다.
- 신규 사용자, 기록 없음, 승인 중량 없음, 계획 없는 근육의 **빈 상태**는 기존 정책을 유지하며 확인 가능한 화면에서 예시를 보강한다. 오프라인 저장·동기화 상태는 기존 데이터 상태 UI를 유지하고 실제 저장/ACK 구분은 구현 검증 대상이다.
- v0.8 HTML은 **기존 47개 화면을 그대로 유지**하고 필요한 컴포넌트만 변경. 디로딩 시작 조건의 다양한 사례는 오른쪽 **시연 패널**에서 테스트할 수 있으며, 이는 사용자가 앱에서 직접 설정하는 항목이 아니다.
- 사용자는 v0.8 HTML 전체를 직접 클릭해 본 뒤 v0.9 수정안을 전달한다. 이때 검토 피드백으로 합의가 변경되지 않는 한 추가 임의 변경은 하지 않는다.


## 10.10 v0.9 · 전체 클릭 검토에서 승인한 UI 변경 (2026-11-05)

**효력:** 이 절은 직전 v0.8 이후 사용자와 항목별로 검토·승인한 **20개 UI 피드백의 최신 적용 기준**이다. 3~10.9절과 충돌할 경우 이 절이 우선한다. 이전 기능을 임의로 재설계하지 않고 **기존 HTML 화면 구조 및 데이터 보호 규칙은 보존**한다. v0.9는 독립 실행형 HTML **46개 시연 화면(시작 확인 화면 1개 제거)**이며 실제 PWA/서버 구현과 다르다.

### 10.10.1 홈·루틴 — 01~06

### 10.10.5 기존 정책과 충돌하지 않아야 할 내용

1. 디로딩 추천 분석 ON/OFF는 **권장 주수·게이지 계산**에만 영향. 분석 OFF에서도 **주간 계획 2일 이상 + 오늘 제외 직전 7일 내 일반 실제 수행 + 이전 종료 후 신규 일반 수행 + 당일 수행 없음 + 활성 일반 세션 없음**을 검사해 수동 시작 가능(DL-80~84); 0% 숫자만으로 시작 차단하지 않음.
2. 디로딩 기간은 권장 7일, 10일차 종료 시 자동 완료; 완료한 당일 일반 운동 시작 불가, 다음 날 복귀. 전부 쉬거나 미수행 임시 루틴을 전부 삭제해도 디로딩 지속·정상 완료 가능.
3. 실제 디로딩 세트는 운동 이력/근육 통계에는 포함하되 **일반 공식 승인 중량 평가에서는 제외**. 각 세트의 실제 수행 당시 제조사·부하 방식/계획은 불변 원본으로 보존.
4. 통계 v0.8의 범위 필터 연동, 성장 추적 검색, 보조근 펼침도 보존. 유산소 시간·거리와 웨이트 볼륨을 무분별하게 합치지 않음.
5. 본 HTML의 고정 날짜·예시 수치·시연용 자격 패널은 **제품 정책 또는 실데이터가 아니다**. 독립 HTML에는 API·인증·IndexedDB/서버 ACK가 연결되어 있지 않다.

### 10.10.6 HTML 기준 검토 및 미연동 확인

- 기준 HTML: **`Overload_UI_Baseline_Wireframe_v0.9.html`**, 화면 선택 목록 **46개**. 직전 v0.8의 47개에서 `디로딩 시작 확인` 화면을 제거함.
- 고정된 시연 날짜 `11.05 목`, 일부 주간 일정의 임시 루틴명, 테스트 수치 등은 화면 예시이며 실제 날짜/루틴을 계산하지 않는다.
- 32px 운동 아이콘은 HTML에 내장되어 있으므로 단일 파일로 브라우저에서 열 수 있다. 운영에서의 이미지 리소스 관리, 관리자 카탈로그의 대표 아이콘 매핑은 실제 앱 적용 시 검증한다.
- 시연에서 클릭되는 조작과 실제 저장/동기화/승인 중량/디로딩 상태전이를 혼동하지 않는다. 정상 서비스에서 해당 조건을 서버·오프라인 흐름으로 검증해야 한다.
- 이전 HTML 화면 안에 남은 `v0.6`/`v0.8`의 역사적 안내 라벨은 실제 정책 또는 최종 버전 표시로 사용하지 않는다. 코드 통합 시의 잔존 문자열 점검 대상이다.

- 운동명은 왼쪽, **저장된 계획값**은 같은 행 오른쪽 정렬: `60kg · 4세트 · 10회`, 유산소는 `20분 · 8km/h` 등 실제 저장된 항목만 표시. 입력·수행한 값과 혼동하지 않는다. 계획 반복수/중량이 가변이라면 실제 저장 계획에 맞는 범위·요약을 사용하고 임의 값 확정 금지.
- 좁은 화면은 이름만 말줄임 우선, 오른쪽 요약은 보존. 기존 운동 시작/오늘만 다른 루틴 선택 및 구분선 유지.

### 10.11.3 홈 '이번 주 일정'의 지난 날짜 상태

- 7열은 **날짜 숫자 / 요일 또는 수행상태 / 루틴명**의 3단 구조.
- **과거 예정 운동 완료일**: 요일을 제거하고 해당 자리에 어두운 초록 `✓` (`#74A68A`).
- **과거 예정 운동 미수행일**: 요일을 제거하고 해당 자리에 어두운 빨강 `×` (`#B17B83`).
- **과거 휴식일**: 요일을 제거하고 같은 자리에 어두운 중립색 `-` 표시. 이 기호는 완료 판정이 아니다.
- 오늘/미래 날짜는 기존 **요일 글자** 유지; 오늘은 모드 메인 컬러로 테두리/배경 등을 강조. 과거 날짜 숫자와 루틴명은 각각 어둡게 하되, 상위 `opacity`로 ✓/×까지 흑백·희미하게 만들지 않는다.
- 상태는 **해당 날짜의 승인/확정된 계획과 실제 수행 기록의 제품 판정**에 근거한다. 단순 지난 날짜/세트 일부/세션 시작만으로 완료로 판단하지 않는다. 서버 연동 전 목 시나리오(11/02 ✓, 11/03 ×, 11/04 -, 11/05 목)는 표시 예시에 불과. 정상/디로딩은 각자 해당하는 일정·수행 기록에 따라 판정한다.
- 날짜 선택 시 전체 루틴명과 수행 상태 표시 동작 유지. 7열/모바일 터치 간격 보존.

### 10.11.4 홈 분석 ON — 디로딩 누적주 게이지 (기존 초록→노랑 규칙 대체)

- 분석 ON·미진행 헤더에서 **0주부터 항상 가늘고 긴 수평 트랙**을 표시한다. `0/8주`일 때는 트랙만 보이고 채움 길이는 0. 분석 OFF일 때만 게이지 미노출.
- 채움 길이 `clamp(유효 훈련 주수 / 8, 0, 1)`; 8주 이상 100% 유지. 이 게이지는 피로도/의료적 위험 점수가 아닌 **디로딩 추천 누적 유효주**다.
- **0 ~ 4.0주(4.0 포함): Dusty Blue `#6C93C6`**. 회색/초록이 아니라 일반 모드 메인 컬러.
- **4.0주 초과부터** 노랑 → 주황 → 빨강 계열로 점진 변화하여 8주에서 빨강 고정. 실제 UI의 경고색 후보는 노랑 `#D6BC65`, 주황 `#D98D55`, 빨강 `#C96763`. *이 세 HEX는 미세 조정 가능한 경고색 후보*이며 시작 경계(4.0 포함)와 변화 방향은 확정.
- 4주 이하의 게이지를 숨기는 과거 결정, 4주부터 초록색으로 바꾸는 과거 규칙, 단순 모드 주 강조색만 고정 표시하는 Spike 시안은 **채택하지 않는다**.

### 10.11.5 운동 진행 — 종목 구간 **누적** 채움

- 상단 중앙은 `현재 x / n종목`과 **n개 구간**. 1기반 `index`에서 `i < index`, 0기반 `position`에서 `i <= position`인 칸이 모두 채워진다.
- 예: 4종목 중 2번째 **`[■ ■ □ □]`**, 3번째 **`[■ ■ ■ □]`**. 해당 종목 한 칸만 켜지는 `[□ ■ □ □]` 시안은 잘못된 표시다.
- 이전 종목으로 탐색하면 채워진 칸도 위치에 맞춰 감소. **완료한 세트/종목 수나 수행률이 아니라 현재 탐색 위치** 표시다.
- 일반·디로딩 공통이며 전체 운동 시간/휴식 시간 3열, `기존 기록 | 이번 기록`, 반복 ±/입력 구조 유지.

### 10.11.6 운동 검색 아이콘 자산 분리

- 6종: **가슴·등·하체·러닝·걷기·사이클(자전거)**. 기존 HTML의 `v9Icons` 원본 PNG를 변형 없이 `assets/exercise-icons/`로 추출하여 원본 128×128을 보존한다. 32px는 실제 UI의 CSS 표시 크기이며 원본 파일을 축소·재인코딩하지 않는다.
- **실제 UI는 32 CSS px**(고밀도 PWA 화면에서는 128px 원본을 32 CSS px로 렌더링 권장). 중립 Onyx 배경, 파스텔 컬러 원형/임의의 PPL 화살표 추가 금지. 기본 원본에 없거나 의미가 불명확한 아이콘은 엉뚱한 근육 아이콘으로 대체하지 않는다.
- 원본의 정확한 식별·SHA-256·파일 위치는 [manifest.json](assets/exercise-icons/manifest.json)과 [아이콘 README](assets/exercise-icons/README.md) 참조. 파일이 존재한다고 실제 운영 PWA에 자동 적용되는 것은 아니다.

### 10.14.2 루틴 주간 일정

- **가로 기본:** 월~일 7타일. 홈 타일 디자인 재사용, 날짜 숫자 생략. 요일과 명시 태그(미지정은 실제 이름 말줄임), 휴식을 간결하게 표시한다. 종목 상세·운동 아이콘은 넣지 않는다. 선택 상세에서 전체 이름을 확인한다.

### 10.14.3 저장된 루틴 목록

- `저장된 루틴 n개` 오른쪽 **단일 필터**: 전체 / 최신순 / 오래된순 / 배정된 루틴 / 미배정된 루틴. 전체·배정·미배정은 생성 최신순이며 수정으로 순서를 바꾸지 않는다. 목록 태그 필터는 없다. 요일 선택 중에는 요일명으로 잠긴다.

- 배정 카드는 홈 계열 블루그레이 그라데이션 배경, 미배정은 중립 카드다. 파란 선택 테두리로 배정 상태를 표현하지 않는다. 실제 컬러는 [Visual Theme Spec](Overload_UI_Visual_Theme_Spec_v0.9.md#7-t02-b-공통-표현--2026-11-07-개정), HTML은 회색 대응값을 사용한다.

## 10.15 · 2026-11-07 디로딩 v1.7 표현 정정

### 운동 루틴과 주간 일정 프리셋

- **운동 루틴**은 운동 종목·세트·반복·중량과 기존 수행·기록·성장·승인 흐름을 담당한다. **주간 일정 프리셋**은 월~일에 배정한 기존 운동 루틴 ID만 관리한다. 여러 프리셋에서 같은 루틴을 서로 다른 요일에 참조할 수 있다. 운동 구성 편집은 요일 배정을 바꾸지 않고, 프리셋 편집은 운동 구성·수행 기록·성장·승인에 영향을 주지 않는다. 프리셋 자체에 별도 성장·승인 사이클은 없다.
- 최대 4개다. 신규 계정은 요일 배정이 비어 있는 **1번 프리셋 하나**와 **자동 순환 OFF** 상태로 시작한다. 자동 순환의 초기 OFF는 별도 G4 분석 설정과 독립적이다. 표시 번호는 현재 정렬 결과다. 내부 데이터는 표시 번호와 독립적인 안정적인 ID를 사용한다.
- 기존 계정과 데이터의 전환 범위는 [V1 출시 전 전환](../../../overload-server/docs/api/weekly-schedule.md#v1-출시-전-전환)을 따른다.
- `+`는 월~일 배정이 없는 빈 프리셋을 생성한다. 새 프리셋은 자동 순환에서 기본 제외하며, 생성만으로 활성 프리셋과 순환 위치는 바뀌지 않는다.
- 현재 활성 프리셋과 마지막 1개는 삭제할 수 없다. 자동 ON에서 삭제 후 포함 프리셋이 2개 미만이 되거나 디로딩 보호 중이면 삭제할 수 없다. 서버에서 실제 활성·보호·포함 상태를 검증한다. 삭제해도 과거 적용 이력·세션·확정 근거는 유지한다.

### 적용과 자동 순환

| 동작 | 적용 결과 |
| --- | --- |
| 번호 선택 | ON/OFF 모두 조회 중인 프리셋만 바뀐다. 가능한 범위에서 기존 조회 결과를 활용해 로컬로 전환한다. |
| 자동 OFF에서 `전환` 선택 | 보고 있는 프리셋의 적용 요청을 보낸다. 성공 후 활성으로 표시한다. |
| ON → OFF | 자동 순환을 멈추고 현재 활성 프리셋을 유지한다. |
| OFF → ON | 포함 2개 이상일 때 첫 번째 포함 프리셋을 즉시 적용한다. 이후 월~일 고정 주차를 기준으로 순서대로 돌고 마지막 다음에 첫 번째로 돌아간다. |
| 활성 프리셋의 요일 배정 저장 | 기존 즉시 적용 정책으로 반영한다. 순환 위치는 유지한다. |
| 비활성 프리셋의 요일 배정 저장 | 해당 프리셋만 바뀐다. 현재 적용 일정과 순환 위치는 유지한다. |
| 전체 편집 저장 | 포함 여부 또는 전체 순서가 달라지면 ON에서 첫 포함 프리셋부터 다시 시작한다. 제외 그룹 내 순서 변경도 포함한다. OFF는 활성 프리셋을 유지하고, 무변경 저장은 순환 위치를 유지한다. [서버 기준](../../../overload-server/docs/api/weekly-schedule.md#자동-순환-설정) |

수요일에 적용하면 적용 가능한 수요일 이후에 새 배정이 반영된다. 월·화의 당시 계획과 기록, 기존 START·최초 MISS·InitialPlan 등 고정 근거는 보호한다. 순환 ON/OFF는 G4 분석 설정과 별개다. 매주 로컬 월요일 00:00부터 전환 대상이며 실제 적용 시각부터 효력이 발생한다. ACTIVE 보류와 서버 중단 복구는 [자동 순환 적용과 세션 보호](../../../overload-server/docs/api/weekly-schedule.md#자동-순환-적용과-세션-보호)를 따른다.

### 루틴 탭과 전체 편집

- **변경 이력**. 초기 다중 일정안의 채운 별·빈 별과 공통 상태 슬롯, 이후 조작 아이콘 옆 상태 태그를 거쳐, 2026-11-09~10 사용자 피드백 반영으로 제목 행 오른쪽 태그를 확정했다. 실제 활성은 `✓ 진행중`, OFF의 다른 일정은 위쪽 오른쪽·아래쪽 왼쪽 화살표가 겹쳐진 SVG와 `전환`, ON의 다른 일정은 눈 SVG와 `보기`다. `보기`의 접근성 이름에는 조회 전용임을 표시한다.
- 다음 행은 번호·이름, 순환 → 가로/세로 → 메뉴 아이콘 순서다. 아이콘에 보이는 사각 배경과 테두리를 제거하고 기존 터치 영역·포커스를 유지한다. 세로 보기의 요일과 루틴 사이에 여백을 두고 오른쪽 종목 수와 긴 이름의 줄임표를 유지한다. 원형 조회 번호와 `+`는 카드 아래 중앙에 둔다.
- **ROUTINE-06**은 루틴을 먼저 고르고 요일을 일괄 교체하던 초기안을 대체한다. 조회 중인 프리셋의 월~일 독립 드롭다운에서 루틴 또는 휴식을 고른다. 배정 유무·태그·전체 보기 필터와 변경 전후 확인을 제공한다. 루틴 저장 성공 후 한 번 `✓ 새 루틴 생성 완료`, 실제 루틴 이름, `주간 일정에 배정할까요?`를 표시하고 `나중에`와 `배정하기`를 제공한다. 배정 편집에서만 새 루틴을 `✦ 새 루틴 · 이름`으로 상단에 강조하며 요일은 직접 선택한다.
- 메뉴의 이름 편집은 처음에 시연 전용이었고, V31에서 `이름 변경`의 실제 저장이 추가됐다. 이름 변경으로 조회·적용 일정과 배정·순환을 바꾸지 않는다. 전체 편집과 삭제는 기존 메뉴에 둔다. 삭제와 순환 재시작의 조건은 [서버 계약](../../../overload-server/docs/api/weekly-schedule.md#자동-순환-설정)을 따른다.
- **ROUTINE-07**의 포함·제외 목록은 두 줄 정보 왼쪽에 32px 정사각형 번호를 가운데 정렬한다. 작은 `추가`·`제외` 버튼은 다른 그룹의 끝으로 옮긴다. 위아래 버튼 대신 핸들을 사용한다. 마우스·터치로 끄는 동안 카드가 따라오고 주변 카드가 이동한다. 키보드 순서 조작을 유지한다. 취소는 초안을 폐기하고 저장은 구성 전체를 한 번에 보낸다. ON에서 포함 2개 미만은 저장할 수 없다.
- 저장된 루틴 목록에는 `전체 / 최신순 / 오래된순 / 이 일정 배정 / 이 일정 미배정`을 제공한다. 배정과 요일 필터는 조회 일정 기준이다. 루틴 구성의 변경과 요일 배정은 각각 저장한다. 루틴 삭제 시 모든 프리셋의 배정을 해제하고 과거 기록을 보존한다. [현행 화면 명세](ui-ux.md#32-루틴-목록--routinelist)

### 홈과 디로딩

- 초기안의 `현재 주차` 필터와 루틴 검색은 사용자 피드백 이후 제거했다. 최종 구성은 `전체 / 미배정 / 저장된 일정 번호(01~04)`다. 기본 선택은 실제 활성 일정 번호이며, 미배정은 모든 프리셋 기준이다. 제외 프리셋도 조회할 수 있고 루틴 ID로 중복을 제거한다. 선택은 오늘 카드만 바꾸며 기존 START·InitialPlan·기록 정책을 사용한다.
- 디로딩 보호 중 일반 프리셋과 순환 목록은 조회할 수 있다. 관리·활성화·순환 변경은 잠기고 기존에 허용된 임시 계획 편집은 유지한다. 미리보기·시작에서 디로딩 원본 프리셋을 선택할 수 있으며 기본은 활성 프리셋이다. 제외된 프리셋도 원본으로 선택할 수 있다. 정지·복귀와 원본 선택의 도메인 규칙은 [디로딩 v1.7의 프리셋 연동](Overload_Deloading_Design_Specification_v1.7.md#105-주간-일정-프리셋-연동)을 따른다.

## 10.17 · 휴식 타이머 시각·효과음 알림

아래 내용은 초기 정책과 검증 계획의 이력이다. 운영 구현과 최신 화면 규칙은 [10.35절](#1035--세트-사이-휴식과-휴식-타이머-알림--2026-11-19)을 따른다.

**정책 확정 · v0.9 HTML 시연 · T03.5 구현 예정.** 웨이트 본세트 사이의 휴식 종료가 가까워졌음을 화면과 소리로 알린다. 기존 휴식 카운트다운, 세트·운동 기록과 저장 방식은 유지한다.

### 시각 알림 범위와 동작

- 색상 반전 범위는 최상단 개발 데모·상태 표시 아래, `홈 / 루틴명 / 운동 종료` 탐색 영역 위에 있는 **3열 시간 정보 바 전체**다. 전체 운동 시간·운동 진행·휴식 시간의 배경과 내부 텍스트를 함께 반전하고, 진행 바의 채움·트랙도 구분할 수 있는 대비를 유지한다. 상태 표시, 탐색, 운동 종목, 세트 카드, 하단 고정 버튼 및 나머지 화면은 기본 색을 유지한다.
- **B 방식**으로 매초 한 번 짧게 반전한 뒤 같은 초 안에서 원래 색으로 돌아온다. 5초 전 설정에서는 5·4·3·2·1초, 10초 전 설정에서는 10초부터 1초까지 적용한다. 0초 또는 수동 `휴식 종료`에 즉시 기본 색으로 돌아온다. `+30초` 뒤에는 새 종료 시각에서 계산한 실제 남은 초로 다시 판단한다. HTML에서 선택한 짧은 반전 시간은 시연값이다.
- `prefers-reduced-motion`에서는 반복 반전을 정적인 테두리 등으로 대체한다. 카운트다운과 기존 10초 이하 `다음 세트 준비` 안내는 계속 표시하며 색만으로 종료 임박 상태를 전달하지 않는다. 반전이 자동 스크롤이나 포커스 이동을 유발하지 않게 한다.

### 효과음과 설정

- **설정 → 운동 설정 → 휴식 타이머 알림**에서 **화면 깜빡임 ON**, **시작 시점 5초 전**, **효과음 ON**이 기본이다. 시작 시점은 10초 전 또는 5초 전이며 화면 깜빡임이 OFF이면 선택을 비활성화한다.
- 효과음 ON은 시각 알림과 독립적으로 **5·4·3·2·1초에 한 번씩** 짧게 재생한다. 시각 알림을 10초 전으로 바꿔도 효과음 시작은 5초 전이다. 재생 실패와 운동 기록 저장은 분리한다. [과거 핸드오프](../handoff/Overload-Project-Handoff-Task001-005.md)의 무음 정책은 이 효과음 설정으로 대체한다. 진동 금지와 전체 화면 플래시 금지는 유지한다.
- 실제 앱에서는 변경값을 앱 재실행 후에도 유지한다. 180·120·90초 등의 기존 `세트 사이 휴식` 값과 분리하고, 필요한 경우 기기 로컬 설정을 사용한다. 전용 Backend API나 DB 변경을 전제하지 않는다.
- T03.5에서 사용자 조작에 따른 오디오 활성화, 브라우저 자동 재생 제한, 음악 앱과 동시 재생, 화면 잠금 및 백그라운드 복귀를 iPhone Safari와 설치형 PWA에서 확인한다. 현재 [HTML 시연](Overload_UI_Baseline_Wireframe_v0.9.html)은 탭 안에서만 설정과 카운트다운을 바꾸고, 효과음은 예정 시점을 텍스트로 표시한다. **실제 PWA 구현과 iPhone 실기기 검증은 예정 상태다.** [Frontend 구현 지침](../engineering/frontend.md#t035-휴식-타이머-시각효과음-알림)

## 10.18 · 2026-11-11 공통 운동 검색 UI·CATALOG-02 1차 확정

**적용 범위:** 이번에 독립 HTML 두 종류(CATALOG-01 전체 펼침, STATS-02 접이식 운동별 필터)를 사용자 피드백으로 조정하고, 통합 무채색 HTML에 적용한 UI 결정. **실제 Backend API 연결·운영 DB 마이그레이션·원본 GIF 제공 권한 승인은 포함하지 않는다.**

### 10.18.1 공통 검색 외형

- 검색 라벨은 `표준 운동 검색 · 이름 또는 별칭`, 입력 예시는 `예: 벤치, barbell`. 운동명·별칭에 입력을 적용한다.
- `전체·가슴·등·어깨·팔·하체·코어·유산소·기타`의 27px 높이 둥근 텍스트 태그를 한 줄로 유지하고 가로로 스크롤한다. 태그에는 아이콘을 사용하지 않는다.
- 32px 원형 공식/확장 아이콘, **운동명 + `대분류 · 핵심 PRIMARY`** 2줄, 구분선과 오른쪽 `›`를 동일 간격/타이포그래피로 사용한다. 선택형 목록의 `›`는 해당 항목이 눌린다는 의미이며 설정 목록에서만 상세 페이지로 이동한다.
- 새 어깨·팔·코어 아이콘은 사용자가 제공한 그림을 기존 회색 아이콘 테마로 변환해 사용한다. 유산소는 원래 걷기 아이콘을 재활용한다. 기타는 자산 미제공 시 `ETC` 문자 표시를 허용한다.
- 검색 결과가 없거나 해당 필터에 데이터가 없으면 `검색 결과가 없습니다.`. 실제 운동명/별칭/PRIMARY/아이콘 매핑은 서버 연동 시 검증해야 한다.

| **WORKOUT-06 운동 진행 중 종목 추가/교체** | 시안의 팝업으로 펼침 | 있음 | 선택·취소 시 기존 운동 화면으로 복귀. 교체 조건과 초기값은 10.18.4절 적용 |
| **STATS-05 성장 추적 종목 선택** | 현재 선택된 운동명의 검색 바만 보임 | 펼치면 있음 | 기존 성장 추적 검색 결과에서 선택 후 자동 접힘, 승인 중량 추이 유지 |
| **STATS-02 운동 현황 → 운동량 추이 → 운동별 필터** | 현재 선택된 운동명의 검색 바만 보임 | 펼치면 있음 | 조회 기간의 실제 수행 이력이 있는 운동만 선택 후 자동 접힘, 선택 종목의 완료 세트·총중량 그래프와 합계 표시 |

- 닫기 버튼은 **검색 입력 옆이 아니라 펼친 검색 UI의 `운동 종목` 제목 오른쪽 끝**이다. 닫으면 선택값은 유지하고 검색·태그·목록을 접는다. 결과 선택 시에도 자동으로 닫는다. 팝업 검색은 기존 오버레이를 닫는다.
- 접이식 목록은 열린 동안 필터를 좌우 스크롤하고 결과 목록만 최대 높이 범위 안에서 세로 스크롤하여 아래 그래프를 과도하게 가리지 않는다.
- STATS-02는 `전체/운동별/근육별`, `세트/총중량`, 조회 기간을 유지한다. 운동별 선택에는 접이식 공통 검색 UI를 적용한다. Backend가 기존 완료 운동 기록을 현행 정책으로 집계하고 PWA는 선택한 범위의 집계 결과를 표시한다. HTML의 그래프와 합계는 UI 시연용 예시다.
- 성장 추적은 검색 UI와 펼침·닫힘 동작을 변경하고 [현행 성장 추적 계약](../../../overload-server/docs/api/approved-weight-growth.md)의 조회 범위를 유지한다. 선택 기간에 유효한 완료 웨이트 세트 또는 공식 승인 중량 변경 이력이 있는 운동을 검색한다. 공식 승인 이력만 있는 종목, 비활성·미공개 종목 및 삭제된 루틴·배치의 과거 이력도 기존 계약에 따라 조회한다.
- 운동 현황의 운동별 검색에는 해당 기간의 실제 수행 종목을 사용한다. 화면마다 기존 데이터 소스와 선택 조건을 유지한다.
- 루틴·운동 진행 화면은 기존 세트 목표, 장비 제조사, 부하 방식, 임시 변경 등의 폼/선택·복귀 절차를 변경하지 않는다.

### 10.18.3 표준 상세·Backend 후속 정리

- CATALOG-02의 분할 태그/핵심 PRIMARY/미제공 GIF/접힌 방법/빈 상태 기준은 8.3절을 적용한다.
- 제조사·머신·부하 방식 선택은 사용자 루틴 배치와 진행 운동에서 제공한다.
- **확정 정책 / 실제 GIF 표시 미구현.** 인증·인가는 [Spring Security 세션 계약](../../../overload-server/docs/engineering/security-session.md#http-보안-계약)과 [V35 보호 전송 계약](../../../overload-server/docs/api/standard-exercise-catalog.md#보호-gif-전송과-ui-계약)을 적용한다. 회원별 권한, 현재 대표 출처, 파일 유무와 보호 미디어 미캐시 정책을 따른다. 표준 운동 UUID로 원본 ID나 GIF URL을 추정하지 않는다. 현재 GIF 안내 UI를 유지하며, 보호 경로 전달·권한 및 파일 부재·전송 실패 표시와 최종 안내 이미지는 후속 연동에서 처리한다. 실제 파일 권리·배포 조건 충족 전에는 기능을 활성화하지 않는다.
- **당시 상태.** 이 결정 시점에는 10.18절의 PWA 검색·선택 및 상세 연결이 후속이었다. 설정 카탈로그의 현행 상태는 8.3절을 따른다. 기존 조회·선택 API와 정렬·검수 계약을 유지한다.

### 10.18.4 운동 진행 중 종목 교체

**기존 교체 구현 / 후속 정책 미구현.** 완료 수행이 없는 종목의 세션 전용 교체는 LocalWorkoutFlow에 연결되어 있다. 조합별 최근 실제 중량 조회·기록 없음 0kg·조합별 메모·공식 평가 전체 제외·대체 슬롯 완료 인정은 10.21절을 적용하며 아직 연결하지 않았다. 기존 참고 기록과 HTML 시연을 이 기능의 구현 근거로 사용하지 않는다.

- 유효한 완료 세트가 없는 종목만 교체할 수 있다. 완료 세트가 있으면 교체할 수 없으며, 사용자가 완료 기록을 명시적으로 취소해 유효한 완료 세트가 모두 없어지면 교체할 수 있다.
- 교체는 현재 세션에만 적용한다. 원본 루틴과 공식 승인 중량을 보존한다. 취소하거나 저장에 실패하면 기존 세션 상태와 로컬 스냅샷을 유지한다. [세션 보존 계약](../../../overload-server/docs/api/workout-sessions.md#교체삭제정정)
- 교체 전 운동의 중량·반복값을 새 운동에 복사하지 않는다. 새 표준 운동·제조사·중량 방식 조합의 최근 실제 중량을 조회하고, 유효 수행이 없으면 중량을 0kg으로 제안한다. 조회 실패는 기록 없음과 구분하며 반복값을 임의 생성하지 않는다. 상세 기준과 구현 확인은 10.21절을 따른다.

### 10.18.5 성장 추적 검색 메타데이터

**확정 정책 / 공통 검색과 메타데이터 보강 미구현.** 검색 대상, 기간, 조회 자격과 승인 중량 그래프·기록은 10.18.2절과 기존 성장 추적 API를 따른다. 이름·별칭·부위 검색은 기존 이력 접근 범위에서 제공한다.

- 근육 정보가 없는 과거 운동은 기존 자격을 충족하면 `전체`에서 조회할 수 있다. 부위별 필터에는 포함하지 않는다.
- 해당 결과에 공통 기본 아이콘과 `근육 정보 없음` 보조 문구를 표시한다. 조회 자격이나 기존 승인 이력 표시를 변경하지 않는다.

### 10.18.6 운동량 추이와 디로딩 표시

**확정 정책 / 선택 범위의 날짜별 집계·디로딩 그래프 표시 미구현.** Backend는 기존 완료 운동 기록을 집계하고 PWA는 집계 결과를 표시한다. 선택 종목·근육의 날짜별 완료 세트·총중량은 기존 통계 설계에 따라 후속 구현한다. 날짜 귀속, 정정·삭제·복구, 디로딩 중 실제 수행 포함, 맨몸 추가 부하 규칙은 현행 계약을 유지한다. [현행 통계 API](../../../overload-server/docs/api/statistics.md#statistics-응답과-실제-집계)

- **디로딩 표시 B안.** 주간·월간 운동량 그래프에서 디로딩 날짜와 구간을 시각적으로 구분하고 시작일과 종료일을 확인할 수 있게 표시한다. 조회 기간과 일부만 겹치면 겹치는 구간을 표시한다.
- [기존 디로딩 기간 조회 API](../../../overload-server/docs/api/deload-periods.md#인증읽기쓰기)를 우선 재사용한다. 이 결정은 통계 설계 ST-45의 그래프 표시 방식을 구체화한다.

## 10.19 · 공통 숫자 입력 세로 휠 피커

**확정 UI 정책 / 구현·실기기 검증 대기.** 운동 중 숫자를 빠르게 조절할 수 있도록 `[−] [현재 숫자] [+]` 구조에 세로 휠을 연결한다. React PWA에서 구현하는 커스텀 컴포넌트이며 iOS 숫자 휠의 조작 방식을 참고한다. 10.10.2절 08항의 반복 입력 배치와 1회 증감을 이어받고, 적용 대상의 중앙 터치와 키보드 진입은 이 절을 따른다.

### 10.19.1 적용 범위

- **입력값:** 편집 가능한 운동 중량(최초·작업·실제 중량, 명시 승인·재승인, 기존 선택형 맨몸 추가 중량 포함), 세트 수, 반복 횟수, 최소·최대 반복 등 반복 범위.
- **화면:** 루틴 생성·편집, 일반 운동 진행·세트별 기록, 운동 중 임시 루틴·세트 편집, 운동 기록 정정, 디로딩 임시 루틴 생성·편집, 디로딩 운동 진행 및 수행 기록 정정. 진행 중·종료 후 기존 승인 해결에서 사용자가 직접 입력하는 재승인 중량도 포함한다. 디로딩 임시 루틴에는 기존 흐름에서 허용된 수동 입력에 적용하며, 자동 편성·감량과 기간·편집 권한은 현행 계약을 따른다.
- **제외:** 모든 유산소 수치, 휴식 시간·휴식 타이머 설정, 자동 운동 시간 측정·타이머, 인증번호·OTP, 통계 그래프·기록 요약·복구 원본 등 읽기 전용 수치, 디로딩 기간·진행일 등 표시값, 개발·검증 전용 입력. 이 항목은 기존 조작을 사용한다. 읽기 전용 데이터와 자동 계산 결과는 새 입력 필드로 만들지 않는다.

### 10.19.2 조작과 값 보존

- `− / +`는 즉시 현재 초안을 조절하고, 가운데 숫자 영역을 터치하면 휠을 연다. 기본 증감 간격은 두 방식 모두 **중량 2.5kg**, **세트 수·반복 횟수·최소 및 최대 반복 각각 1**이다. 필드별 유효 범위와 별도 확정 도메인 규칙을 우선한다. 종료 후 중량 검토의 승인 예정값 수정은 10.23.5절의 PLATE/STACK 2.5kg·기타 1kg을 적용하며 기본 승인 권고 폭 5kg·2kg과 구분한다.
- 휠은 숫자를 상하로 스와이프한다. 중앙 선택값을 강조하고 주변 값은 흐리게 표시하며, 스크롤을 멈추면 가장 가까운 선택 항목에 정렬한다. 기존 값이 있으면 해당 값에서 시작한다. 사용자가 선택한 값은 별도 확인 없이 현재 초안에 반영한다.
- `직접 입력`은 휠 안에서만 제공한다. 선택하면 숫자 키보드로 전환해 기존 값을 수정하고 초안에 반영할 수 있다. 최솟값·최댓값·소수 자릿수·정수 여부·최소/최대 관계는 각 필드의 기존 검증 계약을 따른다. 2.5kg 간격은 조절 기준이므로 허용된 `52.3kg`을 `52.5kg`으로 반올림하거나 잘라내지 않는다.
- 기존 숫자와 과거 기록 기반 자동 입력을 보존한다. 빈 값은 휠을 열기만 해서는 그대로 유지되며, 값을 선택하거나 입력하는 등 명시적으로 조절할 때만 변경한다. 조합 선택 시 중량 제안은 10.21절을 따르며 유효 실제 기록 없음은 0kg, 조회 실패는 별도 상태다. 반복수의 빈 초안과 정상적인 0kg 수행, 맨몸 추가 부하의 입력·계산 규칙을 구분한다.
- 휠 선택과 직접 입력은 초안에만 적용한다. 세트 완료·휴식 시작, 공식 승인 변경, 서버 저장, 운동 종료는 기존 확정 동작과 검증을 따른다. 디로딩의 일반 승인 제외와 기존 오프라인 초안·복구 경계를 적용한다. [루틴 수치 계약](../../../overload-server/docs/api/routine-management.md#수치-계약--이번-사용자-승인으로-확정) · [세션 계약](../../../overload-server/docs/api/workout-sessions.md#snapshot-정확한-요청-계약) · [맨몸 추가 부하](../../../overload-server/docs/api/bodyweight-additional-load.md)

### 10.19.3 구현 및 실기기 검증 대상

- 실제 iPhone Safari와 홈 화면 설치형 PWA에서 스와이프·관성·중앙 스냅, 빠른 연속 스크롤, 스크롤 중 의도치 않은 값 반영, 화면 세로 스크롤 충돌을 확인한다.
- 직접 입력 전환 시 숫자 키보드, 작은 화면과 Safe Area, VoiceOver와 보조 입력, Android 동작을 검증한다. 값 변경 후 취소·복원과 오프라인 초안 보존을 함께 확인한다.
- 관성, 애니메이션, 행 간격, 선택 반영 타이밍과 휠의 구체적인 디자인은 실제 iPhone 검증 후 확정한다. [실기기 검증 체크리스트](ui-ux.md#공통-숫자-입력-실기기-검증)

### 2026-11-13 실제 API 운동 기록 검수 통합 수정

사용자의 최신 검수 지시가 앞선 종료 요약 수정 범위를 명확히 했다. 삭제 대상은 `운동 수행` 제목과 전용 여백이며 WEIGHT/CARDIO 수행 기록은 유지한다. 화면 순서는 요약 → 중량 검토 → 실제 수행 → 기록 돌아가기다.

- 중량 검토는 운동명 / 기존 판단 중량과 ↑↓, 완료/계획 세트 / 실제 반복 목록의 두 행이다. 화살표는 증량·감량 접근성 라벨을 갖는다. 반복 강조는 서버가 제공한 기여 수행만 사용한다. 유지와 자료 부족·오류를 구분한다.
- 사용자는 정책 질문에 **미완료 감량은 중량 검토 권고만 변경하고 공식 기준 기록 자격은 유지**하도록 확인했다. 현재 assessment GET의 weightReview가 권고를 제공하며 최초 공식 평가·벤치마크·승인값은 유지한다. [현행 계약](../../../overload-server/docs/api/workout-sessions.md#종료-화면의-중량-검토-권고--공식-평가와-분리)
- 수행 기록 목표 행은 당시 계획의 기준 중량을 표시한다. 종목명과 세트·총 볼륨 요약은 동일한 크기·두께·톤이며, 이름만 줄바꿈하고 수치 요약은 한 줄을 유지한다.
- 기록 상세의 ⋮ 메뉴는 개별 박스 없는 목록형 행이다. 정정/복구/삭제/평가 이력은 기존 실제 API를 재사용하되 사용자용 정보 위계와 상태·입력 보존을 적용한다.
- 위 항목은 당시 재검수 기록이다. 사용자 확인 및 코드 커밋 후 현행 마감 상태는 아래 10.20절을 따른다.

## 10.21 · 루틴 중심 중량·메모·대체 정책 — 2026-11-13 후속 확정

**상태: 제품 정책 확정 / 후속 구현 필요.** 기존 화면 구조·규칙을 유지하며 조합 변경 시 승인값 유지, 교체 시 중량 공란, 대체 운동만 제외하고 나머지를 개별 공식 평가하는 과거 방안을 교체한다. 현재 코드는 제조사·부하 변경 후 승인값 유지, 장비를 구분하지 않는 공식 비교, 세션별 로컬 메모와 원래 세션 운동 ID별 완료 판정을 사용한다. 이번 반영은 Markdown 설계 정합성 수정이며 코드·API·DB·HTML 구현이 아니다.

### 10.21.1 정규 루틴과 조합

- 공식 점진적 과부하의 기준은 사용자가 저장·확정한 정규 루틴이다. 승인 중량은 기존 `routine_weight_placements.approved_weight`로 배치별 독립 관리한다. 같은 조합의 다른 루틴·배치에 승인을 전파하거나 개인 조합별 공식 승인 원본을 만들지 않는다.
- 조합은 관리자 제공 **표준 운동 ID + 제조사 ID + 중량 방식**이다. 개인 조회·메모에는 사용자와 dataGeneration 경계를 적용한다. nullable 제조사·부하는 각각 미지정 값이며 다른 조합의 wildcard가 아니다. 개인 장비 등록·모델 DB·실물 기구 ID·사용자 장비 프로필은 요구하지 않는다.

### 10.21.2 최근 실제 중량과 루틴 저장

- 조합을 변경하지 않은 정규 루틴의 다음 운동은 해당 배치의 현재 승인 중량을 사용한다. 조합 신규 선택·변경에는 동일 사용자의 동일 조합에서 **가장 최근 유효 실제 수행 기록의 마지막 유효 완료 세트 중량**을 제안한다. 정규·다른 루틴·오늘만 추가·대체 출처를 구분하지 않으며 최고·평균·최빈 중량은 사용하지 않는다.
- 유효 수행 기록이 없으면 UI는 0kg으로 시작한다. 조회 실패는 기록 없음과 구분하고 0kg을 자동 저장하지 않는다. 사용자는 제안값을 수정할 수 있다. 실제 100kg 이후 105kg 승인만 하고 미수행했다면 A사→B사→A사 재선택에서 100kg을 불러온다. 조합별 과거 승인값 복원 저장소는 만들지 않는다.
- 표준 운동·제조사·중량 방식 중 하나라도 변경하여 저장·확정하면 기존 배치를 논리 제외하고 같은 위치에 NEW 배치를 만드는 방향을 적용한다. 확인·수정한 값으로 새 배치의 최초·승인 중량을 초기화한다. 변경하지 않은 조합에 불필요한 NEW를 만들지 않고, 저장 전 취소는 원본을 바꾸지 않는다. 사용자에게 별도 운동 등록 절차를 추가하지 않는다.
- 변경 배치의 공식 평가·benchmark는 새로 시작한다. 같은 조합 복귀도 옛 배치 평가를 복원하지 않는다. 과거 실제 수행은 그대로 독립적인 기록이며 삭제·수정하지 않는다. 새 배치의 첫 운동도 기존 세트·반복·승인 조건을 충족하면 즉시 증량·감량 평가하며 적응·유예 횟수를 추가하지 않는다.

### 10.21.3 오늘만 변경과 공식 평가

- 원래 계획한 운동을 **오늘만 다른 표준 운동·제조사·중량 방식으로 변경·대체하면 해당 세션의 공식 증량·감량 평가를 전체 제외**한다. 나머지 정규 종목도 개별 공식 평가하지 않는다. 대체 수행의 중량을 원계획 운동 평가에 사용하지 않는다.
- 대체하지 않고 원래 운동을 건너뛴 일반 미수행도 기존 공식 평가의 전체 완료 제한을 유지한다. 일부 정상 종목만 공식 평가하는 예외를 만들지 않는다.
- 단순 추가 운동·초과 세트는 실제 기록에 모두 포함하되 공식 평가에는 계획된 첫 N개만 사용한다. 정규 계획을 그대로 충족한 세션은 추가분만으로 전체 제외하지 않는다. 기존 `TODAY_ONLY` 중량·승인 문맥·미완료 감량 권고 산식을 다른 정책으로 바꾸지 않는다.
- 최초 종료 공식 평가와 정정 후 현재 공식 평가를 구분한다. `weightReview`는 별도 화면 권고이며 공식 자격·승인 적용의 증거가 아니다. 임시 추가·대체 종목은 공식 증감 평가 대상이 아니며 정규 루틴에 저장한 뒤 해당 배치 기준으로 평가한다.

### 10.21.4 대체 슬롯 완료와 실제 통계

- 원계획 슬롯과 실제 대체 운동을 연결하고, 다음 **네 분류가 모두 정확히 일치**하며 원래 계획 세트 수를 충족하면 해당 슬롯 완료로 인정한다: 전면/후면(`frontBackSplit`), PUSH/PULL/LEGS(`pplSplit`), 검수된 운동 부위 분류, 관리자 순서상 첫 PRIMARY 근육. 부위는 원계획 운동과 대체 운동 각각의 검수된 운동 부위 분류를 비교하며 기존 가슴·등·어깨·팔·하체·코어 분류를 사용한다. [ST-27의 분류 원칙](../../../overload-server/docs/product/Overload_Statistics_and_Tracking_Design_Specification_v1.4.md#41-기본-집계)에 따라 근육별 `muscle.group_code` 연결값을 임의로 운동의 단일 대표 부위로 간주하지 않는다. 표준 운동명 유사도나 일부 근육 겹침은 근거가 아니다.
- PRIMARY는 저장된 `primary_order`의 첫 항목을 사용한다. 분류·순서가 없거나 판정 근거가 불명확하면 임의 근육 선택·일치 추정으로 완료시키지 않는다. 현재 저장 구조에서 운동 부위 분류의 판정 근거가 불명확한 경우도 구현 확인 사항으로 남기고 완료를 임의 인정하지 않는다. 기존 DB의 순서·분류 품질과 슬롯 연결·재계산은 구현 확인 대상이다. 별도 동작 계열·장비 엔터티를 만들도록 요구하는 정책이 아니다.
- 분류 불일치·세트 부족은 슬롯 미완료다. 인정은 하루 완료 표시, ST-17~23 주간 완료율, DL-08 및 G4 유효 운동일·훈련 주수에 연결한다. `완료한 계획 종목 / 전체 계획 종목`을 유지하므로 3/3=1.0, 4/5=0.8이다. 0/1 이진 판정이나 새 피로 산식을 만들지 않는다.
- `실제 수행 정상 기록 / 루틴 완료 인정 / 디로딩 유효일 반영 / 공식 중량 평가 전체 제외`가 동시에 가능하다. 실제 근육·세트·볼륨은 실제 대체 운동으로 한 번 집계하며 슬롯 인정 실적을 중복 합산하지 않는다. 일반 예정 루틴 후보·단일 최고 세션·일일 상한과 디로딩 기간의 기존 산식은 유지한다.

### 10.21.5 조합별 최신 기구 세팅 메모

- 사용자·dataGeneration·표준 운동·제조사·중량 방식별 최신 메모를 서버에 저장한다. 같은 조합이면 루틴·임시 운동과 기기를 넘어 조회하고 A사→B사→A사 선택에 따라 각각의 최신 메모로 전환한다. 없음은 빈 상태, 조회 실패는 오류로 구분한다.

**UI 설계 확정 / HTML 합성 시연 / React·Backend 구현 필요.** 10.21~10.22절의 제품 정책을 유지하고 당시 별도 검토였던 UI를 아래와 같이 확정한다. 기존 정상 구현·API 계약·디로딩 산식과 과거 결정 이력은 보존한다. HTML의 데이터·권장값·승인은 메모리 시연이며 실제 저장·서버 검증의 근거가 아니다. 이번 최종 HTML 수정은 전체 보기 토글 위치만 변경한다.

### 10.23.1 기록 메인과 분석 진입

- 운동 분석 바로가기는 2×2로 배치한다. 첫 행은 `운동 현황 / 성장 추적`, 둘째 행은 `근육별 계획 분석 / 근육별 통계 분석`이다. 별도 `운동 이력` 바로가기는 제거하되 최근 운동 기록의 `전체 보기`와 하단 홈/루틴/기록/설정 내비게이션은 유지한다.
- 계획 분석과 실제 통계 분석은 각각 독립 페이지다. 기록 메인에서 계획 분석으로 들어가면 현재 활성 주간 프리셋, 루틴 프리셋 `··· → 계획 분석`에서는 조회 중인 해당 프리셋을 기본 선택한다. 비활성 프리셋도 조회할 수 있으며 조회·선택이 실제 활성 프리셋·일정·자동 순환을 바꾸지 않는다.

### 10.23.2 근육별 계획 분석

- 순서는 `제목 / 우측 끝 전체 보기 토글` → `분석 대상 프리셋 선택과 분류별/근육별 탭 카드` → `현재 월~일 계획 · 권장값은 참고용 합성 가이드입니다.` → 그래프다. 토글은 분석 대상 카드 안에 두지 않는다. 모바일에서도 제목과 겹치거나 가로로 넘치지 않게 하며 접근 가능한 라벨과 키보드 조작을 유지한다.
- 선택 프리셋의 **현재 월~일 배정 루틴 계획**만 분석한다. 과거 날짜별 적용 이력·실제 실적·디로딩 임시 계획을 섞지 않고 주간/월간 전환·날짜 이동을 제공하지 않는다. 같은 루틴의 반복 요일은 각각 집계한다.
- `전체 보기`는 일반 ON/OFF 스위치이며 기본 OFF다. OFF에서는 계획이 **정확히 0세트인 항목만** 숨기고 ON에서는 표시한다. 분류별/근육별 공통이며 탭·프리셋 변경 후 상태를 유지한다. 정보 없음·확인 불가를 0으로 치환하지 않는다.
- 분류별은 전면/후면, PPL, 부위를 각각 원본 계획 세트와 검수된 운동 분류에서 독립 계산한다. 세부 근육 기여의 합으로 상위를 역산하지 않는다. 분류 누락·부위 판정 근거는 10.21.4절·ST-27의 확인 필요 원칙을 유지한다.
- 근육별은 **전체 하나의 카드**, 부위명과 구분선이 같은 행인 목록을 사용한다. 각 근육에 가로 막대와 `현재 계획 기여 세트 / 권장 최대 세트`를 표시하고 PRIMARY 1.0 / SECONDARY 0.5를 적용한다. 권장 시작점은 막대 위의 `▼`다.
- 최대를 넘으면 실제 숫자는 보존하고 막대만 100%로 제한한다. 초과 경고·위험색·강제 제한을 추가하지 않는다. 권장 범위는 참고용이며 HTML의 시작 4 / 최대 12세트는 합성 예시다. 미확정 항목에 과학적 표준·제품 권장값을 임의로 만들지 않는다.

### 10.23.3 근육별 통계 분석

- 실제 유효 완료 기록을 분석하며 프리셋 선택과 전체 보기 토글은 없다. 주간(월~일)/월간(1일~말일), 이전/다음 기간, 달력, 분류별/근육별, 기존 `세트 / 총중량` 버튼 배치를 유지한다. 달력 날짜 선택은 현재 모드의 전체 주간 또는 월간으로 이동한다.
- 달력의 일정 완료 여부와 수행 통계는 구분한다. 미래·판정 대기 날짜를 미완료로 만들지 않는다. 분류별은 전면/후면·PPL·부위를 독립 집계하고 근육별은 계획 분석과 같은 한 카드의 부위별 근육 목록을 사용한다.
- 세트는 `실제 수행 / 해당 시점 계획`이다. `10 / 12세트`, `0 / 6세트`, `3 / —세트`처럼 표시하며 `—`는 계획 없음으로 0과 구분한다. 실제가 0이어도 계획이 있는 항목은 표시한다. 세부 기여와 실제 참여 정수는 ST-24~31에 따라 구별한다.
- 총중량은 실제 완료 세트의 중량×반복 합계를 kg으로 표시한다. 계획 총중량을 생성하거나 세트 기여용 PRIMARY/SECONDARY 0.5를 총중량에 적용하지 않는다. 맨몸 추가 부하·측정 근거 없음은 기존 ST-33~37을 유지한다.

### 10.23.4 루틴·메모·오늘만 편집

- 기존 루틴 편집 UI를 재사용한다. 같은 운동·제조사·부하 방식 조합은 기존 배치 승인 중량을 사용한다. 조합 변경 저장은 기존 배치 제외+NEW 및 최근 유효 실제 완료 기록의 마지막 세트 제안을 적용한다. 기록 없음의 0kg과 조회 실패를 구분한다. 내부 NEW 상태는 사용자에게 별도 안내하지 않는다.
- 기존 textarea를 사용하고 `메모는 같은 운동·장비 조합에서 공유됩니다.` 취지로 안내한다. 사용자·표준 운동·제조사(nullable)·부하 방식(nullable) 조합의 최신 **서버 공유 메모**이며 사용자/세대 경계를 지킨다. 로컬 전용·메모 이력·별도 관리 화면을 추가하지 않는다. 서버 API·동시 수정·저장 실패/오프라인 처리는 10.21.6절의 후속 계약 사항이다.
- 운동 중 기존 화면의 오늘만 제조사/부하 변경, 다음 종목 추가, 유산소 추가, 현재 종목 교체/제외, 기구 세팅 메모를 재사용한다. 교체와 다음 추가는 별개다. 대체 슬롯의 네 분류 일치·원계획 세트 충족은 완료율·G4에 반영하되 오늘만 원계획 조합을 변경한 세션 전체는 공식 증감 평가에서 제외한다. 실제 기록은 유지한다.

### 10.23.5 중량 검토와 명시 승인

- 종료 요약의 제목을 `이번 운동의 중량 검토`에서 `중량 검토`로 바꾸고 카드 헤더에 `수정 / 전체 승인`을 둔다. 수정 모드의 각 운동은 승인 선택 체크박스, 운동명, `기존 승인 중량 → 승인 예정 중량`, 무게 수정 버튼을 표시한다.
- 전부 선택하면 `전체 승인`, 하나라도 해제하면 `선택 승인`, 전부 해제하면 승인 버튼 비활성이다. 체크 변경과 모달 확인은 승인 예정 초안만 바꾸며 서버 승인하지 않는다. 수동 수정값은 승인 확정 전까지 따로 보존하고 최종 전체/선택 승인으로 명시 확정한다.
- 기본 승인 권고 증감 폭은 PLATE/STACK **5kg**, 기타 방식 **2kg**이다. 기존 중량 설정 모달을 재사용하며 이 승인 예정값 수정 용도에서 `변경 방식`과 `완료한 세트는 보존됩니다.`를 제거한다. `현재 승인 중량 60kg → 65kg`처럼 왼쪽 현재 기준값은 고정하고 오른쪽 초안을 실시간 변경한다. 취소/확인은 유지한다.
- 수동 중량 휠과 ± 조절 단위는 PLATE/STACK **2.5kg**, 기타 방식 **1kg**이다. 기본 승인 권고 폭과 혼동하지 않는다. 이 모달 용도 변경을 운동 중 기존 오늘만/진행 중량 변경 계약 삭제로 확대하지 않는다.
- 10.21절에 따라 공식 증감 평가 전체 제외인 세션은 기존 `weightReview`가 미완료 세트 등의 이유로 감량 권고를 계산하더라도 최신 UI 정책에 따라 `중량 검토` 카드 전체를 표시하지 않는다. 이는 `weightReview`의 계산 규칙·최초 공식 평가·현재 공식 평가의 산식을 변경하라는 요구가 아니다. 실제 완료 세트·총중량 등 수행 기록은 그대로 표시한다. 세션 단위 제외 근거의 연결은 후속 계약 사항이다.
- **전체/선택 승인은 HTML 시연 설계이며 실제 React·신규 승인 API 연결은 미구현이다.** 승인 대상·최신 루틴 version/승인값·사건·실패/경합 처리는 후속 계약·구현 검증 대상이다. 기존 records PATCH나 PENDING 해결 API를 신규 일반 승인 API로 간주하지 않는다.

### 10.23.6 기록 정정과 과거 승인 안전성

- 기존 검증된 기록 상세·정정 UI를 유지한다. 정정은 실제 세트 중량·반복과 허용된 맨몸 추가 부하·유산소 측정값, 개별 수행 삭제를 처리한다. 최초 계획·종목/ordinal·제조사·부하 방식·최초 승인 문맥은 바꾸지 않고 최초 평가와 현재 재평가를 구분한다.
- `PATCH /api/v1/workout-sessions/{id}/records`는 루틴 공식 승인값·승인 사건·routine.version을 변경하지 않는다. 이후 날짜의 승인을 과거 기록 정정으로 덮어쓰지 않는다. 공식 중량 변경은 별도 명시 승인이다.
- 기존 `POST /api/v1/workout-sessions/{id}/closed-approval-resolutions`의 KEEP_CURRENT/REAPPROVE를 유지한다. 미해결 PENDING 전체와 출처, 현재 세션/루틴 version·현재 승인값을 검증한 새 요청으로 해결한다. 동일 해결의 재확인은 중복 적용하지 않는다. 과거 날짜라는 이유만으로 금지·삭제하지 않는다.
- KEEP_CURRENT는 최신 승인값을 유지한다. REAPPROVE는 현재 값에서 사용자가 선택한 새 승인 사건을 만들며 기존 후속 승인 사건을 재작성하지 않는다. 종료 후 요청은 과거 수행의 승인 근거로 소급 사용하지 않는다. 기록 정정·신규 전체/선택 승인·기존 PENDING 해결을 합치지 않는다. 구체 보존·버전 계약은 [세션 API](../../../overload-server/docs/api/workout-sessions.md#종료-후-정정삭제복구--v15)를 따른다.

### 10.23.7 디로딩과 공통 UX

- 대체 슬롯 완료는 기존 완료율과 G4 유효 운동일에 연결한다. 디로딩 추천 게이지·진행·종료 UI, 유효 주수·일정·종료·복귀 조건과 산식은 [v1.7](Overload_Deloading_Design_Specification_v1.7.md)을 보존한다. 대체 연결의 실제 구현 완료를 뜻하지 않는다.
- **후속 React 요구사항:** iOS Safari/PWA에서 브라우저 History와 앱 화면 이동을 맞추고 기본 가장자리 뒤로가기로 이전 화면에 복귀한다. 편집 초안·취소 보호를 유지하며 브라우저 자체 제스처를 재구현하지 않는다.
- **후속 React 요구사항:** 모달을 열 때 닫기 X에 불필요한 파란 자동 포커스 테두리를 만들지 않는다. 키보드 focus-visible 표시는 유지하며 닫은 뒤 원래 조작 요소로 포커스를 복원한다. 실제 iOS·설치형 PWA 검증은 별도다.

## 10.24 · 기록 탭 최종 개편 — 2026-11-14

**설계 확정 / 기존 HTML 합성 시연 반영 / 실제 React·Backend 연결 필요.** 이번 사용자 결정과 현재 HTML의 화면·상호작용을 기준으로 기록 탭을 갱신한다. 임의 날짜·루틴명·수치·임시 자료구조는 서버 계약이나 제품 계산의 근거가 아니다. 10.21~10.23절의 변경되지 않은 정책과 과거 이력은 보존한다.

### 10.24.1 기록 메인과 표시명

- 2×2는 첫 행 `운동 현황 / 성장 추적`, 둘째 행 `주간 근육 계획 / 주간 근육 통계`다. 이전 `근육별 계획 분석 / 근육별 통계 분석`의 최신 표시명을 바꾼다. 기존 화면 식별자·라우팅 이름까지 바꿔야 한다는 뜻은 아니다.
- 별도 운동 이력 분석 카드는 두지 않는다. 최근 운동 기록의 전체 보기에서 월간 운동 이력으로 이동하며 기존 하단 네비게이션·기록 카드·상세 진입을 유지한다.

### 10.24.2 주간 근육 계획과 주간 근육 통계

| 화면 | 데이터·기간 | 조작 |
|---|---|---|
| 주간 근육 계획 | 선택 프리셋의 현재 월~일 반복 계획. 과거 적용 이력·실제 수행·디로딩 임시 계획과 별개 | 기록에서 활성 프리셋, 루틴 `··· → 계획 분석`에서 해당 프리셋을 기본 선택. 조회는 활성 일정·자동 순환을 바꾸지 않음 |
| 주간 근육 통계 | 이번 주 월~일 실제 유효 완료 기록과 당시 유효 계획 | 프리셋·전체 보기·주간/월간·기간 이동·날짜 선택·달력 없음. 분류별/근육별·세트/총중량 유지 |

- 계획의 제목 우측 전체 보기 스위치는 기본 OFF로 정확히 0세트인 항목만 숨기고 ON에서 표시한다. 프리셋·탭 변경 후 유지하며 확인 불가를 0으로 만들지 않는다. 계획에는 기간·날짜 UI를 추가하지 않는다.
- 두 화면의 분류별은 전면/후면·PPL·부위를 검수된 운동 분류와 원본에서 독립 집계한다. 세부 근육만 PRIMARY 1.0 / SECONDARY 0.5 기여를 적용한다. 하위 기여 합을 상위 물리 세트로 사용하지 않는다.
- 근육별은 한 카드의 부위별 목록·가로 막대를 재사용한다. 계획의 시작점 `▼`, 최대 초과 숫자 보존/막대 100%, 참고용 권장 범위를 유지한다. 합성 4/12를 제품 권장값으로 확정하지 않는다.
- 실제 세트/당시 계획과 0·계획 없음 `—`·확인 불가를 구분한다. 실제 0이어도 계획이 있으면 표시한다. 총중량은 기존 실제 완료 중량×반복 합계이며 기여 세트 계수 0.5를 적용하지 않는다.

### 10.24.3 운동 현황의 공통 기간·통합 검색

- 상단 하나의 주간/월간·이전/다음·달력 선택을 운동량 요약·추이·예정일/운동 달성·유산소 현황에 공통 적용한다. 주간은 월~일, 월간은 1일~말일이며 달력 날짜는 해당 주/월 전체로 이동한다. 카드별 기간 선택기를 중복하지 않는다.
- 추이의 종전 `전체 / 운동별 / 근육별` 탭은 제거한다. 기존 운동 검색 컴포넌트를 재사용해 왼쪽 `전체 / 운동별 / 분류별 / 근육별`, 오른쪽 검색 입력과 이름·보조 설명·목록 내부 스크롤·항목 선택을 제공한다. HTML은 `v10SearchUi`·`v10SearchRows`를 공통 사용하며 실제 React에서도 기존 검색 패턴을 재사용한다.
- 전체+검색어 없음은 전체 운동량이다. 전체+검색어는 운동·부위 분류·세부 근육 후보를 함께 표시한다. 운동별은 표준명·별칭, 분류별은 기존 부위, 근육별은 세부 근육을 검색한다. 이름과 소속을 구별하고 선택값을 표시하며 해제하면 전체로 복귀한다.
- 선택 항목의 그래프에 공통 기간·세트/총중량을 함께 적용한다. 후보 조회와 사용자 통계 조회는 별개다. 입력마다 전체 과거 기록을 재집계하지 않고 후보 수를 제한하며 선택 후 통계를 읽는다. 후보 없음·유효 수행 없음·조회 실패를 구분한다. HTML의 후보 최대 12개는 합성 시연값이며 서버 limit 계약이 아니다.
- 유산소는 하단 독립 카드의 실제 시간·종류별 거리·출처·상세 진입을 유지하고 공통 기간에 연동한다. 상단 웨이트 요약에 시간·거리를 추가하지 않는다. 실제와 계획 목표를 구분한다.

### 10.24.4 홈과 기록의 날짜별 달성 표시

**후속 변경(2026-11-16):** 아래 당시 시간/거리 비교에서 실제 거리 미입력 처리는 [10.25.1절](#10251-원계획-달성과-유산소-거리-미입력--정책-3-1)이 보완한다. 실제 거리가 없으면 시간만 비교하며 미입력 자체로 미확인 처리하지 않는다. 50%·원계획·혼합 규칙은 유지한다.

| 표시 | 의미 |
|---|---|
| ✓ | 기존 공식 원계획 슬롯 완료 기준으로 루틴 전체 완료 |
| △ | 전체 미완료이며 아래 UI 부분 달성 조건 충족 |
| × | 판정 가능한 확정 예정일이 부분 달성 조건 미달 |
| – | 근거가 확인된 휴식일 |

- 홈의 이번 주 일정과 운동 현황의 예정일/운동 달성은 **같은 날짜·같은 근거에 같은 판정과 기호**를 사용한다. HTML은 `recordTabDayResult`·`recordTabPartial`을 재사용한다. 미래·검사/확인 대기·근거 확인 불가를 네 확정 결과에 끼워 넣거나 ×로 조기 확정하지 않는다.
- 전체 완료를 먼저 판정한다. 기존 InitialPlan·대체 슬롯 인정 기준은 유지하며 근거가 불명확하면 완료를 추정하지 않는다. 전체 미완료일 때만 아래 △/×를 판단한다.
- 웨이트가 있으면 `원계획 내 실제 수행 세트 / 원계획 웨이트 세트 ≥ 50%`이고 `수행 인정 종목 / 전체 계획 종목 ≥ 50%`여야 한다. 세트 분자는 종목별 원계획 수를 넘겨 세지 않는다. 계획 밖 추가 운동·추가 세트로 비율을 부풀리지 않는다.
- 웨이트 종목 인정 최소치는 **min(2, 원래 계획 세트 수)**다. 1세트 계획은 1세트, 2세트 계획은 2세트, 3세트 이상은 2세트로 종목을 인정한다. 최소치 미달 종목은 종목 수행률 분자에 넣지 않는다. 개별 종목 인정만으로 그날 △가 되는 것은 아니다.
- 유산소는 최초 계획에 있는 목표만 평가한다. 시간만 있으면 시간 50%, 거리만 있으면 거리 50%, 둘 다 있으면 **시간과 거리 각각 50% 이상(AND)**이어야 그 종목을 인정한다. 정확히 50%를 포함하며 없는 목표·수행 시간·거리를 만들지 않는다. 거리 계산 근거는 기존 측정 계약을 따른다.
- 혼합 루틴은 웨이트 세트 비율을 웨이트만으로 계산하고 전체 종목 비율에는 웨이트·유산소를 모두 넣는다. 각 종목은 위 인정 조건을 적용한다. 유산소에 최소 2세트를 적용하지 않고 유산소 전용에는 웨이트 세트 비율을 요구하지 않는다. 적용되는 모든 조건을 충족해야 △다.
- **표시 전용 분류다.** 공식 루틴 완료율·유효 운동일·G4 훈련 주수·공식 증감 평가의 기존 산식을 변경하지 않는다. `effectiveDay`나 완료 종목 비율을 △의 동의어로 사용하지 않는다.

| 경계 사례 | 표시 또는 인정 |
|---|---|
| 계획 4종목·12세트에서 2종목 각 3세트 | 6/12·2/4로 △ |
| 같은 계획에서 2종목 각 2세트 | 종목은 2/4 인정되나 세트 4/12로 × |
| 원래 1세트인 종목에 1세트 | 종목 인정. 날짜 최종 판정은 전체 두 비율을 따로 확인 |
| 유산소 30분 목표에 15분 | 해당 종목 인정 |
| 30분·5km 목표에 15분·2.5km | 두 목표 50%로 해당 종목 인정 |
| 같은 목표에 20분·2km | 거리 미달로 종목 미인정 |
| 전체 완료 / 휴식 / 미래·판정 대기 / 확인 불가 | 각각 ✓ / – / 중립·미확정 / 확인 불가 유지 |

복수 세션이 있는 날의 △ 후보 선택·비교, 대체 연결의 부분 수행 인정 근거, 정정/늦은 동기화 후 표시 갱신과 부족한 근거의 표현은 실제 계약에서 확인한다. 공식 ST-20의 가장 높은 단일 세션·세션 간 부분 실적 합성 금지와 일일 상한을 임의로 변경하지 않는다.

### 10.24.5 최근 7일과 월간 운동 이력

- 기록 메인의 최근 기록은 **오늘 포함 최근 7개 로컬 날짜**의 유효 완료 세션을 최신순으로 표시한다. 이번 주와 다르며 월요일에 지난주 기록을 버리지 않는다. 같은 날 여러 세션도 개별 카드다. 없으면 빈 상태이며 기존 카드 정보·전체 보기·상세 진입을 유지한다. 홈 최근 카드의 기존 표시 상한과 디로딩 시작 자격의 오늘 제외 직전 7일은 별도 범위다.
- 전체 이력은 현재 월 기본, 이전/다음 월·달력으로 선택 월의 완료 세션을 조회하는 피드다. 주간/월간 전환은 없다. 정렬은 종료 시점 기준 최신순이며 날짜·루틴·웨이트/유산소 요약·운동 시간·총중량을 표시한다.
- 검색은 기존 공통 목록으로 `[루틴별 ▼] [이름 검색]`을 구성한다. 루틴별은 루틴명, 운동별은 실제 세션에 포함된 운동명을 사용한다. 검색 시 전체 과거 기간임을 표시하고 검색 해제 시 이전 선택 월로 돌아간다. 후보·보조 설명·내부 스크롤·선택을 재사용한다.
- 기록이 있는 월~일 주의 **첫 카드 위에만 얇은 주차 제목·실제 날짜 범위 구분선**을 둔다. 빈 주 제목·큰 주차 컨테이너·접기는 없다. 검색 결과도 날짜순이면 같은 구분을 쓴다. 같은 날짜 여러 카드와 선택 월 필터를 유지하고 월 경계 밖 세션을 더하지 않는다.
- 예: `11월 2주차 — 11/9~11/15`, `11월 1주차 — 11/2~11/8`. HTML 주차명은 그 주 월요일이 속한 달을 기준으로 하며 날짜 범위는 월 경계를 그대로 넘는다. 이는 UI 표시 규칙이며 서버 주차 ID나 새 집계 단위가 아니다. 앞선 HTML 검토 중의 '주차 구분자 없음' 결정은 이번 얇은 구분선으로 변경되었으며 당시 이력은 보존한다.

### 10.24.6 구현·계약 경계와 유지 정책

- 실제 코드·현재 HTTP 지원 및 부족한 데이터는 [통계 API](../../../overload-server/docs/api/statistics.md#기록-탭-최종-ui의-지원-범위--2026-11-14)와 [종료 목록 API](../../../overload-server/docs/api/workout-sessions.md#월간-이력최근-7일검색-요구와-현행-목록의-차이)를 따른다. 새 경로·DTO·응답 enum·페이지 크기를 이번에 확정하지 않는다.
- 중량 검토·전체/선택 승인 초안·부하별 간격, 공식 제외 시 카드 숨김과 weightReview 계산 보존, 기록 정정·PENDING 해결·최초 승인/계획·사건 보존은 10.23.5~6절을 유지한다.
- 조합별 최근 실제 중량·NEW 배치·서버 공유 메모·오늘만 대체·공식 평가 전체 제외, 분류별 집계·기여·권장 범위, 디로딩·iOS History·모달 포커스 정책은 이번 개편으로 바꾸지 않는다. 공식 중량은 루틴 배치별 원본이며 조합별 공식 승인 원본이나 루틴 간 전파를 만들지 않는다.

## 10.25 · 2026-11-16 최신 정책 확정과 구현 경계

**상태: 사용자 확정 / 구현 상태는 별도.** 2026-11-16 사용자가 제공한 「최신 확정 정책 검증 및 문서 정합성 정리」 3-1~3-8이 근거다. 이 절은 10.21~10.24의 미정 사항과 아래 명시한 이전 규칙을 보완·대체한다. 과거 결정·검증 기록은 당시 사실로 보존하며 실행 코드·API·DB를 변경하거나 새 HTTP/DTO/오류/테이블을 확정한 기록이 아니다. 코드 확인 기준은 PWA `56993a0`·Backend `732e0c3`이며 테스트 실행·서버 기동·DB 적용 확인은 하지 않았다.

### 10.25.1 원계획 달성과 유산소 거리 미입력 — 정책 3-1

- 운동 시작 시 불변 InitialPlan이 종료 직후 요약·이력·상세·홈·운동 현황의 공통 달성 기준이다. AppliedPlan은 실제 진행 계획이며 원래 달성 분모·목표를 바꾸지 않는다. 기존 전체/부분/기준 미달 규칙과 실제 수행·공식 중량 증감 평가의 구분은 유지한다.
- 유산소 시간은 앱에서 실제 활동 시간을 자동 측정한다. 루틴에는 목표 시간과 거리를 함께 지정할 수 있으나 **실제 거리는 선택 입력**이다. 실제 거리 근거가 없으면 확인 가능한 실제 시간만 최초 목표 시간과 비교한다. 실제 거리가 있으면 최초 목표 시간과 존재하는 최초 목표 거리를 함께 비교한다.
- 실제 거리 미입력을 0km나 UNVERIFIABLE의 단독 사유로 사용하지 않는다. 부분 인정의 기존 50% 기준도 같은 비교 대상 선택을 적용한다. 예: 30분·5km 목표에서 거리 미입력·실제30분은 시간 충족, 거리 미입력·15분은 시간50%로 종목 부분 인정 대상이다. 실제20분·2km는 거리50% 미달이다. 날짜 최종 부분 판정에는 기존 전체 종목/웨이트 세트 조건도 적용한다.
- 목표 거리 복사·목표 속도로 실제 거리 추정은 금지한다. 기존 유효 실제 속도 기반 계산 거리의 출처·정정 계약은 유지한다. 실제 시간 부재·기록 유효성 불명과 기존 속도/강도·경사/저항 등의 별도 미확인 보호를 임의로 면제하지 않는다. 이번 변경은 거리 미입력 조건에 한정한다.
- [ST-19 및 3.3절](../../../overload-server/docs/product/Overload_Statistics_and_Tracking_Design_Specification_v1.4.md#31-하루-종목-완료-기준)이 통계의 기준이다. 이전의 거리 누락 자체를 미확인으로 처리한 구현·설명은 이 정책으로 대체하며 아직 코드 전환이 필요하다.

### 10.25.2 Benchmark 동점 — 정책 3-2

- 초기 Task 002의 ‘총 반복 동점이면 이전 기준 유지’ 대신 현재 Backend의 최신 종료 기록 우선 방식을 **사용자가 채택**했다.
- 비교 가능한 유효 단일 세션의 **첫 N개 완료 세트 총 반복 내림차순 → endedAt 최신순 → UUID 오름차순**이다. 여러 운동일의 세트별 최고 반복을 혼합하지 않는다. 현재 WorkoutAssessment.benchmarkOrder와 일치하며 초기 정책은 역사 기록이다.

### 10.25.3 웨이트 수행 시간 A안 — 정책 3-3

관찰 가능한 구간만 집계하는 이 원칙은 유지한다. 준비시간 제외, 명시적 종목 시작, 휴식 종료 후 자동 재개 조건은 [10.40절](#1040--p1-개선-정책과-순서)이 보완한다.

- 현재 구현을 유지한다. 화면이 활성이고 실제 웨이트 수행 화면이 표시되는 확인 가능한 구간만 합산한다. 휴식·워밍업·유산소·종목 완료/종료 구간의 기존 제외 조건을 유지한다.
- 화면 잠금·백그라운드·관찰 불가능한 틈을 수행 시간으로 추정하지 않는다. 전체 경과는 시작/종료 시각 차이이며 누락을 수행/휴식 시간으로 채우지 않는다. 불완전 측정과 0은 구분한다.
- 백그라운드 시간 확장은 장기 검토 대상이며 현행 구현 요구가 아니다. [V37 시간 계약](../../../overload-server/docs/api/workout-sessions.md#웨이트-시간-구간--v37)을 따른다.

### 10.25.4 조합 변경 NEW 배치 — 정책 3-4

10.21.1~2를 유지한다. 표준 운동·제조사·중량 방식 중 하나라도 바꿔 저장하면 기존 배치 논리 제외+NEW로 독립 승인값·Benchmark를 시작한다. 조합 불변은 불필요한 NEW를 만들지 않고 옛 승인값/Benchmark 자동 승계·별도 NEW 등록 절차는 없다. 현재 Frontend의 처리와 Backend의 강제 범위가 다른 부분은 [루틴 계약](../../../overload-server/docs/api/routine-management.md#1차-frontend의-실제-저장-경로--2026-11-16)의 구현 필요 항목이다.

### 10.25.5 오늘만 대체 — 정책 3-5

10.21.3~4를 유지한다. 오늘만 표준 운동·제조사·중량 방식을 변경/대체한 세션의 공식 증감 평가는 **세션 전체 제외**다. 이와 별개로 전면/후면·PPL·**검수된 운동 부위 분류**·관리자 순서상 첫 PRIMARY의 네 일치와 원계획 세트 수 충족 시 원슬롯을 완료 인정한다. 근육 group_code 연결을 운동의 단일 대표 부위로 추정하지 않는다. 실제 수행/운동량은 대체 운동 자체로 한 번만 보존한다. 홈·날짜·통계·G4 연결 미구현은 정책을 바꾸지 않고 구현 필요로 남긴다.

### 10.25.6 최근 실제 중량과 조합 메모 — 정책 3-6

**최근 실제 중량**

- 동일 사용자·dataGeneration·표준 운동·제조사·중량 방식의 정확한 조합에서 **FINISHED만** 대상으로 한다. ACTIVE의 완료 세트는 제외한다. 정규·다른 루틴·오늘만 추가·대체도 유효한 최종 종료 기록이면 후보가 된다.
- 가장 최근 유효 종료 기록의 마지막 유효 완료 세트 중량을 제안한다. 삭제/무효 수행은 제외하고 정정된 현재 유효값을 사용한다. 승인값·과거 최고값으로 대체하지 않는다. 없음은 UI 0kg 제안, 조회 실패는 별도 오류다.
- 종료 시각 동률·마지막 세트 동률의 구체 해소 순서 등 여기서 정하지 않은 세부 조회 계약은 구현 검토 사항이다. Benchmark의 UUID 규칙을 최근 중량 조회에도 자동 적용하지 않는다.

**조합별 최신 서버 메모**

- 동일 사용자·세대·정확한 조합별 최신 서버값 하나를 공유한다. 입력 중에는 로컬 초안만 수정하고 **변경된 메모를 blur에 저장**한다. 화면 이동/조합 변경으로 입력을 종료할 때도 저장을 시도한다. 무변경이면 쓰지 않는다.
- 온라인 저장만 지원하며 별도 오프라인 자동 동기화 시스템을 추가하지 않는다. 실패 시 초안·오류·재시도 경로를 보존하고 성공 응답 전 저장 완료로 표시하지 않는다.
- 동시 수정은 **서버에 마지막으로 정상 반영된 저장값 우선(Last Write Wins)**이다. 클라이언트 시각·응답 도착 순서로 최신값을 정하지 않는다. 충돌 선택 UI·메모 변경 이력은 만들지 않는다.
- 오래된 조회/저장 응답이 현재 작성 중인 최신 초안을 덮지 않게 한다. 메모 변경은 routine.version·승인 중량을 바꾸지 않는다. 새로고침 후 미저장 초안 보존은 미확정이며 이 정책에서 보장하지 않는다.
- 10.21.6의 ACTIVE 포함·저장 시점·오프라인 재시도·동시 수정 미정 표시는 이 절이 대체한다. HTTP/DTO·저장 구조는 아직 확정하지 않으며 현재 CombinationMemo는 메모리 초안만 있는 **구현 필요** 상태다.

### 10.25.7 전체 과거 이력 검색 — 정책 3-7

10.24.5의 선택 월 조회·검색 해제 후 월 복귀를 유지한다. 루틴명/실제 세션 운동명 검색은 선택 월이나 불러온 일부 페이지에 제한하지 않는 **전체 과거 기록** 대상이다. 서버 필터와 페이지 조회로 순차 검색하며 전체 기록 일괄 다운로드는 사용하지 않는다. 최근7일과 월간의 날짜 범위·정렬 의미를 구분한다. 현재 closed 20건 cursor+클라이언트 루틴명 필터와 운동명 검색 대기는 이 요구를 충족하지 못한 **구현 필요**다. 새 경로·query·정렬 계약을 여기서 만들지 않는다.

### 10.25.8 독립 분류 집계와 선택 대상 일별 추이 — 정책 3-8

10.22·10.24와 ST-24~31을 유지한다. 전면/후면·PPL·검수 운동 부위·세부 근육의 네 수준에서 계획/실제를 구분하며 상위는 해당 수준의 검수 분류와 원본 세트로 독립 집계한다. 세부 근육만 PRIMARY 1.0·SECONDARY 0.5를 사용하고 그 합을 상위 물리 세트로 올리지 않는다. 선택 운동/분류/근육의 일별 세트·총중량은 실제 날짜별 기록으로 제공하며 기간 합계를 임의 분배하지 않는다. 선택 프리셋 현재 계획·당시 계획·실제를 섞거나 미확인 분류를 추정하지 않는다. 기존 저장 기록 집계/조회이며 새 피로·점수·성과 알고리즘은 아니다. [현행 구현과 부족 범위](../../../overload-server/docs/api/statistics.md#1차-frontend-연결과-계산의-실제-범위--2026-11-16)를 완료로 확대하지 않는다.


## 10.26 · 기록 메인 최종 UI 승인과 문서 동기화 — 2026-11-17

**상태: 기록 탭 메인 디자인 승인·구현·코드 커밋 완료.** 사용자가 이번 문서 동기화 요청에서 최종 승인을 확인했다. 기준은 Frontend 커밋 `594cf2575df7aed2d440ebfd6d5bb28e9ed94fb5`(`style(record): refine record main layout and UI`)의 StatisticsPanel·RecordFeed·RecordMain.module.css다. 초기 외부 `Overload_Record_Main_UI_Spec_v1.0.md`와 다른 한 줄 루틴명·최종 날짜/시간·안내 제거 등은 이 승인 구현을 우선한다. 기존 10.21~10.25의 결정·검증 이력은 보존하고 아래 명시한 기록 메인의 시각 표현만 갱신한다.

### 10.26.1 승인된 메인 구성

- 중복 `운동 기록`/`운동 기록·분석` 제목과 부제 없이 **이번 주 요약 → 운동 분석 → 최근 운동**이다. 이번 주 요약은 범위·큰 루틴 달성률·수평 진행 바·계획/완료 운동일과 마지막 3열 `총 운동 시간 / 웨이트 세트 / 유산소 시간`이다. 시계·덤벨·같은 진행 방향의 발자국을 사용하며 지표 아래 긴 안내는 제거한다.
- 분석은 첫 행 `운동 현황 — 운동량과 추이 / 성장 추적 — 중량과 기록 변화`, 둘째 행 `주간 근육 계획 — 운동 부위별 계획 / 주간 근육 통계 — 근육별 운동 분석`이다. 같은 크기의 전체 클릭 카드에 좌상단 20px 선형 아이콘·우상단 화살표·하단 제목/설명을 배치하고 아이콘 배경 박스와 상시 강조 테두리는 없다. 제목은 기존 밝은 주본문색·15px·600, 설명은 기존 보조색·12px·400, 키보드 포커스는 유지한다. 섹션 제목 오른쪽에 장식이나 기능을 추가하지 않는다.
- `운동 분석`/`최근 운동` 제목은 18px·600이다. 최근 헤더 오른쪽에 기존 범위의 `YY-MM-DD ~ YY-MM-DD`와 `전체 보기 ›`를 놓고 긴 기간 문구는 제거한다. 375/393/430px은 한 줄, 320px은 날짜만 다음 줄 오른쪽이다. 카드 모서리는 홈·루틴과 같은 5px이며 분석/최근 카드 간격은 8px다.
- 최근 카드는 **날짜·상태 → 루틴명 → 완료 종목 수·전체 경과시간**의 3행이다. 날짜는 `MM.DD · 요일 한 글자 · HH:mm`, 상태는 기존 판정의 아이콘과 `전체 완료 / 부분 완료 / 기준 미달`이며 미확인도 보존한다. 루틴명은 한 줄 말줄임이다. 시간은 기존 분 단위 버림으로 `총 42분 / 총 1시간 / 총 1시간 10분`처럼 표시한다. 총중량·거리·세트별/구간별 기록은 기존 하위 화면에서 확인한다.

### 10.26.2 데이터·와이어프레임 경계

- 이번 승인은 조회·저장·동기화·기간/정렬/시간대·통계/달성률·판정/승인·라우팅을 변경하지 않는다. 주간 총 운동 시간은 현행 Overview에 없어 `미확인`이고 임의 합산하지 않는다. 최근 종목 수는 기존 완료 종목 수이며 모든 일부 수행 종목을 새로 집계한 값이 아니다. 로딩·빈 상태·오류·미확인 보호와 10.25의 미완성 구현 범위는 유지한다.
- [UI/UX 3.10절](ui-ux.md#310-기록-및-설정--history--settings)과 [Frontend 마감](../engineering/frontend.md#기록-메인-최종-ui-보정마감--2026-11-17)에 최종 상태를 반영한다. 기존 [HTML](Overload_UI_Baseline_Wireframe_v0.9.html)은 기록 메인의 구조·전용 스타일·설명만 갱신한다. 다른 탭·기록 하위 화면·공통 테마·시연 조작은 유지한다.
- HTML의 밝은 무채색 콘셉트·기존 팔레트·카드·하단 내비게이션을 유지한다. 실제 UI의 밝은 제목 토큰은 밝은 와이어프레임의 기존 주본문색으로 대응한다. 수치와 최근 상태명은 명시적인 합성 배치 표본이며 서버 판정·실제 계정값·새 계산 기능이 아니다. 새 앱 기능이나 판정 로직을 만들지 않는다.
- **전 화면 색상·강조 포인트의 통합 검토는 추후 진행한다.** 이 동기화로 새 색상 정책을 확정하거나 Visual Theme Spec의 전역 토큰을 바꾸지 않는다. 제품 요구사항·API·React/CSS·기존 기능 테스트는 수정 대상이 아니다.

## 10.27 · 운동 현황 최종 UI 승인과 문서 동기화 — 2026-11-17

**상태: 디자인 승인·구현·코드 커밋 완료.** 기준은 `37512e9b8a21925b6be5697b7b6516238e5f8351`(`style(activity): refine activity UI and preview states`)이다. [화면별 UI/UX](ui-ux.md#운동-현황)와 [Frontend 구현 현황](../engineering/frontend.md#운동-현황-최종-ui-승인-및-구현-완료--2026-11-17)에 반영한다.

- 한 줄 헤더, 통합 기간 카드, 별도 요약 카드 두 개, 추이, 주간 달성, 유산소 순서를 승인했다. 주간 `MM/DD ~ MM/DD`와 월간 `YYYY/MM`을 한 줄에 놓는다. 두 세그먼트는 200ms 이동과 모션 줄이기를 공유한다. 이전·다음·달력 외형은 36px 정사각형이고 달력은 열린 상태에서 강조한다. 키보드 포커스는 별도로 유지한다.
- 운동 현황의 검색 범위만 둥근 팝오버를 사용한다. 검색 원형 버튼은 평상시 중립이며 활성·포커스 상태를 구분한다. 검색 입력은 16px이며 iPhone에서 검색 아이콘을 눌렀을 때 키보드가 열리고 화면 배율이 유지됨을 사용자가 확인했다.
- 주간 루틴 달성 범례는 `– 휴식`, `· 미수행`, `? 미확인`이다. 기존 판정과 공식 달성률을 사용한다. 월간 조회에서도 달성 카드는 선택 날짜가 속한 주를 표시한다.
- 유산소 상세는 카드 안에서 펼쳐지며 안에서 운동 이력으로 이동한다. 운영 응답으로는 종류별 수행 요일을 연결할 수 없고 누적 일수는 `미확인`이다. 날짜와 종류를 연결하는 집계 계약은 후속 검토 항목이다. 검토 전용 옵션은 주간 상태·달성률·유산소 시간과 일수·요일과 거리의 유무를 합성 데이터로 시연한다.

- 전체 이력의 주차 제목/날짜 범위·구분선·정렬·동일 날짜 복수 기록·스크롤·추가 로딩/중복 방지·오류 재조회·빈/로딩 상태를 보존한다. 최근 7일 피드로 교체하지 않는다. 운영의 루틴명 검색은 불러온 기록 범위이며 **전체 과거 실제 운동명 검색은 서버 연결 대기**다. 합성 시연의 검색을 실제 서버 기능 완료로 기록하지 않는다.

### 10.30.3 공통 UI와 문서 동기화 경계

- 공통 헤더의 실제 적용은 기존 네 화면에 상세·전체 이력을 더한 6개 화면이다. 기존 핸들러·브라우저/PWA 뒤로 가기·상태 복원을 유지하며 공통 헤더를 다시 설계하지 않았다. 기간·검색·카드의 재사용 범위는 [UI/UX 표](ui-ux.md#전체-운동-이력)를 따른다.
- 기존 [HTML](Overload_UI_Baseline_Wireframe_v0.9.html)의 상세·전체 이력은 이 구조를 밝은 무채색으로 대응한다. 기록 메인은 최근 종목 표기만 갱신하고 나머지 배치를 보존한다. 기존 합성 원본·판정/계산·정정/복구/이력 시연을 실제 API로 승격하지 않는다. 운동 현황·성장·근육 페이지와 다른 화면은 유지한다. 실제 React·CSS·테스트·API·데이터 생성 코드는 이번 문서 작업에서 변경하지 않는다.

- **최종 하단 배치.** 이전의 추가 간격 4px을 제거하고 `env(safe-area-inset-bottom)`만 적용한다. 전후 모두 안전 영역은 각 배치 계산에 한 번 적용한다. Chrome 모의 안전 영역 0px·34px의 탭바 간격은 4→0px·38→34px, 본문 여백은 76→72px·110→106px로 측정됐다.
- **동작과 검증 경계.** 탭 이동·재선택·브라우저 이력, 입력 중 키보드에 따른 숨김·복원, 화면별 표시 정책, 접근성 이름과 포커스, 운동 및 모달 연계를 유지한다. HTML은 기존 밝은 무채색 프레임에서 배치와 상호작용을 시연한다. 실제 iPhone Safari와 설치형 PWA 검증은 후속이다. [구현 및 검증 이력](../engineering/frontend.md#공통-하단-내비게이션-리디자인-현황--2026-11-19)

## 10.37 · 하단 탭바 접기·펼치기와 정적 와이어프레임 — 2026-11-19

- **접기·펼치기.** 문서 세로 스크롤의 같은 방향 누적 24px에서 전환한다. 아래 방향은 탭들이 중앙으로 모여 현재 탭의 46×46px 원형 버튼을 남기고, 위 방향이나 원형 버튼 선택은 네 탭을 복원한다. 원형 버튼은 현재 화면과 스크롤 위치를 보존하고, 숨겨진 세 탭은 접근성 트리와 키보드 탐색에서 제외한다.
- **최종 표현.** 접기 320ms, 펼치기 340ms, `cubic-bezier(.32, .08, .26, 1)`이다. 확장 `#6C93C6`과 축소 `#5E82B1` 사이를 연속 전환한다. 각 아이콘의 확장 칸을 기준으로 수평 이동과 축소를 분리해 펼침 종료 좌표를 안정화한다. 일반 탭 선택은 200ms `ease`, 루틴·기록 활성 윤곽선은 검은색 3px이다. 움직임 줄이기에서는 즉시 전환한다. [시각 명세](Overload_UI_Visual_Theme_Spec_v0.9.md#15-공통-하단-내비게이션--2026-11-19)
- **하단 경계.** 확장·축소 모두 `env(safe-area-inset-bottom)`을 쓴다. 원형 버튼이 이미 해당 경계에 닿으므로 추가 하향 이동은 보류했다. 0px·34px 모의 환경의 하단 간격은 0px·34px, 본문 여백은 72px·106px이다. iPhone Safari 및 설치형 PWA와 마지막 좌표 보정 뒤의 전체 검증은 후속이다. [검증 이력](../engineering/frontend.md#공통-하단-내비게이션-리디자인-현황--2026-11-19)
- **당시 문서 결정.** HTML을 밝은 무채색 정적 화면으로 정리하고 JavaScript 기반 조작을 제거했다. 이후 10.38절에서 검토 목적의 기본 조작을 다시 허용했다.

### 운동 진행과 시간

- ACTIVE 세션은 오늘의 루틴 카드 위치에 `진행 중인 운동`을 표시한다. 종목 상태, 루틴명, 전체 경과, 웨이트 완료/계획 세트, 현재 적용된 WEIGHT/CARDIO와 이어가기를 제공한다. 운동 전과 종료 확인 후에는 홈 기본 카드를 표시한다.
- 이전처럼 모든 종목을 버튼으로 넘기던 흐름을 바꿨다. 마지막 세트 완료 후 WEIGHT → WEIGHT, 유산소 기록 확정 후 CARDIO → CARDIO는 다음 미완료 종목으로 자동 이동한다. 마지막 WEIGHT → 첫 CARDIO에서는 `다음 종목으로`와 `남은 유산소 건너뛰고 종료` 선택을 유지한다. 건너뛰기 종료는 유산소의 실제 기록을 생성하지 않는다. 최종 운동 종료는 사용자가 선택한다.
- 새 종목은 준비 상태로 표시하고 `운동 시작하기`에서만 실제 측정을 시작한다. 준비시간은 첫 종목의 준비운동 완료 또는 직전 종목 완료 시각부터 계산하며 웨이트·유산소 사이 선택 시간도 포함한다. 기존 사본의 복원 기준과 세션 시작 시각 대체는 유지한다.
- WEIGHT 시간은 선택된 미완료 종목을 실제 시작한 뒤 화면에서 관찰 가능한 수행 구간만 합산한다. 워밍업·준비·휴식 및 연장·유산소·완료 이후는 제외한다. 휴식 종료 시 별도 조작 없이 누적을 재개한다. 화면 잠금·백그라운드 등 관찰 불가능한 시간을 추정하지 않는다.
- 종료 요청·서버 확인과 수행 보존은 기존 FINISH 규칙을 따른다. 운동 종목을 탐색할 때는 본문 세로 위치를 유지하고, **종료 후 운동 기록 요약은 새 SPA 페이지로 최상단에서 시작**한다. 상세 및 브라우저 탐색은 기존 이력을 따른다.
