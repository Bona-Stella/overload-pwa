## 조회 실패와 새로고침

| 검수 분류 | 재현 및 확인 |
| --- | --- |
| 공통 UI Preview | `조회 실패·새로고침`에서 `조회 성공`, `조회 실패`, `응답 시간 초과`를 각각 선택하고 `새로고침`으로 실행한다. |
| 주간 일정·계획 분석 | `데이터 없는 일정 조회 실패` → `새로고침`. 기존 일정 보유 오류, 배정·전체 편집, 첫 계획 조회와 기존 계획을 유지하는 오류도 각각 연다. 쓰기 차단과 충돌 시 `최신 구성 다시 열기`를 확인한다. |
| 최근 운동·전체 이력 조회 | `데이터 없는 기록 조회 실패`에서 다음 새로고침의 성공·실패·시간 초과를 예약하고 `새로고침`을 누른다. 기존 기록 보유 오류에서는 목록과 스크롤 유지, 정상 빈 기록에서는 빈 안내를 확인한다. |
| 홈·루틴 | 첫 로딩, 기존 데이터 유지와 재조회 실패, 빈 루틴 목록 및 데이터 없는 오류를 비교한다. 정상 루틴·일정 상단에는 수동 조회 영역이 없으며, 오류에서 필요한 조회 복구를 제공한다. 홈 시작 결과 미확인에서는 `운동 시작`으로 기존 요청을 확인한다. |
| 카탈로그·성장 추적 | 없는 목록과 기존 목록을 보존하는 카탈로그 오류를 비교한다. 대기 중 예시를 바꾸면 이전 결과가 적용되지 않는다. 성장 추적은 운동 검색과 기간·배치 조회, 데이터가 있는 그래프 유지와 복구를 확인한다. |
| 운동·계정 | 종료 확정 요약, 잠정 중량 검토, 계정 조회와 로그인된 기기 예시의 실패·새로고침을 확인한다. 기기 목록은 검수용 합성 응답이다. 기록 변경·종료·계정 변경의 저장 결과 확인은 각 쓰기 복구 동작을 사용한다. |

대기 중 아이콘만 반시계방향으로 움직이고 버튼은 비활성화된다. 이어서 눌러도 같은 요청을 중복 전송하지 않으며, 성공·실패·시간 초과 후 정지한다. 실패·시간 초과에는 다시 누를 수 있는 버튼과 오류 Toast를 확인한다. 정상 데이터가 표시된 화면에서는 대기와 오류 전후 카드 및 스크롤 위치를 비교한다. 모션 감소 설정에서는 정적인 진행 표시를 확인한다. ## Toast·Dialog·복구

| 화면·검수 분류 | 확인할 동작 |
| --- | --- |
| 루틴 생성·편집·삭제 | 이름·종목 수정 후 저장하거나 삭제를 확인한다. 완료 응답 후에만 성공 Toast가 표시된다. 미저장 변경에서 취소·뒤로 가기는 폐기 확인을 열고 기존 입력을 보존한다. 오래된 루틴으로 운동을 시작할 때는 새 계획 확인 경로를 제공한다. |
| 일정 배정·전체 편집·메뉴 | 바꾼 배정 또는 순환 설정에서 취소한다. 폐기와 계속 편집, 저장 충돌 후 최신 데이터 확인, 프리셋 이름 편집과 삭제를 검수한다. 편집 중 중복 조작 차단을 확인한다. |
| 휴식 설정 | 휴식 시간 편집 중 취소·뒤로 가기, 정상 저장과 충돌 확인을 확인한다. 휴식 타이머 알림의 `휴식 테스트` 토글과 일반 알림 미리보기는 유지 대상이다. |
| 운동 입력·세트 조작 | 중량·횟수 미입력 및 범위 오류에서 완료를 시도하고, 유산소는 시간·거리·속도·심박수 검증 예시를 확인한다. 입력 오류는 조작 직후 알리고 입력과 카드 위치를 유지한다. 취소·제외 확인과 쓰기 오류 시에는 기존 입력 및 원본을 보존한다. |
| 운동 저장·오프라인·인계 | 상단 `저장 완료`, `저장 중`, `전송 대기`, `저장 실패`와 상세 복구를 확인한다. 내부 저장·전송·복원 실패와 사용자 조작 오류를 비교한다. 5초 지연 저장 중 입력 검증을 실행해 두 상태가 독립적으로 표시되는지 확인한다. 오프라인 원본, 편집 잠금, 다른 기기에서 편집 중인 상태와 인계도 검수한다. |
| 운동 종료·중량 승인 | 종료 확인의 중립·주의 액션, 지연·실패·결과 미확인 복구를 확인한다. 종료 확정 결과에서 단순 조회 실패와 중량 승인·충돌·미저장 승인 초안의 복구를 각각 검수한다. |
| 기록 정정·삭제·복구 | 기록의 메뉴에서 정정·누락 수행 복구·전체 삭제를 연다. 결과 미확인, 버전 충돌, 로컬 보존 실패 및 재확인 예시와 처리 중 잠금을 확인한다. |
| 계정·설치 | 이메일 후보·코드·재인증·연결과 해제 확인의 성공과 실패를 검수한다. 설치·오프라인 준비·업데이트·미전송 데이터 안내와 계정·기기 단순 조회 복구를 확인한다. |

Toast는 중복 공지를 줄이고 자동 종료와 `알림 닫기`를 지원한다. Dialog는 의미별 아이콘·액션, 확인·취소, 키보드 포커스 복귀와 History 닫기를 확인한다. 대표 메시지형 Dialog에서 설명 끝과 액션 상단 사이를 계측한다. 숫자 휠에는 전용 조작과 화면별 규격을 적용한다.

## Preview 구현과 격리

일반 화면과 운동 화면은 실제 공통 컴포넌트·페이지·테마·동기화 코드를 사용한다. 네트워크 응답, 장치 쓰기, 락, 계정 상태는 탭 메모리의 합성 데이터로 공급한다. 4173 검수 HTML의 CSP가 네트워크 연결 및 폼 전송을 차단한다. 운영 빌드와 PWA 사전 캐시는 Preview HTML·전용 번들을 제외한다. [공통 Preview](../../tests/fixtures/review/CommonUiPreview.tsx) · [FRONT 18 Preview](../../tests/fixtures/review/Front18Review.tsx) · [검수 HTML](../../scripts/review/common-ui-preview.html) · [전용 빌드](../../scripts/recovered-data-review-server.mjs)

두 Preview가 공유하는 `reviewRead`는 기본 검수 응답의 성공·실패에 2.7초를 적용한다. 명시적인 장기 지연 예시는 3.6초를 사용하고, 시간 초과 예시는 실제 `readWithDeadline`에 검수 제한 2.7초를 준다. 화면·예시가 바뀌면 기존 요청을 취소한다. 실제 서비스와 운영 빌드는 검수 지연의 영향을 받지 않는다. 실제 OAuth 이동, 이메일 발송, 실기기 설치·업데이트 및 실기기 저장소 장애는 Preview 외부의 확인 범위다.
