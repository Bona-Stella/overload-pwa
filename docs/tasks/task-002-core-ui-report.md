전체 운동/휴식 타이머는 저장된 발생 시각과 현재 시각의 차이로 계산한다. 마지막 본세트에서도 자동 휴식이 시작되며, 다음 종목 이동 후에는 이전 종목의 마지막 실제 완료 시각부터 경과시간을 표시한다. 다음 세트 완료 시 휴식 카운트다운으로 전환한다.

## 데이터와 정책

- `types.ts` / `model.ts`: 종목 정의, 루틴, 요일 일정, 승인 중량, 현재 세션 복사본, 완료 세트, 기준 기록, 이력을 분리한다. 루틴 내 종목 배치는 안정적인 ID를 가진다.
- 기준 키는 루틴 ID·배치 ID·종목 ID·목표 세트 수·최소/최대 횟수·승인 중량을 포함한다. 동일 키의 한 세션 전체 반복 합계가 커질 때만 교체하고 동점은 유지한다. 여러 날의 세트 최고값을 조합하지 않는다.
- 보수적인 초기 가정으로 **모든 세트를 완료한 세션**만 기준 갱신 대상으로 삼는다. 해당 종목의 세트 구성 임시 변경, 오늘만 중량 변경, 서로 다른 완료 중량은 비교에서 제외한다. 부분 완료도 실제 이력에는 보존한다.
- 세트 완료 당시의 중량과 오늘만 변경 여부를 별도 스냅샷으로 보존한다. 이후 진행 중량을 바꾸어도 기존 실제 기록의 의미는 바뀌지 않는다.
- 새 중량에 비교 가능한 기준이 없으면 미완료 반복 입력을 비운다. 목표 하한으로 자동 초기화하지 않는다. 권고는 중량을 변경하지 않는다.
- 세션에서 완료한 세트·종목은 바로 제거하지 못한다. 실수였다면 명시적으로 완료 취소 후 수정/제외할 수 있다. 미완료 초안 제외 후에도 완료 세트의 원래 번호를 유지한다.
- 기존 루틴 편집의 최초 중량은 현재 승인 중량을 바꾸지 않는다. 진행 중량 변경은 운동 화면의 별도 확인으로 수행한다.
- 사용자 종목 추가는 종목 정의를 즉시 로컬 저장한다. 루틴 편집 취소는 루틴 초안을 버리며, 명시적으로 추가한 종목 정의는 유지한다.
- 총 볼륨은 완료 본세트의 kg × 실제 횟수 합계이다. 0kg 및 소수 중량을 허용하며, 실제 0회와 미입력을 구분한다.

## 로컬 저장과 한계

`storage.ts`의 교체 가능한 `StorageAdapter`에 `localStorage`를 연결한다. 키는 `overload.core.v1`, 스키마 버전은 1이다. 운동 입력·완료 시각·준비 단계·현재 종목·휴식 예정 종료 시각·이력·메모·설정을 저장한다. 새로고침 후 홈의 이어하기로 저장된 단계에 복귀한다. 루틴 편집 중 저장 전 초안과 오늘만 루틴 선택은 메모리 UI 상태이다.

외부 저장값은 런타임에서 검사한다. 손상·지원하지 않는 버전·접근 실패는 편집을 막아 원본을 보존한다. 쓰기 실패는 현재 입력을 메모리에 유지하고 재저장을 제공하며, 이탈 전 경고한다. 다른 탭의 쓰기 감지 시에는 덮어쓰기 충돌을 막기 위해 편집을 멈춘다. 다중 탭의 동시 쓰기를 원자적으로 조정하는 시스템은 구현하지 않았으므로 한 탭에서 사용한다.

로컬 기록은 브라우저 데이터 삭제·기기 손실로 사라질 수 있다. 서버 저장, 계정, 백업, IndexedDB 마이그레이션, 동기화, Service Worker, 설치 가능한 PWA, 푸시, 차트, 디로딩 계획은 미구현이다. 서버 요청은 설정에서 진단을 열 때 기존 `/api/v1/health`만 호출한다.

## 시연 기본값과 UI 가정

- 초기 Mock 루틴: PUSH / PULL / LEG, 3본세트, 6–10회. 초기 이력·기준 기록은 비어 있어 실제 완료로 오해하지 않는다.
- 사용자 선택 종목: 예시 3세트, 6–10회, 최초 중량 직접 입력. 운동 중 임시 추가 종목은 0kg 예시로 시작하며 중량 변경 메뉴로 수정한다.
- `model.ts`의 `DEFAULT_REST_SETTINGS`: 상한 8회 이하 180초, 9–12회 120초, 13회 이상 90초. **확정 처방이 아닌 예시 기본값**이며 설정에서 수정한다.
- React 상태와 일반 CSS를 사용하고 새 의존성은 추가하지 않았다. 화면 전환은 앱 내부 상태 기반이며 URL 라우팅은 후속 범위이다.
- 다크 모드, 44px 이상 조작 영역, 16px 입력 글꼴, Safe Area, 상단 고정 타이머, 하단 고정 CTA와 스크롤 여백을 적용했다. 실제 iPhone 키보드·Safe Area 검증은 남아 있다.
