## Summary — 선행 조사와 구현 결과

### A. 반복 횟수 빠른 입력

기존 `WorkoutScreen.tsx`는 세트마다 직접 입력만 제공했으며 ±1 버튼은 없었다. 기존 `WeightInput`은 중량 전용이어서 변경하지 않고, 반복 횟수의 정수·최솟값 정책에 맞는 작은 `RepsInput`을 추가했다.

- 각 본세트에 `[−1] [중앙 숫자·회] [+1]`을 표시한다. 중앙은 `type="text"`, `inputMode="numeric"`, 명확한 세트별 레이블을 갖는 편집 가능한 입력이다.
- 버튼은 해당 미완료 세트 초안만 바꾼다. 다른 세트, 실제 완료 값, 타이머, 루틴, 승인 중량, 변경 이벤트, benchmark를 변경하지 않는다. 직접 입력·초안 저장은 기존 `editReps`/`useWorkout` 경로를 사용한다.
- 1회에서 감소, 최대 안전 정수에서 증가를 막는다. 빈 값·음수·0·소수·미완성 문자열·안전 정수 범위 밖 입력은 버튼으로 자동 치환하지 않는다. 목표 상한을 넘는 11회 등은 허용한다.
- 직접 입력 텍스트는 16.8px, 좌우 버튼과 중앙 입력 높이는 최소 44px다. 완료한 세트의 입력과 ±1은 잠기며 기존 완료 취소 후 다시 편집할 수 있다.
- 행 완료와 하단 완료 모두 기존 `recordSet → completeSet`을 사용한다. 중간 세트 휴식, 마지막 세트 직후 종목 이동, 전체 완료 후 수동 종료를 유지한다.

**0회 정책 확인:** 요청 문서는 완료 가능한 값이 1 이상의 정수라고 명시하지만, 실제 기존 `completeSet`과 기존 테스트는 0회 완료를 허용하고 있었다. 이번 명시적 조건에 맞춰 새 완료 검증을 1 이상의 안전한 정수로 강화했다. 기존 테스트의 0회 성공 예시는 1회 성공으로 바꾸고, 0회·큰 수 거부를 추가했으며 중복 완료의 멱등성 검증은 유지했다. 저장 검증기는 변경하지 않아 과거 v1의 0회 실제 기록은 그대로 로드·저장할 수 있다. 별도 회귀 테스트로 무변경 round-trip을 확인했다.

### B. 휴식 종료 준비 신호

기존 화면은 휴식 남은 시간을 파란색으로만 표시했으며 종료 임박 상태·문구·애니메이션은 없었다.

| 남은 시간 | 결과 |
| --- | --- |
| 11초 이상 | 기존 파란 타이머 |
| 10~6초 | 주황/노란 타이머 및 `다음 세트 준비` |
| 5~1초 | 같은 문구·색상과 타이머 숫자 배경만 1.6초 주기의 부드러운 강조 |
| 0초 이하 | 기존 `휴식 완료`와 다음 세트 완료 조작, 경고 제거 |
| 종목 전환·모든 종목 완료 | 준비 신호 없음 |

- 기존 `resolveWorkoutTimer`, 저장된 `endAt`, App의 기존 `now` 갱신만 사용한다. 표시 초는 남은 milliseconds를 올림하여 1초 미만의 실제 휴식 중에 0초로 보이지 않도록 했다.
- 새로운 interval, 저장 필드, 매초 localStorage 쓰기, 상태 전이 또는 알림 기능을 추가하지 않았다.
- `+30초`로 10초를 넘으면 즉시 일반 표시, 수동 종료 시 경고 제거, 새로고침·홈 복귀·탭 이동 후에는 동일한 종료 시각으로 파생한다.
- 강조 대상은 오른쪽 타이머의 숫자 배경뿐이다. 화면 전체 점멸·빠른 깜빡임·소리·진동·권한 요청은 없다.
- `prefers-reduced-motion: reduce`에서는 `animation: none`으로 정적인 색상과 문구를 유지한다.

### 실제 브라우저 DOM 검증

CUA를 사용하여 데스크톱 Chromium의 실제 App에서 클릭·직접 입력·저장·새로고침·이어하기를 수행했다. 타이머 경계는 격리 fixture의 시계 버튼으로 재현했으며 실제 120초를 기다린 시험은 아니다. 시각 조절 자체는 제품 저장값을 바꾸지 않는다.

- 첫 세트 `10 → +1 → +1 → −1 = 11`, 두 번째 세트 7, 세 번째 빈 초안의 독립성을 확인했다. ±1 조작만으로 실제 완료나 휴식은 발생하지 않았다.
- 빈 값·0·음수·소수·안전 정수 초과 값은 실제 하단 완료에서 오류를 표시하고 완료하지 않았다. 1회 감소·최대 안전 정수 증가의 비활성화도 확인했다.
- 새로고침·이어하기 후 `11 / 7 / 빈 값` 초안과 완료 뒤 실제 11회 기록이 복원됐다.
- 11초는 일반, 10/6초는 준비 강조, 5/1초는 urgent 클래스, 0초는 경고 제거와 다음 완료 버튼 복귀를 확인했다. 이 경계 관찰 내내 제품 저장 쓰기는 1회로 유지됐다.
- 5초에서 +30초 후 35초 일반 표시, 수동 종료 후 경고 제거, 5초 상태의 새로고침·이어하기·기록 탭 왕복 후 복원을 확인했다.
- 브라우저의 `prefers-reduced-motion: reduce` 실제 값이 **true**였다. 5초 urgent 상태에서 계산된 `animationName`은 **none**이고 문구·색상은 유지됐다. 기본 모션의 1.6초 배경 강조 CSS도 확인했지만 이 브라우저 설정에서는 애니메이션을 직접 관찰하지 않았다.
- 실제 완료 취소 후 0세트·편집 가능 상태를 확인하고 11→8 수정 후 행 완료로 저장했다. 두 번째 세트는 +1로 8을 만든 후 하단 완료를 사용해 같은 휴식 전이를 확인했다.
- 마지막 본세트 완료 시 현재 종목에 머물며 즉시 `다음 종목으로`와 전환 경과시간을 표시했다. 경고·휴식 카운트다운은 없었다.
- 다음 종목 초안 1→11 직접 입력과 ±1을 확인하고 완료했다. 전체 완료 후에도 활성 세션이 유지됐고, 새로고침 후 수동 종료 대기 상태와 실제 값이 복원됐다.
- 명시적 종료 후에만 세션 한 건이 생성됐다. 최종 실제 값은 벤치 60kg `8/8/10`, 인클라인 20kg `11`, 총 4세트·1,780kg 볼륨이었다. 승인 중량 변경 사건은 생성되지 않았다.

### 검증 중 문제 및 정리

- 로컬 Vite 최초 실행은 Console Ninja의 `127.0.0.1:3119` 연결이 sandbox에서 EACCES로 차단되어 종료됐다. 로컬 검증에 한정한 실행 권한이 허용된 뒤 정상 시작했다. 설정 파일을 바꾸지 않았다.
- 기존 완료 취소의 브라우저 confirm에서 DOM 자동화가 timeout됐다. 키보드로 확인창을 처리한 뒤 실제 완료 취소 상태와 재수정·재완료를 확인했다. 제품의 확인 흐름을 우회하거나 교체하지 않았다.
- 자동 검사 실패와 미해결 구현 오류는 없다. 패치 적용 중 파일 위치 확인 오류는 실제 파일을 확인한 뒤 수정했으며 부분 덮어쓰기는 없었다.
- 검증 서버 실행 세션 `68778`을 Ctrl+C로 종료했고 3048 listen 연결이 0건임을 확인했다. 생성 탭 12를 닫고 viewport override를 복원했다. 기존 사용자 서버는 건드리지 않았다.
