## 데이터 호환성 및 저장·복원

- 로컬 키 `overload.core.v1`과 버전 1을 유지한다. 기존 저장값을 로드 시 마이그레이션하거나 다시 쓰지 않는다.
- 현재 종목 ID, 완료 스냅샷의 `completedAt`, 기존 transition/rest 구조를 그대로 이용한다. 화면 진입만으로 자동 이동이나 새 타이머가 생기지 않는다.
- 미완료 초안을 이력에서 제외하면 당시 변경된 계획 수를 복원할 수 없으므로 새 이력에 종목별 `plannedSetCount`를 추가했다. 원본 루틴의 `setCount`나 실제 기록을 수정하는 대신 종료 직전 현재 세트 수만 보존한다.
- 기존 이력에 선택 필드가 없으면 임시 변경되지 않은 종목은 원래 `setCount`로 완료 범위를 계산한다. 임시 변경된 과거 이력은 계획 수를 추측하지 않고 `당시 계획 수 미확인`으로 표시하며 전체 완료라고 단정하지 않는다.
- 실제 세트 번호·중량·횟수·완료 시각·오늘만 변경 스냅샷, 승인 중량, 기준 기록 비교 규칙과 모든 실제 이력을 보존한다.
- 손상 데이터 차단, 저장 실패 시 메모리 입력 유지, 다중 탭 충돌 방어 코드는 유지했다. 새 선택 필드의 손상 차단도 테스트한다.

- 375×812, 390×844, 430×932 뷰포트에서 운동 화면을 확인했다. 스크롤바를 제외한 문서 폭은 뷰포트 안에 있었으며 가로 넘침은 없었다.
