## 접속과 데이터 보호

1. PC의 `overload-pwa`에서 `npm run dev`를 실행한다. 검증용 서버는 작업 후 종료했으므로 다시 실행해야 한다.
2. iPhone과 PC를 같은 **신뢰 Wi-Fi/LAN**에 연결한다. 기존 `server.host: true`, 포트 3000 설정을 유지했다. 인터넷 공개 배포나 포트 포워딩은 하지 않는다.
3. PC에서 `ipconfig`로 실제 사용 중인 네트워크 어댑터의 IPv4 주소를 확인한다. Safari에 `http://<개발 PC의 LAN IP>:3000`을 입력한다. `<...>`는 실제 주소로 교체하며 IP는 추측하지 않는다.
4. 연결되지 않으면 개발 서버의 포트·실제 LAN IP·같은 네트워크 여부·방화벽 허용 상태를 점검한다. 방화벽을 통째로 끄지 않는다.
5. 기존 데이터가 있으면 `Task004 시험` 같은 별도 루틴/종목을 만든다. **사이트 데이터 삭제, localStorage 초기화, 실사용 루틴 삭제를 수행하지 않는다.**
6. 같은 기기에서도 호스트/IP·포트·브라우저가 달라지면 저장소가 다르다. 복원 시험에서는 동일한 Safari 주소를 사용한다. PC 기록이 iPhone에 자동으로 나타나는 기능은 없다.
7. LAN HTTP에서 운동 시작을 막던 UUID 오류를 수정했다. 실제 iPhone에서도 M04를 먼저 확인한다.

## 현재 구현의 경계

- localStorage 저장은 서버 백업이 아니다. 서버 동기화/전송 재시도/백업·복원/IndexedDB/Service Worker/설치형 PWA/푸시 알림은 이번 작업에서 구현하지 않았다.
- 네트워크가 끊긴 상태에서 새 탭·새로고침·앱 재실행이 실패하는 것은 현재 예정된 제한이다. M22는 **이미 로드된 화면의 로컬 기록 지속**만 시험한다.
- 데스크톱의 16px 이상 글꼴/CSS Safe Area/타임스탬프 계산 확인은 iOS 키보드·Safari 스크롤·화면 잠금 검증을 대체하지 않는다.
