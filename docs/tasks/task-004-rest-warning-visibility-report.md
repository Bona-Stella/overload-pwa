## Summary

일반 본세트 사이 휴식의 남은 시간이 10초 이하이면, 기존 하단 고정 `휴식 종료`/`+30초` 버튼 바로 위에 호박색 준비 카드가 나타난다. `다음 세트 준비`와 큰 초 숫자를 함께 표시하고, 5~1초에는 숫자 배경만 기존 1.6초 주기의 부드러운 강조를 적용한다.

상단 전체 운동 시간·휴식 시계와 색상 강조를 유지했다. 준비 문구는 하단에 모아 중복을 줄였다. 상단 헤더 높이가 경고 진입 때 바뀌지 않으며, 경고 표시를 위한 자동 스크롤·포커스 이동도 없다.

### 표시 계약

| 상태 | 하단 준비 카드 |
| --- | --- |
| 일반 휴식, 11초 이상 | 없음 |
| 일반 휴식, 10~6초 | 호박색 카드·`다음 세트 준비`·남은 초 |
| 일반 휴식, 5~1초 | 같은 카드·큰 숫자·숫자 배경의 느린 pulse |
| 0초 또는 만료 | 즉시 숨김, 기존 `휴식 완료`와 다음 세트 완료 조작 |
| `+30초` 후 10초 초과 | 즉시 숨김, 다시 10초가 되면 재표시 |
| 수동 `휴식 종료` | 즉시 숨김 |
| 워밍업·일반 입력 대기·종목 전환·전체 완료 대기 | 없음 |

상·하단은 같은 기존 `Math.ceil((endAt - now) / 1000)` 파생값을 읽는다. `10.001초 → 표시 11초`에서는 카드가 없고 `10초 → 표시 10초`에서 진입한다. 실제 휴식이 남아 있는 1ms는 1초로 보이며 만료 순간에는 사라진다. 자동 세트 완료·종목 이동·운동 종료는 발생하지 않는다.

### 실제 브라우저 및 스크롤

CUA로 데스크톱 Chromium에서 실제 App을 조작했다. 격리한 loopback `127.0.0.1:3050` fixture의 UI로 현재 시각을 제어하여 시간 경계를 재현했다. fixture는 소유 표식 없는 기존 데이터를 덮어쓰지 않으며 production 진입점에서 import하지 않는다. QA 패널은 fixed이므로 시간 버튼을 누르기 위해 본문으로 스크롤하지 않고, pointerdown의 기본 포커스를 막아 실제 입력 포커스도 유지한다.

- **중간 스크롤:** 375px에서 두 번째 반복 입력에 포커스를 둔 `scrollY=377` 상태로 11→10→6→5→1→0→만료를 확인했다. 매 단계에서 스크롤은 377, 포커스는 `2세트 이번 반복 횟수`로 유지됐다. 하단 카드와 상단 시각이 일치했다.
- **아래쪽 스크롤:** `scrollY=590`, 메모 입력 포커스 상태에서 11→10→5초 진입을 확인했다. 스크롤·포커스가 유지됐으며 메모 카드의 하단 y=587.47은 고정 영역 상단 y=653.41보다 위에 있어 마지막 본문까지 접근할 수 있었다.
- **저장 부작용:** 최초 일반 휴식과 두 번째 초안 7회 입력 후 시간·motion·viewport 변경 동안 core 저장 JSON이 동일했고 쓰기 횟수는 5회로 유지됐다. +30초는 기존 동작대로 종료 예정 시각만 저장했다. 연장된 타이머에서도 시간 표시 변경 전후 core JSON의 정확한 동일성을 별도로 확인했다.
- **연장·복원:** 5초에서 +30초 후 35초/카드 없음, 다시 10초 진입 시 카드 재표시, 새로고침·이어하기 및 홈→기록→홈 왕복 후 같은 5초 카드와 종료 시각을 확인했다. 로드·탐색만으로 쓰기는 발생하지 않았다.
- **제외 상태:** 워밍업, 수동 휴식 종료, 마지막 본세트 후 종목 전환, 다음 종목으로 이동한 뒤 경과시간, 모든 종목 완료 후 수동 종료 대기에서 카드가 없었다.
- **포커스:** 세 화면 크기에서 숫자 입력이 포커스를 유지했고 카드가 해당 입력을 가리지 않았다. 데스크톱 numeric 입력 확인이며 iOS 가상 키보드 검증을 뜻하지 않는다.

### 모션·접근성·대비

- 실제 브라우저의 reduced-motion 선호 값은 true였다. 5초에서도 계산된 animation은 `none`이며 문구·숫자·색상은 유지됐다.
- 일반 모션은 fixture UI에서 **reduced-motion CSS override만 일시 비활성화**해 실제 제품의 기본 애니메이션을 관찰했다. `rest-ready`, `1.6s`, `ease-in-out`, `running`을 확인하고 숫자 배경의 시간에 따른 보간값 변화도 수집했다. 이후 reduced-motion 규칙을 복원했다. OS 설정은 변경하지 않았다.
- 카드 문구와 `N초`를 함께 제공하고 `role="status"`를 사용한다. 준비 문구는 화면에 한 번만 나타난다. 색상만으로 상태를 설명하지 않으며 화면 이동·전체 화면 점멸은 없다.
- 카드 전경 `#ffdda3`/배경 `#3c2a17`의 계산 대비는 약 **10.50:1**, pulse의 가장 밝은 배경 합성 시 숫자 대비는 약 **7.14:1**이다.
