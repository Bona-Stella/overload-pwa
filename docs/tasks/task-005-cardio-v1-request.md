## 1. 제품 원칙 — 웨이트와 유산소를 하나의 운동 세션에 기록

- 평소 루틴에 유산소를 **미리 등록**할 수 있어야 한다. 웨이트가 있으면 그 뒤에 예정된 유산소로 이어진다.
- 미리 등록하지 않았더라도 **모든 웨이트 종목 완료 후**, 종료하기 직전에 `+ 유산소 추가`를 선택할 수 있어야 한다. **매번 질문하는 모달을 띄우지 않는다.** 사용자가 그냥 `운동 종료 및 요약`을 눌러도 된다.
- **운동 화면 상단에 상시 노출되는 큰 `+ 유산소 추가` 버튼은 만들지 않는다.** 운동 중 일찍 추가하고 싶을 경우에는 기존 `현재 세션에서 세트 / 종목 변경` 등 세션 편집 메뉴에서 **오늘 세션에만** 유산소를 추가하게 한다. 원본 루틴은 변경하지 않는다.
- **유산소만 있는 루틴**도 생성·시작할 수 있게 한다. 웨이트 없이 유산소 준비 화면으로 바로 들어가고 웨이트 세트/휴식 입력을 강요하지 않는다.
- 예정된 유산소를 건너뛰고 종료하는 것도 허용한다. 미수행을 완료로 조작하지 않으며, 기록에서 부분/미수행 사실을 구분한다.
- 웨이트의 마지막 본세트 → `다음 종목으로` 수동 이동 / 전체 운동 명시적 종료, 중간 세트 휴식, 진행 중량·기준 기록·증량 이력 정책은 유지한다. 웨이트 수량과 유산소 완료 수량을 잘못 합산하지 않는다.

## 2. 루틴 만들기 / 편집하기 — 유산소 계획 항목

### 공통
- 웨이트 외에 **유산소 유형의 종목**을 루틴에 추가/편집/삭제할 수 있게 한다. 사용자가 구분 가능한 종류를 선택한다: 최소 `러닝머신`, `실내 자전거`, `야외 러닝`, `계단 운동`, 필요 시 `기타 유산소`(자유 이름). 기존 운동 종목/루틴 식별자와의 충돌을 막는다.
- 유산소 계획 항목은 웨이트처럼 중량·본세트·반복 횟수를 입력받지 않는다. **유산소에 적합한 입력 UI로 전환**한다.
- 유산소를 추가하면 기본 순서는 웨이트 뒤에 둔다. 루틴 내 유산소 항목은 명확한 순서를 갖고, 같은 루틴의 두 유산소 종목도 구분된다. 원본 루틴의 등록 항목과 실제 세션 스냅샷은 분리한다.
- 기존 루틴의 웨이트 정의·진행 중량·요일 배치를 손상시키지 않는다. 휴식일/오늘만 루틴 선택의 기존 규칙도 보존한다.

### 등록 시 입력값 (V1)
- **유산소 종류**: 필수.
- **목표 시간**: 필수, 분/초 또는 분 단위 등 간단한 UI, 유효한 양의 시간.
- **목표 거리(km)**: 선택, 거리 측정 가능한 종목에서 표시. 모르면 비워둘 수 있다.
- **설정 속도(km/h) 또는 페이스(min/km)**: 선택. 둘 다 강제 입력하지 말고 한 모드만 입력하게 하며 다른 값은 필요할 때 파생 표시한다. 소수/시간 변환에서 분모 0, 무한대, 부동소수 오차, 미입력값을 방어한다. 이것은 계획값이지 실측 평균값이 아니다.
- **경사도(%)**: 러닝머신 등 해당 기구에만 선택 노출. 실내 자전거에는 경사도 대신 **저항 레벨**을 선택 입력으로 제공할 수 있다. 야외 러닝에 기구 경사도 강제 입력 금지.
- 심박수·칼로리·GPS·웨어러블·외부 연동은 루틴 입력 필드로 추가하지 않는다. BPM은 완료 시 수동 선택 입력만 허용한다.
- 검증: 필수값 누락, 음수·NaN·Infinity·비정상 범위, 알 수 없는 타입을 방어하고, 빈 선택값을 0 기록으로 위조하지 않는다.

## 3. 운동 실행 흐름 및 타이머

1. 전체 운동 경과 타이머는 기존 정책대로 작동한다. **유산소 별도 실수행 타이머**를 제공한다. 웨이트 완료, 다음 유산소 화면 진입, 러닝머신 이동·기구 준비만으로 유산소 타이머를 자동 시작하지 않는다.
2. 유산소 준비 화면에서 계획(종류·목표 시간·목표 거리·설정 속도/페이스·기구 옵션)을 보여주고 **`유산소 시작`을 직접 눌러야** 별도 시간 측정을 시작한다.
3. `일시정지`/`재개`/`유산소 완료`를 지원한다. **일시정지 구간은 유산소 실제 운동 시간에서 제외**한다. 전체 운동 타이머는 기존대로 흐른다.
4. 시작·누적 활성 시간·일시정지 시각 등에 대한 시간 기반 모델로 계산하고, Safari 백그라운드·잠금·새로고침·홈→이어하기 이후에도 측정 시간과 상태를 복원한다. 렌더링 프레임 또는 JS setInterval 호출 횟수만으로 시간을 누적하지 말고, 매초 저장하지 않는다.
5. 목표 시간이 지나도 **자동 완료하거나 종료하지 않는다.** 사용자가 명시적으로 완료를 눌러야 한다.
6. 일시정지/미시작/진행 중인 유산소를 건너뛰거나 운동을 종료할 경우 기록 누락 여부가 불분명하지 않도록 경로를 마련한다. 예를 들어 미완료 상태에서 종료 시 `기록하고 완료`와 `건너뛰고 종료`를 명확히 구분한다. 중복 완료/중복 기록 방지.
7. 유산소가 2개 이상일 경우 한 종목씩 진행하고 다음 종목으로 이동 가능. 유산소 뒤에 더 진행할 종목이 없을 때만 최종 운동 종료를 제공하되, 일반 세션의 조기 종료/부분 저장 경로는 계속 허용한다.
8. 웨이트 일반 휴식시간의 `10초/5초 하단 준비 카드`는 **유산소 타이머에는 적용하지 않는다.** 유산소 별도 타이머를 휴식 카운트다운과 혼동하지 않는다.

## 4. 유산소 완료 입력은 최소화

- `유산소 완료` 시 **실제 운동 시간은 유산소 타이머에서 자동 채움**. 기본적으로 다시 입력시키지 않는다.
- 완료 시 직접 입력하는 것은 원칙적으로 **실제 거리(km)**와 **평균 심박수(BPM)**뿐이며, 둘 다 측정하지 않았다면 비워둘 수 있다. 거리를 제공하지 않는 기구에는 실제 거리 강제 금지.
- BPM은 **수동 평균값 기록**이며 측정 기능처럼 표현하지 않는다. 칼로리 추정·자동 페이스 산정·외부 센서 연결은 넣지 않는다.
- 사용자가 타이머를 종료하지 않고 방치했을 때처럼 특별한 상황에 한해 **완료 요약의 실제 시간 수동 정정**을 제공한다. 자동 기록값과 수동 정정 여부가 분명해야 하며 과거 시간·거리 값을 임의 계산해 생성하지 않는다.
- 완료 확정 전 수정/취소는 가능해야 한다. 완료 기록에는 최소 종류, 당시 계획 스냅샷, 실제 활동 시간, 입력한 실제 거리/평균 BPM, 완료 시각을 보존한다. 진입만 했거나 미수행인 계획값을 실제 수행으로 저장하지 않는다.

## 5. 기록·홈·부분 운동

- 한 번의 운동 완료 이력에 **웨이트 실제 완료 본세트와 유산소 실제 완료 기록을 함께** 저장한다. 상세 화면에서 명확하게 분리해 보여준다.
- 기존 **웨이트 볼륨 = Σ(kg×실제 반복 횟수)** 로만 계산. 유산소 거리·시간·BPM을 웨이트 볼륨이나 세트 수에 합산 금지.
- `웨이트 n/m 세트`와 `유산소 완료 k/j 종목`처럼 각각 사실대로 표시한다. 유산소 미완료/건너뛴 종목이 있다면 전체 루틴 완료라고 거짓 표시하지 않는다. 기존 부분 기록도 그대로 유지한다.
- 홈의 진행 중 운동 카드/이어하기에는 유산소 준비·진행·일시정지·완료 확인 등의 정확한 상태를 표시하고, 유효할 때 유산소 경과시간을 제공한다. 재진입해도 같은 유산소 종목과 초안·시간 상태가 유지된다.
- 유산소 기록만 있는 세션도 운동 종료 후 기록 목록/상세에서 정상 조회된다. 원본 루틴에 없는 오늘만 유산소도 해당 세션 이력에는 남는다.
- 기존 증량/감량 권고, 최고 **단일 완료 세션** 기준 기록, 승인 중량과 오늘만 중량, 변경 이벤트 및 기존 세션 기록 보존. 유산소만 수행했다고 웨이트 benchmark를 갱신하거나 판단 근거로 사용하지 않는다.

## 6. 로컬 저장 호환·안전

- 현재 저장 키 `overload.core.v1`와 기존 데이터는 보호한다. 기존 데이터를 지우거나 강제로 초기화하지 말고, **기존 v1 데이터를 안전하게 로드**할 수 있게 타입·검증·필요 최소한의 호환 처리를 설계한다. 스키마 버전 변경이 정말 필요하면 무조건적인 리셋 대신 명시적인 버전/마이그레이션 방안을 코드·문서에 구현하고 근거를 보고한다.
- 유산소 신규 엔티티 ID·종목 배치 ID·계획과 실제 결과를 구분하며, 구 저장 데이터에 없는 선택 필드의 기본값·검증을 명확히 한다.
- 완료·취소·재시도, 저장 실패의 표시, 다중 탭 충돌 차단 등 기존 방어를 우회하지 않는다. 실패 시 성공했다고 표시하거나 운동 기록을 잃게 하지 않는다.
- 브라우저 origin이 달라지면 localStorage도 별개임을 고려하고, 테스트 전용 origin에서 검증한다. 기존 사용자 iPhone 데이터/브라우저 저장값 삭제 금지.

## 7. 수용 테스트 — 반드시 포함

1. **Task 004 회귀:** 기존 전체 테스트를 통과시킨다. 웨이트 루틴 CRUD, 주간 기본/오늘만 선택, 워밍업, 세트 ±1, 중량 ±2.5, 중간 휴식 및 10/5초 경고, 마지막 세트의 수동 다음 이동, 명시적 종료, 기준 기록/승인 이력·부분 저장/복원 유지.
2. **등록:** 웨이트 뒤에 유산소 1개 또는 2개 계획, 편집·삭제·재정렬 가능 범위, 유산소만 있는 루틴, 휴식일/오늘만 루틴. 유산소 필드는 웨이트 필드와 다르게 노출.
3. **진입점:** 웨이트 진행 중 상단에 상시 `+ 유산소 추가` 없음; 모든 웨이트 완료 후 종료 영역에 `+ 유산소 추가`; 종료 선택 시 팝업 강제 없음; 세션 편집 메뉴에서 오늘만 유산소 추가; 예정 유산소 있으면 다음 유산소 준비 화면으로 이동.
4. **시간:** `유산소 시작` 전 별도 타이머 0, 시작 후 증가, 일시정지 동안 불변, 재개 후 증가, 목표 초과 자동 종료 없음, 완료에서 실제 시간 자동 기록, 새로고침/홈 이어하기/탭 이동 시 정확한 복원. 필요 시 테스트용 가짜 시계를 사용하고 매초 저장하지 않음을 확인.
5. **결과:** 실제 거리/BPM 미입력 가능, 각각 선택 입력·검증, 수동 시간 정정, 목표값과 실제값 분리, 유산소 건너뛰기, 2개 유산소, 부분 종료, 유산소 전용 세션 이력, 중복 완료 차단.
6. **격리:** 웨이트 볼륨·세트·증량 권고에 유산소 혼입 없음, 원본 루틴/오늘만 분리, 이미 존재하는 v1 데이터 로드·새 저장 왕복, 손상 데이터 및 저장 실패 방어.
7. **실제 브라우저 DOM**에서 적어도 375×812, 390×844, 430×932 뷰포트와 고정 상·하단 버튼/스크롤/가로 오버플로, 입력 및 수동 완료 동작을 확인. iPhone Safari를 직접 실행하지 못했다면 미검증이라고 분명히 기록한다.
